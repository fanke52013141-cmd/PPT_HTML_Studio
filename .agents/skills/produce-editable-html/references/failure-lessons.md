# 从实际开发中提取的失败经验

证据来源（仓库根目录相对路径）：
`docs/plans/workflow-first-parallel-2026-10-09/deliveries/WORKFLOW-ACCEPTANCE.md`、
`docs/plans/workflow-first-parallel-2026-10-09/deliveries/CANDIDATE-AGENT.md`。
这些是历史实验，不代表所有输入已验证。

| 出现的问题 | 下次必须执行的动作 | 验证责任 |
| --- | --- | --- |
| 人工制作的示例与自动生成混在一起 | 标明模型、程序、人工各自负责什么；记录人工计划或场景修改次数 | 实验记录 |
| 检查通过却没有展示本次 HTML | 打开当前任务实际产物，核对 revision、截图和输入 | 交付验收 |
| 已有图片误入新生图流程 | 明确 assetRef，验证身份、版本和文件内容 | 素材服务与调用方 |
| 初稿未保存就溢出，已保存修复入口无法处理 | 使用未保存候选 Agent，严格校验通过后保存 | 生产服务 |
| 调用遗漏 schema_hint，宽松 mock 没发现 | 真实签名约束测试，覆盖必填参数 | 代码测试 |
| 看见本地约 350 KB 报告就归因于请求过大 | 检查真实模型输入；正常 evidence 已摘要，HTTP 500 根因仍未确认 | 诊断记录 |
| 合理主体与锚点标签重叠被判碰撞 | 按注册关系排除，记录理由并保留原报告 | 几何检查与审阅 |
| 停止观察后误认为供应商请求已取消 | 分开记录本地任务、服务和供应商状态 | 运行服务 |
| 一个冷杯案例成功就认为全部跑通 | 增加长短文案、不同注册模板、人工锁定与错误资源案例 | 回归评估 |
| 有 SKILL.md 就认为 Agent 已使用 | 检查加载入口和实际请求中的版本记录；当前没有 Markdown 自动加载 | 运行时集成 |
| 只追求容量通过，文字越来越小 | 同时审阅字号层次、可读性、留白、对齐与素材融合 | 视觉审阅 |

## 两个必须纠正的表述

错误：本地报告很大导致 HTTP 500，压缩后解决。

准确：正常输入已经摘要；该次 HTTP 500 根因没有确认。后来一次重试成功，不证明之前的失败原因。防御性过滤原始 frames 也不能表述成正常请求的已证实性能收益。

错误：测试通过，整个视频流程已经完成。

准确：报告实际通过的工程检查与真实模型案例；视觉批准、确认音频、视频导出未执行时明确标注。作者时钟与有限时间采样不能代替这些验收。

Skill 负责路由、操作顺序和证据要求；Prompt 负责模型决策约束；代码负责 Schema、权限、版本冲突、重试上限和保存门槛。不得用更长的 Skill 代替缺失的代码校验。
