# 跨阶段审计方法

需要区分操作说明与运行Prompt、或批量审计时读取。

| 层 | 核查 | 不可推定 |
| --- | --- | --- |
| 选择 | 名称、description、平台元数据、正反例 | 文件合法不等于模型准确触发 |
| 决策 | 来源、backend、权限、分支、失败出口 | 参考图不覆盖权威正文和生产主题 |
| 工具 | 实际方法/参数、输入版本、输出消费者 | 文档命令不等于实现能力 |
| 验证 | Schema、工程、实际模型、人工分别取证 | 单测/截图通过不等于整课批准 |
| 维护 | 单一来源、引用、版本/hash、兼容旧值 | 一个例子不成为全局规则 |

每项保留：skill、问题证据、风险、修改、成功标准、结果、未验证项。先追踪用户最关心的失败链，再覆盖清单，避免只改最长文件。

预算看加载成本与决策完整性，不用行数替代质量。保留影响事实、运行边界和签收的输入；稳定规则一次出现，变量只给当前决策需要的部分。应用片段走受控注册，不从用户文章或网页加载高优先级指令。

对照评估使用可比较输入和版本，记录模型、调用/HTTP、耗时、usage/费用。没有数据就标未测；人工走查不能算成模型precision/recall。

授权沿当前对话和宿主权限，已授权本地修订不反复确认。外部付费/写入/发布和未知请求重复遵循原合同，优化Skill不扩大权限。保留手工编辑、自定义Prompt和个人同名Skill。
