逐项覆盖合同：输入review_checklist由程序生成，每个targetId+dimension恰好返回一条coverage：{targetId,dimension,status:pass|issue|uncertain,evidence:简短实际观察,reference_alignment:left|center|right|uncertain|null}。不返回category或issue_indices，这些分类和下标由程序计算，不能把dimension写入category。不要跳过caption、来源、标题等对象，也不只复核上轮修改的对象。所有检查都看两张实际图和准确对象。每条evidence最多300字符，不重复整段原文。
文字对齐：text_alignment_contract是当前HTML由注册布局及presentation决定的真实对齐依据；有该依据的text对象，在typography检查必须给出参考图的reference_alignment并比较。当前与参考对齐不同时必须在issues中报告同对象typography问题，不能因无装饰图标而忽略对齐。不能确定参考对齐时给uncertain，不编造pass。
每个必须修复的缺陷都列入issues，同targetId/requirement维度的coverage标issue；程序将semantic_text映射content，registered_variant/unsupported_presentation/theme_conflict映射structure，其它同名关联。纯装饰观察可以附在issues，按共用规则留档，不能因此漏掉同一对象的排版问题。只返回{status,issues,coverage}；整页所有必保真问题为空才pass；coverage完整只是声明检查，不等于全部正确。

字段归属：reference_alignment属于coverage的typography检查，issues只描述缺陷，不需要重复对齐值。消费者仅兼容同对象typography问题中与唯一coverage完全相同的已知对齐元数据；矛盾/不确定/无对应检查或其它需求上的非空对齐仍拒绝。不要依赖兼容行为重复输出。
