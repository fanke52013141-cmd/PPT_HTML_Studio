# 项目交接：节点状态与下游影响优化

交接日期：2026-09-28。代码仓库：`PPT_presentation_video`。本交接覆盖当前工作区的已实现改动；历史项目数据不在本轮检查范围内。

## 用户问题与目标

用户在生成视频后，仅点击前面的节点就遇到重新生成提示，部分写入还会清掉后续成果。目标是让节点导航保持只读；在**实际内容变化时**准确说明受影响的页面和产物；默认保留旧成果，支持暂缓、检查和后续重新生成；处理成功后自动结清相应提醒。

## 本轮已落地

- `invalidation_service.py` 集中处理业务失效；`impact_registry.py` 登记原因、范围和受影响产物；`project_impact_service.py` 将待处理记录存入项目的 `planning/pending_impacts.json`。该文件属于运行数据，不进入 Git。
- 点击步骤只导航。文章正文变化先标记分镜待核对，不立即清除已有图片、音频或视频合成配置。
- Step 2 根据稳定 `slide_id` 比较视觉输入、旁白文本、增删页和顺序变化。只改旁白不标图片/Mask 过期；仅排序只要求更新输出；删除页资产归档以便恢复。
- Step 3 替换和删除图片前归档旧图及 Mask。上传文件若归一化后的主图和实际生效 raw pair 都与当前相同，则不写入、不归档、不触发下游失效。音频保持可用。
- Mask、旁白、音频、标注、数字人、字幕和视频背景的实际变化分别登记影响。相同值保存尽量保持无操作；标注/数字人变化仅要求新输出，不删除旧视频。
- 影响记录支持按产物逐项结清，并保留已解决记录供审计。异步视频任务启动时捕获记录代号；新修改会递增代号，旧任务不能结清新提醒。渲染输入在任务期间变化时，不将该结果登记为当前成品。
- 视频新鲜度指纹包含标注时间轴和实际参与合成的数字人配置；头像、口型模式等仅用于未来素材生成的字段不误报旧 MP4 过期。
- Agent 数字人配置写入复用 Web 侧影响逻辑，Agent 合约版本和能力矩阵已同步。

## 验证与已知限制

定向测试覆盖分镜差异、失效矩阵、影响记录代号、图片相同内容上传、数字人/标注无变化保存、视频渲染竞态及 Agent 合约。前端 `node checks/test_frontend_quality.js` 与 `node checks/test_visible_flow.js` 已通过。完整 `checks` 测试在 AI Mask 的 `test_detect_elements_is_pixel_deterministic_across_fresh_dirs` 失败；这项失败曾在本轮状态影响改动前出现，尚未定位根因，不应宣称全量通过。

本轮仍未完成：图片替换时提供完整的“保留待核对/主动清理”三选项；Mask 和标注几何的人工复用确认；所有写入入口使用内容哈希绑定影响版本；数字人生成素材与音频变更的完整联动；完整的清理前受影响文件预览。详见 `docs/downstream-impact.md` 的状态列。当前旧产物默认保留，失效标记并不代表必须从头生成。

## 后续接手顺序

1. 先补清理前预览和用户选择，清理动作限定在具体页面和具体产物，保留归档恢复路径。
2. 再补按页复用确认：图片变动后可选择沿用旧 Mask/标注，但必须通过当前输入哈希或预览确认；不可单靠“已查看”解除提醒。
3. 补齐每个影响写入点的 `source_version`，并让异步图片、音频、PPTX 等任务像视频一样使用任务启动快照。
4. 调查 AI Mask 像素确定性测试，再跑完整测试与真实项目端到端验收。

开发时遵守根目录 `AGENTS.md` 的模块边界和 Agent Contract Synchronization Policy。新增写入功能须同步更新 `impact_registry.py`、`docs/downstream-impact.md` 与对应回归测试。
