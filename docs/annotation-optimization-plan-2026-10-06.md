# 勾画标注优化与实施方案

日期：2026-10-06。范围：用户可见 Step 6「勾画标注」，内部 annotation / Step 10 链路，以及必要的音频、Reveal、视频输出衔接。

本文为待实施方案，不代表这些能力已经交付。以当前工作区（包含既有未提交修改）为设计基线；不覆盖、不回退其他工作。所有新增字段、模块、接口和数值阈值均为建议设计，实施时通过契约与实测冻结。

## 1. 目标与验收边界

交付后，用户应能够：

1. 让 AI 推荐重点并生成圈、下划线、荧光笔；也能手工选目标使用工具，或直接自由绘制。
2. 每条标注明确绑定「画面里的目标」和「演讲稿里的触发内容」。二者分别存储，允许措辞不同。
3. 在对应内容已经可见、旁白讲到所选内容时，从无笔迹开始播放完整绘制过程。
4. 一笔一笔按保存的轨迹和顺序绘制，最后有明确的完整形态；允许缩短绘制时长，不能切掉路径。
5. 在工作区听到真实音频、看到真实画面显现，并预览与导出一致的标注时间和笔迹。
6. 只标部分页面；其他页面正常导出，不需要伪造标注。
7. 自动定位失败时，人工选词、试听、校准时间，仍能完成这条标注并导出。

「完整轨迹」指保存轨迹在离散视频帧上从起点逐步推进到终点，不要求保留用户绘制时每一次停顿，也不要求每个原始采样点各占一帧。默认保留路径形状、笔画顺序、抬笔边界，统一调整播放速度。

视频 MP4 是动态勾画验收对象。当前图片型 PPTX 不具有这套视频时间轴；不能把 MP4 的动态能力宣称为 PPTX 内的原生动画。PPTX 的标注终态输出属于另行明确的导出选项。

## 2. 已确认的问题与修复对应关系

| 当前问题 | 用户影响 | 必须采取的措施 |
| --- | --- | --- |
| anchor 保存字词范围，时间轴只读取 beat 起点 | 句末关键词在句首先画 | 音频字词定位与明确的文本映射 |
| 标注没有统一加入 audio_start_sec | 整体提前，可能圈空白 | 页面时钟统一，延迟只在一个地方应用 |
| 同 beat 多条默认争抢一个起点 | conflict_beyond_tolerance 阻塞 | 先用真实关键词时间，再执行有限调度 |
| 项目启用后每页都要求非空 events | 部分页面标注无法导出 | 空页面明确视为有效无标注页 |
| beat_end 再加退出时间越过页尾 | 最后一句确认失败 | 最终页长计算、有限收敛与清晰错误 |
| 确认先成功，时间轴后失败 | 界面已完成，导出失败 | 构建就绪后发布确认版本 |
| 预览临时顺排且没有真实声音 | 无法判断实际同步 | 正式时间轴与笔迹资产复用 |
| 未起笔就显示第 0 张非透明图片 | 多笔提前露出笔头 | 每笔开始前隐藏，0% 帧透明 |
| anyRaster 控制全局矢量回退 | 混合资产时漏画 | 禁止整层静默回退，逐笔诊断与重建 |

额外实施注意：当前一个 beat 可以拆成多个 subtitle segment。不能用字典推导让后一个 segment 覆盖前一个；句级范围应按 beat 聚合 min(start)/max(end)。这仍然只是句级范围，不能充当词级时间。

## 3. 用户操作流程

### 3.1 AI 辅助

进入模块 → 识别文字/读取已有候选 → AI 推荐重点 → 建立画面目标与讲稿引用 → 定位音频 → 检查目标可见时间 → 生成预览 → 用户确认 → 可导出。

操作原则：

- 已有有效 OCR、路径、音频定位结果按输入哈希复用。
- AI 的每条结果要显示「圈哪里」「讲到什么时画」「采用什么样式」。
- 推荐只写入草稿，不直接确认。用户修改或锁定的条目继续保留。
- 本页没有合适重点是有效结果，显示「本页无推荐，可手动添加或跳过」。
- OCR 无字级框时，不均分行框伪造字框；允许人工框选目标。
- 第一交付版优先做到 AI 文字目标稳定可用。自动圈图表、插图等非文字对象作为后续增强；人工区域标注始终可用。

### 3.2 使用现有标注工具

支持两种同等有效的操作顺序：

- 先选讲稿短语，再选择画面文字或框选区域，生成圈/线/荧光笔。
- 先选择画面目标并生成笔迹，再选择讲稿短语完成绑定。

新建时如果已有当前页有效讲稿选区，自动使用；没有选区则显示「待关联讲稿」，不能悄悄当作已同步、默认 0 秒确认。保留用户显式选择「指定时间」的能力。

讲稿选区必须绑定当前 project、slide、beat、文本版本。切页后清空，防止旧选区误用。

### 3.3 自由手绘

进入自由绘制 → 按下开始一笔 → 移动记录轨迹 → 抬笔结束该笔 → 可继续下一笔 → 点击完成 → 关联讲稿 → 预览确认。

- 一次手绘标注允许多笔，抬笔后不自动退出整个绘制模式。
- 笔迹保存多个独立 stroke，不把多笔连接成一条线。
- 支持撤销最后一笔、重画、删除整条。
- 缩放、横竖屏、画布滚动后坐标仍转换为项目画布坐标。
- 抽稀保留首尾、转折、闭合点；超过点数预算时对整笔重采样，不截取最后若干点丢掉前半段。
- 压感可作为可选信息；无压感设备也必须可用。
- 可以保留采样时间用于未来「原速回放」，首版默认按路径长度分配时长，避免手绘停顿造成长时间卡笔。

### 3.4 人工时间校准

右侧显示目标讲稿，播放对应真实音频；用户可在听到关键词时「设为起笔点」，并使用波形/时间刻度进行微调。

提供：播放前后约 1–2 秒、循环试听、起笔时间微调、绘制时长调整。波形和标尺为音频控制工具，不参与 PPT 正文绘制。

人工校准保存引用的音频哈希、讲稿范围和校准来源。音频改变后标为待复核，不沿用旧值宣称准确。

## 4. 音频定位：可落地的技术路线

### 4.1 优先级

| 路径 | 使用条件 | 产物精度 | 是否可直接满足准确同步 |
| --- | --- | --- | --- |
| TTS 原生字/词时间戳 | 当前服务真实返回，字段经过验证 | provider_word | 经样本验收后可 |
| 强制对齐 | 已有音频 + 已知实际发音文本 | forced_alignment | 通过质量门的条目可 |
| 人工试听校准 | 自动结果缺失或不可信 | manual_verified | 用户确认后可 |
| 句级时间 | 只有 segment 起止 | sentence_fallback | 仅粗定位、待校准 |
| 估算字幕时间 | 按字数、权重等分配 | estimated | 仅辅助导航，不能自动确认 |

当前 MiniMax 分支读取的是句级字幕时间，其他路径还有 estimated 或 beat_pause_aware_estimated_split。都不能直接升级标记为 word_aligned。

不要要求 LLM 根据文字长度猜秒数。LLM 负责选重点和内容匹配，真实音频时间由音频适配器负责。

### 4.2 强制对齐适配器

推荐先以 WhisperX 的 alignment 能力做一个小规模实测适配器，使用已有讲稿和音频，不把重新生成整份转写作为默认工作流。可选 ASR 仅用于排查文本与录音明显不一致。

官方源码列出了中文对齐模型；官方文档也明确存在无法对齐词汇的限制，尤其数字和特殊字符。因此「能调用引擎」不是通过验收，必须在本项目的中文、数字和混合文本上测量。

来源：

- https://github.com/m-bain/whisperX
- https://github.com/m-bain/whisperX/blob/main/whisperx/alignment.py

环境设计：

- 对齐引擎使用独立、固定依赖的 Python worker 环境，选择经实测兼容的解释器版本。
- 主应用只通过窄接口提交本地音频路径、文本及配置，读取有版本的 JSON 输出。
- 不把大模型依赖直接塞入现有主应用解释器；不再启动第二个应用服务器。
- 模型路径和版本显式配置，首次下载与引擎准备提供明确状态。
- CPU/GPU 选择、超时、内存峰值、单页延迟均在样本上记录，不能提前承诺速度。
- 默认单 worker 限制重任务并发；任务走持久化 job store，可恢复地显示 interrupted/failed/cancelled。
- 停止沿用 generation_control 的精确任务语义；浏览器断开不视为服务端停止。

建议的评测决定：若候选引擎达不到第 12 节的自动可用率和误差目标，自动精准同步阶段不能宣告完成。保留人工校准可完成工作，再更换适配器或改进文本规范化。

### 4.3 文本映射

明确三层文本：编辑器中的讲稿、实际送入 TTS 的发音文本、对齐引擎使用的规范化文本。

维护可逆的范围映射：讲稿 Unicode 码点范围 → 发音文本范围 → 对齐 token 范围。数字、金额、百分数、英文缩写是一对多映射，不能依赖同索引。

例：「增长 20%」可能读成「增长百分之二十」。用户选中 20% 时，绑定整个对应发音区间，不拆成假设长度相等的三个字。

具体要求：

- 复用已有 TTS 标记清理和发音处理规则，避免音频与对齐各自转换成不同文本。
- 对无法确定的读音映射标 needs_review，不静默猜。
- 标点和纯静音标签没有独立发音起点，不创建伪时间。
- 重复短语依靠 beat_id、range、上下文定位，不能字符串第一次命中。
- 前端继续显式转换 UTF-16 与 Unicode 码点；不破坏现有选区协议。
- 整个选中短语都需具备可靠范围。只定位到其中一个字不能把整个短语标成准确。
- provider/engine 的置信分数只能用于各自的校准规则，不能跨引擎直接比较一个固定数值。

### 4.4 对齐缓存

缓存键至少包含音频字节哈希、实际发音文本哈希、文本映射版本、引擎与模型版本、引擎配置。缓存无需包含密钥。

改颜色、笔宽或手绘形状不重跑音频对齐。换音频必须失效；仅改变 audio_start_sec 不重跑音频对齐，只重新编排页面时间。

## 5. 统一时间与内容出现规则

### 5.1 时间定义

- audio_time：音频文件起点为 0，所有对齐结果保存于这个坐标系。
- slide_time：页面第 0 帧为 0，包含音频起播延迟、Reveal 与勾画。
- video_time：整个视频开始为 0，由页面编排层加页偏移。

统一公式：

```text
nominal_start = audio_start_sec + phrase_audio_start + user_offset_sec
safe_start = max(nominal_start, target_ready_sec)
```

user_offset_sec 默认 0。严格同步模式下，负偏移只是校正定位误差的高级操作，必须经过试听，不能默认提前画。

manual_start_sec 必须新增明确 time_reference。用户界面「页面第几秒」保存 slide 时间；音频试听校准保存 audio 时间，由编译阶段换算。旧数据目前注释与实现语义不完全一致，按已产生画面的旧实现进行版本化兼容，并标记需要复核，禁止直接统一加延迟导致旧项目二次偏移。

### 5.2 目标已出现的判定

- 静态整页：target_ready_sec = 0。
- Reveal 页面：每个目标绑定相关 group/layer 的稳定 ID，默认取目标所依赖图层入场动画完成时间的最大值。
- 一个短语跨多个图层：必须保证要画到的目标整体可见。
- AI 文字候选与用户框选区域都需解析图层归属。优先使用已有精确 Mask 的空间交叠和稳定身份关系，不重新改变 AI Mask 语义所有权。
- 若只有非目标附近的装饰尚未出现，不应把整页动画完成时间作为标注门槛。
- 无法确定归属时允许用户选对应内容组，不能默认 0 秒假装安全。

不建议首版使用「画面出现 30% 就可以圈」等难以一致验证的阈值。先采用目标入场完成这一保守、确定性判定。

### 5.3 画面比旁白晚怎么办

safe_start 只保证不圈空白；还必须校验 safe_start 相对实际发音起点的偏差。

建议默认最大自动修正预算 0.15 秒，最终由样本验收冻结。若目标尚未出现造成更大的延迟，返回 target_not_ready，并提供：提前该目标的 Reveal、调整讲稿关联或人工调整。

不能为绕过问题自动把标注拖后 1 秒，然后仍显示「已同步」。允许用户调整 Reveal，但要明确刷新受影响预览和时间轴。

### 5.4 最终编排顺序

当前渲染入口先重建 Reveal、再绑定 Reveal 时间，期间可能改变 audio_start_sec。因此应采用：

```text
确认音频与讲稿
→ 生成/复用音频对齐
→ 构建 Reveal 资产及最终页面播放安排
→ 解析标注目标的可见时间
→ 编译标注时间轴和笔迹资产
→ 统一就绪校验
→ 预览或生成 Remotion props
→ 输出视频
```

工作区预览与正式输出调用同一组编译操作，不能分别推导页面时长和延迟。导出前仍按仓库要求重建 Reveal 与运行时资产；若得到的输入摘要与用户确认快照不同，返回精确失效原因，不静默更改用户已确认的同步效果。

## 6. 完整绘制、并发与页尾规则

### 6.1 每笔显式起止

将隐含 start_offset/gap 计算改为编译产物中的每笔 start_frame、end_frame 或精确的局部起止时间。播放端不再各自推算平均时长。

每笔绘制时长按路径弧长分配；设置最短可见帧数和抬笔间隔。建议普通单笔起始默认 0.45–0.75 秒，多笔或复杂路径按长度延长。这些是调参起点，不是所有场景必须固定的时长。

绘制生命周期：hidden → drawing → complete/hold → exit → hidden。

- t < stroke.start：彻底隐藏，不访问非透明首帧。
- 0% 资产透明；100% 资产包含完整路径。
- 路径进度单调，不能中途回退或跳过某一笔。
- 最后一笔完成后至少保留完整形态若干帧，建议默认 ≥0.2 秒；不得在完成同帧立刻切页。
- 自由笔迹不自动补直线闭合，除非用户选择闭合工具。
- 单笔速度曲线可非匀速，但浏览器和视频必须使用同一曲线。

### 6.2 帧量化

使用最终视频 fps。严格可见下限采用 ceil(time × fps)，避免 floor 造成提前一帧。导出事件记录 fps 和整数帧边界；改变 fps 后重新编译，不复用旧帧号。

测试覆盖 25/30/60 fps、非整数起点、极短绘制。事件完成边界与页面末帧均明确，不因半开区间漏掉最终完整帧。

### 6.3 同时多条标注

先完成真实字词定位，避免当前同 beat 一律同起点的问题。

之后采用「允许有限并行，尽量保持主要动作清晰」：

- 不同目标、同一重点短语：允许至多 2 条同时绘制作为初始配置。
- 前后关键词相距很近：优先适当缩短上一条绘制，不改变目标词的真实起点。
- 同一标注的多个笔画：严格按笔序，抬笔间隔计入总时长。
- 同目标重复建议：AI 规划阶段去重，用户明确添加的重复强调仍可保留。
- 超出并发或最低绘制帧数要求：返回具体条目冲突，用户可减少标注、合并关联或调整时长。

取消当前「默认第二条被推迟超过 0.2 秒就让整页构建失败」的机械规则。新的规则同样不能无限堆积动作或自动把标注挪离发音时刻。

### 6.4 页尾处理

采用最终展示页长，不能把 audio_content_duration 直接当页长。

处理顺序：

1. 完整绘制和最低完整形态停留优先。
2. 可缩短退出淡出，淡出可为 0；缩短超额停留。
3. 绘制时长在安全下限内压缩，路径仍从 0% 走到 100%。
4. 仍不足时报告 insufficient_draw_window，给出还需多少秒。
5. 提供显式配置的「允许页尾延长」选项，例如上限 0.8 秒；开启后统一更新视频、字幕/数字人容器及页间编排。默认不静默改变视频总长。

不通过截掉圈的最后一段来消除错误。

## 7. 数据契约与产物

保持编辑数据与编译产物分离：annotations.json 存用户意图；word_alignment.json 存音频测量；annotation_timeline.json 存最终可播放事件。

### 7.1 编辑条目新增信息

以下为示意字段，实施时统一 schema_version：

```json
{
  "annotation_id": "ann_001",
  "target": {
    "kind": "region",
    "polygons": [[[100, 200], [400, 200], [400, 260], [100, 260]]],
    "mask_group_ids": ["group_02"]
  },
  "anchor": {
    "beat_id": "beat_03",
    "offset_unit": "unicode_codepoint",
    "range": [8, 12],
    "quote": "核心能力"
  },
  "timing": {
    "trigger_mode": "anchor_start",
    "offset_sec": 0,
    "draw_duration_sec": 0.6
  },
  "manual_strokes": [
    {"points": [[100, 200], [120, 210], [140, 205]], "closed": false}
  ]
}
```

示意省略既有 style、protection、status 等必需字段，不作为可直接提交的完整请求。

旧 target.path_points 迁移为一个 manual stroke，不丢点、不重画。新字段不能与 path_points 同时成为可编辑的双重真相；兼容读取，规范写入。

### 7.2 对齐产物

至少存储：schema_version、audio_hash、spoken_text_hash、mapping_version、engine/model/version/config、time_reference=audio、各字词对应的原始讲稿范围和 start/end、证据来源、质量问题。

时刻必须有限、单调且处于音频长度内；没有对应读音的字符保存 unavailable 或映射为空，不均分填满。句级、插值、引擎真实对齐必须可区分。

### 7.3 正式时间轴

至少存储：

- time_reference=slide、fps、slide_duration_frames、编译器版本。
- 每条 annotation 的 anchor_audio_start/end、target_ready_sec、最终起止帧、调度说明。
- 每笔的局部起止、资产引用、路径/样式哈希。
- 输入摘要：图片、讲稿、音频、发音映射、标注 revision/content、Reveal 编排、audio_start、画布、fps、引擎及渲染版本。
- events 可以为空，但必须带明确的 no_annotations 页面状态。
- issues 为结构化列表，包含 slide_id、annotation_id、code、message、可执行修复动作。

确认记录引用上述编译快照。时间轴与确认的内容、时序必须能通过摘要对应，不只比图片/讲稿两个哈希。

## 8. 确认、保存、恢复与导出门禁

### 8.1 页面状态

| 状态 | 含义 | 是否允许携带本页标注导出 |
| --- | --- | --- |
| no_annotations | 本页没有启用标注，数据已正确读取 | 允许，空覆盖层 |
| draft | 正在编辑或未确认 | 不允许 |
| preparing | 对齐/资产编译中 | 不允许 |
| needs_review | 空间、文本映射或时间需校准 | 不允许 |
| ready | 当前输入下预览产物完整 | 等用户确认 |
| confirmed | 当前快照已确认 | 允许 |
| stale | 输入改变使确认快照失效 | 不允许 |
| failed | 本次准备失败，可重试 | 不允许使用失败版本 |

这些是页面派生状态，可保留已有 item.status 字段实现，避免平行维护两套可互相矛盾的状态。取消的任务也是明确终态。

空页不是损坏文件：合法地没有标注可以导出；JSON 损坏、读取权限失败、应存在的条目丢失必须报错，不能通过 catch 伪装成空页。

### 8.2 准备与确认分离

准备：短锁读取 revision 和输入摘要 → 锁外执行对齐/墨迹构建 → 在独立 build_id 目录保存资产 → 短锁复核输入未变 → 原子发布 ready manifest。

确认：先完成前端待保存操作 → 服务端校验 expected_revision 和 prepared_build_id → 复核全部必需产物及输入摘要 → 持久化确认快照 → 更新模块完成状态。

不要先写 confirmed 再尝试构建。生成途中有新编辑时，本次结果标 stale_input，不覆盖新内容。

### 8.3 崩溃和发布一致性

多张 PNG 与多个 JSON 不具备跨文件事务。通过不可变 build_id 目录和最后原子替换的发布 manifest 定义「有效版本」。先写资产、后切指针；进程在任一步退出，旧有效版本仍可读取，新半成品不会被使用。

旧有效版本仅能作为历史预览，只有输入摘要匹配时才可导出。不得因有旧文件就绕过当前 draft/stale 门禁。

持久化任务通过 local_jobs 既有机制管理；若增加数据库字段，使用下一连续 migration，不修改已应用迁移。API 调用者按仓库约定负责数据库提交，纯构建器不提交。

### 8.4 项目就绪

项目启用标注时，逐页检查：合法无标注页直接通过；有启用条目的页面必须 confirmed 且产物当前有效。

允许全项目无标注；前端应明确记录项目「不添加勾画」决定，避免模块决策状态悬空。禁止通过给空页插入假标注来满足导出。

就绪判断由同一服务给摘要、步骤栏、输出工作区、One-click 和视频导出调用。页面标题或 item.content=confirmed 都不能单独作为最终就绪凭据。

### 8.5 错误应可操作

| 错误码示例 | 用户提示 | 操作 |
| --- | --- | --- |
| anchor_unresolved | 找不到所选词的发音位置 | 试听校准/重新关联 |
| target_not_ready | 讲到这里时目标尚未出现 | 调整该内容的出现时间 |
| insufficient_draw_window | 需要额外 0.3 秒完成笔迹 | 缩短绘制/允许页尾延长 |
| stale_audio | 音频已更新 | 重新定位并预览 |
| ink_asset_missing | 第 2 笔资源不完整 | 重建该笔 |
| revision_conflict | 页面已有更新 | 保留草稿并处理冲突 |

任何错误都返回对应页面和条目，界面可定位。不能全部提示为「生成音频后重新确认」。

## 9. 预览与视频一致性

保留编辑态快速轮廓，但把两种功能明确区分：

- 编辑显示：完整笔迹、可选择和修改，不声称真实播放时序。
- 同步预览：使用正式页面编排、真实音频、Reveal 与正式墨迹资产。

同步预览优先接入同版本 Remotion Player，复用 SlideView/AnnotationOverlay；新增 player 依赖必须与现有 Remotion 版本匹配，并验证构建和资源访问。若先做原生预览，也必须消费同一编译产物、共享采样器，以音频播放位置为时钟，不能继续 performance.now() 自行顺排。

支持单条前后试听、本页预览、暂停、拖动、0.5 倍速。资源未就绪显示加载，不能先让音频走、笔迹稍后补上。

正式笔迹统一使用透明 PNG 资产：

- 栅格生成失败时定位到条目，重试或标记失败，不做整层隐藏的静默回退。
- 旧矢量数据可以用于编辑，但正式预览/导出前统一重建资产。
- 浏览器与视频使用同一帧索引和透明度规则；透明度只应用一次，避免 PNG 已乘 opacity 后播放器再次乘导致变淡。
- 对轮廓插值、速度曲线、起笔隐藏与最终完整帧执行一致性测试。

先完成正确性，再做资源优化：逐帧写出避免整批全画布 RGBA 常驻内存；用笔迹局部 bbox PNG + x/y 偏移减少存储，并保留画布尺度元数据。按路径、样式、画布、fps、速度曲线、渲染版本构建缓存，不能跨版本误用。

## 12. 验收标准与测试样本

以下数字为建议验收目标，必须实测，不是现有能力声明。

### 12.1 自动定位样本

固定至少 30 页、100 个短语；至少 10 页只用于盲测。覆盖短句、长句、同句多重点、重复词、句首/句尾、20%/日期/金额、英文缩写、中英混合、停顿、不同声音和语速。

人工标出关键词发音起点，记录标注者和争议区间。对齐引擎不能读取真值；开发/校准与盲测分开。

建议门槛：

- 已自动通过的目标：95% 起笔误差绝对值 ≤150 ms。
- 误差 >300 ms 或匹配错误不得默默进入自动确认，应识别为待复核。
- 自动可用率目标 ≥90%，分母包含全部适用样本，不能通过大量拒绝掩盖准确率。
- 低置信度、无可用读音、重复定位冲突等未通过项可人工校准完成；报告自动与人工占比。
- 若前两项或自动可用率不达标，继续改适配器与映射，不能用测试全绿替代真实音频验收。

### 12.2 完整轨迹硬指标

- 起笔前 0 个非透明笔迹像素。
- 多笔的未来笔画在各自起点前全部隐藏。
- 每笔进度单调，最终资产覆盖完整保存路径。
- 最终完整形态至少显示约定帧数，再淡出/换页。
- 前台预览与最终视频同时间采样，笔迹层像素一致；整幅视频允许编码压缩误差。
- 空页不阻塞，缺失必需资产不静默丢画。

### 12.3 必须通过的场景

| 场景 | 预期 |
| --- | --- |
| 关键词在长句末尾 | 句首先不画，讲到词时开始 |
| 同句两个不同关键词 | 各自命中发音，不共用句首 |
| 同一短语第二次出现 | 命中选中的那一次 |
| 音频起播延迟 0.8 秒 | 标注随页面时间正确后移 |
| 多字幕段属于同 beat | 不被最后一个 segment 覆盖 |
| Reveal 完成晚于目标词 | 报可见性冲突或在预算内调整 |
| 目标静态可见 | 无需依赖其他图层动画 |
| 最后一句、剩余空间很短 | 保证画完；不足则明确修复提示 |
| 3 页仅第 2 页有标注 | 3 页正常输出 |
| 某页全部条目禁用 | 视为无标注页 |
| 自由绘制三笔 | 依次完整绘制，无跨笔连接 |
| 快速手绘、点数超预算 | 保留首尾和整体形状 |
| 横屏/竖屏、缩放后绘制 | 坐标正确，笔迹不偏移 |
| 数字、emoji、TTS 停顿标签 | 引用不偏移，无假发音时间 |
| 预览暂停/seek/0.5 倍 | 采样可重复，不继续偷偷走时钟 |
| 25/30/60 fps | 起止帧、最终完整形态正确 |
| 准备任务中途编辑或切页 | 旧结果不覆盖新草稿 |
| 准备时取消/进程退出 | 状态正确，可重试，无半成品发布 |
| 音频重生成 | 空间和手绘保留，时间待复核 |
| 单笔 PNG 丢失/写失败 | 指明条目并阻止静默漏画 |
| 准备成功后并发修改 | confirm 返回版本冲突 |
| 无改动保存 | 不失效、不重复计算 |

Python 测试必须使用 checks/conftest.py 隔离数据库与 runs；测试不得写用户真实项目。真实引擎测试使用专用临时项目和明确配置，不在 discovery 时导入 server。

## 13. 实施顺序与交付物

### 阶段 A：先消除可确定的阻塞

修复空页导出、确认假成功、错误提示、beat 聚合、音频延迟与页长口径；修复起笔前露墨、最终完整帧以及混合资产丢失。

交付：针对上一轮复现问题的回归测试；静态页与 Reveal 页都能用人工定时输出完整轨迹。此阶段仍不能宣称自动词级同步完成。

### 阶段 B：可靠的人工闭环

多笔自由绘制、双向选词绑定、真实音频试听和人工起笔校准；正式预览、准备/确认快照、资产原子发布。

交付：不依赖新对齐模型，用户已经能够人工做出满足需求的成品；全过程有一份真实 MP4 与逐帧检查记录。

### 阶段 C：自动定位与 AI 辅助闭环

完成独立 worker 小规模 preflight，再实现发音范围映射、对齐缓存、质量门和人工兜底。将结果接入 AI 推荐流程。

交付：冻结引擎/模型/环境版本，提交盲测误差、自动可用率、时延与失败类型报告。阶段不通过时继续保留阶段 B，不把粗略结果包装成精准同步。

### 阶段 D：Reveal 联动与复杂调度

稳定图层绑定、目标可见性约束、同词多目标与近邻重点、页尾不足处理；预览和导出正式共用编译顺序。

交付：复杂 Reveal 页面、同句多重点、最后一句案例全部通过。若阶段 B 已接入部分能力，在此补齐复杂组合。

### 阶段 E：旧项目、性能与整体验收

旧数据迁移、渲染资产缓存、资源峰值控制、One-click/输出状态一致性、整套真实视频验收。

交付：测试报告、真实案例视频、迁移/恢复说明、操作说明。只有 A–E 全部满足对应门槛，才将模块标记为达到完整需求。

工作量按阶段验收后估算。最大不确定项是中文混合文本对齐精度及当前机器的模型运行条件，应尽早用独立试验验证；不在验证前承诺固定几天完成。

## 14. 最小完整成品示例

页面里有「降低成本」目标，用户在讲稿中选中第二次出现的「降低成本」，并手绘一个两笔圈。

假定真实音频测得目标词从 4.20 秒开始，audio_start 为 0.60 秒，目标 Reveal 于页面 4.65 秒完成。

最终起笔 = max(4.20 + 0.60, 4.65) = 页面 4.80 秒。

若采用 30 fps、总绘制 0.60 秒，可将两笔及抬笔间隔分配在第 144–162 帧之间，随后至少保留约定的完整形态停留帧数。第 144 帧之前无笔迹，第二笔起点前无第二笔墨迹，最终两笔完整显示。

若目标直到 5.50 秒才出现，则晚于应起笔的 4.80 秒达 0.70 秒，应提示调整内容出现时间；不能悄悄在 5.50 秒开始并声称准确同步。

这份案例必须能在工作区试听预览、最终 MP4 和自动帧采样检查中得到一致的结果。
