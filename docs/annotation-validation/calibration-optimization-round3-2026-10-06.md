# 第三轮优化：音频变化后的人工校准保护

2026-10-06。本轮修复一个实际同步漏洞，没有改善或重新宣称 24 条自动对齐精度。

## 问题与结果

原流程在音频重生成时删除派生时间轴、撤销确认，但保留 manual_start_sec；构建器仍可以把旧时间直接用到新音频。仅撤销确认不能阻止用户重新构建并确认错误时间。

现在人工时间保留作定位参考，同时持久化 calibration_stale。过期条目不能构建预览或确认，界面提示重新试听。记录当前播放位置或明确修改起笔时间可解除过期状态。改样式、绘制时长和保留方式不会解除；旧客户端省略过期字段也不能解除。禁用条目同样记录失效，防止日后启用旧时间。重复失效是幂等操作。

旧 JSON 未带字段时仍按原兼容语义读取，因此没有修改现有人工标签，也没有数据库迁移。过去已发生且未留下失效标记的替换不能从该字段追溯识别；新音频变更通过原业务失效入口记录。

## 验证

- Annotation 回归 241 passed、1 skipped；随后新增持久化/幂等测试和兼容省略字段保护，专项 40 passed，兼容接口测试单独通过。
- 集成测试覆盖：音频失效 → 旧时间保留 → prepare 拒绝 → 修改绘制时长仍拒绝 → 明确校准 → prepare 成功。
- 前端编辑恢复测试、语法检查、质量检查与 git diff --check 通过。
- 正式与隔离服务在确认无运行中任务后重新加载修改。
