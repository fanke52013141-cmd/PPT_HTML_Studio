# 客户人工修正流程与界面检查

## 结论

AI完成后应进入“检查并修正”，客户从画面或标注列表选中原条目，修正必要的部分，保存、试听预览，再确认本页。客户不应填写标注编号，也不应为了修改一个圈而删除重建整条。

原界面已经支持讲稿重绑定、音频试听/波形、记录当前位置、时间偏移、样式修改、禁用、删除和撤销。但“框选区域/自由画笔”只新增条目，缺少已有条目的范围/笔迹替换入口；属性标题显示内部编号，保存和确认的关系也不够清晰。

## 本轮已实现

- 标题改为“修改标注 · 对应文字”，避免让客户误以为需要填写编号。
- “重新框选范围”：用新范围更新当前条目，不创建第二条，保留讲稿关联、样式、人工起笔时间和指定画面内容组。
- “重画笔迹”：先画，点击“完成绘制”后替换原笔迹；后台自动保存不会提前提交重画中的半条笔迹。
- “取消重画”：保留原条目；切换条目、页面或项目会清理尚未提交的重画状态，避免改到另一条。
- “保存修改”：等待自动保存和延迟属性提交；失败或冲突不会提示保存成功。
- “预览修改”：保存屏障和原同步预览流程继续使用；尚未完成的重画会给出提示。
- 未完成重画不能确认原条目；保存被拒绝不能显示成功。撤销/重做会清理未提交的重画状态。
- 说明保存草稿仍需预览和确认本页，人工修改的条目由已有后端 modified_fields 保护，AI重新推荐不会覆盖。
- 修正过程中直接定位到画布，不使用持续移动的平滑滚动；“完成绘制”仅在画笔模式显示。

## 客户具体操作

| 客户发现的问题 | 操作 |
| --- | --- |
| 圈的位置或大小不对 | 选中原条目 → 重新框选范围 → 在画面拖出正确范围 |
| 笔迹不合适，希望自己画 | 选中原条目 → 重画笔迹 → 画一笔或多笔 → 完成绘制；不满意时取消重画或撤销 |
| 开始太早或太晚 | 试听所选短语 → 用播放器/波形定位 → 前一帧或后一帧微调 → 以当前音频位置起笔 |
| 只需小幅提前或延后 | 修改提前/延后秒数，随后试听预览；负数提前，正数延后 |
| 讲稿关联错了 | 选中原条目 → 在讲稿中选择正确文字 → 将所选讲稿关联到当前标注；该动作恢复按新讲稿自动定位，需重新核对时间 |
| 颜色、粗细、圈/横线不合适 | 修改样式、颜色、粗细、留白、笔迹浓度；调整绘制时长改变画出的速度 |
| 这条不要了 | 优先禁用此条，方便恢复；确定移除时删除，误操作可撤销 |
| 以后仍希望用AI时间 | 恢复讲稿定位，再预览核对；没有当前模型的有效定位时先执行定位音频文字 |

最后统一操作：保存修改 → 预览修改 → 检查目标出现、起笔时机和完整轨迹 → 确认本页。“确认本页”确认该页所有启用条目，不只是选中条目。确认后若需要修改已导出的视频，重新生成MP4；旧MP4不会被编辑界面即时改写。

音频起点和页面起点是两种时钟。直接记录播放器当前位置最容易操作，系统自动加入页面音频延迟，不要求客户自行换算。若音频重新合成，旧人工时间仍保留，但须重新试听校准，不能自动当成已验证。

新增加的条目应先保存，收到服务器编号后再使用替换工具；编号由系统维护，不由客户填写。重画保留指定的画面内容组，若实际改成另一个画面对象，还需调整内容组和讲稿关联。

## 验证

使用8015隔离环境“自由笔迹与人工校准-隔离”，未修改正式用户项目：

- UI重新框选、保存：总数仍为2，条目仍为ann_002，讲稿范围[40,44]、人工时间10.682秒保留；后台modified_fields包含target。
- UI重画、完成、保存：原ann_002增加新的path_strokes，未新增标注；人工时间仍为10.682秒。
- UI保存后显示“已保存”，修改条目从“已确认”变为“待确认”；新的“预览修改”成功打开真实音频与勾画同步预览。
- Node编辑恢复回归：替换保留身份和人工时间、撤销恢复范围、后台自动保存不提前提交重画、切换选择取消未提交笔迹，全部通过。
- frontend quality通过；相关后端契约/规划/时间轴/服务回归70项通过；git diff --check通过。

## 后续值得优化但尚未实现

1. 将当前较长属性面板拆成“范围与笔迹、起笔时间、样式”三个可展开组，高级参数默认折叠；保持现有工作区样式规范。
2. 增加可拖动/缩放的选中框和自由笔迹控制点，让小幅位置修改无需完整重画。当前已实现的是重新框选/重画，并非控制点编辑。
3. 增加仅复核问题条目的清单和“保存并进入下一条”，显示缺少关联、时间失效、目标晚出现等原因；不能只按内部编号让客户查找。
4. 同步预览支持直接跳到当前条目前后，并将音频波形与轨迹预览放在同一视图，减少来回滚动。
