# 开源对齐方案对照（2026-10-06）

结论：Qwen 在这24条上的150ms内命中数从16提高到19，典型误差改善，但尾部误差和严重偏差仍不达标。暂不替换正式默认对齐器，不将实验输出写入项目时间轴。

## 完整实测结果

| 指标 | 现有 WhisperX 中文对齐 | Qwen3 强制对齐 |
| --- | ---: | ---: |
| 有定位输出 | 24/24 | 24/24 |
| 误差不超过150ms | 16/24（66.7%） | 19/24（79.2%） |
| 中位误差 | 103ms | 81ms |
| P95（最近秩） | 241ms | 235ms |
| 最大误差 | 770ms | 822ms |
| 开发组150ms内 | 5/10 | 7/10 |
| 保留组150ms内 | 11/14 | 12/14 |

Qwen 共耗时约403秒，单条中位15.94秒，完成时采样的最大RSS约2396MB。结果只代表当前CPU、线程和机器负载，不是GPU吞吐承诺。SDK在a002、a037的非锚点位置修补了时间；24条锚点均未修补且具有正区间，所以结构保护前后评价一致。

仍超过150ms：a003（822ms）、a004（210ms）、a031（235ms）、a032（210ms）、a049（212ms）。即使去掉评价器的100条样本门槛，235ms的P95和822ms的严重偏差也使本轮未达到自动时间精度目标。

没有依照每条人工标签挑选两个模型中更好的预测，也没有学习全局时间偏移。两组均有改善，但样本量不足以证明所有场景可用；更换模型可以改善通常误差，无法据此取消人工复核。

## 测试边界

使用原24条独立人工标签和对应音频，不重新合成，不移动人工时间，不使用人工时间生成模型输入。每条测试前验证音频 SHA-256 与人工标签绑定的哈希相同。模型输入仅为原音频、完整讲稿和中文语言提示。中文字符按完整顺序映射回讲稿码点，重复短语不按第一次匹配处理。

Qwen3-ForcedAligner-0.6B 固定模型版本 `c7cbfc2048c462b0d63a45797104fc9db3ad62b7`，SDK qwen-asr 0.0.6。独立测试环境位于 `outputs/annotation-bcd/qwen-worker`；使用现有 CPU PyTorch，bfloat16、2线程、逐条推理。正式服务和默认对齐器未切换。

SDK 会通过最长递增子序列和补值修复倒序预测。本试验保存修复前的时间戳和被修改的位置；另计算锚点时间未被修复且长度为正的覆盖率。模型未提供可用于本系统的字符置信度，不伪造分数。该结构检查不能证明声学精度。

测试脚本与原始逐字输出：`outputs/annotation-bcd/qwen-experiment/benchmark.py`、`aNNN.json`。完整评价与资源记录分别保存到 `evaluation.json`、`guarded-evaluation.json`、`performance.json`。资源数据是每条完成时的 RSS 采样，不是操作系统严格峰值。

既有评价器的 `passed` 包含100条门槛。本轮按用户决定仅测试24条，因此单独报告24条的误差和覆盖率，不将它包装成100条全场景验收。数字、中英文混合、倍速等未被这24条人工标签覆盖。

## 已查证的开源候选

- [Qwen3 ForcedAligner 官方示例](https://github.com/QwenLM/Qwen3-ASR/blob/main/examples/example_qwen3_forced_aligner.py)：输入既有音频和文本，适合本项目已知讲稿的强制对齐任务。本轮实际运行此方案。
- [FunASR 官方模型选择文档](https://github.com/modelscope/FunASR/blob/main/docs/model_selection.md)：中文字级时间戳优先查看 Paraformer；SenseVoice 的识别文本、VAD 片段起止不等于逐字起止。该项目本轮仅调研，未冒充实测结果。
- [MFA 官方普通话对齐示例](https://github.com/montrealcorpustools/montreal-forced-aligner/blob/main/docs/source/first_steps/alignment_example.md)：具备普通话预训练字典和声学对齐流程，但需字典及其运行环境，接入成本较高。本轮未实测，不能断言比现有方案更准。

## 接入原则

时间定位保持在音频合成并确认后。视觉区域由 OCR/人工勾画确定；声学对齐器只负责讲稿锚点在这段实际音频上的时间。原生词级时间戳须验证文字和音频哈希，缺失时再使用开源对齐器。完整轨迹仍由现有时间轴与播放采样器负责，不由 ASR 绘制。

两个模型一致只能提供复核线索：a003 两模型相差52ms，但 Qwen 与人工标记相差822ms，仍不能自动接受。人工期望的标记时间和发音起点是否同义，需要通过片段回放核实；本轮保持原人工标签不变。

## 建议的下一步

1. 保持合成/确认音频之后定位。保留人工直接记录当前位置的操作；正式项目中人工确认的时间优先，不由模型覆盖。
2. 将Qwen保留为可选对照候选。要正式接入，应有独立进程、单任务CPU限制、超时、按音频哈希和完整讲稿缓存，兼容原对齐器回退；不能伪造原模型所需的置信度字段。
3. 对剩余5条提供短片段回放和波形，复核人工标记的语义。a003尤其要确认要求的是关键词开始、关键词结束还是讲解强调时刻，原标签不擅自修改。
4. 后续以FunASR Paraformer在同24段音频作对照；识别文本有缺失或替换时，应拒绝为未识别的讲稿字符推算时间。MFA作为有字典维护能力时的备选，不先承担较重的Windows环境接入。
5. 时间候选达到人工精度门槛后，再用正式导出验证触发帧、完整轨迹和音频时钟。这轮Qwen仅验证时间定位，未新增Qwen驱动的导出验收；既有原生时间戳导出验收见同目录另一报告。
