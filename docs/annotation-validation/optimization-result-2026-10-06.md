# 勾画标注优化与验证记录（2026-10-06）

本次已实现三项核心要求的底层链路：AI 推荐与人工工具/自由多笔绘制共用标注数据；目标关联原始演讲稿范围；真实音频定位后开始完整轨迹播放。人工链路已有网页实操证据，AI 推荐尚未完成本轮真实供应商端到端验收。源码已更新，当前运行的旧服务需要重启才能加载新增接口；不能把源码实现等同于当前应用已完整可用。

## 已实现

1. 字词触发必须来自可核验的字/词音频时间，不再把整句开始时间当作所选词时间。重复文字依靠 beat 与原文字符范围区分。对齐输入包括真实 TTS 发音文本到原始讲稿的映射；常见两位百分数支持展开。低置信、模型词表之外或缺字的范围不能冒充准确时间。
2. 新增持久化 `annotation_align` 任务，独立 Python 3.12 CPU worker 执行，最多一个模型任务同时运行；取消后不发布，音频/讲稿变化时丢弃结果。AI 推荐完成后自动进入音频定位，也可单独点击“定位音频文字”。
3. 人工可试听真实音频，暂停后点击“以当前音频位置起笔”。系统区分音频时间与页面时间，音频延迟只加一次。已关联演讲稿的范围保留。
4. 自由绘制支持最多 12 笔，逐笔保存原始路径；完成或离开页面时提交。旧 `path_points` 仍按一笔读取，新数据使用 `target.path_strokes`，不同时维护两份路径。
5. 每笔时间按轨迹长度和抬笔间隔分配，短笔至少有两帧；起笔前及尚未开始的后续笔完全隐藏。第一张墨迹帧透明，最后一张保留完整路径。速度曲线参与栅格生成，透明度仅合成一次。
6. 先检查正式 Reveal 的目标出现时间，再确定起笔。显著晚于讲述的目标提示调整，不能偷偷推迟笔迹。同一时刻可并行绘制两条自动标注，更多冲突明确提示。手绘下划线等不接触正文像素时可显式指定内容组。
7. 页尾时窗不足时压缩绘制时长，保留完整路径和至少 0.2 秒完整形态；连最短窗口都不足时阻止确认。时间轴使用正式视频的页长规则和实际音频探测。
8. “同步预览”采用 `@remotion/player` 与正式 `ArticleVideo`、`AnnotationOverlay`，播放真实音频、Reveal 与相同墨迹帧。可播放、暂停和跳转。
9. 确认先完成构建、输入复核与资产校验，再写确认状态。准备失败不确认；预览输入过期返回冲突。导出复核图片、讲稿、音频、音频时间轴、Reveal、文字布局、对齐、轨迹内容、画布、帧率及墨迹版本。确认记录绑定 build ID，时间轴内容被篡改也会拒绝。
10. 空标注页有效；关闭功能忽略旧时间轴。旧 v1 时间轴保留源标注，但需要重新预览确认后才能携带勾画导出。墨迹使用不可变构建目录，生成串行受限，逐帧写入，避免一次保存所有全画布图片。

## 实测环境

- 主应用 Python 3.13 不安装 Torch；独立 worker：Python 3.12.14。
- WhisperX 3.8.6；Torch 2.8.0+cpu、Torchaudio 2.8.0+cpu。
- 中文模型：`jonatasgrosman/wav2vec2-large-xlsr-53-chinese-zh-cn`。
- 模型 revision：`99ccb2737be22b8bb50dcfcc39ad4d567fb90cfd`，执行与缓存均固定此版本。
- 完整依赖快照：`alignment-worker-lock-20261006.txt`。运行目录 `runtime/annotation_worker` 和模型目录 `runtime/annotation_models` 均不提交。
- 环境变量 `PPT_ANNOTATION_ALIGN_PYTHON` 可指定其他独立 worker Python。中文句边界使用内置保守配置，不依赖联网下载英文 NLTK 训练数据。

如需重建独立环境：使用 Python 3.12 创建 `runtime/annotation_worker`，先从 PyTorch CPU 索引安装 Torch/Torchaudio 2.8.0，再安装锁文件依赖（为带 `+cpu` 的包配置 PyTorch CPU 额外索引）。首次音频定位下载固定版本中文模型；缓存后离线加载。缺少引擎或模型不可用时任务显示失败，人工音频校准仍可使用。

## 本轮真实网页补验

使用 CUA 操作网页，正式应用只做只读检查。端口 8000 的 OpenAPI 缺少新增 prepare 与 ink 接口，证实旧进程未加载新版后端。未停止或重启用户的正式服务。

新版验收进程使用独立数据库、运行目录及端口 8015，未向正式项目写入测试标注。实际框选“人工标注”区域，选中第二次出现的讲稿片段“人工标注，开始画出”（原文范围 `[22,31)`），自动保存。网页启动音频定位任务后使用缓存的真实对齐结果；本轮并未强制重跑模型。点击同步预览、播放、跳转、确认本页成功。

实操发现并修正三处问题：

- 播放器错误请求 `/static/annotation_player.bundle.js` 返回 404；静态目录实际挂载在根路径，改为 `/annotation_player.bundle.js`，修复后返回 200，网页播放器真正打开。
- 页面初始化漏存服务端 `mask_groups`；现在保留内容组供属性编辑器使用。隔离样例是静态页、没有 Mask 内容组，因此本轮仅对数据接线做检查，未把动态 Mask 下拉选择计为实测通过。
- 确认后只更新本地 content 状态，仍显示“等待音频”；现在确认后重新加载服务端页面，以服务端 word_aligned/manual 状态为准。
