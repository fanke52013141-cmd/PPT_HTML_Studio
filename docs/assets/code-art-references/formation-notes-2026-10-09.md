# 资产形成与讨论备注 · 2026-10-09

## 已明确的原则

用户认可代码主导、少量独立插画的方向可以继续，同时明确当前画面美感不足。用户两次补充美感输入：首先充分告诉模型代码能实现哪些表现；进一步强调应先把代码自身能达到的美感做出来，再传给生图模型。不能只给平庸能力测试图而期待模型组合出稳定美感。

因此：真实漂亮代码样板是美术依据，完整目录是能力边界，风格图指导插画及协调，当前内容和对象关系决定新画面。构思时就区分代码/插画，模型保留组合空间，选中方案后冻结精确执行定义。美术参考、生成提案和实际HTML分别审阅。

## 实际形成经过

1. 制作61项真实代码效果演示，分几何/描边、填充/表面、文字/组合、数据/Canvas、运动五张截图；属于首版技术参考，不等于漂亮的生产美术参考。
2. 使用已有文本模型按“水为什么结冰”讲稿进行真实画面拆解，初次后端枚举不符，返回模型修正一次；最后为13对象、11代码、2插画。
3. 实际向用户指定图片模型发送五张代码截图、一张风格参考，以及固定规则和对象表，生成2048×1152完整提案。
4. 依据完整提案分别模型编辑水杯、冰块为独立透明2048²PNG。此方法会重绘细节，不能备注为原像素无损抠图。
5. 保留原PNG字节，分析alpha可见主体框，以HTML缩放/平移映射；简单接地投影由代码绘制。
6. 将文字、三卡片、刻度、曲线、关系箭头、热量箭头和标签用实际HTML/CSS/SVG绘制；保留13对象身份。布局从生成构图转录，未把LLM粗略框假称为精确设计。
7. 修复右侧正文容量和纵轴标签重叠；曲线下降起点与20℃刻度对齐，仍为定性示意；真实浏览器截图及参考/HTML切换、滑动对照、隐藏插画可查看。本轮未生成语音。
8. 用户反馈方案比较OK，要求先建设地基，并明确美感仍不足；据此形成优化方案和本资产形成规范。

## 差异和未完成项

- 原生成图改变标题效果、主体比例及部分位置；代码又转录与校准，因此还未证明自动稳定还原。
- 历史主题把F01当渐变，但目录F01是纯色，F02为线性渐变；引用待修，不扩大F01含义。
- 标题80px超出旧目录18–48px；需按真实用途和画布补角色级边界及证据。
- 独立素材冰纹/玻璃高光被重绘；提取保真需专门试验。
- 当前美术问题包括主视觉不突出、等权卡片、部分信息重复、图形与插画层次不够统一。
- 当前内容主要描述结冰过程，标题提出“为什么”；后续须先明确教学目标再选构图。
- 未完成漂亮代码美术参考集的审阅，也未完成第二主题复用验证。

## 分工与可视化提案

人负责教学取舍、偏好和美术结论；AI负责构思、在充分美术参考内组合、拆解及差异分析；程序负责实际渲染、测量、版本和保护。

除了改提示词，后续纠偏入口包括文字/参数编辑、构图比例、可见主体框、关系锚点、资产替换、锁对象、局部重做、回退。入口尚未由此次备注实现。每步应显示实际输入/产物、执行与审阅状态、可改项和返工去向。

具体四个确认点、候选构图和试验顺序仍见[建议方案](../../plans/visual-foundation-optimization-2026-10-09.md)。本次仓库登记落实用户明确原则，不把全部建议或旧样页标为已批准。
