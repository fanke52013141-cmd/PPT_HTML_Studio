# HTML 演示契约变更记录

## 0.6.0 — 2026-10-07

原因：用户指出首版样稿拥挤、缺乏美感，要求明确 HTML/生图职责与模板固化机制。
新增 HPS-023/024/025：素材分工与控制粒度、验收模板定义卡、屏幕内容预算及四层验收。
原子/布局复用不再被视为美术质量保证；生产必须选视觉通过且运行支持的模板。
P02 改为 changes_requested，保留原检查证据，按混合页面重制后再进入 P03。
兼容：只更新设计规则，P01 0.4.0 与分类目录 0.5.0 保留创建版本；无运行数据迁移、
生产 Prompt、应用、数据库、Agent 或导出行为变化。新增规则执行方式仍为设计审查。
验证：规则索引/正文/相对链接及文档发布范围检查；没有新视觉样稿或运行验收结论。

## 0.5.0 — 2026-10-07

原因：用户指出最小对比样板不能代表完整体系，要求补齐分类与扩展机制，再以知识科普
风格试制沉淀定制流程；随后提供具体视觉参考板。

- 新增八层分类、108 项能力目录和 32 个代表案例的覆盖矩阵，明确分类/定义/实现的区别。
- 新增页面区域、嵌套分区、单页/跨页讲解的组合规则与具体推演。
- 新增参数/变体/配方/组件/算法/动作/渲染协议的扩展决策、登记、兼容和回退流程。
- 登记 HPS-019 至 HPS-022；建立 S01—S08 风格定制流程与交付/验收清单。
- 保存用户科普参考原图、哈希、色值标签和视觉/能力缺口分析；色系、字体与样板待试制。

兼容：增量设计规则，未修改 P01 scene/定义 0.1.0；P01 的契约 0.4.0 和原检查证据保留。
旧 layout.two-column 的必选标题/概念槽位继续按原有限范围解释，通用 region/split 为
新候选，不能用目录名称绕过运行能力检查。无应用、数据库、Agent 或生产 Prompt 改动。
数据/行为无运行变化；没有产生新的产品视觉或视频/PPTX 输出，不宣称视觉兼容通过。

验证范围：[分类与扩展交付记录](../../plans/framework-expansion-completion.md)。完成目录/规则/
链接/案例引用/状态与输入图哈希核对；自动布局、风格样板和输出仍需后续实现与验证。

## 0.4.0 — 2026-10-07

原因：用户要求开始实施阶段 1，将基础职责细化为可用于后续开发的最小字段与行为约定。

- 新增 definitions 目录及 19 张定义卡：场景、四原子、概念块、布局/配方、风格/参数、
  资源、目标、时间/三动作、就绪及编辑/输出；关联既有 HPS-001 至 HPS-018。
- 落定公开 part、码点锚点、毫秒触发、动作保持/恢复、参数覆盖与就绪诊断的首轮字段。
- 保存两概念三语块五动作的完整 JSON 草案、夹具风格、两个自绘 SVG、预期时间及错误输入。
- 新增 28 项边界验收说明，保留正常/无效/修改/兼容情况及后续验证阶段。
- 同步入口、索引和阶段状态。正式 Schema、渲染器、API、生产 Prompt 和数据库均未新增。

兼容影响：从未指定具体 HTML 运行字段的设计基线增量细化，无现存 HTML 作品迁移；
已有图片行为、数据和输出不变。未来实现必须区别场景格式 0.1.0、具体定义 0.1.0 与
契约包 0.4.0；夹具值不构成已验收产品风格，也不承诺视觉/导出兼容。

验证：文档链接、状态/版本、JSON 语法、字段/引用一致性、素材哈希、码点范围及时间
算术；详见 [P01 交付记录](../../plans/p01-definition-completion.md)。运行/视觉/导出未验证。
后续：P02 选定实际风格/字体/参考页，P03 将字段转为正式 Schema 并实现静态样板。
