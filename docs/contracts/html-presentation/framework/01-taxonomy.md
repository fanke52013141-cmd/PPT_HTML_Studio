# 八层分类与职责

## HPS-019：需求按语义职责分类

每个新需求先识别内容/关系/讲解组织，再选择视觉组件、空间安排、风格和时间行为。
同一个词可能涉及多个层，但同一项数据只有一个语义所有者；其他层通过引用消费。

| 层 | 核心对象 | 输入 → 输出 | 不应承担的职责 |
| --- | --- | --- | --- |
| 内容 C | 概念、事实、观点、数据、例子、问题、结论、来源 | 材料 → 有身份、来源和必讲标记的内容单元 | 不提前写死像素和图形 |
| 关系 R | 对比、因果、顺序、包含、关联等 | 内容 ID → 可核对关系及证据 | 不因布局需要伪造因果/比例 |
| 讲解 N | 总分、分总、问答、递进等 | 内容/关系 → 页面或跨页的讲解阶段 | 不改变内容事实，不自行合成音频 |
| 表达 E | 原子与有语义的组合组件 | 内容/关系 → 可编辑模型与公开目标 | 不复制主题专属业务组件 |
| 空间 L | 页面区域、排版方法、对象约束 | 区域/测量 → 几何与空间诊断 | 不推断逻辑、不改变讲稿 |
| 风格 S | token、变体选择、素材语言、组合偏好 | 已定义能力 → 外观与适配要求 | 不改关系、目标身份或校验门槛 |
| 时间 T | 语块绑定、动作、阶段/镜头 | 讲解/目标/时间来源 → t 时刻状态 | 不以播放历史作为唯一状态 |
| 输出 O | 预览、图片、视频、PPTX等 | 固定场景/资源/时间 → 支持报告与产物 | 不把像素当可编辑、不静默丢内容 |

以下目录是覆盖分类；各项状态和稳定 ID 见 capability-catalog.json。

## 1. 内容：先明确表达对象

- 名称与定义：术语、概念解释、符号含义。
- 陈述：事实、主张、结论、建议；事实与主张的来源属性不同。
- 例证：案例、情境、反例、引用、证据、来源及讲者备注。
- 数据：标量/单位、类别、序列、时间、二维表、分布、空间数据、不确定区间。
- 任务：问题、答案、条件、操作、目标、练习、反馈。
- 媒体内容：图片、截图、视频、声音、代码、公式、文档片段。

数据须有真实依据；定性强弱不自动变成精确百分比。来源、单位、免责声明等必要信息
属于内容，不能因为“太影响美观”删掉。隐藏备注与必须呈现的来源分别标记。

## 2. 关系：先于画法

| 关系家族 | 代表内容 | 必须保留的语义 |
| --- | --- | --- |
| 并列/分组 | 几类方法、若干特点 | 无隐含先后；组身份稳定 |
| 对比/异同 | A/B、多方案比较 | 比较对象与维度；差异不是因果 |
| 顺序/依赖 | 操作步骤、前置条件 | 先后、依赖边、是否可并行 |
| 因果/论证 | 原因与结果、证据与观点 | 边方向、证据/推断、必要条件 |
| 层级/包含 | 分类树、组织、整体部分 | 父子、多父限制、部分完整性 |
| 分支/汇合/循环 | 决策、反馈、状态流转 | 条件标签、汇合点、循环终止含义 |
| 时间/演变 | 事件、阶段变化、前后状态 | 真实时间与仅讲解顺序不同 |
| 数量/比例/分布 | 指标、占比、相关性 | 单位、尺度、总量与缺失值 |
| 空间/对应/网络 | 地图、部位、概念关联 | 坐标/锚点、边端点、非树连接 |

树形布局只是某种画法；可表达多父网络的数据不能为了树状美观丢边。箭头图形只在有
对应关系或明确讲解指向时出现；箭头不是关系事实来源。

## 3. 讲解组织：可跨页

总→分；分→总；总→分→总；问题→解释→答案；现象→原因→建议；主张→证据→结论；
目标→步骤→结果；案例→抽象原则→应用；已知→未知；对比→选择依据；时间演进；
逐层深入；提问→停顿→揭晓；回顾→迁移练习。它们是组织策略，不直接等于某个布局。

每个阶段绑定内容及目标，可分配到一页的多个时间区间或多页。拆页/合页保留内容身份，
重新分配语块/页时间；不靠重新编号数组来继承动作。讲解策略可复用，实际正文不存入配方。

## 4. 表达：绘制能力与编辑语义共存

原子首轮 Text/Image/Vector/Group；新增媒体原子需单独渲染协议。语义组件家族包括：

| 家族 | 候选组件 | 为什么需要独立模型 |
| --- | --- | --- |
| 文字信息 | 概念、列表、引用、提示、问答、总结 | 项身份、角色、引用和文字范围 |
| 比较 | 对比项、对比表、优缺点、前后对照 | 对象与维度对齐，而非散落方框 |
| 流程关系 | 步骤组、分支流程、循环、层级树、网络 | 节点/边/条件身份和编辑语义 |
| 时间 | 时间线、阶段演变、里程碑 | 时刻、区间、顺序与跨度 |
| 数据 | 指标、表格、柱/线/饼图、散点、分布 | 原始数据、系列/点身份、轴/单位 |
| 图像说明 | 带标注插图、截图聚焦、图例、局部对照 | 原图版本、锚点、标签与连接关系 |
| 专业内容 | 公式、代码、地图、媒体、互动模拟 | 各自专有编辑、测量、时间与输出协议 |

例如流程组件保存步骤和边，底层仍复用四原子。复杂对象的可编辑身份不能在渲染时
消失；要公开步骤、边、单元格、数据点等稳定目标，而不是“第几个 DOM”。

## 5. 空间：多层嵌套

页面结构：标题有/无、标题内嵌主体、副标题、主内容、旁注、来源/脚注、页码、
字幕/数字人安全区。每个区域可独立 optional/required，必需内容不因区域 optional 而消失。

分区方法：横向/纵向切分、堆叠、网格、非均匀网格、叠放、锚定/受约束自由定位。
组件内部可用行/列/换行排列。关系组件还可使用树、分层图、环形、时间轴等专用排布算法；
专用算法属于组件几何，不把“循环语义”等同于“摆成圆形”。

约束类型：固定/比例/内容自适应尺寸、最小最大尺寸、对齐线、顺序、间隔、纵横比、
裁切、避让、锚定、层级。输出比例是规格，9:16 需要重排与容量检查。

## 6. 风格、时间与输出的范围

风格：文字角色、颜色含义、边框/容器、材质、留白密度、图标语言、插图构图、数据编码、
连接线语言、动效默认、兼容变体、配方与参考集。不同知识对象的颜色含义应跨页一致。

时间：出现/消失、强调/勾画、步骤推进、连接线绘制、数据变化、状态变换、局部聚焦、
镜头移动、跨页转场、交互触发。后续交互必须提供固定时间剧本才能导出视频。

输出：在线预览、离线 HTML、静态图、MP4、最终页/分步图 PPTX、基础原生 PPTX、原生
动画/媒体 PPTX。每种单列支持集、资源携带、字体和降级，不能由 HTML 可看推断全部可导。

## 7. 分类完整性的检查办法

每个案例都填写八层及共同约束；空层说明不适用而非随便补一个。每层列正常、边界、
失败与修改后行为，并关联分类 ID。没有归属的需求进入扩展流程；有归属但缺字段的是
具体定义欠缺；有字段但不能运行的是实现欠缺。三种缺口不混写“待优化”。
