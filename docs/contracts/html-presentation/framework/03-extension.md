# 扩展决策与兼容机制

## HPS-021：先归类，再扩展，最后验证

所有新需求保留一个最小真实案例；先核对分类和已有定义，选择最小且能复用的扩展。
新增名字不能代替实现，也不能把风格专用代码包装成“公共组件”。

| 变化 | 应放位置 | 必须检查 | 例子 |
| --- | --- | --- | --- |
| 正文、图、选择顺序变化 | 实例 | 身份、覆盖、资源/锚点、失效 | 换成同步/异步学习 |
| 已有属性取值变化 | 风格 token/允许覆盖 | 范围、对比、容量、视觉版本 | 字体、颜色、间距 |
| 表达模型相同、内部排列不同 | 公共变体 | 公开目标含义不变，编辑/输出保留 | 概念图在上/在侧 |
| 现有能力重新组合 | 配方 | 槽位、关系、素材、阶段与参考页 | 无标题的左右图文对比 |
| 区域分配方式缺失 | 公共布局算法 | measure/arrange、约束冲突、嵌套 | 非均匀网格 |
| 出现新的内容编辑职责 | 语义组件 | 数据模型、子项身份、关系、目标 | 分支流程、表格、公式 |
| 新的时间行为 | 动作/时间协议 | 通道、初终态、seek、冲突、输出 | 路径移动、图表渐变 |
| 新媒体/渲染能力 | 渲染适配器及公共接口 | 资源、就绪、确定取帧、能力预算、导出 | 视频、3D、交互模拟 |
| 原有类别无法表达新语义 | 分类及内容/关系协议 | 是否实际无归属，四种兼容影响 | 地理坐标与空间投影 |

## 1. 扩展提案模板

每次提案记录：extensionId、需求/来源、最小例、分类 ID、现有能力为何不足、拟扩位置、
输入字段与默认/范围、依赖、公开目标/语义、允许风格参数、测量/时间、编辑/失效、
输出支持/降级、兼容四维、替代方案及取舍、正常/失败/修改用例、版本/迁移、结果证据。
采用 [定义卡模板](../05-definition-template.md) 完成能力字段，避免另造第二套卡格式。

相同需求能用已有接口表达时，优先记录为实例或配方；只有真实语义/算法缺口才升一层。
但不能为省组件把流程压成一堆无边身份的矩形，也不强求所有视觉差异只靠调颜色。

## 2. 生命周期与登记

分类记录状态 candidate/defined/deprecated；定义卡仍用 draft/specified/deprecated；
实现状态 not_implemented/implemented；验证状态 not_verified/partial/verified。不得互相推导。
分类 candidate 转 defined 的条件：定义卡完成、关联规则齐全、正常/非法例可审查。
进入运行注册表还需实现入口、适用环境、支持版本、就绪/错误/输出声明和对应验证。

目录登记 type/category 不自动放行 AI 生成。生产检索集合取“运行支持 ∩ 风格覆盖 ∩
当前输出允许”，其余只能提出缺口，不能给模型一个任意 HTML 逃生口。
同一个概念可对应多个候选画法，但选择必须保留关系与内容覆盖。

## 3. 兼容与回退

新能力使用新 ID；变更旧字段/默认/目标发布新定义版本；已有作品固定旧版本。
旧样板的必选标题改为可选属于旧行为/结构变化，应使用新能力或显式升级，不原地放宽。
迁移产生新修订、身份映射与差异；保留源、资源和旧导出，未知字段/版本不能被旧读取器丢掉。

风格不支持某能力时只能：用该风格声明且语义等价的通用变体；选择另一受支持风格；
请求新增风格映射；或报告不支持。输出策略允许时可局部转图，但不能自称完全可编辑。
“其他/自定义”只能成为扩展申请入口，不能成为绕过类型检查的通用脚本容器。

## 4. 四种扩展演练

**无标题对比**：语义仍是对比，原子/概念目标保持；新增区域/配方选择，无需无标题专属概念。
**三选一分支流程**：新增流程图语义，节点/带条件边有身份；页面复用公共区域，风格只管呈现。
**手绘风**：先新增 token、素材和公共线条变体；有随机笔触则固定种子，不能每次取帧随机抖动。
**可交互科学模拟**：内容与交互状态进入专用组件；时间回放、随机种子、资源、输出剧本单独定义。
如果无法确定回放，声明只支持交互预览，视频/PPTX 按实际策略阻断或记录静态降级。

验收扩展机制本身：以上每例都能指出归属、需要新建/可复用的对象、保持的身份、
待实现能力和输出限制；不会因为“所有东西都能画成图片”就视为框架已经支持。
