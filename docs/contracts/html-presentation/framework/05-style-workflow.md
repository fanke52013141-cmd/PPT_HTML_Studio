# 从一个风格试制形成可复用定制流程

## HPS-022：风格按样本覆盖与证据发布

风格包遵守 DEF-STYLE；这里补充从需求到验证的工作流程，不引入另一种生产风格格式。
应用工作台 UI 与演示内容风格分开。风格不会重写语义组件、讲稿或已有音频/数字人方案。

| 步骤 | 工作 | 交付物 | 完成判断 |
| --- | --- | --- | --- |
| S01 风格任务书 | 受众、场景、比例、内容密度、观看环境、情绪 | brief.md，方向与排除项 | 能明确评价画面，不只写“高级” |
| S02 能力范围 | 选参考内容/配方、支持组件和关键状态 | coverage 清单，正常/边界案例 | 支持与待扩展分开 |
| S03 视觉语言 | 字体、色彩、层级、空间、容器、图标/插图 | token 草案、素材规范、来源 | 字体可追溯，颜色按语义命名 |
| S04 第一页试制 | 完整页及初始/讲解状态 | 可查看参考页、截图 | 真实中文、完整正文，关键状态可审阅 |
| S05 参数回收 | 从画面提取可复用值/变体，记录例外 | style.json、配方参数、decision-log | 没有偷偷加入风格专属组件 |
| S06 内容压力 | 长短文、图比例、隐藏/无图、换实例 | 检查记录/边界画面 | 超容量有诊断，不能删内容凑合 |
| S07 跨结构与输出 | 无标题、图文、对比、步骤等支持集；取帧/导出 | 参考矩阵、实际能力报告 | 一页漂亮不推导所有页面通过 |
| S08 发布与维护 | 固定字体/资源/版本、审阅状态、升级影响 | 版本化包、验收与变更记录 | 输入完整、声明范围真实、旧版可追溯 |

S04 可以先用独立参考 HTML 表达视觉方案，但必须标注“设计样稿，非通用内核”；不能把
手工排版参考截图当成场景编译器已经实现。引用帧与实现帧以后要对照，偏差说明原因。

## 每个风格包的交付清单

任务书；版本化 token/组件变体/布局支持；字体文件或明确宿主解析说明与实际字重；
插画/图标/纹理资源及要求；配方/禁用组合/允许覆盖；正常/边界/阶段参考集；
动作默认与显式实例值优先规则；输出支持/降级；审阅/检查证据；决策与问题清单。
缺项允许 draft，但不得标成可生产/verified。字体待定不能靠系统回退冒充确认。

## 首个风格要学到什么

1. 哪些视觉值可以归到 token，哪些需要公共结构变体？
2. 正文长度和插图比例变化时，哪些范围仍然好看，哪些需要另一个配方？
3. 初始只有标题/先出现一侧时，留白是否是有意构图，还是明显空洞？
4. 插画复杂度、颜色和背景边界如何写成稳定素材要求？
5. 一份风格要支持哪些组件才足以覆盖当前课程？
6. 预览字号在实际观看尺寸是否清楚，带字幕/数字人之后是否需要新配方？

这些问题逐个记录“观察→归属→修改→复查”，成为以后定制流程的实际经验，而不是一页
设计完成后凭印象写总结。未经过真实生图的素材要求只能写设计假设，不能说稳定生成已验证。

## 常见问题归属

颜色不协调修风格；某图主体不对修素材；所有风格都溢出查测量/布局；只是内容量超范围
改实例/配方；换风格导致锚点错误修公开目标/几何；为凑版式改了知识关系修规划。
单页例外若不能说明跨内容复用，不提升为公共规则。新风格不继承旧风格的验收状态。

下一种风格复用 S01—S08 的清单、固定内容样例、公共定义和验收方法，重新设计值与资产。
首次试制形成可复用流程草案；至少经第二种风格验证，才记录流程本身已完成跨风格复用。
