# 视觉实现分工与生成契约

契约包：0.7.0；日期：2026-10-07；适用：HTML 混合视觉路线。
状态：现行设计规则，通过文档审查执行；正式 Schema、自动生成编排、资产板提取器和运行门禁尚未实现。
本次只补协议，不生成新图片、不开展新动画测试。文中的交付记录是定义要求，不是已上线接口。

## 1. 与原体系的关系

本协议细化 [视觉生产规则](07-visual-production.md) HPS-023—025，继承身份、时间、资源、编辑和输出规则 HPS-006—017。
原有公共组件、布局能力、风格、模板、内容容量和时间轴继续有效。生成图片不是新的数据源头，也不替代组件定义。

| 层次 | 公共职责 | 风格或实例职责 |
| --- | --- | --- |
| 对象与组件 | 身份、内容角色、目标、资源引用、控制能力 | 实际文字、数据、人物或物体 |
| 布局与模板 | 槽位、约束、容量、允许变体、安全区 | 已审阅的构图参数、当前内容 |
| 风格 | token 和插图任务书结构 | 字体、色彩、线条、材质、光照、运动气质 |
| 实现分工 | 分配原则、拆分规则、检查门槛 | 每个对象的具体实现选择及理由 |
| 运动 | 时间求值、坐标、动作冲突与目标语义 | 本场景顺序、路径、时长、姿态 |
| 资产 | 格式、来源、版本、裁切和锚点要求 | 实际图片、姿态组与授权证据 |

“场景”在本协议表示讲解设计单元，可为静态页面或过程动画；不意味着现有 P01 的 slide 字段已支持世界坐标、镜头或跨场景对象。实现这些能力仍须新定义卡和显式版本。

## HPS-026：同一设计定义驱动生图与代码构建

必须先形成可审阅的结构化设计定义，再分别派生设计图任务、资产任务和代码组装要求。不得以整页图片识别结果取代原始对象定义。
设计定义至少引用内容版本、契约版本、模板及变体版本、风格版本、对象清单、关键帧计划和运动计划。
模板不匹配时进入设计探索；未经视觉与运行验收的构图不得直接当生产模板。

设计图用于验证审美与构图。它可以表现由代码实现的文字、图表和箭头，但图中的文字、数值、连接关系不能反向覆盖权威内容。
发现更好的构图时，先更新设计定义及受影响模板/实例版本，再更新资产和渲染；保留原方案与人工编辑，不凭截图静默改规则。

### 2.1 实现清单：生成前必须逐对象填写

| 项目 | 必填内容与判断标准 |
| --- | --- |
| 身份 | 稳定对象 ID、所属场景/分组、语义角色、对应知识点或讲稿语块；装饰注明无知识映射 |
| 内容 | 权威文字/数据/关系来源、必需与辅助内容、科学禁错点；不得由图片 OCR 定稿 |
| 实现 | HTML/CSS、SVG、Canvas、图片资产或混合分组；选择理由、依赖组件与当前支持状态 |
| 控制 | 是否需独立显隐、移动、旋转、缩放、换姿态、勾画、编辑；公开目标与最小控制单元 |
| 几何 | 模板槽位、设计画布、主体范围、留白/禁入区、锚点、裁切限制、坐标归属 |
| 层级 | 父对象、前后关系、遮挡物、阴影归属、是否随镜头或固定于屏幕 |
| 时间 | 出现/退出及可见窗口、初始/中间/结束状态、运动计划引用；终态不可见也登记 |
| 资源 | 复用或生成、资源 ID/版本、所需姿态、分辨率/透明要求、生成任务引用 |
| 验收与输出 | 内容/视觉/控制验收负责人及证据；HTML/视频/PPTX 各自支持或降级方案 |

以上为文档字段语义，正式字段名和类型须在实现定义卡中确定。对象 ID、资源 ID、资产板槽位 ID 不得混为一谈：多个对象可复用同一资源，一个对象也可引用多个姿态资源。

### 2.2 分工决策

按 HPS-023 的分工表逐项决定。补充以下边界：

- 正文、术语、单位、数据、精确连线和可编辑标签由代码或可靠结构化素材实现。生图不决定科学数值与拓扑。
- 简单形状、路径和粒子可用 SVG/Canvas；复杂材质、人物、装置外观可用图片。Canvas 不自动带有 DOM 目标，须提供独立目标几何映射。
- 混合对象必须展开子对象及边界。例如装置外壳为图片、仪表数值为 HTML、运动齿轮为独立资源或矢量。
- 静态资产只能提供声明的控制粒度。整张机器平移不等于内部齿轮可转；姿态切换不等于骨骼动画；透明淡出不等于真实形变。
- 从侧面转到正面、揭开遮挡或大幅变形需要额外姿态、图层或其他渲染方案，不能依靠对单张图做平面旋转冒充。

## HPS-027：全过程对象与关键帧先于资产生成

对象清单必须覆盖整个讲解过程，包括开场对象、过渡提示、临时箭头、替换前后的状态和结尾已消失的对象。
不得只根据终态图推导资产需求。隐藏是状态，不是删除对象；对象生命周期及引用遵守 HPS-006。

### 3.1 关键帧计划

设计参考以“视觉关键帧”命名，不默认等于终态。简单场景可用一个代表帧；构图、遮挡、姿态或镜头明显变化时，必须补充覆盖变化的关键帧或人工分镜。
每帧记录 ID、对应讲解阶段/计划时间、可见对象及状态、构图意图、屏幕固定元素、与其他帧的一致性要求。
无需为每帧都调用生图；已验收资产可在草图或渲染快照中复用。生成帧只能作设计证据，不能证明中间运动可行。

### 3.2 运动计划

每个有动作的对象须记录：触发语块/事件、顺序与并行组、初末状态、路径或插值方式、时长/缓动、锚点、坐标系、遮挡顺序、退出后的状态。
音频未确认时使用标记为暂定的时间；确认后消费既有音频时间轴并重验节奏，不新建语音合成或强行以估算秒数代替对齐结果。
同一属性的重叠动作必须定义优先级、合成方式或判冲突，不能依赖随机执行顺序。暂停、跳转、倒放、导出取帧必须由给定时间确定状态，继承 HPS-008。

局部、场景/世界、屏幕坐标必须区分并声明换算；镜头变换不得重复施加。标题、字幕等固定屏幕对象不随世界运动。
允许对象在非讲解阶段出画；必需知识须在声明的阅读窗口可见、可读。验收运动扫过范围、遮挡变化和字幕/数字人安全区，不能只检查首尾。
新路径、镜头、姿态能力尚未正式注册，实验代码不能被当成生产支持证明。

## HPS-028：生成任务明确代码层与资产层

必须从已审阅的实现清单派生两类任务；不能用同一段模糊提示词同时要求“完整页面”和“无字独立资产”。

| 任务 | 输入至少包含 | 输出要求 |
| --- | --- | --- |
| 视觉设计图 | 内容摘要、布局/风格引用、对象及实现分工、关键帧状态、文字区和禁入区、统一参考 | 完整视觉参照；代码文字/箭头可示意，须明确仅用于参照 |
| 资产或资产板 | 只含待生成对象、已确认参考、完整轮廓/姿态/遮挡要求、槽位、视角光照、背景及交付要求 | 不含后续由代码叠加的正文、标签、箭头、UI；独立可用的图像素材 |

发送给模型的信息必须明确：哪些仅在设计图中示意、哪些需要实际生成、哪些禁止烘焙进资产、哪些空间需保留、哪些对象会独立运动。
资产需要运动后暴露的部分，应完整绘制；前景遮挡物另层提供。贴地阴影、投影和反光是否随对象移动须预先决定，必要时独立生成。
同一系列共享视角、光向、材质、色彩和尺度参照；不要求模型仅凭相同文字描述保证一致。

生成交付须保存：任务 ID、输入设计版本、模型/服务与实际参数、提示内容或受控引用、参考资源版本/哈希、原始输出、选中版本、审阅记录。不得保存密钥。
模型不支持透明、尺寸或其他要求时须记录实际输出与差异，进入修复或改任务流程；不得把提示词要求当成已实现事实。
生成结果是待验收数据。禁止直接执行模型输出的 HTML/脚本；未来结构化生成须由受约束组件编译并验证。

本文件规定任务语义，不提供已接入生产的 Prompt。接入时按仓库 Prompt 优化规则审查真实输入、解析、预览、回退和下游影响。

## HPS-029：资产板提取保留身份、几何与版本

允许一张资产板容纳多个对象，但它是批量交付容器，不是运行中唯一的大图片。必须预先登记槽位与期望资产 ID，提取后分别登记资源。
不得仅凭生成位置或后验识别自动定名：实际槽位内容必须核对；缺失、重复、串槽和合并对象均须修复或人工确认。

### 5.1 资产板设计约束

- 槽位固定且分离，记录板尺寸、行列/区域、槽位矩形、留边和预期对象。对象、阴影、半透明边缘不得跨槽粘连。
- 编号与名称保存在清单或后加审阅覆盖层，不烘焙进有效素材。
- 同角色多姿态须统一画框、比例、视角和脚底/关节锚点；不得按各自非透明包围框放大至相同尺寸而破坏比例。
- 每个对象在最终最大显示尺寸及镜头放大下要有足够像素。板容量由有效分辨率、复杂度和提取成功率决定，没有通用固定数量；首测 4—6 个仅为实验建议。
- 大主体、玻璃、毛发、复杂半透明物、精细边缘和高分辨率资产可单独生成。不得为减少调用次数牺牲资产质量。

白底不是通用要求。可用真实透明通道或与主体不冲突的纯色底，但须按资产验收：白色物体不能盲目白底抠图；玻璃与反光的背景污染可能无法靠简单色键移除。
棋盘格像素不等于透明通道。alpha 存在也不等于边缘合格；须在浅、深和目标背景查看光晕、缺口、残底及半透明效果。

### 5.2 提取记录与发布

每个提取结果记录源板 ID/版本/哈希、槽位矩形、实际裁切矩形、裁切偏移、透明边距、输出尺寸、原始尺度、锚点、处理方法及参数、输出哈希、内容与边缘审阅状态。
源板坐标中的锚点换到裁切图时，先减裁切原点，再按实际缩放换算；旋转或填边也须记录。原始图保留，不能只留下不可追溯的抠图结果。
提取方式可以是确定性裁切、分割/抠图、人工处理或模型编辑；实际选用方式及误差必须记录。改变轮廓的修复生成新资源版本，并重验锚点。
资产库发布须同时通过身份、内容、风格、边缘、尺寸和运动适用性检查。失败可以单槽重生或替换，不强制重生全板；替换后重新确认系列一致性。

## HPS-030：分阶段验收、影响范围与兼容

| 门槛 | 必须交付的证据 | 不通过时返回 |
| --- | --- | --- |
| G1 分工可执行 | 对象无遗漏、实现支持明确、独立控制粒度足够、模板/预算匹配 | 内容规划、能力定义或模板探索 |
| G2 设计成立 | 关键帧、审阅结论、内容正确、层级留白与整体风格成立 | 构图/风格设计；不能硬靠 CSS 负边距补救 |
| G3 资产可用 | 资产及提取清单、来源版本、透明/边缘/锚点/完整轮廓证据 | 资产修复、单槽重生或重新拆分 |
| G4 组装成立 | 实际 HTML 渲染、与设计对照、真实文字/数据、目标几何、关键状态 | 模板、实现或资产；记录偏差归属 |
| G5 过程成立 | 中间帧及播放、阅读窗口、轨迹/遮挡、安全区、重复取帧 | 运动计划、资源或渲染实现 |
| G6 输出成立 | 目标尺寸与帧率、资源就绪、视频/PPTX 对应实测与限制 | 对应导出实现；不隐式降级 |

不要求与设计图逐像素相同；要求保持已确认的构图、主次、留白、主体质量和风格。明显偏离须记录差异及审阅结论。
自动测量不能替代美感审阅；设计图通过不能替代实际 HTML 审阅；一个样例通过不能代表所有模板与风格通过。
每次验收保存产物版本、检查方法、实际环境、审阅人、结论、未通过项与适用范围。

### 6.1 修改与失效范围

| 变化 | 至少重新检查 | 默认保留 |
| --- | --- | --- |
| 文字或数据 | 内容、容量、对应关键帧与讲解映射；改讲稿则按既有音频规则处理 | 无关图片与手工编辑 |
| 布局/模板/字体 | 排版、槽位适配、目标几何、安全区及相关运动 | 满足新槽位条件的资产 |
| 风格 | 受影响资产/代码样式、关键帧与实际合成审阅 | 不受影响的内容语义与对象身份 |
| 图片或裁切/锚点 | 主体尺度、位置、遮挡、动作连接与下游输出 | 其他资源和独立动作 |
| 动作或镜头 | 运动窗口、分辨率、完整轮廓、过渡帧与输出 | 仍适用的素材 |
| 音频对齐/时长 | 动作映射、阅读时长、字幕/数字人同步与视频 | 静态设计与未受影响资产 |

未来接入业务时将实际影响登记到项目已有影响机制；本次表格不是已生效的缓存或任务失效实现。重生不覆盖用户锁定的资产/布局/内容，须保留可恢复版本。

### 6.2 输出与历史兼容

HTML 支持、视频支持、PPTX 支持分别声明。图片型 PPTX 不保证元素可编辑；分步快照不等于原生动画；连续镜头和 Canvas 动画不能默认保留到 PPTX。
如采用快照或局部栅格化，需记录关键状态选择、知识覆盖、可编辑范围和用户已接受的降级；不能静默丢掉过程知识。
P01 固定 0.4.0 定义及样例、0.5.0 分类目录保留原版本。旧作品不自动升级，不删除旧字段；新动作/镜头/对象关系通过定义卡、显式版本和适配方案引入。
本次没有应用代码、数据库、Agent API、生产 Prompt 或原图片后端行为变更；语音、音频时间轴和数字人继续复用已有方案。

## 7. 可复制的设计交付清单

下一次试制必须先填写下列记录，可以先用 Markdown 表格，不必提前发明运行 DSL：

1. 任务：知识目标、屏幕必需信息、讲稿引用、时长范围、画幅、输出、风格/模板版本、支持缺口。
2. 对象：按 2.1 表逐项填写，标记过程对象及代码/生图归属。
3. 关键帧：帧 ID、阶段、可见对象、构图与遮挡、参考和验收状态。
4. 运动：对象/属性、语块或事件、暂定/确认时间、初末状态、路径、坐标、优先级、锚点。
5. 生成：分开的设计图任务与资产任务、输入快照、板槽位清单、背景/尺寸/禁画项。
6. 资产：实际输出与预期差异、提取记录、资源版本与锚点、复用条件。
7. 组装与验收：真实渲染、设计差异、G1—G6 证据、问题归属、最终支持范围。

示例分工（仅用于解释协议，不是新的样例实现）：“小水滴汇成大水滴”中标题/字幕用 HTML，冷杯用独立图片，小水滴/大水滴与临时指示用 SVG，简单背景用 CSS。小水滴即使结尾消失也在对象清单；如只需整杯移动无需拆杯壁水珠，如需杯壁某颗水珠单独滚动则必须另定义独立对象，不能靠终态图片自动获得。

## 8. 后续验证范围

先完成一个短过程场景的 G1 设计记录，再做关键帧与小资产板试验，对比独立生成的成本、边缘质量和一致性。
须验证代码文字未进入资产、过程对象不遗漏、身份/槽位一致、裁切后锚点正确、初中末状态和任意跳转成立。
本协议不把资产板效率、自动抠图成功率或跨模型一致性当成已证实结论。已有 hybrid-01 的视觉方向反馈及 motion-01 的局部确定性证据仍只适用于各自实验，不构成本协议整体通过。
