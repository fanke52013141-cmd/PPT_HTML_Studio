# 代码美术参考资产的形成与使用

契约补充：0.9.4；2026-10-09（Asia/Shanghai）。细化 HPS-009/014/022/025/026/028/031/032/033/035/037。状态：用户明确原则的设计规范；具体样板、美术参数和自动化仍须逐项试制与审阅。

## 1. 美感的前置依据

必须先用真实代码形成足够美的参考，再把代码能达到的审美水准传递给生图模型。能力目录负责完整性与技术边界，美术参考负责呈现精致的细节、组合和整页；普通技术测试截图不得仅因可运行就成为已批准美术参考。

参考须覆盖足够的可实现表达，允许模型在声明范围内为新内容组合。不能在构思前仅选极少数普通组件，也不能预先锁死整页像素来代替美术探索。效果分类完整不代表美感成立；模型生成美图也不自动批准代码还原。

## 2. 什么形成可复用资产

代码美术参考是由以下内容共同形成的、可定位版本的资产包：

- 真实源码、引用的组件/效果及版本；具体内容实例与布局。
- 主题参数、允许组合、作用边界；代码/插画各自职责。
- 实际截图：精致细节、局部组合、完整样页；候选可有变体比较。
- 字体与图片资源身份/哈希、字体取得方式、自然尺寸/可见边界及锚点。
- 渲染环境：画布、浏览器、字体、DPR、指定静态状态或运动时刻。
- 能力、可复现性与美术审阅记录，问题清单和允许使用范围。
- 无凭据的来源、生成/编辑方法、人工纠偏、原始与采用版本的关联。

仅保存一张PNG或一段提示词不构成完整代码美术参考资产。混合样页必须列明插画，不能把图片材质列作代码能力。系统字体可记录实际文件/哈希，不因此获得重新分发许可。

规范字段卡见[代码美术参考资产定义卡](../definitions/code-art-reference-asset.md)。字段属于设计记录，不是已实现的新运行Schema/API。

## 3. 资产形成顺序

1. **确定用途及美术目标。** 指明参考用于教模型哪种表现，覆盖哪些内容和风格。
2. **审查效果定义。** 对齐ID、定义、实际代码与截图，缺项明示；不能通过重命名旧ID掩盖错用。
3. **在真实代码内打磨。** 设计细节、局部组合及完整页，保留候选；先查看代码自身的美感。
4. **固定输入并渲染。** 采用明确字体/资源/主题/布局，截图与源码同版本，记录环境与哈希。
5. **分别检查和审阅。** 技术检查查资源/几何/内容/边界；美术审阅查层级、比例、留白、图文协调与实际观看效果。两种结论分开。
6. **登记采用版本。** 美术未通过保留试作状态及原因；通过仅适用于审过的版本、风格、构图和容量。
7. **组成固定参考集。** 分类总览、清晰细节、局部组合、完整样页共同交付；注释是参考说明，不进入最终作品。
8. **验证生图与还原。** 记录实际附件、提示规则和参数；对模型组合及实际HTML分别审阅，按问题层次局部纠偏。
9. **验证复用并维护。** 用另一内容和容量边界检查声明范围；改变源码、主题、字体或素材生成新修订，并说明受影响的使用记录。

形成资产在此指完成可追溯材料；成为已批准参考还需要对应美术结论。不得将“已归档”“方向可行”“技术通过”写为“美术通过”。

## 4. 三种展示尺度及完整性

| 尺度 | 传递给模型的内容 | 必须保留的对应 |
| --- | --- | --- |
| 细节 | 字阶/字重、线条、渐变、阴影、边框等经过设计的实际效果 | ID、参数、作用位置、真实截图 |
| 局部组合 | 标题/导语、容器/文字、曲线/标注、插画/代码标签的比例与层次 | 组合效果、对象关系、图文归属 |
| 完整样页 | 主视觉、阅读路径、留白、图文配合及整体审美水准 | 实际HTML、固定输入及审阅范围 |

构思与生图需要充分、清晰地看到当前风格准入的代码表现。完整范围可以分册，多图和放大细节负责可读性；不能只给一个模糊大拼图，也不能提前缩成少量组件。未实现、禁用和未审阅材料必须标识，对人的审查材料和正式可选美术参考须区分。

不同接口的图片数量、上下文和分辨率能力需实际核对；不能假设模型永久记住上一轮参考。复用的是固定材料，不是省略实际有效输入。

## 5. 输入角色和构思分工

代码美术样板是代码部分的审美基准；结构化目录说明完整能力、版本与边界；外部风格图指导插画及整体协调，不能扩大已支持代码效果；本页主题/讲稿和对象关系决定表达内容。

在构思阶段同步声明代码、插画及混合对象各层的职责，保持文字、数值、标签与语义关系可控。初稿允许构图探索；选中方案后固定精确布局、字体和实际素材。独立素材需记录是否为原像素提取或模型重绘，透明背景不代表无损还原。

模型可在允许范围内组合，而无需复制样板版式；输出仍是提案。参考和文字约束冲突时先修输入，模型不作为规则裁决者。

## 6. 纠偏、保护与状态

纠偏可以修改内容、样式参数、构图、可见主体框、锚点、对象连接、资产选择；也可以锁对象、局部重做和回退版本。提示词反馈是其中一种途径，不能代替实际编辑保护。

每次登记问题对象、期望修改、锁定项、受影响范围和前后对照。没有对应执行机制时，界面/文档须写为待实现，不能承诺已具备拖动、锁定或局部生成能力。

最少分别记录：技术状态、美术状态、可复用范围、实际模型输入记录和最终HTML审阅结论。资产候选/待审/需修改/已通过/已被替代是设计记录语义，具体运行枚举待实现时定义。已通过绑定版本，变更不能静默覆盖旧字节或旧结论。
