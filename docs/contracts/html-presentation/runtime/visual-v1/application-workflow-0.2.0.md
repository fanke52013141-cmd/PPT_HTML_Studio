# 应用流程与工作流状态合同 0.2.0

2026-10-10。适用：guided + HTML + 16:9。scene 0.3.0、theme/layout 0.2.0、template/asset 0.1.0 均保持不变；Agent API 1.16.0。本文是应用级状态投影与输出门禁补充，不是新的 scene 格式、任务 API 或视觉能力注册表。

## 工作流状态投影

`GET /api/projects/{project_id}/html-visual/status` 与 Agent 对应只读路由返回相同的 `workflow` 字段。字段格式为 `hps.html.workflow_status` 0.1.0。它只从当前项目、分镜、HTML 场景、审批指纹、音频确认、动作绑定、数字人配置和持久任务记录汇总状态；查询不得启动生成、写入审批或修改项目/任务状态。

`workflow.stages` 固定包含以下七个业务阶段。它是后端业务状态，不替换 UI 中稳定的八个可见位置，也不重编号或合并原图片流程。

| ID | 含义 | 事实来源及就绪规则 |
|---|---|---|
| `project_setup` | 项目设定 | 以已解析的项目和所属 run 目录为基础；记录后端类型。进入 HTML 状态路由即表明项目存在。 |
| `content_planning` | 内容与画面规划 | 当前 `visual_contract.json` 中有分镜页面时为 `ready`；缺文件为 `not_started`；空页面集为 `blocked`。不声称人工内容审阅已完成。 |
| `design_and_assets` | 设计、素材与实际 HTML | 每页必须有可读的已保存 HTML 场景，且已有视觉审批指纹仍对应当前场景和实际输入；缺场景为 `not_started`，无审批为 `needs_review`，过期批准为 `stale`，无效输入为 `blocked`。这只报告现有逐页人工视觉审批状态，不执行新审阅。 |
| `audio` | 旁白与音频 | 只在当前分镜页面集合的音频制品和确认记录有效时为 `ready`。音频可以先于 HTML 场景准备；音频就绪本身不会解锁输出。 |
| `animation` | 动作与音频绑定 | 需要分镜、当前已确认音频、每页有效的 beat ID binding，以及可实际求值的音频时间线。无音频时阻塞并指出先确认音频；不存在或无效的目标 beat 也阻塞。 |
| `digital_human` | 数字人讲解（可选） | 发行配置禁用、项目未启用或尚无数字人配置时为 `skipped`；启用后要求对应模式的非空媒体制品，否则为 `blocked`。它不增加第八阶段，也不作为 PPTX 前置条件。 |
| `review_and_output` | 审阅与输出 | 附带逐目标 ready/issues。无目标可执行时为 `blocked`；至少一个目标可执行时阶段标记 `needs_review`，含义是 H6 全局审阅记录尚未定义/记录，**不是**批准结果。`review_status` 固定报告 `not_recorded`。目标可执行性不伪造人工课程签收。 |

阶段对象带有 `id`、`title`、`status`、`review_status`、`source`、`issues`。实现可附加每阶段事实和逐页状态。状态值 `ready`、`in_progress`、`not_started`、`needs_review`、`stale`、`blocked`、`skipped` 只描述相应事实源的当前状态；它们不是跨阶段的数据库状态枚举。未知事实不得推断为 ready。`workflow.approval_scope` 声明不得从生成、技术审阅或可导出状态推断新的人工批准。`workflow.tasks` 仅包含本项目持久 HTML 任务的 ID、类型、生命周期状态、阶段、尝试次数、安全错误摘要和更新时间；不得携带任务输入、完整结果或幂等键。

## 独立阶段与依赖

内容规划完成后，HTML 场景生产与旁白/音频准备可以各自推进。场景只有在保存成功后才参与视觉审批状态；音频只有当前确认有效才算就绪。动作阶段依赖两者：必须先有场景，再把稳定 beat ID 绑定到已确认的时间线。项目可在没有场景时确认音频，但不能由此批准视觉或导出视频。

项目状态是现有持久事实的读取模型，不把“待规划、生成中、待审阅、已完成”等显示值写回 `Project.step_status`，不更改图像后端状态。原工作区八个可见位置保持稳定；本七阶段投影不能插入或重排这些位置。

## 按目标计算输出门槛

| 目标 | 必需的当前事实 | 不要求 |
|---|---|---|
| HTML 快照 PPTX (`html_snapshot_pptx`) | 分镜中每页都有有效 HTML 场景、当前逐页视觉审批和输入指纹 | 音频生成/确认、动作绑定、数字人 |
| MP4 视频 (`mp4_video`) | 上述视觉条件、当前分镜音频制品和确认、逐页 binding 对当前 scene/beat 有效且可对音频时间线求值；数字人被项目启用时还需对应媒体 | 未启用的可选数字人 |

PPTX 和 MP4 各自携带 `target`、`ready`、`issues` 与其要求标志。MP4 的状态同时汇报音频确认和数字人启用/状态。HTML 视频任务入口重新执行真实门禁；投影结果不得被当作可绕过服务校验的授权。图像后端原有的音频确认、图片来源校验与输出逻辑保持原样。

## 兼容和验收边界

`workflow` 是既有 HTML visual status 的新增响应字段；旧 `revision`、scene 计数、逐页状态、顶层 visual `ready/issues` 保持。无分镜页的项目可以返回结构完整的七阶段状态与两个未就绪目标，不会因为没有页面而伪造完成状态。Web 和 Agent 调用同一个聚合函数，Agent 能力版本由 1.0 升为 1.1，Agent API 版本由 1.15.0 升为 1.16.0。

此增量没有新增数据库表/列或迁移；不会改写历史 HTML scene、批准、音频确认、PPTX、视频任务或图像项目。验证可覆盖 fixture/provider 替身、运行时门槛、持久状态一致性和浏览器渲染；它们分别不构成真实外部供应商证据，也不构成用户对目标风格、完整课程或 H1/H6 全局审阅的签收。H1/H6 持久人工审阅记录未在本版本定义。
