# 容量修复进展证据 0.1.0

HPS-010/013/015/017/023—025。契约包0.9.59，Agent API1.39.0。

## 定义卡

| 项目 | 规则 |
| --- | --- |
| 输入 | 原容量报告的available/measured，新增triggers与effectiveLimits；已保存页报告的原始证据从issues[].details读取 |
| 问题 | 行数、文字边缘或有效约束变化可能不改变DOM盒或scroll/client整数；只比较盒尺寸会误报unchanged_measurements |
| 比较 | 保留已有事实字段及有效限值；每个触发项只比较dimension、actual、limit、tolerance、unit，触发项排序后比较 |
| 噪声 | 说明文字、触发项顺序、截图路径或报告ID变化不构成进展证据 |
| 继续 | 事实发生变化仅允许既有预算内继续，不证明视觉改善或收敛；未保存候选最多原三轮，已保存页最多原两轮 |
| 停止 | 重复候选、重复补丁、测量事实相同、模型停止和预算耗尽保持原规则；不自动重试，不扩大工具或人工保护权限 |
| 通过 | 仍须原严格检查通过；诊断图和变化事实不是批准 |
| 兼容 | 老报告没有triggers/effectiveLimits时仍按已有测量比较；无数据、作者、scene/binding或Prompt输出Schema迁移 |

html_repair_progress.py是候选与已保存页共用进展判断的唯一来源。实际候选Agent原出站payload已保留capacityIssues全部诊断字段，本次不因增加模型上下文重复拼接解释或更改模型/预算。容量runtime Skill仍0.1.0，正文与引用未修改；这是消费端判断修复，不冒充新Skill效果。

## 验证与边界

固定相同DOM盒，分别改变行数和有效上限，确认不会提前停；相同触发事实即使顺序或文字变了仍停止。实际LangGraph使用检查器与模型替身，验证诊断字段进入模型输入、改善后严格通过需两次决策、完全不变一次后停止、仍未通过在两次测试预算后停止，原scene/binding保持且不写作者。

这些验证不证明真实模型能选择最优字体/布局，亦不证明连续变化一定改善；真实渲染与语义/审美/音频/导出验收独立。原未知请求不补发，本机运行换版仍受此前审批阻塞影响。
