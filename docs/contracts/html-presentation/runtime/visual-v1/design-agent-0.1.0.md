# 设计理解、素材分工与还原审核 0.1.0

HPS-011/013/015/017/023—030/035—037，2026-10-13。定义、实现与真实供应商验证分别记录。

| 环节 | 输入 | 输出与门禁 |
|---|---|---|
| 设计理解 | 一张真实设计图、当前页准确对象、各对象适用的注册组件/图标、已有/待生成素材身份 | 每个对象恰好一条外观观察、代码或图片归属、复用或生成决策；不改内容/身份；未知造型明确unsupported |
| 素材分工 | 图片对象明确assetRef，计划已允许的独立主体，已有资源声明 | code对象不得转成图片；新主体经现有素材服务生成，已有主体明确复用；缺失或额外主体返回素材/规划返工，不猜ID。当前最多单主体，多元素拆分不由本增量自动开放 |
| 受控还原 | 图、理解/分工、注册编辑工具、真实几何和人工保护 | 最多两次静态操作；准确文案、关系、对象、动作不改；结构/字体/资源校验沿用 |
| 独立对照审核 | 原设计图＋当前实际HTML截图、准确对象、实测文字/几何 | pass / changes_requested / unsupported，各问题含目标、类别、严重性、观察证据和返工归属；无批准权限，无修复操作 |
| 修复路由 | 审核问题 | layout类可进入剩余还原预算；content→planning、asset→assets、capability→capabilities，明确停止；耗尽保持旧作者与审计 |

理解结果不是仅供下一模型参考的描述：合法variant/icon由程序通过原受保护编辑接口先执行，写入allocation-applied.json；再由还原模型调整位置与文字样式。组件选择不由程序猜测，也不以人工编辑方式改写模型方案。若与人工字段或实际注册能力冲突，明确停止。素材外观观察同样实际进入原素材生成请求。

2026-10-14 容量检查顺序修复（HPS-023—025）：应用理解变体后重新执行严格工程检查，不能继承变体应用前的通过状态。只有容量错误进入既有最多三轮排版 Agent；其他工程错误直接阻断。修复后再严格检查，通过后才请求受控还原；后续还原操作仍须严格检查与独立原图审核。变体检查、修复场景/绑定与完整排版审计归档在还原目录，纳入生产来源指纹。模型未知结果与人工签收规则保持；新增容量决策独立于原还原/审核各两轮预算，不声称整条链路仍最多五次模型决策。

返工路由另经对象归属校验：模型将代码SVG/组件标为asset时，原分类与证据保留，程序将其路由到capabilities而非位图生成，routed_issues记录依据。只有image对象可进入独立图片返工阶段。

三个新运行Skill为设计理解/分工、受控还原、对照审核；与原容量修复共四个。注册身份/hash与输入输出合同由代码约束，不加载用户文档为高优先级策略。保留供应商正常思考，每次等待600秒；不以超时为结构失败重发。

设计子链理解一次、还原最多两次、审核最多两次，共最多五次业务决策；容量修复另按既有排版Agent的独立三轮预算执行，底层JSON格式兼容/修复HTTP另外计数。重复候选提前停止。所有成功候选必须经过独立对照审核；model pass仅是模型建议，human approval始终pending。实际帧的讲稿语义QA仍属A04，不由终态对照取代。

审核与理解版本、附件hash、场景hash、实际调用参数进入审计及生产来源；Skill或源变化使候选/快照过期。Web/Agent/MCP/CLI复用原produce接口，无新数据表和任意代码执行能力。
