# 多标签讲解与注册呈现 0.1.0

关联 HPS-001/006/007/010/011/013—017/019—030/035—037。本卡先定义本批能力；实现、工程、真实模型和人工验收单独记证据。目标是消除多标签插图只能回规划却没有可选模板的缺口，不为某考试编写组件分支。

## 定义卡：语义对象与布局

新增模板 explanation-labeled-v1@0.1.0，复用原十一个槽位的公共对象类型，新增最多六个可选 marker-1…marker-6 text 槽和三个可选 relation-1…relation-3 arrow 槽。每个活动槽必须有独立稳定对象 ID、代码内容、语义角色及明确的初态/讲稿动作；不是图片内部文字或由 OCR 决定的正文。关系必须继续由公开代码对象表达，标签数量不等于完整关系能力。超预算回规划或能力缺口，不截断。

模板固定引用 science-explanation-v1@0.3.0：旧 @0.2.0 原文件与旧模板保持。新版本延续相同画布/安全区与公共布局身份，扩大 intro 容量、为顶部图注和多标签留空间；六个标记槽高于主体、位于字幕区外，默认布局只是可检查的初始几何。已有主题兼容该布局 ID，无需复制主题；色值仍从主题取。layout schema 显式增加 0.3.0，旧读取器遇新版本拒绝，不降级。

标签必须源自权威文章/讲稿/视觉组；原设计发现缺失文字只能提出规划建议，不能据图片直接注入事实。新模板不自动把所有标签设为初始可见、不自动增加动作或批准。资产仍最多一个非语义主体。

## 定义卡：注册变体

scene 保持 0.7.0，新增 ID，不改变旧造型，presentation-variants 登记为 0.3.0。

| ID | 类型及能力 | 边界/预算 |
| --- | --- | --- |
| text-emphasis-bold | text；原 runs.emphasis 选择 700/400 字重 | 不改原字符、run 边界、强调标记、颜色或动作；整 part 编辑仍不提供分段改写 |
| arrow-up | arrow；现有箭头向上呈现 | 至少24×32；仅绘制该对象的既有关系意图，不从位置推导拓扑或添加关系 |
| figure-caption-top | figure；note 顶部、tag 下方独立胶囊 | 至少360×240；note最多2行、tag1行；按各自实际内容宽高测量，主题填充/描边，无任意 CSS |
| summary-relationship-columns | summary；heading、from→to、term+takeaway 三列 | 至少1100×110；heading/takeaway最多2行，其余1行；term在第三列上部，takeaway主题胶囊；独立子区容量与整体溢出均阻断 |

选择仍通过受保护 set_variant，理解/还原依据适用注册元数据作决定。未注册分段样式、任意颜色、层级或语义改写仍失败。新变体不授权运行 Agent 修改源码。

## 规划输入、兼容与验收

生产规划 Prompt 明确将图内语义标签列为代码对象，按标签预算选择模板，不把它们写入 image need。新增模板通过原注册目录/真实槽位预算进入模型输入，网页与 Agent 共用原规划入口；不增加数据库或作者操作权限。旧计划不自动补标签、换模板或变更内容。

同案例复验先经系统规划 Agent 根据原权威内容生成新计划，再用原设计作独立理解诊断；Codex 不手写本例标签对象或模型答案。实际 HTML 需正常工程检查、设计审核、音频与人工门禁；原设计的历史批准不自动迁移为新计划/新版生产批准。结构/容量通过不是视觉或关系语义验收。
