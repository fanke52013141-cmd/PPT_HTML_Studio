# 首轮局部对照证据 0.1.0

关联HPS-010/011/013–017/023–025/037，契约包0.9.71。补充首轮覆盖0.1.0，不以窗口齐全等同视觉识别正确。

## 输入与责任

html_review_evidence.py拥有审核派生对照表，html_design_agent.review_fidelity仅在显式local_comparisons=True诊断实验中消费，默认生产不开启。原设计及实际HTML终态整图仍是图1/2，程序按当前report.geometry的1600×900对象盒及外扩边距，在两张16:9图片相同归一化坐标生成左右窗口。图3/4最多两张对照表；每个有效对象明确targetId、label、image_index及row。原始画面、文字、场景与作者数据不变。

这是unverified_same_coordinate_window，不是参考图对象检测/自动定位。对象位移、窗口混入邻居或原图缺字必须回看整图，不能把窗口当作同一对象的证明。缩略图保持各自宽高比，不能用缩略后绝对字号作测量；当前文字对齐仍以准确注册布局和编辑覆盖合同为依据，非浏览器实测。参考对齐需要视觉识别，仍不明确则uncertain阻断，不能编造pass。

## 预算与失败

最多40对象、两张派生PNG，每张低于400万像素、总体不超过原适配器4张图片；不增加审核调用、修页轮次、输出额度、等待或自动重试。缺/非法/非有限对象边界、越界或非16:9输入逐对象标unavailable；完整整图和原全量review_checklist保留，不凭窗口缺失判断对象不存在。窗口不是必然放大，高密度对象仍受图片预算约束。

manifest绑定完整scene、原图、实际截图和派生图片hash，模型返回后再核对来源；请求记录原图与全部派生图hash，新模块纳入generation snapshot源闭包。所有证据路径必须在隔离run内。没有引用新模块的旧冻结快照不能宣称执行新审核。实验运行片段0.9.0注册为独立内部design_fidelity_review_local阶段，默认生产0.10.0使用双整图；两者删除旧status/issues-only示例，以唯一{status,issues,coverage}格式为准。

## 类型兼容修复

真实0.9.0响应在issues重复写入reference_alignment，导致原协议拒绝。0.10.0仅定义这个已知字段为可选Literal元数据；非空值必须属于typography问题，并与唯一同targetId的typography coverage的参考对齐完全一致。uncertain、矛盾、没有对应项、其它requirement上的非空值和其它未知字段仍拒绝；null不影响视觉判定。不搬移、不猜测、不丢弃任意未知字段，不替模型补问题或改pass。出站Schema仍将此重复字段隐藏，不要求模型重复输出，coverage仍为权威记录。

## 验证与兼容

不新增公开场景字段、渲染变体或人工批准；旧归档可读，工程/覆盖声明/视觉准确/人工签收分别记录。本增量尚未实现模型独立区域定位、OCR或DOM事实采集，不宣称这些能力。固定两图与原0.8.0封存请求配对各三次，低推理与项目模型绑定保持，未知即停；统计有效召回、全召回轮次、协议有效率、集合一致性和耗时，不修页。真实实验未达启用条件，默认关闭局部对照；同一原始响应的0.10.0离线回放只证明解析修复，不能代替新模型请求或完整生产验证。见[实测报告](../../../../plans/html-backend-development/first-review-local-evidence-2026-10-17.md)。
