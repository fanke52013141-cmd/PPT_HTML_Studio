# 固定流程评估 0.1.0

定义卡：HPS-010、013、015、017、023—025、035—037。输入为版本化固定事故清单，输出为隔离执行的逐项结果及原始证据；所有者是开发验证脚本，不属于应用生产 Agent。定义已完成，实现/本机运行证据见开发交接；真实提供者效率和视觉验收独立。

## 清单与验收

唯一可执行清单为 `checks/fixtures/html_workflow_evaluation.json`，版本 0.1.0。每项必须包含稳定 ID、场景、证据类型、明确执行器/测试入口/参数项数量，以及 calls、reuse、route、terminal、author、approval 六项预期。未在该案例验证的事实明确标注，不推断。

## 执行与证据

`scripts/evaluate_html_workflow.py` 只执行清单登记的 pytest 入口及指定浏览器测试，没有 live 选项；以当前 Python 解释器启动，Node 使用项目 Playwright 与共享浏览器解析器。显式错误的 HPS_CHROME 仍报错，不静默更换。

数据库与 runs 环境在子进程中强制指向临时目录，覆盖继承的生产路径；不导入 server、不使用真实课程作为写入夹具。输出必须是 outputs 下的新目录，不能覆盖历史评估；不清理或修改既有任务、批准与产物。每个执行器有超时，Windows 下结束其自有进程树。日志可含替身请求和测试异常，属于 ignored 输出，不提交。

pytest 一次执行去重后的所有选择器，JUnit 中保留每个参数分支。必须收集到固定数量，且每项通过；缺项、额外项、跳过、失败或执行器异常均不得通过。Node 成功以进程零退出为准。报告记录 expected 和实际 test status/items；预期调用数字不是生产观测值。

输出 report.json、report.md、pytest.xml 与执行日志，记录清单 hash、开始/结束时间、Git HEAD、跟踪改动与未跟踪文本散列、日志/原始证据 hash。来源身份在启动时采集，执行期间应保持待验证代码不变；不是生产生成快照或完整环境封存。单项耗时是测试时间，不能作为模型速度提升指标。

## 基线比较与兼容

--baseline 接受历史 report.json。profile、清单字节 hash、案例 ID/顺序必须完全匹配，否则执行前拒绝；不可用改清单把失败项移走后宣称改善。比较只输出 recovered、regressed、unchanged；不对测试耗时设置生产效率结论。新增案例或改变参数数量形成新基线，旧报告保留。

无 Web/Agent/MCP API、数据库、作者 Schema、生产模型配置或导出变更；Agent API 仍 1.32.0。未来真实提供者评估应使用独立 profile、显式供应商证据和最小调用，不混入本离线基线。
