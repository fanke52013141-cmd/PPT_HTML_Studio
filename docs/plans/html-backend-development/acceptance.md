# 验收规范：输入、执行、通过条件与证据

本文件定义后续开发的验收，不代表这些检查现在已经完成。任务与 AC 编号对应见[tasks.md](tasks.md)。每次验收冻结代码、浏览器、字体、资源、主题、布局和输入版本；不同环境截图不直接做严格像素等值比较。

## 测试数据与环境

建立独立测试 fixtures（建议 `checks/fixtures/html_visual/`），测试数据库/产物只用临时目录。遵守 checks/conftest.py 在导入 database 前设置 `PPT_STUDIO_DB_PATH`、`PPT_STUDIO_RUNS_DIR` 的机制。不得以真实项目做失败注入。

- W：已有冷杯/蒸发两场景，检验迁移、资产锚点、参考风格；水蒸气变液态是凝结，不能写成凝固。
- T：Token 真实课程至少五场景：定义、切分过程、输入/输出用量、上下文窗口、结论；至少三种不同结构。文字切分标注示意，真实 Token 数必须注明 tokenizer；不采用固定“1000 token=750 汉字”或一律“超窗自动遗忘”的说法。
- P：12–20 秒对象过程，至少一个过渡对象出现后消失、一个对象移动、一个关系线/数值随讲解变化；终态不包含所有对象。
- X：边界和失败集：长标题/长正文、空可选标题、中文标点/数字、缺字体/图片、坏 hash、重复 ID、无效 beat、超预算资产、越界坐标、非法资源路径、并发修改。
- I：已有 image 项目，覆盖原 Mask、音频确认、批注、数字人选项和输出，作为回归。

模型与 TTS 日常单测用可控 fixture/stub，不靠每次付费调用证明代码正确。正式端到端至少一次使用配置中的实际模型/已有音频方案，留模型配置标识和产物 hash，不保存密钥。服务不可用记 blocked，不能把 stub 结果记成真实服务验证。数字人未配置可单独 blocked，不能因此宣称该可选集成已实测。

## AC01 基线可复现

从清单检查应用和 HTML 源码、工具版本、源提交/遗留改动记录。按已记录命令运行基线检查。通过条件：下一执行者能找到完整源码与固定版本；隔离数据有效；原工作区改动未被覆盖。证据：环境 JSON、命令与退出码、基线失败清单。缺源码/缺依赖不能标 passed。

## AC02 公共与风格分离

同一 W 内容、布局、对象和动作切换两个测试主题；只允许主题声明的外观变化。检查对象 ID、讲稿/资产语义、时间绑定不变；公共 renderer 不按课程名或主题名写分支。旧格式 fixture 仍可读取或明确拒绝并提供版本迁移；非法属性拒绝。证据：结构 diff、Schema 正反用例、代码审查。中性测试主题用于架构验证，不代表新增视觉方向。

## AC03 布局覆盖与容量

运行 T 五场景并逐一标记结构类型，至少图文、数据/关系、过程舞台三类；左右换位/换颜色不算不同类型。加载 X 的长短内容、无标题页面：不得裁字、溢出、无故挤压。装不下时编译/测量明确失败并建议拆页，不暗自缩字。证据：结构清单、截图及对象边界报告。

## AC04 视觉验收（独立人工门槛）

输出真实 HTML 静态截图、对应设计参考和原始风格参考，并排审查，不以生图预览替代实际页面。逐项记录 pass/change_requested/pending_review：

1. 深蓝灰文字、粉色重点与浅色辅助色是否保持主次，避免全页彩色抢重点。
2. 渐变、图标气泡、卡片边线和轻阴影是否存在且一致；没有退化为只有文字和大图的空壳。
3. 标题断行、行距、对齐、留白是否自然；没有拥挤、无意义大空洞或变形拉伸。
4. 插画、图标、关系线的大小与连接对应是否正确；主体纹理可以来自资产，代码负责可编辑结构。
5. 页面形式随语义变化；不是每页三张卡片或同一左右结构。
6. 无多余英文栏目、品牌、系列/来源页脚；科学解释保留，字幕区域专用。

执行 Agent 先自审列差异，再交用户看实际截图/短片。用户未审阅保持 pending_review，不替用户签字。若用户要求修改，M1 视觉不放行，记录具体项继续迭代；可继续不依赖视觉批准的基础开发。不得定义虚构的“美感分数达 90”或自动相似度代替审美。

## AC05 时间和运行时一致

同一场景依次采样 0、25%、50%、75%、终点，再随机乱序 seek，重复三遍；相同环境相同 t 的原始截图像素应一致。动画只由 t 与固定输入决定；等字体/图片 ready 后测试。播放/暂停/恢复不会重置或重复执行。预览和导出 manifest 的 runtime/theme/font/asset hash 相同。缺资源、播放器异常不得继续静默输出。

## AC06 效果图与提示词双约束

第一次生成效果图后，以同版本第二次运行：命中缓存，无新图生成；改变其中一个效果版本只刷新相关缓存。检查实际提交模型的请求上下文包含效果参考图、效果 ID、CSS/SVG/Canvas 归属、可调范围与资产预算。模型返回未注册效果必须诊断，不直接执行。证据：脱敏 payload、缓存计数/hash、失败案例。

## AC07 分镜与关键帧完整

T/P 每个讲稿 beat 有明确画面对象/动作或注明仅旁白；每个图片需求有渲染归属。P 的过渡对象必须在对象/资产/动作表出现，不能因为终态图没有而遗漏。关键帧覆盖关系变化；参考图差异转化为共享定义中的明确决策。证据：beat→node/action 映射、关键帧清单、设计冻结记录。

## AC08 后端兼容和迁移

新建空库、从旧库迁移、再次启动三种路径：旧项目默认 image，HTML 新项目保存/重载/Agent读取一致；迁移重放不重复破坏数据。unsupported 组合返回明确错误。image 流程保留原门槛；HTML 不要求 OCR/Mask。原显示步骤与内部 key、分发隐藏配置正确；数字人未开启不阻断。证据：隔离 DB 测试及两条 UI 流程记录。

## AC09 修改影响与并发

逐项修改：标题、讲稿、单资产、主题、字体、场景顺序、动作、字幕字号；检查影响矩阵：纯外观不重新 TTS，讲稿变更使相关旧音频确认失效，单资产只重建依赖页面及输出，排序更新全局时间而非重生资产。无变化保存不调用模型、不失效。两客户端相同 revision 编辑只有一个成功，另一个 409；旧任务不能覆盖新编辑。证据：调用计数、前后 hash、状态和产物清单。

## AC10 资产与几何

缺失/坏 hash/非法路径/超预算/错误尺寸必须失败。contain 保持纵横比，锚点使用图片实际映射；在三种显示缩放下，计算锚点与渲染测量偏差不超过 1 个逻辑像素。alpha bbox 以真实像素核验；白边、裁切主体、残留邻图、粘连和错命名须人工检查，自动透明检测不能代替。图集提取每项有独立输出及来源区域。证据：manifest、锚点测量、透明底和深浅底资产预览。

## AC11 动作是对象过程

P 检查初始/过程/终态、进入前/退出后边界和随机 seek；临时对象退出后不可见，关系线追踪目标，不出现错连。至少完成三种有讲解作用的动作，不能以全页淡入三次充数。人工动作修改重规划后保留或明确冲突。证据：短片、边界截图、动作与讲稿映射；视觉动态也要 AC04 审阅。

## AC12 音频与字幕

绑定已有确认时间轴，用已知 beat 在边界帧检查动作；绑定输出相对该时间轴误差最多一帧，秒/ms 转换及偏移不重复。此标准不宣称原始语音识别本身一帧准确；实际听看发现词句错位仍需已有校准流程修正。长短字幕、20/32/44 字号、空字幕均测试；底部 y=800–900 不得有正文/插图/数字人，溢出明确处理。修改外观不调用 TTS。证据：绑定报告、听看记录、各字号截图。

## AC13 批注跟随

对文字、SVG 对象、图片锚点各做一个圈/线/强调；对象移动和视口缩放后仍对应原目标，几何偏差不超过 1 逻辑像素。改字体/文字后重新测量，目标删除返回诊断。HTML 过程不调用 OCR；image 回归仍可调用原能力。证据：位置报告与动态片段。

## AC14 视频输出

固定 fps 与时长 T，采样帧数 ceil(T×fps)，每帧 t=i/fps（i 从 0 起）。输出总时长与预期差不超过一帧加音频编码单元时长；在报告中写出实际采样率/编码单元和容差，不能用一个不明的“差不多”。FFprobe 核查尺寸、fps、音轨、色彩元数据和可解码性。

预编码的关键帧与同环境预览在相同 t 像素一致；压缩视频不要求像素零差，另检查无黑帧、缺字、闪烁、截断、字幕重复与累积音画漂移。第一页/跨页/尾句均听看。渲染期间修改输入则旧结果不得登记为当前成功作品。证据：FFprobe JSON、帧比较、完整短片、fingerprint 日志。

## AC15 数字人

分别开/关导出：关闭无占位，启用对口型视频走已有服务并只合成一次，位置避开字幕和声明的重点区。失败时状态明确，不能输出无数字人视频却标全部成功。证明既有音频被复用，未另做 TTS。证据：开关输出截图、服务状态、短片听看记录。没有真实服务时仅接口测试通过，实测标 blocked。

## AC16 PPTX 分级

E03 检查 PPTX 文件结构、页数、16:9、终态/分步顺序、备注和字幕选项；实际在可用的 PowerPoint/兼容应用打开核对，未打开仅记结构通过。UI 明示图片式不可逐对象编辑。E04 另检查原生文字/形状可选中编辑、node 映射和逐项降级报告，不支持效果不可静默丢失。

## AC17 Agent 等价

Web 与 Agent 对同一测试输入创建/改稿/生成/审阅/导出，结果状态与失效一致；HTTP/MCP/CLI 能力映射及生成物校验通过。新增字段要么暴露并正确映射，要么明确登记隐藏；不能一端可写一端丢字段。证据：契约测试、脱敏调用和产物对照。

## AC18 恢复、隔离与安全

注入模型超时、取消、进程重启、用户同时编辑、客户端断开：任务状态可靠持久化，可重试且不会重复覆盖；断开不等于取消。账号/项目越权、路径穿越、任意模型 JS/HTML、外部 URL 应拒绝；渲染不关闭浏览器安全。保留旧成功作品，临时清理范围严格在本作业目录。证据：失败注入、数据库状态、产物清单。

## AC19 旧链路回归

运行 E1/E2/visual-v1 版本对应测试，原 image 项目从创建至输出关键流程，确认新 HTML readiness 不改变 image 的 Mask/音频/批注要求。记录基线已有失败；新失败必须定位，不得全部归类遗留。证据：基线与本次结果 diff。

## AC20 真实闭环与桌面入口

从规范目录中的同一启动脚本打开应用，新建 T 课程，依次完成五场景、三种结构、至少一个对象过程、确认音频、视频和快照 PPTX。关闭后重新打开，显示当前源码对应版本，页面没有旧缓存；原目录/数据库未受影响。不得用独立实验页代替应用集成。证据：操作记录、应用页面、视频/PPTX、实际提交与生成物 hash。

## 命令与证据约定

以下是已存在的检查入口，执行时先核实 package scripts 与浏览器路径；按任务选择，不必每改一份文档跑全部应用测试：

```powershell
# 工作目录 html_engine
npm run build
npm test
npm run build:e2
npm run test:e2
node visual/build.cjs
node visual/tests/verify.cjs
node visual/style-review/build.cjs
node visual/style-review/verify.cjs
# 工作目录项目根；pytest 使用项目隔离配置
python -m pytest checks/test_database_migrations.py checks/test_invalidation_service.py
node checks/test_visible_flow.js
node checks/test_frontend_quality.js
python scripts/generate_agent_contracts.py --check
python -m pytest checks/agent
```

新增功能须交付可运行的新测试入口（建议 `checks/test_html_visual_*.py` 与 HTML 浏览器验收脚本）；这些文件现在尚不存在，任务交付时必须写入确切命令。不要只交一句“所有测试通过”。工具缺失、浏览器缺失、外部服务缺失均不能跳过后记 passed。

建议每次验收输出隔离目录 `acceptance/<run-id>/manifest.json`，包括 commit、dirty diff 摘要、环境、输入/主题/布局/字体/资产/runtime hash、AC 编号、状态、命令/退出码、日志/截图/视频/PPTX 相对路径、阻塞原因及视觉审阅结论。证据必须可读取；不能写到未提交的私人路径后只留一个失效链接。发布包按项目规则保留可共享证据，去除密钥和用户私密内容。

放行条件：所有首发必需 AC 工程项 passed，视觉有明确用户审阅结论，实际服务测试没有冒充。可选数字人实测或后续 E04 的未完成项独立列明；不得将其计入“全部步骤完成”。
