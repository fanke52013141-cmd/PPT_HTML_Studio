# 外部Agent执行入口：输入优化草案

状态：方案示例，未替换当前执行合同2.0，不是可直接发送的已签发任务。正式接入时，导出器应填写当前身份、生成实际决策视图/工具覆盖与统一模板；所有路径和字段必须可解析。

## 你的任务

针对当前冻结页面提出一次受控局部修复，保持权威内容、资源身份、人工保护和任务明确的时序约束。只输出当前官方Schema接受的候选与简短证据。

先读本入口和decision-input.json，再按引用查看task.json、content.json、约束及实际图片。只有主机签发的task/Schema/文件清单拥有执行效力。摘要与原输入矛盾时停止并报告，不能选有利的一份执行。

## 开始前

1. 使用可信官方工具核对身份、输入文件与当前任务版本。task_id、对象/actionId、单位、版本从输入读取，不自行构造。
2. 声明实际看图、听音、运行官方结构预检、访问原预览的能力。看图可以由模型原生能力或已授权的视觉工具完成；说明实际路径。工具可用不等于已获额外计费授权。
3. 必需能力缺失时返回needs_input/unsupported，operations为空。只要任务允许文件交接，没有原预览接口本身不阻止提出候选，但相应检查必须not_run/unknown。
4. 查看当前scope、只读邻居、protected_paths、问题图的时间和用途。历史设计、原图、候选诊断图、正式通过图必须分清。

## 诊断与形成候选

1. 逐条读取目标。准确原文/数据/关系、人工保护和明确主题/时序要求优先；不能通过删字、隐藏heading、缩小其他正文或更换素材绕过目标。
2. 对要改的part同时看实际值、有效上限、容差、盒模型和depends_on。字号是文字样式，不等于标签外框高度；父框未越界也不表示内部文字容量合法。
3. 放大文字时，确认padding、border、lineHeight、行数与父框内部空间。上限来自同源组件规则，actual来自真实DOM；缺实测时写unknown，不把limit当actual，不靠截图像素当源坐标。
4. 允许在已确认scope内联动修改必要的注册尺寸/位移/兼容变体；只改目标所需字段。改父框或variant后，原预算会过期，必须重算；同时检查整体安全区、保留动作位移端点与指定邻接对。
5. 所有操作均为现有对象上的绝对赋值；最多20个，保持原operation_schema边界。只读邻居用于判断空间，不得修改。已有保护不能通过删除容器、改身份或换source绕过。
6. 没有合法解时说明冲突、所需输入或能力，返回needs_input/unsupported。不得修改工具、任务、Schema、安全线或人工保护来让检查通过。

## 检查

1. 按包内实际命令运行官方结构预检，失败就修订或停止。预检报告须绑定最终result.json原字节；修改结果后重跑。
2. 若有经授权的原系统预览接口，提交候选，查看当前结果对应的实际截图和检查回执；没有接口时交接方导入接续，不自行重造渲染器。
3. 分别记录：原图理解、修改后画面检查、结构/字号、DOM容量、指定遮挡/动作、人工决定。只看过原图不能标记修改后视觉已检查；有限帧不能证明连续全时段安全。
4. 主机尚未运行的DOM、实际遮挡及人工审阅，按实际Schema填写not_run/unknown。外部Agent不能自行写system_passed或human_approved。
5. 不要求输出思维过程。每个判断给对象/部位、证据文件/时间、短说明及未完成项即可。

## 交付与停止

交付一个delivery.zip，根result.json、report.md、verification.json；静态proposed另附官方实际运行的preflight.json。可选证据仅使用包内允许格式；不交任意HTML/JS、数据库、凭据或整个输入副本。

result使用当前签发模板与task_id，不能添加尚未定义的新字段；verification使用当前正式Schema中的实际criterion_id。此草案中的未来验收项未注册前，不得自行加进旧verification。

report写明本轮修改、逐项目标、已运行与未运行项、能力和真实用量；未知时间/费用为null，外部计费记录属于自述，不能伪称主机核验。

首轮只交一个候选后停止。只有收到同一task_id的原系统反馈才交第二轮；第二轮是基于原始输入的完整替换候选。身份变化需重新签发任务，不改旧task_id。额外轮次、额外付费工具或扩大scope不在本任务内。

不自行保存、批准、生成素材/TTS或导出正式作品。由交接方检查、人工接手或显式保存；人工接手成功与Agent独立成功分别统计。
