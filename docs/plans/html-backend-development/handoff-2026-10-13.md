## 详细实施方案与顺序

### A01：讲稿语义合同与规划输入（先做 N01）

1. 在规范定义卡中新增独立的“语块—视觉表达”合同，关联 HPS-011/013/028/030；再同步字段模型/校验、生成 Prompt 和 Agent/Web/CLI Schema。下列是拟定字段，不是已支持接口。
2. 演讲稿是语义真值，视觉概括/描述不能覆盖或替换原句；发现与讲稿矛盾的视觉内容须回到规划修复。每个 beat 保留原 `id` 和 spoken_text/hash，新增 visualIntent（表达什么）、targets（可多对象，标明 context/instructional/decorative）、动作列表与可检查的预期状态。narration_only 要有明确原因，不允许默认逃逸。
3. 动作使用独立稳定 actionId，支持一语块多个动作及同对象重复强调；保留旧 scene/binding 版本读取，旧作品不自动重解释。新版本错误不回退旧单目标模式。
4. `html_storyboard_planning` 负责纯标准化和语义引用校验；`html_visual_review_service` 只编排模型请求/有界结构修复；不要把另一套规则塞到验收脚本。

验收：二十个实际语块全部可追踪；未知 beat/target/action、无理由 narration_only、多动作重复身份均被拒绝。用 Token 第 5 页第三句作为负例：“为回复预留空间/检查实际用量”不能仅以无具体表达的 figure 强调宣称完成。

### A02：语义对象分解与生图状态（N02，依赖 A01）

先由讲稿确定应出现、变化和强调的概念，再用基本组件、风格及内容生成设计参考。`html_design_brief` / `html_reference_package` 必须携带语块含义、对象分工和起始/变化/结束状态，设计图不能只含最终槽位文字。

准确文字、输入→处理→输出关系、容量/数据与动态状态由代码对象承担；插图只承担其已定义的主体职责。支持范围内使用独立主体或现有素材板分割服务，保持资产 ID/版本/真实锚点；不以中心 focus 冒充具体内容定位。超出每场景资产预算或真实分割能力则明确拒绝/调整表达，不用整页栅格背景绕过。

验收：流程页可分别显现文本、分词器、Token 单元；上下文页能表达输入占用与输出预留；不画固定 Token/字数比例、不虚构容量/价格。共享美术方向和 low/1K 保留。

### A03：编译与真实配音动作绑定（N03，依赖 A01/A02）

`compile_plan` 消费显式语义角色和多动作计划。初始可见仅用于已声明 context/decorative；讲解目标的进入、关系改变、强调和退出由 beat 驱动。编译前核对标注/标签引用，编译后核对依赖对象的生存时间，不允许标注先于主体或内容在结束前消失。

`html_audio_binder` 继续复用既有 TTS/句级时间轴，以 beat/actionId 的真实时间为唯一正式时钟。重复动作不再使用 object:type 作为唯一身份；处理句间空白、末句尾部、偏移边界和实际音频时长。新流程缺少明确映射必须报错，比例缩放仅用于标为 legacy 的历史作品。

验收：为每个 beat 输出开始/中点/结束截图及对应对象可见状态、动作事件和旁白。动画先后顺序与真实配音一致，尾音完整；仅修改动画不重新 TTS。

### A04：独立语义 QA（N04，依赖 A03）

确定性校验负责完整覆盖、引用、对象可见性、动作时刻/依赖和叙述事实来源。另设带出处的多模态辅助评估，将真实 beat 帧、旁白、视觉意图、资产描述一起送入受控评估服务，反馈“相关/遗漏/矛盾/无法判断”及证据；它不能自己授予人工批准。

分别记录 engineering、semantic、audio、human 状态。实测画面没有相应解释、错误标注/图解含义或关键动作缺失时阻止整课完成；低置信结果待审。复用 S04 冻结快照/报告散列/有界无改善停止机制，禁止生成器仅自称“对应”后自证通过。

验收：本次脱节视频在新门禁中不再因几何通过而被标记完成；正确内容和时间的对照例可通过工程+语义检查；重写报告、删帧或只提交终态不能绕过。

### A05：系统内部课程制作调度（N05，依赖 A01—A04）

先审查 `one_click_orchestrator` 的现有 HTML 分支与 `HtmlWorkflowJobs` 能力，扩展已有项目任务/服务，复用 LocalJob、制作配置绑定、恢复快照与影响账本；不再造一个并行任务库，也不把 `scripts/accept_*` 放到用户路径。

目标状态链：输入讲稿 → 权威分镜/语义对象 → 设计参考 → 既有设计确认停点 → 独立素材/组件 → 场景与工程 QA → 原 TTS 服务 → 真实时间绑定 → 语义动态审阅 → 原音频/作品批准 → 正式导出。各阶段由同一后端服务调度，Web/API/Agent/CLI 调同一入口；用户只在明确既有审批停点参与。

授权范围、输入/模型版本、原请求、成本、复用理由、失败原因和当前/历史状态随任务返回。未知供应商请求只查原任务，不自动补发；暂停/失败重开继续同一任务，不依赖 Codex 注入旧响应。

验收：关闭 Codex，在正常应用中输入同一讲稿可完成审阅媒体；重启服务或刷新页面可恢复；全程没有 fixture 手改场景、FrozenModel 隐式覆盖、缓存响应 monkeypatch 或直接 helper 代办阶段。

### A06：真实回归与交付（N06—N08）

1. 从正常输入入口重做五页 Token 课程，不复用 Codex 预制中间规划作为系统自动生成证据；按授权复用有效媒体，未知请求保留。
2. 校验五页/二十语块的内容表达、多个注册结构、真实帧同步和整课音视频；系统自身导出诊断对照页和调用记录。
3. 改第三页一句话、修改一个标注与一项动画，分别检查最小影响、原手工编辑保护、音频/素材有效复用和新批准失效。再验证一次任务中断恢复。
4. 先验收无数字人路线；启用数字人后单独验证实际合成与同步，不把 optional skipped 当作启用通过。
5. 最终由用户审阅语义与听音后走正式导出；视频全解码，截图式 PPTX 如实标注，整课有序版本与当前输入匹配。
