# 流等待诊断与未知请求停点

承接[多标签能力交接](handoff-labeled-capabilities-2026-10-15.md)，用户授权开始推进真实模型调用稳定性及同案例验证。此批先解决等待事实不清和失败后缺少明确方向；不把诊断修复宣称为提供者可靠性改善。

## 发现与依据

原规划请求总预算1800秒，但共享JSON适配器对stream使用min(request_timeout,120)作为SDK读取等待。归档最后一次进度为155.910秒，流在280.559秒以ReadTimeout失败，适配器281.635秒结束；这与长时间读不到数据一致，不是1800秒耗尽。旧日志没有精确last_chunk字段，不能拿周期进度时间当成最后网络数据包时间。

请求只收到思考流计数、没有完整正文/stop/usage，也没有供应商任务ID。不能查明是否接单/计费或后续是否产出，不自动重复调用、切模型、换目录或补计划。原证据保留在ignored `outputs/live-linxuan-labeled-plan-20261015-v2/`。

## 实现

规范：[流等待与失败证据0.1.0](../../contracts/html-presentation/runtime/visual-v1/stream-failure-evidence-0.1.0.md)，契约0.9.54，API1.35.0。

- 流记录/回调新增实际read/total预算、最后已解码chunk时间、记录时无chunk时长、固定failure_reason；不记录异常原文、endpoint或思考文本。
- ReadTimeout链、流总预算、不完整响应和其他传输失败分别分类。通用API超时没有具体原因时不猜读取超时，ConnectTimeout不冒充ReadTimeout。
- 持久unknown回执和禁重发规则保持，next_action明确provider_verification、automatic_retry=false。源变化仍可保留已发请求失败证据；不因展示建议而重验快照丢弃回执。
- 正常任务详情显示实际预算、最后数据及“记录时”静默，核实原供应商请求方向。未知结果恢复按钮保持关闭；旧记录缺字段不回填。没有后台心跳，静默期间界面并非实时TCP健康探测。
- 模型/思考/max_tokens/温度及超时配置不变，没有新增查单能力、数据库、作者或导出格式变化。

## 验证与状态

流聚合/等待/持久阶段定向25项通过；实际浏览器验证读取超时、1800/120两种预算、125秒静默、恢复隐藏与原工作区行为通过。固定清单0.4.0扩展为22项并通过22/22，不与旧21项直接比较。

共享流适配器、快照、恢复、Agent合同联合回归 **471项通过**；Ruff、JS语法及Agent矩阵校验通过。模拟时钟复现156秒最后chunk、281秒读取失败；失败只执行一次适配器，重复调用仍拒绝，未发真实供应商请求。此联合运行在后续课程暂停改动前完成；后续改动另跑课程与Agent整合回归。

## 后续停点

本批定义/实现和离线诊断验证完成，但供应商断流根因、连接稳定性与新计划仍未验证。原同步未知请求没有可自动查单的ID，继续应先取得供应商侧核实结果，或由用户明确授权保留原未知记录的新付费实验；不能把一般“继续开发”当成默认重复未知请求。

在有明确新实验条件前，可继续独立修复已知父子任务暂停状态或内容限定词保真；不必反复等待/打磨单页。取得新计划后才依次验证标签/关系代码化、理解、素材/还原与独立审核，仍不手写业务计划来代替系统Agent。

用户随后明确选择“先修父子任务暂停，暂不重发”，已按此推进[课程暂停修复](handoff-course-pause-2026-10-16.md)，不再等待或补发真实案例。
