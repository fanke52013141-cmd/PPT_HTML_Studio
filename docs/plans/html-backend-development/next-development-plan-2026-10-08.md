## 3A. N00-A：多对象素材板生成与自动拆分

**目标：** 一次生图交付多个风格一致的配图，拆成有稳定身份、透明背景和可追溯几何的独立资产，供不同页面复用及独立运动。映射 C02/C03/C04、B02、F01/F02；关联 HPS-026–030、HPS-036 与 AC07/09/10/17/18/20。

依赖 N00；真实生成试验需要可用图片服务；确定性处理和异常测试可用隔离 fixtures。计划在 N01 的资产生产之前执行。素材板跨页组织不改变单页图片预算，也不要求每页生成素材板。生产现有入口每页最多一个新主体；扩展到批量资源时需补合同和版本定义，不能仅靠改 Prompt 放开限制。

### N00-A.1 定义对象、板槽位与处理合同

先完成定义卡和兼容/失效表，明确对象 ID、资产 ID、板 ID、槽位 ID 的不同职责。字段名称在定义卡中定稿，以下是语义要求：

- 生成前固定待生成资产清单、语义角色、共享参考、姿态/视角/光照、最终最大显示尺寸和锚点要求；全过程临时对象也入清单。
- 每槽期望一个完整可独立使用的配图；清单记录区域、留边和尺度参照，编号只在审阅覆盖层显示。
- 文字、数据、箭头、卡片和规则图标继续由 HTML/SVG/组件实现；素材板不烘焙这些元素。
- 输出记录源板 hash、槽位/实际裁切区域、遮罩或 alpha 来源、处理方法/版本/参数、裁切偏移、缩放、输出 hash、锚点和人工审阅状态。
- 定义原像素分割与生成式修补的区别：后者可能改变轮廓，作为新资产版本重验，不伪称无损提取。
- 原图、失败候选和人工修订保留；不改变旧单资产接口的既有语义。新增版本/API 与 Agent 契约在实现时同步。

### N00-A.2 三路线真实对照试验

以同一设计定义和参考风格，选择 3–4 个轮廓清楚、不互相遮挡的普通配图，比较以下路线。数量仅为首轮实验规模，不是生产固定上限；按最大显示尺寸核定板分辨率。

| 路线 | 用途 | 提取条件与结果解释 |
|---|---|---|
| A：直接提取设计图配图 | 尽量复用已认可设计图的原像素 | 必须完整、无遮挡、无文字叠压；缺失部分标为需补画或重生 |
| B：参考设计图生成专用素材板 | 默认建设方向，一次生成多个独立配图 | 固定分离区域、足够留边、无正文/关系/UI；核对实际内容与槽位清单 |
| C：分别生成独立资产 | 大主体、复杂透明边缘或板提取失败的回退 | 复用同一视觉参考，单对象修复，不强制全板重生 |

另建失败集：白色主体、接触边界、粘连/遮挡、缺对象/重复/串槽、低分辨率、假棋盘格透明、残底与锚点错误。玻璃、毛发和烟雾等作为复杂边缘探针，首版失败可以明确不支持并单独生成，不作为所有普通素材必须通过的保证。

每路线记录调用次数（含重试）、实际用量/费用或“服务未提供”、生成与处理耗时、风格差异、主体完整性、边缘问题、有效像素与人工修正次数。提交实际图片给用户审阅；未经实测不承诺更省钱、风格更一致或固定成功率。

### N00-A.3 实现识别、分割与透明化

1. 优先利用预定义槽位定位；视觉 AI 核对槽位里的对象是否符合清单，不能只根据位置自动命名。
2. 按需返回对象区域和分割结果；边框定位仅用于候选裁切，不等于精细抠图已通过。模型输出需校验，禁止执行返回的脚本。
3. 接受真实 alpha 时先核验；纯色底仅在与主体不冲突时采用。白色物体不盲目白底色键；棋盘格像素须诊断，不能当透明交付。
4. 生成独立 RGBA PNG；检查残底、白边、细节缺口、阴影归属和半透明边缘，并在浅底、深底和目标背景预览。
5. 原资产锚点按裁切偏移和实际缩放换算；统一尺度与画框，不能把不同姿态各自放大到同一大小。语义锚点不足时交人工补充。
6. 缺失、合并、低清晰度或不完整对象不得自动进入有效资源库；提供修正区域/遮罩、替换单槽、单独生成入口。修补改变像素时登记新版本。

分割/去背景提供者先查本地可复用能力、研究归档、许可证和部署成本，通过定义与实际试验后选择；不在计划中虚构已有精细分割服务。原图片后端的白底 flood fill/AI Mask 仅作为候选算法参考，不能直接套用其整页规范或将其结果冒充通用精细 alpha。

### N00-A.4 接入资产服务、审阅与持久任务

- 复用 `html_asset_service.py`、`html_production_service.py` 和 HTML store 的适用边界；板生成、识别/分割、提取分别有输入摘要和阶段记录，具体文件分工在实施时登记。
- 保留 `html_engine/scripts/asset-tool.cjs` 的确定性裁切/审计能力，扩展必须从源实现并测试，不能只改生成物；应用调用经公共服务适配。
- 缓存覆盖对象清单、参考字节、板规格、模型配置、处理版本和人工修订。槽位处理参数变化只重提取必要资源，不重复调用整板生图。
- 板作为批量交付源，页面引用独立资源。一个源板含多资产，每资产可被多页引用；模型生成费用按板调用记录，页面预算按使用主体数量核算。
- 首轮批量资产以候选集合审阅；身份/质量失败不自动整体批准。后续重试保留已接受资产，待修槽位独立提交；多文件发布与 N04 恢复设计衔接。
- UI 展示源板、对象清单、逐槽透明预览、问题和重试入口；批准仍绑定实际组装页面。同步 Web/API/MCP/CLI、revision 冲突、账户隔离、取消与旧 attempt 保护。

### N00-A.5 放行与证据

交付：定义卡、三路线对照报告、素材板和提取 manifest、原始/透明/多底预览、对象→资源→页面映射、实际 HTML 动态片段、隔离测试和未支持清单。

补充验收 AS01–AS06 见 [验收规范](acceptance.md)，仅为 N00-A 的计划验收项，不代表已通过。身份必须一一对应预期清单；边缘人工检查、尺寸、锚点和失效/恢复均有证据；被测试的普通素材可以在 HTML 中独立显隐/移动而无残底和邻图。

推进设两次检查：先完成真实对照，确认普通素材采用 B、特殊素材回退 C 的适用范围；再完成应用接入并在 N01 真实课程中使用。A 仅用于满足完整性要求的设计图资产复用。批量方案未通过的部分不阻止已有单资产课程路径验收，但不得因此将 N00-A 标为已完成或隐藏未支持项。

## 5. N02：完整对象、动作与语义锚点编辑器

**目标：** 用户能通过产品界面修改模型结果，不依赖编辑 JSON。映射 D01/D03、B02/B03、F01；AC09/11/13/17。

依赖：N00；N01 的实际使用反馈用于调整交互优先级。先沿用现有服务与公共播放器，避免产生独立编辑器渲染分支。

1. **对象面板：** 按页列出稳定 ID、类型、名称、讲稿关联和问题；点击列表与画面双向选择；可修改已注册文字/属性及替换资产。
2. **动作面板：** 选择已注册显隐、位移、强调、关系等能力；编辑开始/结束 beat、边界和手工偏移，显示冲突诊断。先做句子绑定和关键状态，不先建设任意多轨专业视频编辑器。
3. **预览：** 播放、暂停、重播、逐帧/时间跳转；页面标明预览所用修订和音频状态；随机 seek 与顺播一致。
4. **语义锚点：** 文字使用 DOM Range，SVG 使用登记几何，图片使用实际 contain 映射；允许新增、命名、调整语义锚点；目标删除或改字后给出明确修复入口。
5. **人工保护：** 保存 expected_revision；冲突保留本地草稿并提示重载/比较；重规划保留人工覆盖，不能静默覆盖。撤销/重做及锁定规则先补定义卡，区分会话内历史和持久修订。
6. **审阅影响：** 内容、动作、资产、锚点变化使相应批准失效；纯视觉修改不触发 TTS；提供明确的重新审阅入口。
7. **素材板资源：** 对象属性可追溯源板及提取版本，支持换成另一个已接受的独立资产；修改遮罩/裁切产生新资源版本，只影响引用该资源的页面，不改写同板其他对象。

实现归属：既有 HTML action/store/review/annotation 服务承担业务规则；前端模块按实际现存文件补充或拆分，不放回 workflow_state.js，不复用图片 Mask/OCR 伪造 HTML 编辑。新模块更新脚本加载顺序与 frontend-quality ownership 检查。Web/API/MCP/CLI 同步。

交付：对象选择与属性编辑、动作/beat 绑定、锚点编辑、冲突与人工保护、浏览器交互测试及操作示例。

通过条件：用户能完成“选对象→改文字/图片→改出现句子→调整锚点→保存→重开→重审→输出”；重规划不丢人工修改；三种缩放下锚点偏差不超过 1 逻辑像素；同一 t 重复取帧一致。

## 6. N03：项目独立模型绑定与生成配置

**目标：** 项目生成配置可追溯，不受全局设置悄悄变更影响。当前生产读取全局配置，此项为新增产品化工作。

依赖 N00；映射 B01/C01–C03/F01、AC07/08/09/17/18。具体字段、迁移序号和 API 必须在实现前确认，计划不提前注册新接口。

- 项目默认继承全局，允许显式绑定文字与图片提供者/模型；TTS 沿用已有配置机制。
- 界面显示本次将使用的有效配置及来源；明确“继承”与“固定绑定”的变更行为。
- 项目保存凭据引用，不复制明文密钥到场景、日志或导出包；配置包导出遵循已有脱敏边界。
- 任务启动固定有效配置摘要；更改模型不影响正在运行任务的解释，不擅自重做既有已批准作品。
- 素材板生图与识别/分割处理分别记录有效配置；本地确定性处理记录工具版本，不能把所有阶段错误归为同一生图模型故障。
- 缺配置、模型不可用、限流等给明确诊断；连接测试复用现有设置服务和 provider。
- 同步迁移、Agent 字段、配置导入导出和并发测试。修改生产 Prompt 时使用 optimize-prompts 工作流，同步默认/自定义迁移和 UI 预览。

通过条件：两个项目可独立使用不同绑定；全局变化对继承/固定项目的影响符合定义；任务可追溯配置且证据不含密钥；旧项目兼容。

## 7. N04：任务恢复、局部重试与发布可靠性

**目标：** 将已有普通异常回滚提升为明确的进程崩溃恢复保证。映射 B02/F02/F03、AC09/18/19。

1. 先定义场景、binding、plan、revision、resources 多文件更新的提交边界，与数据库任务状态如何协调；不得只加一个“成功”标记声称事务完成。
2. 建议采用作业暂存、输入修订校验、提交记录和可恢复替换；最终方案经过现有存储边界核查后决定，不引入新的业务数据库替代现有迁移机制。
3. 启动恢复识别未提交/提交中/完成：恢复旧一致版本或完成已准备提交；恢复失败保持可诊断状态，保留旧成功作品。
4. 注入每个文件写入/替换节点的进程终止，验证重新启动后的场景与资源一致性。
5. 验证取消晚到结果、旧 attempt、重复提交、客户端断开与用户并发编辑；远端请求已发出后的费用/取消限制如实展示。
6. 单资产重试只影响依赖页面；清理只在当前作业范围，不能清掉历史有效产物或人工资源。
7. 评估 Agent 借用 Web 路由的耦合，按需下沉共同服务；行为与账户隔离保持不变。
8. 覆盖素材板多资源提交中断、单槽处理失败、板生成完成后取消、重试复用既有源板等故障；页面不得引用只写入一半的资源清单。

交付：恢复状态合同、实现、故障注入矩阵、操作诊断和清理规则。通过条件：任何被覆盖的异常窗口都能恢复到一致状态或明确阻断；不得将部分新文件与旧批准拼成成功作品。

## 8. N05：数字人及首版完整交付

**目标：** 首版能力描述与实际验证一致。依赖 N01，完整产品交付还需 N02–N04；映射 E02/F03、AC15/16/19/20。

- 继续使用原数字人服务、音频和合成入口，不重新开发口型或更换 TTS。
- 验证关闭无占位、开启只合成一次；模板声明人物安全区，避免正文重点和 y=800–900 字幕区。
- 真实短片核验口型、音量、同步、跨页；失败必须可见，不把无数字人结果登记为数字人成功。
- 验证快照 PPTX 在目标 PowerPoint 打开、页序、画幅、字幕选项、分步页映射和备注；如分步模式缺失，按 E03 补齐。
- 补全新环境安装与启动验证，发布说明记录已支持/降级/未支持/未验证；旧 image、E1/E2 和 Agent 做必要回归。

数字人服务不可用时可交付“未包含数字人实测”的明确受限版本，不能宣称所有可选能力均已验收。全新克隆启动验证若需要临时检出，必须服从唯一运行副本约束，不创建或启动第二套常驻服务。

## 9. N06：受控批量与一键生产

**目标：** 在人工 guided 质量门槛可靠后减少重复操作。依赖 N01–N04；属于后续扩展，不自动放开当前首发范围。

- 批量生产前展示页数、缺失资源、有效模型、可用用量/费用估算及并发设置。
- 逐页保存进度，失败页和成功页分开；支持从失败阶段恢复及单页/单资产重试。
- 用户批准后的模板与复用资产优先命中缓存；已有人工编辑和当前有效作品保持保护。
- 依据跨页唯一资产清单组织素材板批次，按清晰度、风格和边缘复杂度分组；失败按槽位回退，不把同板所有成功资源一并重做。
- 静态检查通过只表示工程检查通过；需要视觉批准时暂停并展示实际结果，不让模型替用户批准。
- 批量导出仅消费当前批准和确认音频；遵守原服务并发治理，不另设绕过全局限制的线程池。

通过条件：同一真实课程 guided 与批量运行采用相同门槛和输入解释；失败、停止、恢复不会重复覆盖成功页；有实际模型耗时/用量记录。

## 10. N07：有限原生可编辑 PPTX

**目标：** 将“图片快照”提升为明示支持范围的可编辑输出。对应 E04，独立里程碑，不阻塞 guided 首版。

1. 固定转换器版本并核对许可证，阅读已有开源借鉴映射；未研究前不提前选定新库。
2. 定义 native/rasterized/unsupported 表：首批文字、图片、矩形、圆形、线条；图表、复杂 SVG、渐变、效果逐项增加。
3. 对象 ID 映射至 PPT 对象；保持坐标、层级、文字和字体语义。复杂效果允许明确局部转图，不能整页转图后称可编辑。
4. 每页提供降级报告；用户要求全可编辑而存在必需转图时明确拒绝或要求调整内容。
5. PowerPoint 实际选择、改文字、替换图、保存重开；检查修改后无旧像素残影。

交付：兼容矩阵、转换实现、可编辑示例、降级报告及目标软件打开证据。原生 PPT 动画、公式和母版另立任务。

## 11. N08：按真实内容缺口扩展

在核心闭环稳定后按需求拆分立项，不一次铺满能力目录：

| 扩展 | 开始条件 | 验收重点 |
|---|---|---|
| Canvas 效果样本 | CSS/SVG 已注册能力不足以表达真实过程 | 定义卡、seed 与纯时间求值、图谱缓存、预览导出一致 |
| 5–8 类布局 | 真实课程记录证明三结构无法合理承载内容 | 语义差异、容量、边界和实际视觉审阅 |

| 9:16 | 明确的手机交付需求 | 重做密度与安全区，不缩放横版冒充竖版 |
| 图表/公式/更复杂过程 | 出现可复现课程需求 | 定义、编辑、时间、输出能力分开验收 |

继续遵守代码主导、有限图片辅助边界，不恢复水彩手绘主风格、大量拼贴或全页栅格动画路线。

以下是排期用的初步工程估算，未经本轮运行校准，不是承诺日期；按一个主要开发者、现有实现可复用计算。不包含等待服务、用户视觉评审、目标软件或不可预测的多轮美术返工。N00 和第一轮真实课程后重估。

|---|---:|---|
| N00 基线核对 | 0.5–1.5 人日 | 可复现源码和启动/验收环境 |
| N00-A 素材板与自动拆分 | 4–8 人日 | 对照试验、独立透明资源、应用任务/审阅接入 |

| N03 项目模型绑定 | 2–4 人日 | 两项目配置隔离和可追溯任务 |
| N04 恢复加固 | 3–5 人日 | 进程终止后的一致性恢复证据 |
| N05 首版交付 | 2–4 人日 | 数字人可选实测、安装与交付报告 |

## 13. 每轮完成与首版放行标准

每个实现单元必须记录：任务/HPS/AC 编号、定义卡与字段影响、代码修订、实际修改文件、输入版本、验证命令与退出码、产物证据、兼容性、未完成项。HPS 重点涉及 015/017（规则变更与验证）、019–022（扩展）、023–030（视觉生产）、031–037（效果及能力边界）；按实际能力定位具体条款，不把整段编号当作免读规范。

测试按变更范围执行：存储/配置用隔离数据库和失效测试；编辑器用真实浏览器操作、几何与 seek；引擎改动执行对应 build/tests；Agent 改动执行生成物检查；导出必须实际编码、ffprobe、完整解码或目标软件打开。纯文档计划不要求重跑全部应用测试。

首版完成必须同时满足：

1. 当前源码能在明确环境启动，旧图片路线回归通过。
2. 真实模型驱动的五场景课程覆盖三结构及对象过程。
3. 实际 HTML 截图和动态效果得到用户视觉结论。
4. 真实讲稿、字幕、动作完成逐句听看；输出对应当前批准修订。
5. 用户能编辑对象、动作与锚点，保存重开且人工修改不被重规划覆盖。
6. 视频和快照 PPTX 完成实际输出验证；能力标签准确。
7. 任务失败/并发/取消/重启行为有证据；新恢复保证经过故障注入。
8. 可选数字人、原生可编辑 PPTX、Canvas 或其他未验证能力单独列明，不归入全部通过。
9. N00-A 的首版普通素材路径完成 AS01–AS06：素材板可拆成独立透明资产，身份/锚点可追溯，失败有单槽回退，实际课程至少一次使用已验收的板提取资产；复杂边缘等限制独立列明。

保持 definition / implementation / verification 分开；partial、pending_review、blocked、not_run 均不改写成 passed。新证据补入既有账本，保留历史测试适用的修订与环境。
