# 开源组件驱动的还原与二次编辑优化方案

日期：2026-10-17，Asia/Shanghai。适用于HTML路线。状态：方案与一手来源核对完成，依赖尚未安装、编辑功能尚未实施；既有测试通过不能作为本方案的验收。来源档案[RES-20261017-01](../../research/2026-10-17-open-source-scene-editor/README.md)。正式规则仍由HTML presentation契约目录拥有。

## 1. 要交付的产品结果

Agent按组件、风格、权威讲稿和设计参考生成结构化可编辑场景；用户可像操作演示文稿一样拖动布局、像操作剪辑轨道一样调整已有动作；用户和Agent使用同一份场景、同一套受控编辑操作、同一个预览/导出播放器。人工修改受到保护，局部修改不触发无关重新生图或TTS。

首个端到端验收故事：

1. 打开一张已有真实HTML页，选中“人选来源”卡片。
2. 拖动位置、调整宽度；正文正常重排，关联指向仍正确，撤销/重做有效。
3. 在动作轨道中把已有入场动作延后0.3秒，仍绑定原句；调整持续时间。
4. 播放真实音频并在多个时刻跳转，画面和声音一致。
5. 保存、重新打开；基础位置、语块绑定和偏移保留。
6. 让系统Agent修改另一个允许字段，先前人工修改不被覆盖。
7. 用原正式输出链路验证结果，编辑与输出保持一致。

演示不代表整课程泛化。首轮不新增任意旋转、warp、自由关键帧、任意节点增删或图片内部拆分；这些功能需要各自公开能力、语义及输出验证。

| 完整编辑器交互组合 | Scena锁定源码 | 研究选择、属性、画布、时间轴如何协作，适用的独立逻辑再按来源复用 | 应用外壳、业务数据和持久化仍走现有工程 |

前三项采用成熟包，不重写拖拽手势、选择区域或轨道控件。Scena是Scene.js编辑器，整体替换会同时引入它的场景和播放体系；采用它的组件组合可以直接获得主要交互能力，也能延续本项目已有的数据和音频。Theatre Studio采用AGPL-3.0，Core采用Apache-2.0，故不把顶层许可当作整个Studio可直接嵌入的依据。

版本来自当日npm发布元数据，是P0验证候选；使用精确版本、lockfile及本地打包，不使用latest CDN。保留第三方许可证/NOTICE；复制源码时追加到sources.json的文件路径、上游commit、修改说明。当前没有依赖安装或采用成功的结论。

## 3. 一套数据、两类编辑

### 布局编辑

切换到暂停的完整布局视图；未入场对象可作为编辑辅助轮廓显示，但不得写回initialVisibleIds或混入导出。对象列表、画布选中态、属性栏同步。

- 拖动修改基础offsetX/offsetY；尺寸手柄修改width/height。调整文字框宽度引发重排，不通过CSS scale把文字一起压扁。
- 图像对象保持自身资源/锚点和适用的比例约束；图片内部内容没有独立对象身份时不能单独拖。
- 只开放Schema和capabilities登记的操作。首轮不启用Moveable的旋转、warp等其它能力。
- 多选是一组选择，不新增持久化group业务节点；一次群组拖动形成一次原子patch和一次undo。
- 吸附参考画布、安全区、登记槽位和其它公开对象的几何；所有预览/保存继续执行边界和容量约束。
- 库产生的连续事件只更新本地候选与编辑辅助层，按RAF合并；dragEnd校验形成一次事务，不每个pointermove发模型请求或数据库写入。

### 动画编辑

使用真实音频预览；没有音频时明确标注作者预览时钟。暂停、播放、上一/下一帧和seek全部接入现有播放器。布局修改与动作参数分开展示，避免在某帧拖动就无意写入关键帧。

- 每个对象对应动作轨道，每个已有动作条由稳定actionId标识；高亮对象和动作相互联动。
- 讲稿片段轨道及音频时长是只读参照，不拖动讲稿本身；先显示语块范围，无需先引入波形库。
- 横向拖动作条改变所绑定句子的offsetMs；拉动作条右端改作者durationMs；左端resize同步计算偏移与时长。界面可显示秒，内部单位仍为毫秒。
- 不自动跨句绑定：拖过合法语块范围时显示阻断/原因，显式选择其它允许语块后才重绑。原句hash、顺序和语义验证继续生效。
- 当前已有编辑器锁定新版语义动作身份、类型、顺序；新增/删除/改动作类型须回到规划，不为时间轴放宽这些规则。
- 同时显示作者设定和实际生效时长；音频binder因语块尾或后续动作裁短时显示原因，不能画一条与实际播放不符的条。
- 入场和强调仍按既有公开类型及参数运行。自由路径/关键帧暂不列入首轮。

## 4. 与现有工程的接线

```text
Moveable / Selecto              React Timeline Editor
        ↓ 编辑意图                    ↓ 编辑意图
       坐标适配器                 动作/语块适配器
                ↘               ↙
             统一编辑命令与本地草稿
                        ↓
          原preview / revision / 保护 / save
                        ↓
             scene + motion_binding
                        ↓
         原音频binder与共享播放器/正式输出
```

### iframe和坐标

现有播放器运行在同源iframe内。选框/手柄优先放在iframe内独立编辑层，使用该document的实际目标；业务状态在原编辑器持有。模板重渲染后按objectId重新取得DOM并刷新控件，不缓存已失效节点。

通过实际stage矩阵、iframe位置、缩放/滚动计算作者坐标，不硬编码1920×1080，也不将2048×1152参考图坐标直接当HTML坐标。布局草稿通过共享渲染器解析，不能把动画transform与布局transform互相覆盖。

### React局部模块

现有前端是经典原生JS，timeline发布包要求React/ReactDOM >=18。拟在`editor_ui/`建立仅构建的局部UI包，esbuild输出本地bundle，挂载在编辑器时间轴容器中；不新增另一个可运行应用或业务服务器。关闭/切页时销毁React根、Moveable/Selecto实例、事件和订阅。

外壳继续复用docs/ui-spec.md和现有橙色、面板/按钮规范。Scena提供交互结构参考，不整体移植其样式或路由。

### 一个实际播放时钟

Timeline有自身engine接口，但本项目只采用其编辑UI和游标交互。播放由现有音频/播放器统一驱动；时间轴跟随当前时间，拖游标请求原seek。P0必须验证engine适配或只编辑模式能阻止第二套effect/tick写DOM；不依赖两个时钟“看起来差不多”。

有真实音频时以音频currentTime驱动共享播放器；无音频仅使用标记明确的作者预览。重新配音后根据稳定beatId重新派生动作时间，保留人工offset/duration及原字段保护，不将新绝对秒数覆盖作者文件。

## 5. Agent、组件和Skill如何一起提升

Agent与用户共用编辑意图和验证，不分别生成一套HTML/DOM操作。

1. **读取能力**：当前页允许的对象/部件、尺寸/字体范围、变体、已有动作与可绑定语块、人工保护、实际测量。
2. **提出局部操作**：位置/尺寸用set_presentation；字体用set_text_style；已有动作参数用set_motion；语块/偏移用set_binding。新动作或缺组件回归对应规划/能力定义。
3. **验证候选**：共享renderer测量容量、越界、关系目标，按真实音频抽查起点/中间/终点；视觉参考和内容保真单独检查。
4. **有界修正**：复用原候选预算、无进展和unknown规则；不因接入编辑库增加无限模型循环。
5. **受保护保存**：重新检查revision、人工字段和候选当前性；通过后只保存实际改变，冲突返回具体路径。原作品在失败时保留。

Skill优化以实际工具为依据：精简重复规则，明确输入/可用操作/失败路由，加入“只改卡片位置”“只调已绑定动作偏移”“保留人工字体”正反例。操作型SKILL.md和真正加载的runtime_skill片段分开验证。工具未支持的操作不能只写入Skill就声称已有能力。

近期文字边缘诊断仅作为问题证据，不能将墨迹包围盒直接作为修正建议；误报和背景干扰仍须验证。人工逐行盲审为可选离线工具，不是本方案前置条件。

## 7. 固定验收案例与指标

以下均为拟定目标，不是本次已取得结果。用独立临时数据库/runs，冻结主题/组件版本、模型、输入与预算，记录设备、窗口/DPR及源hash。

### 确定性工程案例

至少覆盖20种行为：单选、框选、多选、缩放后拖动、iframe滚动后拖动、文字框resize重排、图片比例、边界/容量拒绝、关联箭头、隐藏对象编辑轮廓、动画播放后位置、群组原子撤销、redo、动作偏移、动作resize、跨句拒绝、同对象动作顺序、保存重开、陈旧revision、人工保护。再补刷新/切页销毁、同值保存以及无音频作者预览隔离。

| 指标 | 第一版目标/判据 |
| --- | --- |
| 拖动坐标 | 在0.5/1/1.5/2倍显示及典型滚动/DPR下，作者坐标回写与预期偏差≤1作者像素 |
| 数据一致性 | 保存/重开不丢位置、尺寸、actionId、beatId与offset；同值保存0次无关重建 |
| 人工保护 | 固定保护反例中0次被AI静默覆盖；冲突可定位且作品不变 |
| 音画跳转 | 固定动作边界与乱序seek下，时间源一致，预览/导出帧对应误差≤1输出帧 |
| 单事务体验 | 一次完整拖动/resize只形成一个undo项，取消或校验失败可恢复 |
| 交互性能 | 先测基线，再以现有Schema上限40个对象的合法固定场景测输入到可见反馈p95；初始目标≤100ms，注明设备，不将它换算为模型效率 |
| 生命周期 | 多次开关编辑器/切页无重复监听、幽灵选择框或双播放时钟 |

### Agent效果对照

固定三类输入：布局偏差、已有动作时间偏差、带人工保护的局部修改；包含不可修正/缺能力/背景干扰的应停反例。受控场景拥有独立几何和预期动作真值，不要求用户逐框标注。

先比较基线，再分开记录“只改工具适配”“再改Skill”的结果：有效操作率、修复成功率、误修率、保护冲突数、平均修复轮数、模型/HTTP调用、端到端及模型耗时、unknown数。对照使用相同输入/预算，失败和unknown不剔除；真实费用未知为null。首次基线测量后再设具体改善门槛，不预先宣称提升百分比。

现有检查入口可复用并按变更扩展：`checks/test_html_scene_editing.py`、`checks/test_html_scene_editor_fixture.py`、`checks/test_html_scene_editor.cjs`、`checks/test_html_audio_binder.py`、`checks/test_html_rebuild_plan.py`、`checks/test_html_runtime_skills.py`、`checks/test_frontend_quality.js`。真实browser交互和渲染/视频解码单独验收，最小DOM测试不能替代。

## 8. 契约和兼容工作

实施关联HPS-007/008/009/010/011/013/014/015/017/023–025/037。优先复用现有presentation及motion_binding，不默认扩Schema。涉及新字段、新动作类型或新编辑对象身份时，先完成定义卡、owner/兼容/迁移，再同步代码、runtime_skill hash、源闭包和检查。

编辑手柄和辅助轮廓不进入生产scene、正式截图或导出。旧scene/binding格式仍读取并依原规则处理；新版完整语义路线需显式plan_version0.2，不能静默把旧作品批量迁移。正式视频的批准/音频确认/逐句语义门禁保持，普通手动编辑与每次拖动不新增人工批准弹窗。

实施过程直接在当前开发仓库推进；调研模块和构建子包不另建运行副本。源码和方案可随Git发布，项目数据库、原图、响应、运行报告及凭据继续不入仓库。
