# 通用文字边缘完整性核验

2026-10-17。承接文字片段对应/跨版式验证，用户要求处理通用文字边缘完整性。按HPS-010/011/013–017/023–025/037、合同0.9.76和`reference-text-edges-0.1.0.md`实施。

## 当前交付

系统独立定位入口已在合法part区域解析后接入本地像素边缘核验，返回`edge_verification`。它逐targetId/partId/region_index检查原图，不消费参考gold或HTML位置，不修改模型原框/转录，不另发模型请求。

输出分为疑似截字`possible_clip`、不确定`uncertain`、未见跨界`no_detected_clip`。任一疑似使整轮`needs_review`；没有疑似但存在不确定时整轮不确定。所有情况下都不能自动签发正式审核可用区域，不会因“未见跨界”就签收文字完整、OCR正确或视觉通过。原独立定位尚未接正式审核，本轮也没有扩大其准入范围。

## 方法与边界

`html_text_edge_verification.py`拥有本地策略0.1.0：以行高决定局部观察范围，估计局部主背景色，追踪原框边界上强前景的8邻接组件。组件若同时延伸到框内、框外且无已识别干扰，则提供墨迹边界、越框方向和像素数量作为疑似证据，不把组件边界当新文字框。

独立图标或线条不因邻近而吸收。与邻近文字、长细线、实心图形/图标、声明容器相交，或背景复杂、透明、对比度不足、靠图像边缘、达到窗口/组件预算时，保守不确定。相连且未能识别的装饰仍可能触发疑似警报；程序不是OCR/图像分类模型。

存在完整字符落在框外且与框内墨迹不相连的盲区；低于前景颜色阈值的细笔画、错误身份、整段漏定位也不能由边界连通核验消除。专门保留了“框外独立字符没有触发”反例，避免把当前规则包装成完整文字识别能力。

新增模块纳入生成源闭包；参考图原hash、前后当前性检查及原严格解析保留。模型Schema/Prompt0.5.1未变，没有新依赖，使用原PIL/NumPy。未修改作者场景、用户工程数据、既有gold或IoU/覆盖阈值，没有重启服务或发布。

## 对照与留出验证

原模型响应结构合法不代表像素完整。旧系统没有这项独立边界证据；本轮衡量新增诊断的检出与保守警报，不声称定位坐标已经修正。

受控样本的强墨迹真值来自单独绘制的文字alpha层（alpha≥128），不是模型框或诊断输出。先冻结规则，在微软雅黑32px、浅底/灰底/深底反白/有色文字上测试完整/四边截字/完整且邻近图标线条；再使用18/54px微软雅黑、18/54px宋体留出组，颜色组合和截字方法不变。留出字体/字号未用来调阈值。

| 离线独立样本 | 初始控制组 | 留出字体/字号组 | 合计 |
| --- | ---: | ---: | ---: |
| 强墨迹被框截断 | 16 | 64 | 80 |
| 标为疑似截字 | 16/16 | 64/64 | 80/80 |
| 完整框样本 | 8 | 32 | 40 |
| 完整框误标为疑似截字 | 0/8 | 0/32 | 0/40 |
| 完整框标为不确定 | 0/8 | 8/32 | 8/40 |

8个完整框不确定集中于18px宋体，原因是颜色阈值下仍有前景触边。强墨迹真值与像素诊断阈值不同，不能静默把这些保守警报计为完全正确；若都需人工复核，则40个完整负例有8个（20%）增加复核量。样本数量、字体、底色和构造方式仍有限，不能把80/80推广为真实页面百分之百检出，也不能把0个疑似误报称为没有复核成本。

低对比/透明/非均匀背景、线条/实心图标相连、相邻文字交叠、边界观察不足、噪点、无文字、非法几何和计算预算耗尽另有单元反例；这些样本没有并入上述受控文字检出率分母。
