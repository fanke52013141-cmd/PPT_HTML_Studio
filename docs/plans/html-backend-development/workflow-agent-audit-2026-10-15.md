# 流程与 Agent 运行复盘 · 2026-10-15

## 目标与判断边界

用户澄清：真实课程用于暴露流程、Agent 协作及恢复问题，交付目标是改进系统，不是逐页打磨或制作一条成片。后续开发以可复现的失败案例和系统验收为依据；当前课程保留为回归输入，不继续为美观逐页生图。

前序执行偏差：Codex 将真实验收转成单页视觉修正，在需要系统诊断时不断推进生成和人工选图。根 Agent 应先定位失败所属层、验证输入/输出与恢复路径，再决定是否需要外部请求；不能把用户反复说“下一步”当作整条流程健康的证据。

本报告为诊断和实施优先级，不修改现行批准规则或登记新能力。工程、模型遵循、视觉与人工决定保持独立。没有真实配音的链路仍未验收。

## 已证实的问题

### F01 · 修改设计没有明确的局部修订语义（P0）

证据：同一第三页 contract hash `af419bf2586261ec43e1f5fa0efafdd9c4ce2c1600461957748a8aa73f6c349b`，旧候选采用 `explanation-cards-v1`，新候选采用 `data-relation-v1`。原本针对右侧主体和标签的修正最终成为三栏重排。

`html_production_service.py` 的设计分支仅在带 `design_candidate_key` 时读取原计划/brief/参考图；而 `HtmlProduceRequest` 禁止该 key 与 `design_instruction` 同传。仅有 instruction 时重新执行 `generate_scene_plan`，规划调用没有收到修正要求或旧构图；后续生图引用新装配的组件参考包，没有附原设计图。修正要求到 `design_prompt` 才加入。故已证实输入连续性缺失；单凭这次结果不能归因为生图模型不听话。

修复方向：区分“重新设计”和“基于指定候选修订”。为后者定义来源候选、保留项、可变项、明确修改目标和关系；让规划及生图阶段消费相同的修订意图。是否复用规划应由变化范围决定，不能靠空 key 隐式决定。需要同步严格请求合同、快照、任务身份、Web/Agent 与下游当前性，不在旧请求上改参。

验收：固定旧图和计划，只要求修改标签时，不重调无关规划、不改变未授权模板/对象/文案；明确整页重新设计时允许形成新计划。两种操作的来源、外部调用与批准状态可区分，旧候选保持。

### F02 · 中断后的安全检查路径不完整（P0）

第三页旧任务 `html_eb1347e111fc42b3b7c3` 为 interrupted，缺结果的文字阶段为 intent，`lookup_supported=false`，无 returned/upstream 回执。其余 10 个 returned 文件散列有效；已存在截图的场景通过当前严格检查，重演截图与归档完全一致。

禁止盲重发是正确保护。缺口在于 `html_manual_candidate_review.inspect_candidate` 只接受 failed + 一个 unknown，因进程退出留下的 interrupted + intent 不在入口范围内。已有证据因此无法沿正常界面检查；本轮只能在隔离目录诊断，不能签收或保存。

修复方向：先定义进程中断与已提交但无返回的语义，再依据可证明的证据开放只读检查。不得把 intent 改为 returned/failed 来绕门禁。查单能力、响应可恢复性、未保存候选可重演性、作者可提交性应分别表达。无法确定远端结果时，依旧保留未知，不自动重试或批准。

验收：覆盖请求前退出、请求后退出、回执写入但数据库未登记、无查单同步接口、取消与旧 attempt；能够查看有效证据，同时不能因查看或工程通过而重发、保存或签发批准。

### F03 · 同页新候选不会可靠更新审阅界面（P0）

本轮新任务 `html_3e22b1acce4244aaa055` 已 succeeded/design_review；API 当前候选为 `ee4f7699…`，浏览器同页仍显示 `3ba6165c…` 和旧任务阻断提示。步骤间往返仍未刷新；完整刷新并重开课程后才显示新候选。

`static/html_review_panel.js` 使用 `${project.id}:${slideId}` 判定上下文，设计和任务只在上下文改变时恢复。另一路径创建同页新任务时，这个 key 不变。已证实本地 UI 状态过期，并非服务没有生成。

修复方向：以任务/候选变化通知或有界重读刷新相关事实，保留现有 generation/项目隔离。避免为刷新而重复触发生产。还需覆盖外部 Agent 创建候选、浏览器后台运行和迟到响应顺序。

验收：同页新增候选无需整页刷新即可显示新图和对应状态；旧请求迟到不能覆盖；切项目不串页，刷新只读、无生成或批准请求。

### F04 · 阶段耗时可见，但还没有有效的效率验收（P1）

本次规划调用约 477.943 秒，完整正文 5562 字符；流进度记录处理字符计数约 98159。这些是进度统计，不是 token、费用或思考内容的质量证据。后续生图成功，不能据此证明整个响应时间合理。

源码存在单次 1800 秒总等待和生产调用数量上限，但本轮未见证据证明已有按任务复杂度评估的时延/输入量/重复调用验收。规划重做是本轮可定位的额外成本；单次慢还可能受模型与供应商影响，尚未分离。

修复方向：先统一每阶段 elapsed、输入/输出量、模型/参数身份、缓存复用与重试原因、usage（可用时）和用户等待；在固定输入上比较。尊重现有模型和满额输出偏好，不能为加速静默改模型、关闭思考或降低用户配置。基于证据决定是否减少无关规划输入或复用前序结果。

验收：同一个局部修订案例能报告阶段调用清单及必要性；使用提供者 usage 才报告 token/费用，无值保留空缺；正常思考和等待不会被误判为成功、失败或取消。

### F05 · 能力不足与排版问题仍容易混在一起（P1）

第三页归档中，选择总结面板后容量失败，进入三轮排版修复；后两轮将 from/to 字号依次缩到 19、17。严格容量最终通过，但右侧面板/胶囊和标签造型仍偏离设计。表明几何通过不能回答组件能否表达设计。

这不足以认定所有模板或修复 Agent 失效。应检查设计理解是否将不支持的造型误分给已有组件，以及审核是否能把缺口路由回 capabilities，而不是继续缩字或改位置。

修复方向：建立固定“能表达 / 需受限替代 / 不支持”的能力案例；对构造能力缺口停止位置微调，将证据交给公共能力开发。保留独立 fidelity 审核，禁止容量通过替代视觉通过。

验收：缺面板、缺标签造型、长文容量、资源错配四类例子分别进入正确分支；容量修复不能靠删改正文通过，也不能把缺组件当位置问题无限循环。

### F06 · 测试重心偏向页面，缺少跨阶段事故案例（P1）

六页三宽度、正常入口、音频夹具等已有有效覆盖，但没有覆盖本次“同页外部新任务完成后显示旧图”和“局部修订导致重新规划换模板”。真实课程仍缺正式页面及音频，不能把这些 UI 检查当整条生产链路通过。

修复方向：用现有真实输入归档构建可离线重放的流程案例；模型成功/失败/超时由明确替身注入，少量真实提供者调用单独登记。测试重心转为职责交接、状态恢复和请求次数，而非重复比较每张图是否更漂亮。

## 实施顺序与退出条件

第二批已推进 F04 适配器测量/复用证据、F05 能力归属路由和 F06 预算/退出故障案例；见 [第二批交接](handoff-workflow-agent-evidence-2026-10-15.md)。真实提供者效率及全量事故覆盖仍需后续证据。

首批优化已进入实现：F03 同页只读重读/响应隔离、F01 指定候选修订与规划复用、F02 interrupted/intent 严格证据入口及多轮重演。实现/最终验证/待办以[首批优化交接](handoff-workflow-agent-optimization-2026-10-15.md)为准；下述顺序保留为原诊断计划。新代码不使旧输入快照自动当前，也不追认旧任务成功。

1. 先修 F03，补跨入口同页状态更新回归。边界较小，可先得到一个确定的系统修复。
2. 定义并实现 F01 的修订合同和复用边界；同步 Web/Agent、快照与来源。用固定例验证不再无关重规划。
3. 完成 F02 的中断证据检查路径，保持未知结果禁重发和独立人工决定。
4. 将 F04/F05/F06 合成流程评估集：成功、容量失败、能力不支持、无查单中断、回执恢复、同页并发、人工改动保护、音频过期、输出阻断。每项有预期路由、调用次数和最终停点。
5. 上述离线案例通过后，只用必要的真实调用验证提供者边界；是否做完整成片由其能否验证剩余系统风险决定。

本轮只完成诊断与计划，没有为本报告新增生图、模型调用、作者修改或批准。后续每次变更应回答：修的是哪一类流程失败、固定案例如何复现、是否降低人工介入、是否保留原保护；不以“这一页更好看”作为系统完成标准。
