# HTML 基础体系定义审查记录

本文件是 v0.1/v0.2 审查的历史记录。当前生产与开发规范已迁入
[HTML 演示体系契约](../contracts/html-presentation/README.md)，后续规则在该处更新。

日期：2026-10-07。审查对象：模块定义 v0.1、构建路线与原项目复用方案。
方法：检查职责、输入输出、身份、状态、失败行为、变更依赖与验收；用换风格、长
文本、重排、改音频、复制删除、导出中编辑等场景推演。并核对原项目 AGENTS.md、
annotation_contracts.py、impact_registry.py、repository_paths.py 的有关约定。
本轮是文档和架构审查，没有运行尚未实现的 HTML 内核，也没有新增业务接口。

## 结论

v0.1 的分层方向可以保留：结构化场景为源、公共组件与风格分开、独立素材、确定
时间播放、输出分适配器。这些内容不存在需要推倒重来的方向性问题。

但它主要是能力目录，还不能直接作为开发契约。很多问题不是完全没提，而是只有
概念，没有所有权、优先级、生命周期或失败规则。直接据此并行实现，容易出现
各模块自行补规则、换风格丢绑定、改一处全量重做、预览与导出不一致。

修订成果：能力目录升为 v0.2，新增 [协作规则与数据契约](html-foundation-contracts-v0.md)。
下列“已补”均指规则草案已补，不表示 Schema、代码或兼容验证已完成。

## 三个应当修改的原有表述

### 1. 页面文字变化不等于音频输入变化

原第 7 节将“讲稿或节点文字改变”同时关联音频时间和锚点失效，范围过宽。
例如把页面解释缩短一行，而旁白完全没变：应重排本页并校验锚点；音频不应自动重做。
若修改改变了含义，则保留原音频文件，同时把画面与讲稿的一致性标为待检查。
音频字节可复用和整个作品已通过内容检查，是两件事。

### 2. 复用不能被限制成只有换色换字体

v0.1 已允许变体，但还不足以说明复杂风格如何实现。有些风格需要改变图标与文字
关系、背景轮廓或装饰结构。应允许登记可复用的呈现变体，并保留内容模型与公开
目标。不能为每个风格复制一套业务组件，也不能强制所有风格长成同一个组件外形。

### 3. 原子能力与语义组件不能互相替代

表格可以由文字和图形画出来，但它还需要行列、单元格、排序与数据语义；不能只
存成很多矩形之后再猜关系。原子复用解决渲染基础，中层语义解决编辑与讲解。
四类原子是首轮静态页面范围，视频等媒体还需要独立能力声明。

## 场景推演检查

下列是对定义的推演结果，不是运行测试结果。

| 场景 | 原草案的不确定点 | v0.2 应答 |
| --- | --- | --- |
| 对比项由左图变成上图 | 原 DOM 变化后动作找谁 | 绑定实例公开目标，变体负责映射 |
| 列表第 2 项移到第 1 项 | 动作按位置还是内容移动 | 稳定 itemId 随内容保留 |
| “学习”在同段出现两次 | 哪次被画线 | 文本修订、码点范围、引用与上下文共同定位 |
| 图片 cover 裁切并随父组缩放 | 图内锚点如何定位 | 原图到画布的完整变换链 |
| 淡入与淡出重叠 | 谁的透明度生效 | 同目标同通道重叠报冲突 |
| 从第 5 秒回到第 1 秒 | 已显示对象是否残留 | 按时间重算状态，不依赖事件播放历史 |
| 只改正文颜色 | 是否重新生成语音/素材 | 按依赖只重绘相关输出 |
| 长正文放不下 | 自动缩到多小 | 检查允许的布局变体或报溢出；不无限缩字号 |
| 生图失败或字体缺失 | 还能否显示“导出成功” | 草稿占位可见；正式输出有明确阻断条件 |
| 导出时又改了标题 | 旧结果是否覆盖最新结果 | 任务快照与当前修订比较，保留历史归属 |
| 单页正常，扩成多页 | 谁拥有全片时长 | 文档合成安排负责局部到全局时间 |
| 请求全部可编辑 PPTX，含复杂 CSS | 是否静默整页转图 | 能力报告与输出策略决定；不虚报可编辑 |

## 当前仍未完成的定义

以下尚未填写或实测，不能把 v0.2 当成最终技术规格：

1. 组件/布局/风格/动作的正式字段 Schema、默认值、限制与兼容版本。
2. 字体文件和首个风格的真实色值、字号、间距、参考页及视觉验收阈值。
3. 实际布局测量实现和固定渲染环境；现有文档只定义接口与行为。
4. 文档持久化、修改命令、能力注册表与错误枚举的实际实现。
5. 多页时间编排、恢复执行及视频导出的真实性能和音画验证。
6. PPTX 各类对象及动画的真实支持范围；不能凭接口设计承诺全部转换。

这些不是本轮需要一次性实现的功能。下一步先完成文档/身份、文字/锚点、四类原子、
概念块、左右布局、风格/配方与三个动作的定义卡；再制作一个风格的样板。

## 审查后的建设顺序

1. 能力目录与协作规则：本轮已补充草案。
2. 核心定义卡与正式字段：下一步，将正常值、边界、错误、依赖逐项填实。
3. 一个风格的可播放样板：审阅完整页和逐步状态，修正抽象。
4. 替换内容、第二种风格、额外布局、最小多页：验证复用与组合。
5. 视频/PPTX 支持集验证，再接入原项目公共能力。

后续规则在正式契约目录维护；本审查记录保留为问题与决策的历史依据。
所有实现状态以实际代码、样板和验证结果为准。
