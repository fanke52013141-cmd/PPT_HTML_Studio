# HTML 演示内核：先构建基础，再接入应用

2026-10-07 讨论稿。本文记录建议的建设顺序，不表示 HTML 功能已经实现。

当前规范已迁入 [正式契约入口](../contracts/html-presentation/README.md)。本文件仅维护
实施顺序：依据契约填写核心定义卡，再选一种风格制作样板；样板通过后，用第二种
风格验证复用能力。审查依据见
[基础体系审查记录](html-foundation-review-20261007.md)。

## 目标与边界

现有项目提供课程、讲稿、音频、任务、数字人和作品管理。新的根基是可独立运行的
HTML 演示内核：在没有数据库、AI 服务和旧图片管线的情况下，也能把一份结构化
场景渲染成精美、可控制、可重复播放的页面。先以样板验证它，再接入原项目。

不先重写应用，也不先铺满二十种模板。用一个完整实例发现真正的公共能力，避免
抽象协议很多却不能稳定画出一页。

## 规范、风格、布局、组件的关系

| 层次 | 定义 | 典型内容 |
| --- | --- | --- |
| 公共规范 | 所有实现遵守的接口和有效性规则 | 内容角色、稳定 ID、资源引用、画布坐标、布局接口、动画时间与版本 |
| 风格包 | 符合规范的视觉实现与组合规则 | 字体层级、颜色、间距、线条、容器外观、插图与图标画风、密度限制、参考页 |
| 布局 | 根据内容与约束分配区域的算法/配方 | 左文右图、两列对比、步骤展开；槽位容量、对齐、留白和长文本处理 |
| 通用组件 | 承担独立表达职责的可复用结构 | 对比项、步骤项、带标注的插图、数据指标、引用说明 |
| 页面实例 | 具体内容的组合结果 | 本页选择的布局、组件内容、资源、风格和讲解顺序 |

风格不是公共规范本身的子集，而是遵守规范的一种具体实现；它可以限制该风格允许
使用的组件变体和组合。风格也不只是一组组件颜色：排版、素材、密度和组合关系
必须一同定义。

原子组件先限定为文字、图片、矢量图形/路径、分组。箭头、卡片外观、图标等复用
这些能力。中层组件保留语义职责和数据接口，外观由风格包控制。只有新增表达能力
才新增组件类型，不因新增一个风格而复制组件实现。

美感需要经过设计的组合。精美的单个元素不能保证任意拼装也精美；布局配方、比例、
内容容量和参考页都属于可复用资产。验证过的组合可以登记为页面配方，而无需复制
整套代码。

## 核心数据与渲染

建议先使用可校验的 JSON 场景描述，暂不创造新语法。后续如需要给作者更方便的
标记语言，可以编译为同一份场景数据。大模型首先选择已有能力并填写内容，不能
通过生成任意 CSS 来绕过稳定性约束。

场景至少保存：画布、内容节点和稳定 ID、内容角色、布局参数、风格引用、资源引用、
旁白语块与动作目标。组件可维护内部稳定子节点，避免拆解后无法绑定某个步骤。

保留两个层次：内容与布局意图，以及排版后求出的几何与文本分行结果。HTML 是
渲染产物，结构化场景是编辑与导出的来源。字体和资源加载完成后再测量定位。
元素 ID 可直接定位整体；句内短语使用 DOM Range，并处理跨行矩形、画布缩放和
坐标转换。图片内部对象仍需独立素材或资源锚点。

动画以 `render(scene, time)` 为目标：相同场景与时间得到相同画面，支持暂停、
跳转和重复取帧。先记录“旁白语块触发何种动作”，取得音频时间戳后再绑定时间；
不把 CSS 的自然播放时间当作唯一时间来源。浏览器预览与视频取帧使用同一套求值。

## 第一阶段：一页完整样板

选择一页“两种概念对比”：标题、两个解释区域、两张插图/图标，以及三个讲稿语块。
先人工编写固定内容，不接 AI、TTS、数字人或项目数据库。

1. 完成最小场景描述、四类原子节点和一套两列布局。
2. 先制作一个经过设计的风格包和参考页，审阅美感；样板稳定后再加入第二种风格，验证同一场景的复用。
3. 把三个旁白语块绑定到出现、强调、勾画动作，加入播放与时间跳转。
4. 输出静态最终页与指定时间的画面，作为后续视频导出的基础。

验收：内容和 ID 不变即可换风格；文字可编辑；插图可替换；修改标题或正文不会
静默溢出；勾画位置跟随实际排版；暂停、回退、重播显示正确状态；每个状态的
美感可直接审阅。长内容采取重新排版、拆页或明确容量错误，不能无限缩小字体。

这页是第一件成果。规范、组件和渲染器伴随它形成，之后再稳定接口。

## 第二阶段：扩展可复用基础

用真实课程内容验证 5—8 种常用布局及少量中层组件：概念解释、图文、对比、步骤、
时间线、数据和结论。每种布局定义适配内容、容量与溢出策略。十几种版式可作为
产品目标，但不是所有内容变化均可穷尽；需参数和可控降级。

把两套风格完成为可展示的参考页集合。素材库记录画风、透明背景/边界、槽位适配、
安全区和锚点；生图模型负责插画等素材，HTML 负责文字、结构与时间控制。每个
需要单独出现的对象在生成前就拆成独立资源，避免之后重新做图像分割。

先验证 16:9 课程演示；9:16 短视频应重新选择布局与内容密度，不能仅缩放同一页。
质量检查同时覆盖视觉参考、溢出/遮挡、字体加载、资源加载与时间跳转。

## 第三阶段：输出验证

先实现一个真实短视频：固定场景、测试音频、确定时间轴、帧渲染、编码；确认画质、
字体、时间一致性和速度，再决定浏览器逐帧或 Remotion 等最终适配方式。

PPTX 分开验收：图片型 PPTX 可以先实现；可编辑 PPTX 从场景数据映射文字、图片、
形状等受支持对象。复杂 CSS 效果可局部转图，原生对象动画需要单独映射。不能把
HTML 页面存在或图片型 PPTX 导出等同于实现了可编辑 PPTX。

## 第四阶段：接入现有应用

内核通过接口接收场景/资源/时间，返回预览、对象几何和导出产物。再逐步接入原项目
的分镜规划、AI 素材、讲稿/TTS 时间戳、勾画编辑、数字人、安全区、任务和作品输出。

图片路线保留原有门禁，HTML 路线增加独立的场景、布局、资源和时间有效性规则。
集成时再实现画面后端选择、数据库迁移、Agent 契约、失效传播与产物哈希。内核不
直接依赖旧图片 Mask 文件和 OCR 服务。

先审阅模块定义和首轮范围，再选一种风格制作第一阶段样板；审阅画面与交互后完善
规范，并决定后续风格、布局和组件清单。
