# HTML 制作整体流程图：审核稿

2026-10-12。供流程审核，未启动稳定性改造。适用当前 HTML + 16:9 路线。现有组件库、模板库、默认黑灰白风格及音频服务作为基础。

本稿描述实际模块分工及拟优化流程，不表示全部路径已经真实验收。当前只有指定案例的自动初稿与二次编辑验证，完整课程、真实新生图供应商、声音与导出仍需分别验收。业务流程图不重排应用八个可见工作区位置。

## 1. 完整制作流程

这张图沿用现有生产分工：模型规划、注册组件渲染、局部修复、独立音频与输出门禁。设计/实际画面/音频/节奏的审阅可以按一组页面集中进行；普通技术步骤不增加人工确认。内容规划与整段交付的统一持久审阅记录仍未实现。

```mermaid
flowchart TB
    U[用户：提供文章或主题、受众与讲解目标]
    P[项目设定：HTML、16:9、默认黑灰白、模型与输出目标]
    C[AI与用户：整理文章、分页、准确上屏文字、旁白与语块]
    V[程序：保存内容版本和稳定页面/语块 ID]
    L[已注册组件、模板、效果、风格与相关分类参考图]
    U --> P --> C --> V

    subgraph VIS[画面制作分支：逐页处理]
      PL[文字模型：选择注册模板、对象关系、动作和代码/图片分工]
      SC{程序：计划结构与引用是否合法？}
      PR[文字模型：有限次数纠错]
      STOP[停止并保留诊断：资源、能力或结构问题]
      NEW{需要新生成图片吗？}
      DR[生图模型：完整页面设计参考]
      H2{用户：设计方向是否接受？}
      RD[调整设计要求，产生新候选]
      IM[生图模型：仅生成需要的独立图片主体]
      AC[程序：校验图片身份、尺寸、透明边缘和锚点]
      RE[程序：复用校验通过的已有素材；纯代码页无需图片]
      BUILD[程序：按 plan 用注册 HTML/CSS/SVG 组件展开场景]
      Q{程序：实际字体测量、容量、边界与资源检查}
      AG[排版 Agent：看实际截图和测量，最多三轮局部修复]
      SAVE[程序：严格复验通过后保存 scene、资源与 revision]
      HTML[可打开、可编辑的实际 HTML 与截图]
      H3{用户：实际画面、素材与美感是否接受？}
      EDIT[修改对应内容、设计、素材或局部排版]
      READY[当前版本视觉批准有效]
      PL --> SC
      SC -->|是| NEW
      SC -->|格式可纠正| PR --> SC
      SC -->|超限或不支持| STOP
      NEW -->|是| DR --> H2
      H2 -->|修改| RD --> DR
      H2 -->|接受当前候选| IM --> AC --> BUILD
      NEW -->|否| RE --> BUILD
      BUILD --> Q
      Q -->|通过| SAVE --> HTML --> H3
      Q -->|容量或局部排版可修复| AG --> Q
      Q -->|资源错误或修复超限| STOP
      H3 -->|需修改| EDIT
      H3 -->|接受| READY
    end
    V --> PL
    L --> PL
    L --> DR

    subgraph AUD[音频分支：讲稿稳定后可提前进行]
      TXT[当前旁白与读音配置]
      TTS[已有语音服务：复用有效音频，或生成/导入音频]
      ALIGN[程序：核验实际音频、时间戳与显示字幕的对应关系]
      H4{用户：试听内容、读音、断句与完整性}
      RA[修改旁白/读音或重做对应音频]
      AR[当前音频确认有效]
      TXT --> TTS --> ALIGN --> H4
      H4 -->|需修改| RA --> TXT
      H4 -->|接受| AR
    end
    V --> TXT

    SAVE --> BIND[程序：scene 对象/动作与确认音频的 beat 时间绑定]
    AR --> BIND
    BIND --> PRE[实际有声预览：字幕、动作、中间状态与阅读停留]
    PRE --> H5{用户审节奏；程序检查指定区间与对象关系}
    H5 -->|需修改| MOT[修正动作或绑定；排版/讲稿问题退回对应阶段]
    MOT --> BIND
    H5 -->|接受且版本有效| VID[视频制作准备就绪]
    VID --> DH{启用数字人吗？}
    DH -->|是| HUMAN[复用已有数字人服务，检查实际同步与遮挡]
    DH -->|否，跳过| MP4[程序：逐页渲染、拼接和视频检查]
    HUMAN --> MP4
    READY --> MP4
    MP4 --> OUT[实际成片：连续观看、完整听审与输出检查]
    OUT --> DEL[登记本次有效交付，保留版本与验收记录]
    READY --> PPT[程序：导出并检查 HTML 快照 PPTX]
    PPT --> DEL
```

**图中失败分支的补充规则：** 结构纠错次数按现有服务上限；不会无限回到同一节点。独立图片失败只返回对应素材任务，不自动重做所有页面。绑定失败保留 scene 与有效音频，定位 beat/对象错误。H3/音频/动作修改可导致旧指纹失效，按当前门禁重新核验。正式合成、完整听审与 PPTX 打开是需要执行的验收动作，并非看到图就已完成。

**音频和画面的依赖：** 音频可以先于 HTML 准备。动作可在作者时钟下做草稿预览，但图中正式有声联调必须有实际保存场景和当前确认音频。图中的 H5 是节奏审阅流程；现有导出 API 技术门禁以实际合同为准，不能把图里的接受自动当成新增审批字段。

## 2. 生图和可编辑代码之间的关系

```mermaid
flowchart LR
    CONTENT[准确文案与视觉目标] --> PLAN[文字模型输出受约束 plan]
    LIB[注册组件/模板与分类参考图] --> PLAN
    PLAN --> REF[需要新图片时生成完整设计参考]
    REF --> ACCEPT[用户选择设计候选]
    ACCEPT --> ASSET[生成独立图片主体]
    PLAN --> CODE[共享组件渲染器]
    ASSET --> CODE
    CODE --> PAGE[可编辑 HTML：文字、结构、关系与独立图片]
    OLD[明确提供的已有素材] --> CHECK[身份、版本与文件检查]
    CHECK --> CODE
```

完整设计图指导外观，不是正文数据源。准确文字来自 plan，程序按注册布局组装；没有通过 OCR 从整张图恢复任意 HTML 的默认路径。图片自身的像素通过换素材或重生成修改；HTML 中的文字样式、对象位置和受支持动作通过编辑器修改。

现行约束：注册模板决定槽位及容量；生图参考须服从支持范围。计划不可执行时回到规划/能力定义，不能让 Agent 通过任意 CSS 硬凑。新图片设计确认与实际 HTML 视觉确认是两个不同对象；纯代码或仅复用已有素材的页面直接展示实际 HTML。

## 3. 修改和失败后返回哪里

```mermaid
flowchart TB
    R[用户修改或 QA 发现问题] --> T{判断问题类型}
    T -->|事实/语义/分页| C[回内容与规划，产生新版本]
    T -->|布局/字号/位置| E[已保存页面：读取 revision 和 scope]
    E --> PATCH[人工明确参数或模型提出局部候选]
    PATCH --> Q[预览、检查、保护人工字段；模型最多两轮]
    Q -->|通过并处于授权范围| S[保存并重开实际 HTML]
    Q -->|失败/冲突/超限| KEEP[保留原页面与失败证据]
    T -->|主体错误/透明边缘| A[替换或单主体返工]
    T -->|读音/漏读/字幕对应| AU[回旁白与音频阶段]
    T -->|动作时机/遮挡| M[回动作与音频绑定]
    T -->|网络/鉴权/缺文件| SYS[定位对应服务或资源；保留有效进度]
    T -->|编码/文件损坏| EXP[回输出任务，不自动重生图片]
    C --> IMP[核算影响范围与旧批准有效性]
    S --> IMP
    A --> IMP
    AU --> IMP
    M --> IMP
    IMP --> RUN[重验受影响部分，再查看实际结果]
```

现有服务已有部分失效、缓存、人工保护和冲突逻辑；完整的阶段依赖与最小重建计划为 S03 待实现。不能由此图承诺目前所有导出都已按页缓存复用。语义修改需要从权威内容重规划，不属于字体/位置 patch 的权限。

以下虚线框节点均为待改造能力，并不要求用户多确认技术步骤。

    FLOW --> STAGES[拟增 S02：阶段记录和复用校验]
    STAGES --> REV[对应内容版本的审阅与确认]

    SNAP --> SEG[拟增 S05：隔离工作目录、有效分段复用]
    SEG --> FINAL[拟增 S05：最终文件检查与版本化交付]

## 5. 各交接点的输入输出

| 交接 | 输入 | 输出与责任 |
| --- | --- | --- |
| 内容 → 规划 | 页面目标、准确文字、旁白、语块 ID、素材声明 | 文字模型选择注册模板与对象；程序校验 plan |
| 规划 → 设计 | plan、真实分类参考、主题描述、槽位几何 | 生图模型输出完整设计候选，仅作为参考 |
| 设计 → 素材 | 用户选定设计、主体要求、已有资源 | 独立主体或校验后的复用资产；程序检查身份与边缘 |
| 规划/素材 → HTML | 注册模板、scene 数据、资源、人工覆盖 | 程序渲染实际 HTML，模型只提出受限修复 |
| 旁白 → 音频 | 当前朗读文本、声音/读音配置 | 已有服务生成音频；程序校验音频/字幕时间对应；用户试听 |
| HTML/音频 → 动作 | 保存场景、稳定目标 ID、确认的语块时间 | 程序解析 binding，实际有声预览；人工/模型调整受支持动作 |
| HTML → PPTX | 当前有效场景与视觉批准 | 快照图片 PPTX；不能声明为原生文字/对象可编辑 PPTX |
| HTML/音频/动作 → 视频 | 当前视觉批准、音频确认、合法 binding、可选数字人 | 实际 MP4 与检查记录；拟增正式快照、分段恢复和完整交付账本 |

## 6. 审核时优先判断的五个问题

1. 规划先落到注册模板，再生成设计参考的顺序是否满足创作需求；设计自由度受执行能力约束，不能假定参考图的任意构图都能还原。
2. 新图片路径分别审设计参考和实际 HTML 是否合理；纯代码/复用素材路径无需额外整页生图。
3. 音频与画面可以分别推进，正式有声联调等待两者当前版本就绪。
4. 内容、图片、排版、音频、动作和导出的问题分别返回对应阶段；不将所有问题交给排版 Agent。
5. HTML、快照 PPTX 与视频有不同交付能力与前置条件；是否符合实际使用目标。

审阅意见应注明节点及修改方向，再调整本图与实施方案。流程确定后，才实施 [S00—S08 改造](html-production-stability-2026-10-12.md)。
