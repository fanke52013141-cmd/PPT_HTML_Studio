## 1. 目标与范围

在现有组件库、模板库、共享渲染器、灰阶默认风格、素材与音频服务上补齐生产稳定性。第一版必须做到：

1. 每次生产的输入、模型请求、素材、HTML、音频与导出对应明确版本。
2. 修改后只重做受影响部分；人工改动保留，过期批准明确失效。
3. 中断后可以复用经过校验的已完成阶段；供应商结果未知时不盲目重复请求。
4. 实际页面及最终文件经过相应检查；失败不会把旧作品冒充本次结果。
5. Skill 的运行时参与可追溯，新版本以同一批真实任务对比后决定是否启用。

不更换组件库、模板库、音频/对齐服务或数字人方案，不迁移到手绘渲染器。原图片流程保持独立。暂不增加任意代码执行、多 Agent 调度平台、通用分布式队列或自动语义改稿。

代码核对基于当前工作树，非单纯线上 HEAD。起始 HEAD 为 `25610ce`，本地仍有 E/编辑/Agent/Skill 等未提交改动；之前的发布请求尚不能登记已完成。先执行 S00 收束，不能把这些本地实现当作线上已发布能力。

## 3. 目标流程与数据所有权

```text
现有内容与项目版本
→ 按任务预检
→ 固定本次生成输入 + 创建 run
→ 规划 / 设计审阅 / 素材解析（按实际需要）
→ 初稿编译 → 检查 → 必要时有界修复 → 保存可编辑源
→ 当前版本视觉审阅 + 复用并核验确认音频
→ 冻结正式渲染快照
→ 按页复用或重渲 → 拼接 → 检查最终文件
→ 登记产物与交付检查 → 展示本次有效交付
```

生成输入冻结与正式渲染快照是两个时点：前者固定内容、可用能力、模型配置引用和生成参考；后者额外固定已经选定的实际素材、音频、时间轴、字体与渲染实现。生成阶段尚未产生的图片不能虚构为已有快照内容。

| 数据 | 唯一负责人 | 新能力如何接入 |
| --- | --- | --- |
| 作者内容/scene/binding/人工覆盖 | 原有内容服务与编辑器 | 不另存可编辑的第二份正文；快照是只读派生物 |
| job 状态与取消 | LocalJob + 原任务 store | 继续作为执行状态真相；manifest 不拥有另一套可写任务状态 |
| 阶段执行记录 | 新的阶段记录存储适配层 | 关联现有 job、attempt 和 run；通过 store 更新，禁止各 Agent 自写状态 |
| 文件与快照内容 | 快照/产物服务 | 内容哈希索引，固定实际字节与可用路径 |
| 改动影响 | invalidation_service + project_impact_service | 新重建计划读取其结果，API 调用方持有数据库提交 |
| 输出与下载 | artifact_records + 现有作品服务 | 按版本展示新旧作品；manifest 是可导出的审计视图 |
| 规则和 Skill | 正式合同 + 受控 Skill 注册 | Skill 引用合同，不能扩展模型写入范围 |

建议的新运行目录：项目运行目录下 `planning/html_visual/builds/<run_id>/`，包含 input、stages、qa 和 staging；已验证分段使用项目级受控缓存，键由依赖内容决定。目录不能依赖标题/数组下标，不通过全局“最新文件”选结果。跨账户不共享可见路径。

## 4. 数据与状态提案

新增定义卡先登记以下字段，不直接把本文示例当作已有 API：

- 运行：`run_id / project_id / source_revision / job_id / attempt / input_digest / runtime_versions`。
- 阶段：`stage_id / scope_ids / dependencies / input_digest / attempts / outputs / provider_request_id / budget_used`。输出逐项记录路径、散列、格式和验证结果。
- QA：`check_id / issue_id / scope / artifact_digest / checker_version / status / evidence / severity / allowed_repairs`。
- 交付：现有 artifact ID、源版本、快照摘要、实际文件摘要、技术检查与人工批准引用；有效交付关系由作品服务拥有。
- Skill 审计：`skill_id / version / content_hash / loaded_sections / prompt_version / tool_schema_version`，没有加载时明确为空。

图片请求沿用用户指定的默认 2K/low，并分别记录请求参数与供应商实际返回尺寸、格式及 alpha；不把请求值当作执行成功证据。图片分辨率与 HTML 逻辑画布、最终视频尺寸分别记录，不能因“生图 2K”就宣称视频为 2K，也不能借本轮稳定性改造静默改变现有渲染尺寸。

兼容状态模型：LocalJob 保留已有 queued/running/succeeded/failed/interrupted/cancelled 等状态。阶段内部可以定义 pending/running/succeeded/failed/interrupted/skipped，另用 freshness=current/stale 表示输入有效性。未知供应商结果用独立 `external_outcome=unknown`，不强行塞入已有任务状态枚举。审阅停点作为业务 stage，不假装仍有线程运行。

文件提交：同文件系统任务临时目录 → 格式/散列检查 → 原子更名或发布不可变目录 → 在同一数据库事务中登记阶段与产物引用。文件系统与数据库没有跨介质原子事务，启动恢复需识别已写文件未登记、已登记但文件损坏等窗口。未登记文件不得出现在正式下载列表。

恢复校验必须检查内容，不只看 succeeded 标记。由进程互斥与 attempt 条件更新保证旧 worker 不能提交新 attempt 的结果；不能因为引入阶段记录就启动第二个服务。

所有任务初始状态均为 planned。新模块名为建议所有权边界，实现时可按现有结构合并，但不得将业务逻辑重新堆回路由、Prompt 或大服务文件。每个任务交付定义、实现、自动检查、实际证据与未验边界。

### S00：收束基线与任务预检（P0）

2026-10-12 实施与实际验证见 [S00 交付](workflow-first-parallel-2026-10-09/deliveries/S00.md)。本节保留原任务要求；发布同步状态以该交付的最终追加记录为准。

**目标：** 获得可以复现的当前版本，提前发现浏览器、字体或服务缺失。

**修改归属：** 现有 doctor/媒体工具解析、相关检查和交付记录；新增 HTML 预检适配函数。业务生成模块仅调用预检结果。

**执行：**
1. 保存当前 diff/文件哈希清单，复核既有 E/Agent/Skill 改动；完成已有发布与 handoff，核对远端提交，避免混入新计划尚未实现的能力。
2. 预检按请求目标区分：静态 HTML、已有素材生成、需要新图片、确认音频的视频、快照 PPTX。已有素材任务不要求生图连接；静态预览不要求音频。
3. 使用共享媒体和浏览器定位，检查实际启动、字体加载、输出权限、磁盘可用空间；返回能力、阻断项和修复提示。
4. 不默认发出收费连接测试；使用已有配置验证，小请求需显式选择。检查前不导入会触发真实任务恢复的 composition root。

**输入 → 输出：** 请求目标/项目资源 → 结构化能力报告 + 可继续/阻断原因。

**验收：** 缺 Chromium 但有已配置 Edge 时正确定位；字体缺失阻止需要该字体的正式渲染；无图片连接但资产齐备的 HTML 成功预检；隔离数据验证。旧的浏览器路径失败记录保留，不改写为通过。

### S01：分层快照与依赖指纹（P0，依赖 S00）

2026-10-12 首版单页快照与独立检查已实现，证据见 [S01/S04 交付](workflow-first-parallel-2026-10-09/deliveries/S01-S04.md)。自动生产消费与正式输出接线尚未完成，本节原始要求保持。

**修改归属：** `html_input_manifest.py`，拟新增 `html_build_snapshot.py`；现有资源和模型绑定服务提供引用。

**执行：**
1. 实现生成输入快照和正式渲染快照两个不可变格式，记录源 revision 与实际能力版本。
2. 捕获 scene、binding、theme/layout/template、注册表、播放器、图像、字体、音频、时间戳及字幕配置的传递依赖；外链先通过既有资源服务解析成固定文件。
3. 正式冻结时逐文件重算内容哈希；规范化 JSON，处理路径根目录，拒绝越界与缺失。
4. 快照建立期间持有现有协调锁或比较起止 revision/digest，变化时放弃候选快照，避免复制出混合版本。
5. 资源以固定副本或不可变内容寻址文件保留；不能用可原地修改的硬链接冒充不可变文件。字体无法再分发时保留本机可恢复副本并在跨机器导入明确缺依赖。

**输入 → 输出：** 项目 revision + 请求/批准引用 → snapshot ID、输入摘要、固定依赖路径。

**验收：** 冻结后修改工作区素材不改变旧快照画面；同名同尺寸且恢复 mtime 的文件变化仍被发现；缺字体、坏素材、建快照时改稿均明确失败；快照不含密钥。

### S02：阶段记录、恢复与外部请求状态（P0，依赖 S01）

**修改归属：** `html_task_store.py`、`html_workflow_jobs.py`、`html_production_service.py`；拟新增 `html_stage_store.py`。数据库字段/表变更通过实施时的下一个连续 migration，不预占编号。

**执行：**
1. 给计划、设计候选、素材、场景编译和检查建立阶段 ID 与依赖摘要；先接现有边界，不把每个函数都做成一个 job。
2. 阶段完成先验证文件再登记；恢复只跳过输入一致且输出仍有效的阶段。
3. 外部调用前持久记录请求意图，成功响应绑定本次 request/asset ID；收到响应后先落原始结果，再进入加工。
4. 超时但无法确认供应商结果时标记 unknown。供应商支持状态查询/幂等键则核对；不支持时清楚提示是否重新请求和潜在重复费用，禁止自动承诺恰好调用一次。
5. 鉴权/参数错误停止，网络/限流按分类与预算重试；已取消任务不得自动重启。实现失败恢复窗口的对账。
6. attempt、自动重试次数、模型调用预算跨恢复累计，不能重启一次就重置预算。

**输入 → 输出：** 原 run/job + 可恢复阶段记录 → 续跑决策及复用/重做原因。

**验收：** 生图响应已落盘后中断，恢复不再次调用生图；输出文件删除时不得虚假复用；迟到旧 attempt 不能落库；进程重启、取消、结果未知分别呈现。

### S03：最小重建计划（P0，依赖 S01；执行接入依赖 S02）

**修改归属：** `invalidation_service.py`、`project_impact_service.py`；拟新增纯函数模块 `html_rebuild_plan.py`，编辑/生成服务提供结构化 diff。

**执行：** 将变更映射为明确的失效节点，返回“哪些复用、哪些重做、为什么”，先 dry-run 后执行；幂等保存不创建新影响。批准与 QA 随其真实依赖失效；历史产物保留为旧版。

| 修改 | 必须重做/重验 | 应复用 |
| --- | --- | --- |
| 字号/位置 | 本页几何、可读性、动态检查、本页画面与总片 | 旁白、音频及不相关页 |
| 屏幕字，朗读输入未变 | 对应布局、显示映射/字幕（若相关）、本页画面 | 已确认音频，前提是朗读哈希一致 |
| 一句旁白 | 现有服务的最小稳定语音单元、对齐、字幕、绑定、本页视频与全片时间偏移 | 无关页音频与图像；不为省成本强行切成逐句 TTS |
| 替换图片 | 引用该素材的页及封面、内容边界与锚点检查 | 音频、未引用该图的页 |
| 字体 | 引用该字体的测量、布局、字幕与画面 | 生图、朗读音频 |
| 顺序/删除页面 | 总片顺序、全片字幕偏移、引用和课程检查 | 顺序无关的有效分段 |
| 调整动作 | binding/时间检查、本页视频 | 音频，除非修改了讲稿 |
| 更换模型配置 | 新生成任务身份 | 已冻结的实际素材和历史交付；不自动重生 |

**验收：** 修改页二标题后，其他页模型/配音调用数为 0；重复保存为 no-op；语义旁白变化不得沿用错误音频批准；字体变更不能只换文件不重新测量。

### S04：统一 QA 与有界修复决策（P0，依赖 S01；可与 S02/S03 的专属模块并行）

2026-10-12 首版静态 QA 格式、版本和证据校验已实现。连续时间、无进展检测和进一步修复决策仍待实施，见上述交付范围。

**修改归属：** 拟新增 `html_quality_report.py`；`html_visual_review_service.py`、`html_scene_repair.py`、`html_candidate_agent.py` 与现有静态/时间检查适配器。

**执行：**
1. 统一问题 ID、对象/公开 part、字段路径、时间范围、实际与期望测量、截图引用、严重度和允许操作。原始诊断保留。
2. 工程检查、内容/美感建议、音频、导出状态分别存储，不把模型审美评分写成人工批准。
3. 错图、坏引用、越界等阻断；合理覆盖按注册关系判定，记录理由；不能为了通过任意删除检查对象对。
4. Agent 优先修复阻断问题，比较同规则前后结果。保存累计轮次，识别相同补丁/相同问题反复出现；无进展则 needs_revision，并指出所需重新规划范围。

6. 原文、资产身份、人工字段、模板切换范围受代码保护；需要语义改稿时返回规划阶段，不能暗中删字满足容量。

**验收：** 无效补丁不落盘；重复补丁提前停止且有原因；scope 外修改、人工字段覆盖、旧 revision 被拒绝；过期 QA 不能批准新版本；每个报告能打开对应实际 HTML/截图。

### S05：渲染隔离、分段复用与可信交付（P0，依赖 S01—S04）

## 7. 验收样本与通过条件

### 固定样本

准备三类内容，至少覆盖三个当前已注册模板：短文案纯代码页、长中文解释页、已有独立图片辅助页。另准备五页课程，包含顺序变化、动作绑定和已确认音频。所有“已批准”标记来自真实适用审批，不能在验收脚本中伪造用户视觉通过。

真实模型对照建议三类内容各三次/每配置，共每配置九次；先记录真实费用与耗时。预算允许后再扩样本，九次只用于初期诊断，不足以承诺长期成功率。Skill 对照只改变 Skill 版本，其他条件尽量一致，保留全部失败与取消记录。

| 编号 | 操作/故障 | 必须观察到的结果 |
| --- | --- | --- |
| ST-01 | 同一冻结输入重复渲染、乱序 seek | 固定环境下目标帧/布局/时间结果一致；生成服务调用为 0 |
| ST-02 | 改一句旁白 | 受影响音频单元和绑定更新，无旧音频混入；无关素材调用为 0 |
| ST-03 | 改字号或位置 | 本页检查/画面更新，TTS 调用为 0，重开编辑保留 |
| ST-04 | 换一个图片文件，路径相同 | 内容哈希发现变化；引用它的页面失效，无关页复用 |
| ST-05 | 素材已落盘、阶段登记前进程退出 | 对账后复用经过验证的同请求结果，不按“最新图片”寻找 |
| ST-06 | 供应商已接收但客户端超时 | 标记结果未知，按供应商能力核对；无无限自动重发 |
| ST-07 | 截图/渲染中断或第三页失败 | 失败段不交付，已验证前两段可恢复复用 |
| ST-08 | 删除成功缓存、破坏中段视频 | 重新验证发现异常；旧 succeeded 不能绕过检查 |
| ST-09 | 旧 attempt/旧 revision 迟到保存 | 冲突被拒绝，当前手工内容和新交付保留 |
| ST-10 | 重复点击生成、运行中改稿 | 幂等任务不重复启动；新旧 revision/run 明确隔离 |
| ST-11 | 模型同补丁循环、越权改稿 | 有界停止或拒绝，原作品不变并给出具体问题 |
| ST-12 | 合法标签覆盖、长文案、小屏阅读 | 合法覆盖有依据；容量和可读性分开判断，不靠无限缩字通过 |
| ST-13 | 字体缺失、无生图连接、磁盘不足 | 按任务目标阻断或允许；错误在正确阶段出现 |
| ST-14 | FFmpeg 失败、尾句截断、缺页/重复页 | 对应技术检查/听审发现问题，交付状态不能通过 |
| ST-15 | 第二操作 Agent 按 Skill 执行 | 不修改渲染核心完成生成/局部修改；人工帮助如实计数 |
| ST-16 | 图片后端与旧 HTML 工程 | 现有流程/旧数据兼容回归通过；不受 HTML 新状态侵入 |

最终验收：上述定义范围内错素材/错版本/假成功为 0；确定性故障案例全部具备正确失败或恢复结果；实际五页 HTML 可编辑，视频完整解码、音频完整听审、PPTX 实际打开；视觉和节奏由用户对当前版本确认。未执行项必须列出，不能汇总为“全流程通过”。

指标分别统计：技术完成率、初稿通过率、人工返修率、自动修复轮数、人工分钟数、各阶段模型调用数、费用和耗时、故障恢复成功率。收费信息缺失标 unknown，估算必须注明单价来源版本；首次运行与缓存重跑分开。小样本不设凭空的 95% 一次通过率目标。
