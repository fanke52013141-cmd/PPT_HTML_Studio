## 1. 当前起点与最终目标

已有成果是隔离的原应用基线、启动规范、HTML 演示体系契约和结合本项目的借鉴分析。
HTML 内核、字段 Schema、风格样板、HTML 动作与输出适配仍待实现。文档完成不代表能力完成。

建设目标：内容和讲稿经规划形成结构化场景，公共组件、布局、风格包与独立素材将其
渲染为 HTML，讲稿时间驱动画面动作，再输出视频及分级支持的 PPTX。

实施顺序为：**最小定义 → 视觉样板 → 静态内核 → 可播放样板 → 复用验证 → 真实输出
→ 应用接入 → AI 生产 → 全链路验收**。先证明一页做好，再扩大生产范围。

正式规则以 [契约入口](../contracts/html-presentation/README.md) 为准；本计划负责顺序、
交付与验收，不另建一套规则。技术任务对应
[DEV 实施卡](../research/2026-10-07-skill-and-workflow-reports/implementation-cards.md)。

## 2. 全程保持的边界

- 公共层保存语义、接口、约束与操作；风格包提供参数、呈现变体、素材风格及组合规则。
- 风格是遵守公共规范的实现，不能仅等同于色系，也不为每个风格复制业务组件。
- 结构化场景是编辑、版本与导出的来源；HTML 是渲染产物。首轮使用 JSON，不另造语法。
- 图片服务生成可独立控制的插图等素材；文字、布局和动画由渲染系统控制。
- 现有本地/云端语音合成、音频时间轴/对齐/校准、数字人方案直接复用。
  时间轴与语音合成是不同职责；本项目新增的是时间结果到 HTML 目标的绑定。
- 保留图片路线。HTML 精确定位不依赖 OCR/Mask；位图内部对象仍须独立素材或资源锚点。
- 初期固定 16:9。竖屏必须重新排版；原生 PPTX 动画不作为首版前提。
- 预览和导出使用同一修订及相同时间求值；不能以预览能播放代替视频导出验收。

## 4. P01：先把最小体系定义清楚

本阶段已完成，交付 [最小定义卡包](../contracts/html-presentation/definitions/README.md)。
只细化首张“两种概念对比”页面用到的能力；能力目录中的
其他候选保持待定义，避免先写完全部组件再开始设计。

### 4.1 固定一个贯穿开发的内容样例

样例包含标题、两个概念、各一段解释、各一个独立插图或图标，以及三个讲稿语块。
明确每个语块解释哪个概念、触发哪个动作。另备长标题、长正文、缺图、多行中文等
边界内容。样例首先人工填写，不让 AI 生成的不确定性掩盖基础接口问题。

### 4.2 逐项产出的定义清单

| 定义对象 | 首轮必须明确的内容 | 归属 |
| --- | --- | --- |
| 场景与修订 | 场景/页面/节点 ID、内容、引用、版本、复制删除规则；引用不可随排序漂移 | 公共规则，实例填写 |
| 四类原子 | Text、Image、Vector、Group 的输入、边界、子节点与公开能力 | 公共组件 |
| 概念块 | 标题、解释、配图的语义接口，哪些子目标可绑定动作，缺省内容如何处理 | 公共组合组件 |
| 两列对比布局 | 槽位、比例、间距、最小空间、文字容量、素材裁切和溢出诊断 | 公共布局，风格限定参数 |
| 风格包 | 字体层级、颜色、间距、线条、背景、变体、素材画风、组合约束、参考页 | 风格实现 |
| 参数解析 | 公共默认、风格值、允许的实例覆盖、非法覆盖和最终解析快照 | 公共规则 |
| 素材与槽位 | 比例、透明边界、安全区、锚点、控制粒度、来源版本、就绪与失败状态 | 公共接口，风格与实例提供内容 |
| 目标与几何 | 整节点、公开子目标、文字范围；多行矩形、缩放与坐标转换 | 公共规则，几何为计算结果 |
| 语块与动作 | 语块 ID、目标引用、出现/强调/勾画参数、冲突、起止与回退状态 | 公共动作，实例绑定 |
| 时间接口 | 时间单位、帧率、区间边界、页面偏移；与现有秒/帧表示的显式转换 | 公共规则及适配 |
| 就绪与诊断 | 字体/图片加载、排版完成、错误归属、检查通过/失败/跳过 | 公共运行能力 |
| 编辑与输出边界 | 什么可改、改后哪些结果失效、人工修改保护、输出支持及降级 | 公共规则及后端能力表 |

每项按 [定义卡模板](../contracts/html-presentation/05-definition-template.md) 写清字段类型、
必填/默认/范围、正常与非法例子、依赖、公开目标、布局/时间行为、兼容影响和验收方法。
中文文字范围遵守现有契约的 Unicode code point 与半开区间规则，不另用含混的“第几个字”。
正式 Schema 在 P03 落地并回验 P01 样例；P01 不宣称已有运行校验器。

**完成条件：** 能从一份手写场景追踪到组件、风格、素材、语块和目标；每个参数有归属；
缺图、超长文字、无效目标等有确定处理方式。尚未决定的项显式记录，不能藏在默认行为里。

## 5. P02：选择一种风格，先确认美感

用户已选知识科普方向并提供视觉参考板，详见
[科普风格任务书与参考分析](../styles/science-explainer/README.md)。用户要求先完善体系，
本轮已完成 P01-B；色系、实际字体和样板按 S01—S08 流程后续试制。目录里未定义/未实现
的能力不自动进入首版；参考图中的图表、流程和多色标题须先检查相应公共能力缺口。

在 P01 内容样例上选定一种风格及少量参考页。风格选择围绕课程受众、内容密度和观看尺寸，
避免只写“商务风”或“动画风”。此时再共同确定视觉方向，不提前购买或批量生成素材。

交付一页完整参考设计，连同标题/正文排版、插图和图标规范、留白比例、动作关键状态。
固定素材可先满足设计验证；需要生图时，仅生成本页必要的独立资源并记录生成要求。

验收同时检查：文字易读、主次明确、插图与文字协调、留白合理、重点突出、逐步出现时
画面仍完整。样板应在实际播放尺寸下审阅，不能只看放大的静态截图。

**完成条件：** 视觉方向有可指认的参考画面和审阅结论，关键设计能映射到公共能力或
可复用变体。遇到视觉问题先判断属于风格、布局、素材还是组件，再修改对应层。

## 6. P03：让定义真正生成静态 HTML

实现最小 Schema、参数解析、四类原子、概念块、两列布局和资源就绪。以独立预览入口
运行，暂不依赖数据库和 AI 服务；具体文件结构在实现时按项目目录与所有权规则登记。

把 P02 设计还原为从场景生成的页面，保存解析后的参数、资源与测量快照。文字保持
可编辑，图片可以替换；先实现必要的变体，不为将来所有风格建设庞大引擎。

验收覆盖正常页、换文字、换素材比例、缺字体/图片、未知组件和超容量。
资源未就绪不能当作成功截图；超容量不得静默删字或无限缩小字号。

**完成条件：** 同一输入可重复生成目标页面；设计与渲染结果并排核对；失败诊断能指出
对象和原因。第一轮源码同步在此阶段落实：先核对本地继承改动，按明确范围发布所需
应用基线与新增实现，并记录依赖/启动方式；不把整个工作区未提交内容一次性混入提交。

## 7. P04：做成第一张可播放样板

为三个讲稿语块绑定出现、强调、勾画；支持节点、组件公开子目标及中文短语范围。
先使用固定测试时间，提供播放、暂停、时间跳转和重播。普通出现/隐藏不改变布局占位。

几何在字体与素材就绪后测量；排版变化后重新计算。多行文字、父组变换、整体缩放
都应得到正确标注位置。任意时间的画面由统一求值决定，不依赖此前播放过哪些动画。

**完成条件：** 顺播、直接跳转、倒退及乱序取帧在相同时间得到一致状态；修改文本后
标注仍正确；初始、中间、最终画面都有参考帧和视觉结论。

这是**第一个主要里程碑：一页精美、元素可控、可重复播放的 HTML 演示**。

## 8. P05：证明基础确实可以复用

用同一份内容与节点 ID 切换第二种轻量验证风格，复用公共组件和动作绑定。
第二种风格不是再写一个页面；若必须复制业务组件，回查公共语义与视觉变体的边界。

在两列对比之外加入图文解释、步骤展开，共三类布局。用真实课程片段构成小型多页
样例集，覆盖长短内容、素材替换、跨页时间和布局容量。步骤语义若需要新组件，先补定义卡。

**完成条件：** 组件跨页面与风格复用；布局切换只需明确的槽位映射；不能容纳的内容
得到可理解的拆页/重排建议。首版不要求直接铺满 5—8 种布局，后续按真实内容缺口扩展。

## 9. P06：尽早验证真实视频和 PPTX

### 视频

复用现有 Remotion/编码任务路线，增加 HTML 画面适配。先用已有有效音频样例和
确定的时间结果，输出真实 MP4。检查字体、素材、页间切换、旁白完整性、时长和关键帧。
页面偏移与视觉提前量只能计算一次；不能让视频端和预览端各自解释一份动作规则。
只有出现可复现的适配障碍时，才另立其他渲染方案比较任务。

### PPTX

先导出最终页图片型 PPTX，再输出按讲解步骤展开的快照 PPTX。两者都必须标明图片型，
分步快照也不等同于原生动画。复用现有导出任务边界，记录失败页、降级和实际支持。
记录打开检查所用软件；若目标软件不可用，保留该项待验证，不能宣称兼容通过。

**完成条件：** 有真实可播放 MP4 和可打开检查的 PPTX；产物对应固定输入修订；
预览关键帧与视频画面一致，输出能力描述与事实一致。

## 10. P07：接入原应用的保存、编辑和任务

在现有框架中增加明确的 HTML 后端选择和数据保存，保留图片作品的原有流程与门槛。
接入页面预览、内容/素材修改、目标选择和动作绑定的最小编辑能力。

按现有 ownership 实现服务调用，登记路径、业务影响、数据库迁移及 Agent 契约。
保存场景修订、输入快照、任务指纹和产物归属，处理局部失效与失败恢复。

**完成条件：** 保存重开不丢编辑；无变化保存不触发重做；旧任务返回不能覆盖最新修订；
替换单张素材只重做受影响结果；旧图片作品仍可打开与输出。变更触及的既有流程执行回归。

桌面快捷方式始终使用 `D:\Program Files (x86)\PPT_HTML_Studio`，关闭重开使用该目录
当前源码。每轮记录提交/修订与启动方式，避免多个运行副本造成版本混淆。

## 11. P08：接入 AI 规划与素材生产

将现有分镜规划结果映射为已定义的场景，让模型选择注册布局/组件并填写内容。
只提供当前任务需要的规则与能力；模型输出先校验，再渲染和检查。生产 Prompt 依项目
optimize-prompts 规范维护。不能允许模型生成任意 CSS 或修改校验规则来绕过约束。

素材生成复用现有 provider、风格参考和并发治理，新增独立素材用途、槽位和资源版本。
每个需要独立出现的对象在生成前拆分；不恢复整页生成后再依靠 AI Mask 拆解的路径。

失败处理按对象、素材或页面最小范围重试；保存修复前后记录。自动提案遵守原有人工
保护规则，不能覆盖已锁定的人工修改，也不能用删内容制造“校验通过”。

**完成条件：** 一份内容能生成合规多页场景；不合规输出有明确诊断/修复范围；素材失败
不破坏已有有效资源；修改与重试不会重做无关音频或整部作品。

## 12. P09：真实课程全链路与首版验收

选取一段覆盖三类布局的真实课程，走完内容、讲稿、分镜、素材、场景、时间绑定、
人工调整及导出的过程。接入现有音频时间结果：沿用 provider/Qwen/人工校准路径，
明确未解析锚点和过期音频如何处理；不新增语音或对齐模型选型。

数字人直接使用现有方案输出的人物视频，仅验证摆放、安全区、时间同步和最终合成。
人物区域不得遮挡关键内容；此处不重新建设人物生成和口型系统。

首版完成的定义：

1. 一种经过设计的产品风格、第二种复用验证风格、三类已验收布局。
2. 文字/独立素材/基本形状可控制，讲稿驱动出现、强调和勾画。
3. 支持内容与素材调整、保存重开、局部重试和人工修改保护。
4. 真实 MP4、图片型及分步快照 PPTX 输出通过对应验收。
5. 现有音频和数字人接入通过；图片路线所受影响的回归通过。
6. 文档记录已支持、降级、未支持和未验证项；桌面重开可看到本轮代码。

产出使用说明、真实作品、验收记录和已知问题。测试覆盖与人工视觉结论分开记录，
不能因为结构校验全部通过就宣称画面精美。

## 13. P10：首版之后的独立扩展

以下按实际使用反馈单独排期，不捆绑成一次重构。

| 次序 | 扩展 | 开始条件与验收边界 |
| --- | --- | --- |
| 优先 | 基础可编辑 PPTX | 先映射文字、图片、矩形、圆形、线条；检查坐标、字体、层级及修改后无旧像素重影。复杂效果明确局部转图；要求全可编辑时遇到必要转图必须报不支持 |
| 随内容需求 | 扩展到 5—8 类布局 | 收集当前三类确实无法表达的内容，新增语义/配方而非复制整页 |
| 随输出需求 | 9:16 竖屏 | 重新定义密度、布局和人物安全区，使用真实手机观看尺寸验收 |
| 随视觉需求 | 更多风格与素材库 | 每套有参考页、可复用变体和边界用例；先验证组合美感再扩大素材数量 |
| 另立任务 | 图表、公式、母版、原生 PPT 动画 | 分别定义编辑/渲染/导出支持，不由基础 PPTX 成功推导为全部支持 |

可编辑 PPTX 是明确后续交付项，不用图片型输出冒充完成。如果后续产品优先级将其提升
为首版必需，应把这一子任务移到 P09 验收前，并同步首版范围与工作量。

## 14. 每轮实施与问题反馈方式

每轮围绕一个可演示成果推进，不要求一轮完成整个阶段，也不为所有常规实现反复确认。
需要共同判断的是首个视觉方向、参考页的美感及影响产品范围的取舍。

实施记录至少包含：阶段及 DEV/HPS 编号、输入样例/修订、交付文件、验证环境、通过/
失败/跳过结果、截图或产物位置、剩余问题。定义、实现、验证三个状态分别填写。
当前 P01 为定义完成/实现未开始/文档检查部分验证；P02 已有样稿待审阅，P03—P10 待实施。
后续状态必须引用实际证据后更新。

发现问题按归属修正：实现未遵守规则则修代码；特定风格问题修风格；素材问题修资源；
公共规则缺失才更新契约，并同步索引、变更记录、受影响定义和验证。不得为了某一页
方便而放松整个系统的约束。保留旧修订与人工编辑，不自动迁移所有已有作品。

以成果验收控制阶段进度，暂不承诺精确工期。P04 完成后，可根据实际组件复杂度、
排版返工和渲染成本重新估算后续工作；P06 再用真实输出耗时校准生产效率。
