# 混合视觉工程流程与实施顺序

日期：2026-10-07；状态：实施方案。规范依据为 [契约 0.7.0](../contracts/html-presentation/README.md)，尤其 HPS-023—030；本文件安排工程，不新增第二套规则或运行字段。
实验依据：[motion-02](../styles/science-explainer/experiments/motion-02/README.md)；用户认可其视觉及短对象过程动画方向。不是整个生产体系已验收。

## 1. 工程结论与当前缺口

本路线可继续：结构化设计驱动，生图承担复杂外观，代码承担文字、布局和对象控制，统一时间求值驱动预览与输出。
实验验证了三个同板资产的独立使用、过渡对象的完整定义、代码运动与视频取帧；不证明任意内容都能稳定生成。
制定本计划时，motion-02 实现仍是手工实验：对象位置、路径和文案写在 player/motion/CSS 中，JSON 没有真正被通用渲染器消费；裁切、审阅和导出也没有接入应用任务。
这一问题已由 E1 限定链解决，见 [交付记录](e1-data-driven-engine-completion.md)。下一步 E2 扩充受约束模板与资产复用，应用接入仍待后续。

## 2. 主流程及产物

| 步骤 | 输入和工作 | 必须保存的产物 | 通过条件/失败返回 |
| --- | --- | --- | --- |
| 1 内容规划 | 已有文章/讲稿；提取知识目标、必要上屏信息、语块和场景边界 | 内容版本、场景清单、知识/语块映射 | 含义准确，内容容量合理；超量回规划 |
| 2 设计与分工 | 选择运行支持且视觉认可的模板、风格和变体；设计探索单独标记 | 共享设计定义：对象、实现方式、槽位、资产、完整运动和关键帧 | G1；缺能力回定义卡，缺模板回设计扩展 |
| 3 视觉预演 | 从定义派生设计图任务，检查构图、层级、留白和过程 | 代表设计帧及必要分镜、审阅和修订记录 | G2；明确资产/代码分工；修改必须回写设计定义 |
| 4 资产准备 | 优先复用已合格资源；缺失部分生成单图或固定槽位板 | 生成任务、原图、选中版本、提取清单、资源/锚点/来源/哈希 | G3；不合格只修受影响资源，锁定人工选择 |
| 5 场景编译 | 校验定义，解析风格/模板参数、资源和目标，构建受约束画面 | 编译快照、资源清单、目标几何、诊断、可预览 HTML | G4；失败指出对象与所属层，不靠随机 CSS 修补 |
| 6 时间绑定与预览 | 初期用显式暂定时间；随后读取现有已确认音频时间结果 | 动作到语块/时间映射、就绪状态、关键帧和播放证据 | G5；确定时间求值、阅读窗口、遮挡/安全区成立 |
| 7 作品输出 | 锁定设计/资产/字体/时间修订，使用与预览相同求值 | 视频、输出清单、参数/哈希/诊断；PPTX 明确等级 | G6；实测目标画幅、时长、音频和输出限制 |
| 8 归档与局部修改 | 保存用户审阅、手工编辑、锁定项；变更后计算影响 | 可恢复修订、任务记录、受影响产物和重验结果 | 只重做受影响部分，旧作品不自动升级 |

视觉预演与资产准备允许受控迭代：已有资产时直接拿来做预演；新角色可先试一张小板再形成设计参考，如 motion-02。
这不是固定每次都要生“整页图＋资产板”。模板和资产已合格时可以直接渲染实际关键帧审阅；需要探索才新增设计图。
最终冻结的设计参考、资产和渲染必须对应同一设计修订；若采用不同资源版本，记录差异并重验，不能只因它们分别漂亮就算合成通过。
人工美术审阅是流程的一部分，自动检查只能覆盖结构、尺寸、引用、时间和部分工程问题。

## 3. 模块职责与现有项目复用

下列是职责划分，不是已经创建的模块或 API。实际路径须在实现定义卡中登记，保持现有服务所有权。

| 职责 | 新增工作 | 复用边界 |
| --- | --- | --- |
| 场景规划/设计编译 | 内容到对象、模板、分工和关键帧；受限结构化生成 | 既有 storyboard_planning.py 的纯规划/语块思路；不把新后端逻辑混入请求服务 |
| 模板与风格解析 | 槽位、预算、变体、参数与支持能力 | HPS 公共/风格归属；已认可样例回收参数，不复制风格专属业务组件 |
| 资产任务与资源库 | 复用、生成、槽位、提取、透明/锚点/版本、人工锁定 | 既有图片服务和任务基础；HTML 插图不套用旧整页白底/Mask 门禁 |
| 渲染与目标几何 | Text/Image/Vector/Group、HTML/SVG/Canvas 适配、资源就绪 | DOM 文字范围/矢量结构可直接定位；Canvas 与位图内部须显式几何，不能只拿画布框 |
| 时间求值与播放器 | 出现/路径/旋转/淡出、冲突处理、任意时间状态 | 读取既有音频对齐与时间轴，不替换 TTS，不另算一套导出时间 |
| 输出适配 | 浏览器取帧或受验证的渲染适配、音视频合成、PPTX 降级 | 现有作品/任务/视频与 PPTX 管理；图片型、快照型、原生可编辑能力分开声明 |
| 应用和任务管理 | 保存/编辑/重试/确认/错误/失效/权限 | 课程/项目/数据库/Agent/影响登记继续沿用现有架构，能力变化同步原契约 |

数字人继续作为已有服务输出的视频层接入；需要的是时长、位置、安全区与合成适配。本轮不研究替代方案。
AI 负责按约束输出设计数据或素材，不负责自由生成运行脚本。编译器负责派生坐标/排序/时间转换和确定性校验。

## 4. 数据与任务生命周期

先定义一个最小 Scene Schema，连通对象 ID、资源 ID、模板/风格版本、语块、动作及关键帧；不直接将 motion-02 自有 JSON 宣布为正式 Schema。
公共语义与风格值、实例值、测量结果分开。路径/旋转等新能力先补定义卡，兼容 P01 原字段与限定动作，不静默修改旧夹具。
作者定义是编辑来源；编译快照是对应修订的冻结输入；HTML/截图/视频是派生产物。几何和解析结果必须能够追溯到输入版本。
资源就绪、结构校验、内容审阅、视觉审阅、运行支持、输出验证分别记录；一个 approved 不能代表所有维度。

后台任务需按阶段和受影响对象重试，保存输入快照、状态、诊断和产物版本；具体任务状态枚举在接入时与现有任务系统统一。
失败或取消不得覆盖上一份有效作品。模型超时先确认任务实际状态，再决定是否重试，避免重复付费；原图和人工锁定项保留。
变更依据 HPS-011/030 计算最小影响：文字改动不默认重生插画；换资源重验锚点/裁切/运动；音频变化重绑相关时间，不默认推翻美术设计。
视频取帧前锁定输入和资源，不允许渲染过程中重新生成素材或随意更新远程图。

## 5. 接下来分四步实施

### E1 最小数据驱动渲染链（限定范围已交付）

先完成与首例相关的 Scene/资产/路径/旋转/坐标定义卡，落实最小 Schema 与校验。将 motion-02 中硬编码文案、布局、资源和路径收回结构化输入。
构建一个独立渲染入口，读取输入、等待资源/字体就绪、输出 HTML 和可查询的目标几何；保持浏览器直接预览，不先依赖应用数据库。
验收：同一渲染代码生成纸飞机例和第二个换内容实例；修改标题、换资源、换轨迹无需改 player/CSS；未知能力、缺资源、非法时间及容量失败有明确诊断；相同 t 可重复取帧。
交付：定义卡、Schema、编译器/渲染器/时间求值、两个实例、关键帧与测试证据。只注册真正实现和验证的能力。

### E2 模板与资产复用验证

将认可样例提炼为少量受约束配方，明确画幅、槽位、预算、允许变体及插图风格。先做开放过程场景和已有双概念解释，不追求一次覆盖所有布局。
把固定槽位提取、版本/哈希/锚点追溯和边缘审阅变成可复用工具，改善 motion-02 的留边与源尺寸边缘。资产板和独立生成分别允许，不强制所有主题用同板。
验收：换主题而不复制组件；人工替换资源不破坏动作；长标题/缺图/前景遮挡得到诊断；逐状态视觉认可。未经范围验证的配方保持 draft。

### E3 真实音频与作品输出

读取原项目已有有效音频与时间结果，绑定动作和字幕，先输出真实短视频；再接已有数字人视频验证合成和安全区。
按现有输出管理适配图片型/关键状态快照 PPTX，明确动画和编辑限制；原生可编辑 PPTX 单独排期。
验收：预览/视频用同一修订与求值，旁白不截断、字幕与动作一致、数字人不遮知识、PPTX 过程知识覆盖不丢失。

### E4 应用持久化与受限 AI 生产

将 E1—E3 的独立能力接入现有应用：画面后端选择、设计/资源/时间版本保存、预览编辑、任务重试、审阅锁定和影响登记。
同步数据库迁移、Agent 参数/能力/版本与生成契约；保留原图片路线。AI 规划和素材接入按真实 Prompt 输入输出优化，限制到已支持模板与能力。
验收：从真实课程内容完成计划→设计审阅→资产→编辑/时间→输出；能局部修复和恢复旧版本，重启后不丢人工选择；记录质量和失败原因。

E1 对应原 P03/P04 的核心实现，E2 对应 P02 收尾/P05，E3 对应 P06，E4 对应 P07/P08/P09。独立实验是前置证据，不让所有阶段自动变为完成。

## 6. 本例沉淀与保留问题

可沉淀：生成前分工、固定槽位交付、独立资源身份、完整过程对象、代码与图片合成、确定时间求值、分层验收。
需继续验证：复杂半透明与边缘处理、规模化模板复用、真实课程内容、音频/数字人/PPTX、跨环境字体、生成成本与失败率。
用户的认可支持继续这一方向；不将单例认可扩大为全部资产和全部风格的质量保证。工程优先补数据驱动复用，再扩设计覆盖。
