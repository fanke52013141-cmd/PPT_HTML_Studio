# HTML 视觉制作地基优化方案

日期：2026-10-09（Asia/Shanghai）。版本：建议稿 0.2，已吸收本轮两次关于美感核心的补充。

用户已要求将本轮讨论和资产形成备注更新到仓库。明确原则由[代码美术参考资产规范](../contracts/html-presentation/framework/12-code-art-reference-assets.md)维护，实际材料与过程见[资产登记](../assets/code-art-references/README.md)。本方案中的具体确认点、候选构图、试验顺序及未来界面仍保留建议状态。建议流程可在[可视化说明](visual-foundation-flow.html)查看。

本方案依据当前用户反馈及“水为什么结冰”的真实生成图、对象拆解和静态HTML。目标是先确定视觉制作方法、人员职责、纠偏机制与美感标准，再决定工程接入。本文不修改运行代码、原课程、模型配置或批准状态，也不把建议登记为已经确认的流程。

**核心原则：先把代码能做到的美感做出来，再把这个审美水准传递给生图模型。** 技术目录全面只是基础；丑或平庸的代码截图不能承担美感教学。模型应看到真实代码已经呈现的精致排版、线条、色彩、层次、组合和完整画面，并据此为新内容进行美术组合。

因此，先做“代码美术样板→人工美感审阅→固定美术参考”，再做内容构思和联合参考生图。不能在模型构思前只挑少量普通组件作为全部输入，也不能预先锁死构图让模型填空。能力范围要完整，美术参考要足够好看，两者共同构成输入；只有前者不足以支撑美感。

### 新增首要工作：代码美术样板

先在实际HTML/CSS/SVG/Canvas内设计和打磨能看得见的美感，不以“已实现”“能运行”或“有61项”作为完成标准。此处允许少量设计试作代码，但不推进业务流程改造和大规模组件工程。

样板分三个尺度：

- **精致细节：** 真实中文字形、字阶和强调，线条端点、箭头比例，渐变过渡，阴影与边框层次等。展示组合前后的视觉差异；效果本身要干净、协调。
- **局部组合：** 标题与导语、图形与注释、曲线与标签、容器与内容、插画与代码标注。让模型看到比例、间距和层次如何协同，而非只看到孤立原子。
- **完整样页：** 展示整体视觉重心、阅读路径和图文关系。以实际代码呈现，不以AI生成图冒充代码证据；混合页必须标出哪些部分是插画。

每份样板都要有真实代码和同版本截图，表达“这套视觉确实可以这样实现”。完整页用于美感和组合参考，细节图提供可辨认的视觉语言，参数附表负责约束。普通能力测试图保留作技术核对，不默认成为主美术参考。

先提出少量实质不同的代码美术方向，选择后把一套打磨好，再扩充它的表达覆盖。每个待入选的局部还要放回完整画面检查；单独漂亮的卡片不代表整页漂亮。用户对代码样板本身认可后，才拿它作为新生图的主要美感依据；否则回到样板继续打磨。

这不能保证模型每次生成都好看，但它使输入有明确、可实现的审美标准，后续可以定位是参考本身、模型组合还是HTML还原损失了美感。

## 二、样例暴露的具体问题

### 2.1 已查到的定义问题

1. **效果编号错用。** `effects-catalog.json` 的F01是纯色，F02才是线性渐变；静态还原主题和说明却将标题/刻度渐变写为F01。这说明“编号、定义、截图、实际实现”还未统一。应修引用并核对参数，不能把F01的含义改掉来掩盖错误。
2. **字号边界不一致。** 目录T类写18–48px，实际标题为80px；目录没有区分标题、正文和标注的用途及画布尺度。应建立按角色和画布定义的字号示例，重新审阅对应版本，不能直接宣布所有大字号已验证。
3. **参数界限过于笼统。** 同一大类多项共享一句范围说明；“多色渐变”与“2–3色”的关系、组合效果是否允许、坐标与文字容量等缺少逐项约定。
4. **检查覆盖不足。** 当前拆解检查查ID、白名单、粗略几何和讲稿覆盖，没有证明最终图片严格遵守字体、色值、参数、主体尺寸及文字容量。结构检查通过不等于视觉一致。
5. **参考图和执行定义有漂移。** 模型改变了标题效果、对象比例及位置，HTML又按结果手工校准。调整可以是合理设计选择，但应列出差异和新版本，不能无声改变原定义。
6. **插画提取存在重绘。** 当前杯子和冰块是参考引导的模型编辑，玻璃高光及冰纹已经不同。还没有证明可重复、无损的分层提取。

这些问题不要求先重构系统；先把错误、约束、缺项和对应样例整理成可审查材料。

### 2.2 我的画面判断

- 三张同权重卡片、两张插画、温度计与曲线同时争夺视线，缺少一个明确主视觉。
- 标题很大，但最值得理解的“凝固时继续放热而温度不变”没有得到相应的视觉权重。
- 蓝、粉、绿、紫同时承担装饰与强调，颜色含义不够集中。
- 温度计和温度曲线的作用部分重复；是否都保留，应由教学目标决定。
- 柔和体积插画与较平的卡片/线条还没形成统一的线宽、层次和精致程度。
- 留白集中在局部，并未充分服务对象之间的关系和阅读顺序。
- 标题提出“为什么”，现有内容主要解释“结冰经历什么过程”。第一步需要选清：本页讲过程，还是讲原因；如果要讲微观机制，应补内容和适合的示意，不能只美化现有三张卡片。

以上是对当前样例的审美与内容判断，不是自动评分结果。

## 三、需要固化的四层材料

### 第一层：代码能力目录——能画什么（完整性与边界依据）

保留较全面分类，逐项填补缺口；不要为了省事将表达范围缩成几张卡片，也不要承诺穷尽浏览器的一切能力。

| 类别 | 本轮应覆盖/审查的内容 |
| --- | --- |
| 几何与路径 | 直线、折线、圆弧、贝塞尔曲线、圆/椭圆、多边形、复合路径、开闭路径 |
| 描边与连接 | 线宽、端帽、接头、虚线、箭头、引线、端点锚定、避让；区分已演示与待补 |
| 色彩与表面 | 纯色、透明度、线性/径向/多色渐变、内外阴影、裁切、遮罩、有限纹理/滤镜；主题可禁用其中一部分 |
| 排版与标识 | 中文字体、字重、字阶、长短标题、行距、换行、混排、单位、上下标、公式、强调、文本描边或渐变的组合边界 |
| 图标与教学符号 | 常用符号、状态、指示、简单结构图；不让每个简单图标都依赖生图 |
| 布局与组合 | 网格、对齐、分组、重叠、层级、间距、主次、内容容量、安全区、图文配合 |
| 信息表达 | 过程、比较、因果、结构、层级、循环、时间线、知识卡；按解释任务选择 |
| 数据与示意 | 坐标轴、刻度、图例、数据图、定性示意；真实数据与教学示意分别声明 |
| 图片组合 | 透明边界、可见主体尺寸、比例、视角、锚点、阴影、遮挡、颜色与代码背景衔接 |
| Canvas二维示意 | 粒子、波形、路径、热力及有限状态变化；明确示意身份，不暗示物理仿真 |
| 运动与状态 | 显隐、位移、缩放、旋转、描边、遮罩揭示、支持的形变；本阶段仅登记后续边界 |

每项效果最少配：稳定ID和版本、用途、真实代码截图、具体参数、组合条件、允许和失败样例、适合的画面尺寸、实现状态、当前主题是否允许。组合也需要样例：单独阴影和单独渐变能画，并不代表任意叠加都好看或好复刻。

在已打磨并审阅的代码美术样板基础上，给生图模型的参考应有四种相互补充的视图：

1. **完整分类总览。** 让模型知道整个可用表达范围，避免只想到卡片、圆和箭头。总览负责检索，不承担全部细节。
2. **美术效果细节分册。** 以清晰多图展示每种实际效果中经过设计的变体，以及参数变化和边界，例如协调的渐变方向、阴影软硬、圆角、线宽、中文字阶和曲线。每张图来自真实代码；不能让生图模型自己画一张“代码支持图谱”作为证据。普通测试变体不能仅因能运行就成为推荐美术变体。
3. **组合示例。** 展示标题与下划线、渐变容器与细描边、曲线与标注、插画与代码标签等组合的完整局部；示例说明组合规律，允许模型提出其他遵守边界的组合，不固定唯一版式。
4. **完整画面样板。** 让模型理解层级、留白、图文比例和视觉重心。样板必须标清哪些是实际HTML、哪些只是风格参考；初期未审过的样板只作候选，不作为批准依据。

构思和生图阶段要能实际看到完整的、已验证且当前风格允许的代码表现集合，必要时再放大某些细节。因接口图片数量/分辨率限制需要分册或多阶段传递时，应先试验可读性和输入能力并留记录，不能悄悄删成极少数样例。缓存的是同版本参考材料；每次有效请求仍需携带对应输入，不能假设模型永久记住前一轮。

“完整”指已定义版本内的完整分类和支持范围，不声称穷尽HTML/CSS/SVG/Canvas的所有理论组合。未实现、禁用、待审项对人可见，但不能以未标注的正面示例混入生图可选集合。

完成标准不是“数量够多”，而是所选页面任务用到的效果无隐性缺项，且效果ID、截图、参数、代码相符。其他候选明确留在待补列表。

### 第二层：视觉风格规范——从漂亮的代码样板中提炼

先把代码样板打磨好，再从实际结果中提炼背景、字体与字阶、主辅色含义、线宽、圆角、阴影方向/强度、渐变种类和使用位置、插画视角与细节程度。选定一套主风格后沉淀参数和实际参考页；不能先凑一组色值和圆角，就假定它有美感。

效果大全与风格规范分开：能力可以广，某套风格实际使用的组合应克制。同一目录可以支持多套风格；一张页面不需要展示全部能力。

### 第三层：画面构图范例——怎样解释不同内容

建立经过审阅的主视觉解释、过程、比较、因果、结构标注、数据关系等范例。每个范例说明信息主次、阅读路径、主体数量和内容容量，而非只给空卡片框。

先用几种实质不同构图验证美感，再形成可复用配方。不要先把所有内容锁到“横排三卡片”。

### 第四层：插画资产规范——怎样放回来不走样

至少固定主体、视角、光向、色调、可见轮廓、完整性、透明边缘、独立控制粒度及是否自带阴影。主体可见框与文件外框分别记录，用同一份素材放入最终页面。

背景优先由代码绘制固定色。透明插画不得依赖周围背景纹理；玻璃等半透明主体需在目标底色和对照底色查看边缘。简单接地阴影可交代码，复杂且与主体不可分的阴影作为素材的一部分明确登记，避免重复画两层。

## 四、建议确认的完整流程与分工

人负责内容取舍和美术决策；AI负责理解、提案、拆解及差异分析；程序负责已确定规则的渲染、测量和记录。AI审阅是辅助意见，程序检查也不能替人宣布“好看”。

| 步骤 | 输入与产物 | AI做什么 | 程序做什么 | 人做什么 |
| --- | --- | --- | --- | --- |
| 0 打磨代码美术参考 | 实际代码美术细节、局部组合、完整样页及能力目录 | 提出设计方向、辅助美术迭代、审查缺口 | 真实渲染设计、显示不同变体、导出同版本截图 | 审阅代码样板本身的美感；选择可作为模型依据的版本 |
| 1 明确教学目标 | 主题/讲稿→本页一句核心结论、必讲事实、上屏/口述分配 | 判断过程/原因/比较等任务，缩减重复 | 记录版本和来源 | 决定本页到底要观众理解什么 |
| 2 构思与实现分工 | 核心结论+完整代码表现参考→对象、关系、代码/插画/混合分层表 | 在充分可见的能力范围内构思并标明归属；提出风险 | 查能力及素材数量 | 可改变主次、对象职责和分组 |
| 3 比较构图草案 | 对象表→2—3个构图意图 | 提出实质不同阅读路径和取舍，不提前锁死全部像素 | 必要时用灰度或现有素材低成本呈现 | 选教学主次，提出构图偏好；允许下一步AI继续组合 |
| 4 联合参考设计 | 已审阅的漂亮代码样板+完整准入范围+组合细节+风格参考+本页对象关系→完整视觉提案 | 参考代码样板的美感，在明确能力边界内为新内容自主组合并指出偏差 | 保留实际请求、附件角色和版本 | 对整页美感选择、标注、局部反馈 |
| 5 固定资产与可执行设计 | 选中方案→独立素材及精确视觉定义 | 提取/编辑/生成所需素材，比较漂移 | 测可见边界、字体、锚点与位置 | 选择素材版本；不接受的重绘退回 |
| 6 组装实际HTML | 固定字体/素材/布局→真实页面 | 辅助解释差异、提出局部调整 | 同源渲染文字、图形、关系和素材 | 可直接调结构参数、文字、尺寸和位置 |
| 7 对照与纠偏 | 参考+HTML→差异及修订 | 按内容、构图、字体、素材、效果分类 | 提供同尺寸叠加/滑动/对象显隐、显示改动 | 决定接受、局部改或回到前一步 |
| 8 沉淀与迁移验证 | 通过样页→可复用规则及另一主题样页 | 尝试换内容并指出超容量项 | 按已定配方重新渲染 | 判断同风格是否仍成立、是否可扩大制作 |

本阶段聚焦0—8的静态方法。后续既有音频、动画、数字人和导出接在静态视觉通过之后；数字人需在构思时预留区域。动态页面还要审初态、中间态和终态，不能仅凭静态好看通过动态审阅。

### 在最开始就拆分吗？

**是，要在构思时同步拆分。** 先明确解释目标和画面关系，再让每个候选对象带上实现归属。初稿只定区域、比例、关系和角色；过早固定所有像素会压缩构图探索。

例如“水杯上的温度标注”是一个语义组合：杯子是插画，温度文字、引线是代码，两者共享稳定的对象关系。不是先让模型画成一张图，再猜里面有哪些东西。

对象分工表最少包括：对象ID、表达意思、必须准确的文字/数据、代码/插画/混合归属、引用效果、与其他对象关系、初步区域、是否需要独立动作。未支持的表达明确提出替代或补能力，不能静默简化。

### 人工确认点不应过多

代码参考库首先有一次风格级的美术确认，后续使用同一版本时可复用。下面四个确认点针对新画面的探索，不表示每页都重复审一遍代码库。

风格探索阶段建议四个关键确认点：①教学目标；②构图与风格方向；③完整设计及实际资产；④最终HTML。每一步都可看，但不要求每一步都手动确认。

成熟后，相同风格和容量内的页面可复用已定选择、集中批量审阅；遇到内容含义变化、布局超容量、素材明显重绘或新效果才升级人工决策。确认绑定具体版本，保留“方向认可、需修改、视觉通过”的区别。

## 五、提示词应如何组织

### 通用结构

每个任务只包含四组信息：**职责、固定约束、当前输入、要求的产物和自查**。固定规则按版本复用，页面只填写自己的内容、所选构图、对象表和局部反馈。模型有system/user区分时把稳定规则放system；只有单prompt的图片接口则按清晰段落组装并去重。

固定效果库应全面，并以足够清晰的分层参考呈现给模型：完整准入范围、经过设计的单项细节、漂亮的组合示例和完整代码样板。主要美感依据必须来自已经打磨好的代码视觉。先让模型据此选择和组合，再输出本页采用的效果清单。可以追加细节参考，不能在构思前只给少量普通组件而剥夺其他可实现的选择。每页变化的是内容与关系，固定参考与规则按版本复用。

充分告知并不等于把所有小图压进一张模糊大海报。应审查模型实际收到的图片、可读尺寸、编号解释、参数约束是否一致，尤其是组合示例里有没有暗含未声明的效果。构图方案也应保留探索空间，初稿的对象框是约束意图，选择完整设计后再冻结精确位置。

### 六类任务模板

| 任务 | 关键要求 | 输出 |
| --- | --- | --- |
| 内容理解 | 本页核心结论、必要条件、屏幕与讲稿分工；不添加无来源数据 | 内容简报及疑点 |
| 构思与分工 | 在允许表达内提出不同构图；每个对象声明职责和代码/插画归属 | 构图提案、对象关系表、风险 |
| 整页视觉设计 | 明确每张附件的角色、视觉主次、固定背景、字体/效果边界、具体内容 | 完整视觉提案；偏离项待审 |
| 独立素材 | 一个或明确分层主体、参考的已选版本、视角/光向/边界/透明度；无文字关系线 | 独立PNG及实际生成记录 |
| 审阅 | 同尺寸参考与HTML、必须保留项；只报告可见差异与位置，不自行宣布通过 | 可定位问题、严重性、建议改动层次 |
| 局部修订 | 目标对象、具体变化、锁定对象、不得改变的关系；输出变更摘要 | 最小范围修订和对照 |

**构思提示片段：**

> 先查看完整代码表现参考和组合示例，再根据讲稿写出本页唯一核心结论，提出两种解释它的画面组织。每种方案说明主视觉、阅读顺序、上屏文字、插画主体和关系。充分利用所示可实现效果进行组合，逐对象声明代码/插画归属及所用效果；插画不承担可变文字和精确关系。把不确定或超能力内容单列，不强行补满卡片。

**整页设计提示片段：**

> 附件A组是真实代码已实现的美术样板、细节及组合示例，是代码部分的审美基准；附表给出完整准入范围和边界。继承样板的精致程度、排版层级、线条和层次，为本页内容重新组合，不必复制示例版式。附件B只参考插画画风及与整体的协调；附件C是构图意图。根据对象关系组织主次、留白与阅读路径，主视觉为〔对象〕，主要结论为〔文本〕。背景固定〔色值〕。标题、标签、关系和图表使用参考中可执行的效果；插画在主体区域完整呈现，与其他主体及标签保持净空。若参考风格和代码能力冲突，服从能力约束。不要添加与解释目标无关的面板和装饰。最终仍须检查，不将提示约束当成已遵守的证据。

**局部纠偏片段：**

> 只修改〔对象ID〕的〔问题〕：从〔现状〕改为〔目标〕。锁定〔其他对象〕的内容、素材、位置与风格版本。需要移动相连关系时保持端点绑定。返回修改项和受影响对象；无法在当前约束内完成时说明冲突。

这些是待试用模板，不是本轮已上线生产Prompt。后续试用应保留输入/输出和采用原因；正式接入前遵循现有提示词归属与优化规范。

## 六、纠偏不能只靠改提示词

| 问题 | 人可以怎么改 | 应修改哪层 | 主要重做范围 |
| --- | --- | --- | --- |
| 没讲清主题 | 改核心结论、上屏内容、删重复信息、拆页 | 内容和构思 | 受影响页面及后续产物 |
| 构图呆板 | 选另一草图、拖动主次区域、放大主视觉、调整对齐 | 布局意图 | 布局和HTML；能复用的插画保留 |
| 字太多/太小 | 编辑正文、换行、换构图或拆页 | 内容与排版 | 文字容量和页面；不要只持续缩小字号 |
| 某效果不合适 | 直接选择已审阅的颜色、字阶、线宽、阴影、渐变变体 | 风格或效果参数 | 相关代码对象 |
| 插画不合适 | 对比候选、替换既有素材、局部编辑、选择提取方法 | 资产 | 指定素材及其边界/锚点 |
| 主体位置不对 | 调可见主体框、比例、锚点、对齐基线 | 几何定义 | 主体与相连标注 |
| 箭头指错 | 选择目标对象/锚点、拖动连接端点 | 对象关系 | 对应关系线 |
| AI改坏已满意部分 | 锁对象/素材/区域、局部重做、回退版本 | 编辑保护 | 被授权的局部范围 |
| 整体不好看 | 标明视觉问题，比较不同构图或风格候选 | 美术方向 | 必要层次；不能默认全页重生 |

人提出“标题太抢眼”“冰块太小”时，AI先转换为明确变更清单供查看；可直接调整的参数由程序执行。锁定信息必须在编辑范围上真实生效，仅把“别改其他内容”写进提示词不够可靠。

每次纠偏保留：问题截图或对象、修改目标、受影响范围、锁定项、修改前后对照和回退点。连续同类失败时先找根因；例如两次仅改措辞仍出现比例失真，应转到素材框/构图约束处理，不继续盲目重抽。次数上限是建议的成本控制策略，尚非已确认产品规则。

## 七、如何让全过程看得见

建议先确认“每一步展示什么”，再做正式流程界面。讨论期用可点击流程说明和审阅包就能验证理解。

未来界面每个步骤至少呈现：

1. **正在做什么、由谁负责。** 显示具体任务，如“比较两份构图”或“生成冰块素材”。
2. **实际输入。** 讲稿、所选效果、风格参考、构图、对象表；提示词和参数可展开。
3. **实际输出。** 草图、图片、透明素材、HTML；未生成的不能用占位图冒充。
4. **状态及依据。** 待制作、制作中、待审阅、已通过、需修改、执行失败、已过期；模型完成默认进入待审阅。
5. **可采取的操作。** 选方案、改文案、调参数、锁对象、局部重做、退回指定步骤、回退版本。
6. **修改影响。** 这次会重做什么、哪些已满意对象能复用、哪项既有确认需要重审。

画面本身支持代码/插画分层查看、对象轮廓、参考/HTML滑动与叠加、差异对象定位、素材可见框。默认展示画面与当前决策，详细模型记录折叠，避免用户被日志和技术字段淹没。

流程可视化还应保留返工路径：信息不对回内容；构图不对回草图；素材不对回素材；参数不对留在HTML。不要只提供一个“重新生成全部”。

## 八、美感如何提高，以及如何控制下限

### 8.1 先做美术选择，再制定数值规范

前提是代码美术参考本身已经足够漂亮，而且模型充分看到它。先由我们在真实代码里完成设计打磨，再让生图模型基于这些参考承担新内容的组合探索；人负责解释目标、偏好和审阅。不能把普通能力图谱交出去，就期待模型自行补齐参考中没有体现的美感。所有候选使用同一份有质量、覆盖充分的代码美术参考，使比较反映组合选择而不是输入缺失。

以同一讲稿、同一主体素材制作三种构图方向：

- **主视觉解释：** 一个明显主视觉，文字围绕它组织，步骤弱化为辅助。
- **过程叙事：** 以降温到凝固的变化引导视线，避免每一步都套等大卡片。
- **关键关系解释：** 以温度曲线及恒温区为主视觉，杯子和冰块辅助建立直觉。

先比较灰度构图，再比较同一固定配色下的完整样板。每轮主要改变一个维度；同时换配色、素材、内容和布局，会让人无法知道改善来自哪里。优先复用当前素材；只有选中画风确实不适配才新增生图。

对当前页面，我倾向先试“关键关系解释”：把凝固阶段恒温作为焦点，将三个步骤缩成阅读引导，评估是否删除重复的温度计。但这依赖第一步确认本页解释目标，仍是候选，不先定为唯一模板。

### 8.2 美感审阅看哪些具体问题

| 维度 | 人应该看什么 | 纠偏方向 |
| --- | --- | --- |
| 教学表达 | 标题提出的问题是否被画面回答？核心关系是否准确？ | 内容取舍和表达类型 |
| 主次 | 第一眼落在哪里？它是否就是核心信息？ | 面积、对比、位置、留白 |
| 阅读顺序 | 视线从哪里开始，如何移到下一处？ | 对齐、分组、关系线、节奏 |
| 排版 | 标题/正文/标注是否协调？行长、换行是否自然？ | 实际字体与容量 |
| 色彩 | 每种强调色是否有稳定意义？是否装饰过多？ | 主辅色职责、少量重点 |
| 图文统一 | 插画细节、图形线宽、阴影与标签是否属于同一套视觉？ | 资产规范与效果变体 |
| 空间 | 哪些地方挤，哪些地方空得没有理由？ | 主体比例、组内外间距 |
| 还原 | 选中的构图、素材轮廓、文本和层次是否保持？ | 字体、几何、资产与效果差异 |
| 实际观看 | 缩到用户常看的尺寸，内容还清楚吗？ | 减内容、改构图；不只看放大图 |

不虚构“美感90分”或“相似度95%”。内容和技术存在可客观检查的项，美感通过明确参考、同条件候选比较和人工结论形成判断。AI可辅助找问题，不能将自己的评分作为通过依据。

### 8.3 如何提高稳定性

稳定性来自“审过的字体/效果组合 + 审过的构图 + 固定素材 + 明确容量 + 局部返工”。每次新页面先检查是否在已验证范围内；超出时提出问题而不是偷偷压缩文字、改变比例或增添装饰。

第一轮保留用户偏爱的正面样板，也保存典型失败样板及原因；后续把“不要太丑”转化为可指出的具体问题。先做一个审美通过的完整HTML，再换另一个主题验证同套规则；增加长标题、密集标注等边界情况，明确何时该换构图或拆页。

### 8.4 素材保真的专门试验

固定背景能改善组合稳定性，但不会自动解决半透明边缘、主体高光和形状漂移。建议比较：

1. 本次的“整页提案→参考引导编辑为独立素材”，观察风格与轮廓漂移。
2. 条件合适时，用原像素分割/抠图保留主体，检查透明材质边缘及缺失处；是否采用具体工具另做可用性试验。
3. 先固定独立插画，再把其参考附到完整设计，并使用同一原文件组装；仍要检查模型是否在提案里重绘了素材。

构思和初步分工始终在前。上述只是素材准备与完整设计的局部顺序实验，不跳过用户要求的联合参考生图。成熟模板可直接复用资产与代码，不必每页重生整页设计。

素材、字体和精确布局就位后的实际HTML，应作为后续可执行视觉基准。原设计图继续保留供比较；发现差异先说明并修正，不可把难以还原的部分悄悄降级成新目标。

## 九、接下来应交付什么

| 阶段 | 交付物 | 完成条件 | 需要确认的决策 |
| --- | --- | --- | --- |
| A 能力审查 | 完整分类、已知错漏、修订建议、真实示例与反例 | 编号/参数/截图/实现对齐，缺项明示 | 范围及允许组合是否合适 |
| B 代码美术打磨 | 实际代码的精致细节、局部组合和完整样页，整理成可复用美术参考 | 人直接看代码样板就认为足够好看；所有主要表现真实可实现 | 哪一套代码美感值得交给模型参考 |
| C 方法确认与生图试作 | 输入输出流程、职责、提示词及同内容的不同构图提案 | 模型实际看到代码美术参考，能以它为依据组合出好看的完整页面 | 流程及模型组合结果是否合适 |
| D 保真对照 | 固定资产、实际HTML、逐项差异、纠偏记录 | 语义完整、可见差异可接受，实际页面保持已选美感 | 选哪个可执行版本作基准 |
| E 迁移验证 | 第二个主题及容量边界样例 | 无须逐页重写风格与提示规则，失败有明确处置 | 是否可进入模板化工程 |

推荐先按A→B→C→D→E推进；完整机制试通并看到跨主题效果后，再安排生产组件、任务编排和界面实现。允许为试作写少量可视化脚本，但避免把未定方法提前固化到项目业务流程。

本轮需讨论的六项：①先审代码美术样板本身，再交给模型；②以实际HTML视觉通过作为可交付标准；③构思时同步明确代码/插画职责；④风格探索采用四个人工确认点；⑤先选统一主风格，再积累多个构图；⑥通过同主题美感与第二主题复用两次审阅后再扩大工程。“先传递代码本身的美感”已由用户明确，其余具体规则和完整细化流程仍是建议，不预填“已确认”。
