## 2. 首先交付什么

第一批成果是可执行的流程表、状态与确认规则、失败恢复清单、统一接口卡，以及已发布标准库 1.0 在真实内容上的视觉复核。优先修现有断点，并保留对设计参考和实际 HTML 的独立审阅。

建议先完成以下五件事：

1. A 线梳理七步状态、版本和确认范围，对齐页面、API、Agent、后台任务；处理本轮失败用例。
2. A 线冻结跨团队接口与文件归属，写出最小流程验收用例。
3. B 线同期复核已发布的代码美术细节、局部组合和完整样页，用真实内容找出需要修正的项目，直接让用户看实际 HTML。
4. 用现有组件跑纯代码页与素材辅助页两条最小通路；记录真实停点、批准与返工，不用独立演示替代应用入口。
5. 在参考输入、实际 HTML 和第二个内容主题的复用都得到相应审阅后，按真实缺口扩充生产能力。

## 5. 同目录并行的约束

所有对话使用唯一开发目录，采用文件独占，不能多个对话同时改共享大文件。A 维护写入登记，遇到冲突先提交修改需求或片段，由当前所有者合入；只读和专属文件工作继续。

- 各对话不执行分支切换、reset、clean、stash 或全仓暂存；当前工作区已有未提交内容，不能把别人的改动一起提交。
- A 在实施前记录基线和任务文件归属；集成/提交仅覆盖明确属于本轮的文件及片段，遵循仓库发布范围。
- 公共 Schema、编译器、渲染器入口、注册表、Agent 合同、迁移、失效登记和前端主入口由 A 独占。
- B/C/D 先在专属源模块实现，提供接口增量；公共接线由 A 完成。版本、迁移编号和公共生成产物统一分配。
- 只运行一个真实应用服务；重启、数据库迁移、公共 bundle 构建和真实课程联调由 A/F 预约窗口，避免覆盖彼此产物。
- 测试使用独立数据库、临时目录和各自输出；不得在真实课程上注入失败。调用现有供应商时沿用全局并发治理。
- 每次交付记录基线、改动路径、接口版本、验证命令/退出码、证据、未完成项、所需集成修改。没有用户审阅不登记视觉通过。

## 6. 技术选型安排

本轮以已有共享 HTML 渲染器推进。HyperFrames/Remotion 对比属于独立、非阻塞调研：用同一固定输入比较接入成本、任意时间取帧、字体资源一致性及预览/导出一致性，再记录采用或不采用的理由。动效库的对象身份、参数和时间语义由本项目定义。

调研可由 C/F 在核心交付之后另开任务，不能同时在生产运行时装入两套时钟。当前 Remotion 图片输出、现有语音及数字人服务按原职责复用。新框架并非流程贯通的前置条件。
