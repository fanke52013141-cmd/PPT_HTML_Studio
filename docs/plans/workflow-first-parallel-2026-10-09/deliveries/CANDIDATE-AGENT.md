## 实现

固定生产服务仍负责权威输入、模型规划、素材、资源、修订、批准和保存。未保存初稿出现实际 CONTENT_CAPACITY_EXCEEDED 时，进入 LangGraph 1.2.14 的 evaluate → decide → apply 循环：严格检查 → 同一渲染器诊断截图/测量 → 豆包选择 patch 或 stop → 编辑器验证受限操作 → 重验。最多三次决策。

模型选择要修改的对象和数值，程序没有预设冷杯字号/坐标答案；正文、身份、主题、动作和绑定保留。共用已有 JSON 多模态适配器，不声称已验证豆包原生 tool_calls。只支持注册文字样式和基础位置/尺寸；没有任意代码执行、文件访问或自动重写组件。诊断画面永远 passed=false，只有正常严格渲染通过后保存。

框架选择参考 [LangGraph 官方说明](https://docs.langchain.com/oss/python/langgraph/overview)：采用状态图管理局部循环，复用现有模型连接，未采用新的模型客户端或 LangChain 全项目 Agent。候选审计文件记录各轮 Prompt/响应/截图/错误；持久任务沿用 LocalJob，没有实现图断点恢复。项目锁覆盖修复期间，同项目编辑会等待，失败回滚。
