# S05 正式快照导出交接

2026-10-12；契约 0.9.26、Agent API 保持 1.19.0、produce-editable-html Skill 1.4.0。定义见 [正式快照导出 0.1.0](../../../contracts/html-presentation/runtime/visual-v1/formal-export-0.1.0.md)。

## 已完成与实际流程

```text
原任务提交 / 原视觉、音频、binding 门禁
  → 项目作者锁内冻结整课有序页和源指纹
  → S01 页面快照：实际文字、素材、字体、共享播放器
  → 固定导出工具 + 浏览器/Node/FFmpeg 身份
  ├─ PPTX：冻结终态 PNG → ZIP/页数/逐页嵌入图片比对
  └─ 视频：页内分段 → 命中也完整校验 → 整数帧顺序拼接
       → 可选本地数字人合成（固定配置与固定视频）→ 最终完整解码
  → staging 候选验证通过
  → 项目作者锁内比较冻结指纹与当前输入
       ├─ 一致：登记作品、完成对应输出、提交数据库后原子替换默认视频
       └─ 不一致：登记为历史作品，保留新版进度与默认视频
```

- `html_export_snapshot.py` 固定有序整课、引用已验证 S01 页面快照，复制导出工具。数字人配置/所选上传或已有生成视频也冻结；不调用 9001 或新模型。启用但缺失/超限阻断；Light 版禁用时忽略旧配置。
- `html_build_snapshot.py` 增加正式 `pptx` 目标，必须原批准有效，固定作者场景并去除字幕；原诊断 preview 与严格 video 门禁分别保留。
- Node 导出工具在正式模式只打开冻结页面，使用本地字体/素材/播放器，禁止 HTTP 加载；截图按 1600×900 原生画布获取，不受审阅面板 padding/缩放影响。
- `html_frozen_video.py` 消费整课快照，独立 export-work，每页缓存键覆盖实际消费输入、导出工具、运行二进制/Playwright 版本和编码参数。顺序/全局 revision/其他页及未引用素材不进入页内键；已验证分段保留，失败中间文件不进缓存。
- 缓存命中检查实际字节 hash、格式/帧数/时长和完整双流解码。分段、拼接及最后数字人合成都检查实际最终文件；编码结构、音轨长度、帧时长、完整解码与最终 hash 分开记录。
- 拼接清单显式使用整数帧时长，页顺序变化后重新累计 offset_frames；音频按同一时间轴重组。页尾视频保持，向上取整覆盖 MP3 尾部，不用 `-shortest` 截旁白。
- `html_pptx_snapshot.py` 完整读取 PNG、验证尺寸，构建后检查 ZIP、页数和每页实际嵌入图片，再发布；PPTX 仍是 image_only_snapshot，不是逐对象可编辑 PPTX。作者 HTML 保持可编辑。
- `pptx_service.py` / `video_render_service.py` 沿用原持久任务、项目/全局并发控制及作品登记。登记前刷新数据库项目行，避免长任务持有旧设置或进度；源变化的结果可完成为历史候选；不消除新版影响或更新默认视频。HTML 合成走 HTML 格式校验，不拿冻结 HTML 目录去运行图片/Remotion 资源门禁。
- `video_artifact_service.py` 增加内部 make_current 控制与默认文件原子替换；HTML 默认状态以源散列判断，删除/兜底选取不能把过期历史视频升为当前默认。未提交数据库的 HTML 候选失败时清理自身文件，旧作品保留。已成功任务的重复提交也复验源指纹、当前工具、运行身份、最终 hash 与全解码；损坏或缺少新证据的旧 HTML 成品不能只凭文件存在复用。

## 格式与兼容

新增内部 `hps.html.course_export` 0.1.0；作品 metadata 增加 export_evidence、historical。视频 evidence 包含固定课程身份、逐页 cache_key/reused/offset_frames、运行身份、分段与最终校验。PPTX evidence 包含固定课程身份、逐页快照与嵌入图片 hash、ZIP/图片/最终 hash 校验。

课程快照在 `planning/html_visual/export-builds/<snapshot_id>`，原页面快照在 `builds/<snapshot_id>`；临时目录在 `export-work/<独立run>`，验证分段在 `segment-cache/<key>.mp4` 与相邻 JSON。runtime 文件不提交。数字人单视频上限 1 GiB；本机 Chrome/Node/媒体工具须可用，二进制变化阻断或改变缓存身份。

没有数据库迁移、新公共 API/Agent/MCP/CLI 能力、第二任务账本或新数字人服务。原导出入口接线；显式 allow_legacy_unbound 仅保留旧工程探索/测试兼容，生产默认严格。原图片后端的来源和门禁继续有效。
