# S06 受控 Skill 接入 Agent 交接

2026-10-12；契约 0.9.27、Codex 操作 Skill 1.5.0、运行片段 candidate-layout-repair 0.1.0；公共 Agent API 保持 1.19.0。定义见 [runtime-skills-0.1.0](../../../contracts/html-presentation/runtime/visual-v1/runtime-skills-0.1.0.md)。

## 当前真正接入了什么

只有**未保存容量候选的排版修复**接入一个受控片段。LangGraph 仍管理 evaluate → decide → apply；模型通过既有兼容 chat 接口返回 patch/stop，代码执行既有 set_text_style/set_presentation 并严格复验。没有新增六个自主 Agent，没有新 LangChain 服务或新数据库任务源。

Codex 总入口 `.agents/skills/produce-editable-html/SKILL.md` 与豆包运行片段分开。前者指导操作助手；后者在 `config/html_runtime_skills/`，由 `config/html_runtime_skills.json` 注册 ID、版本、适用阶段、I/O 合同、正文与引用 SHA-256。既有便携打包排除 `.agents`，所以运行资源放 config；不用改打包器或携带 Codex 私有目录。`.gitattributes` 对这些固定 hash 的 Markdown 和注册 JSON 强制 LF，避免 Windows checkout 改字节。

```text
生产候选容量失败
  → 原严格/诊断浏览器检查，资源或Schema错误不进模型循环
  → 校验注册与输入/输出合同、路径、正文和显式引用 hash
  → 固定工具合同 + 仅当前 stage 的排版策略
  → 当前对象/publicParts/槽位/主题默认/人工保护/真实诊断 + PNG
  → 豆包 patch 或 stop
  → 原权限/Schema/容量工具校验（AI source 不可伪装 human）
  → 严格 review_scene
  → 原生产保存与 revision 门禁
```

Loader 不跟随网络或 Markdown 链接、不读取用户/模型返回路径、不动态注册。错 hash/缺文件/未知合同/非法引用失败，不静默回退。装载后每个边界复验；generation 快照包含 loader、注册、正文与引用，并核对装载时的期望 hash，避免验证与捕获之间的变更。S02 的未知付费请求防重发保护保持。

每轮 `request.json` 记录实际 system/user/schema、图片 hash、request_id、Prompt hash、mode、Skill 装载身份；`result.json` 和生产 provenance/layout_agent 也记录身份。模型不生成这些字段。Skill 内容、版本或注册修改改变快照/实验/请求身份。完整 SKILL.md 不进入模型；已保存修复、音频、素材、审美批准和 S05 导出不借此扩大权限。

## 真实豆包对照与默认选择

模型 **doubao-seed-2-1-pro-260915**，使用已有连接，只读原配置；运行数据库与产物隔离，没有导入 server、启动第二服务或更改用户业务项目。每 arm 两次决策预算，HTTP 预算六次、temperature=0、max_tokens=2048、timeout=90s、SDK 无隐式重试；按 AB/BA/AB 顺序运行，每 arm 从原候选开始。

| 模式 | 严格工程通过 | 模型适配器调用 / HTTP | 未解决案例（需介入） | 合计耗时 | 输入/输出/总 token |
|---|---|---|---|---|---|
| 原 Prompt 0.1.0 | 2/3 | 4 / 4 | 1 | 81.418 秒 | 19068 / 1323 / 20391 |
| 受控 Skill Prompt 0.2.0 | 3/3 | 3 / 3 | 0 | 49.560 秒 | 15306 / 765 / 16071 |

三个模板分别为 explanation-cards-v1、data-relation-v1、process-stage-v1。每对首轮实际 user JSON 和 PNG hash 相同，代码/模型配置/预算相同；只有策略模式不同。合计七次真实 HTTP，供应商 usage 36462 token。费用未取得，cost=null。原模式失败原样保留，没有重跑选最好结果。

冷杯与三温度案例两个模式均一轮通过；长中文页头原模式尝试 56、54px 后仍溢出，Skill 模式一轮选择 46px 通过。实际截图已查看：未观察到通过极小字号挤过关。文案、节点、素材、动作与绑定未改，人工场景补丁为 0。图片来自既有案例，未重新生图；未调用 TTS/数字人供应商。

据此启用 default_mode=runtime_skill；原 SYSTEM_PROMPT 字节与 legacy_prompt 入口保留为显式内部对照。实验后只迁移运行片段到 config、启用默认和加固来源捕获/检查；**当前实际 Skill system_prompt hash 与三次实测的出站字节完全相同**。原实验源码在本地归档，归档字节匹配冻结起点 hash；后续实验自动捕获源码副本。注册默认和路径改变会产生新 selection_id，不伪称整个注册文件没有变化。

实测摘要已纳入 [evaluation-summary.json](../../../reviews/2026-10-12-s06-runtime-skills/evaluation-summary.json)。本地完整证据：`outputs/s06-runtime-skills-evaluation-2026-10-12/` 的 input/results/http-attempts/source、各轮 request/response/diagnostic/strict-review、final.png。preview.json 指向由真实 Skill arm 的 repaired-scene 原样保存并冻结的 HTML，不是手改设计冒充模型结果。runtime outputs 不提交。

这些是三组固定样本，不能宣称普遍成功率或生产速度提升。工程通过与查看截图不等于用户审美批准、音画同步或整课导出签收。原 Prompt 的失败也不等于 workflow 普遍不可用；此对照检验的是同一 Agent 中策略片段的影响。

## 验证与兼容

现有案例实际已从最初 22 项扩为 24 项（8 个触发、16 个行为）。全部加入标注 facts/expected_route 并执行：只有候选容量修复可取得 runtime_stage，其余路由进入原职责或不适用。它们是结构化事实测试，不声称证明自然语言触发的识别率；原 required/forbidden 描述保留。

首次 loader/出站 Prompt/权限测试 37 项通过；加入评估编排后41项通过；默认启用后的候选/生产/恢复/工作流/快照联合80项通过。迁移 config 与补捕获竞态/删除/无Codex目录的检查后，loader/评估43项通过。最终候选/生产/阶段恢复/工作流/快照/任务联合123项通过；已保存编辑/多模态修复/重建定向31项通过。Ruff、Skill结构、Agent契约文档、Git diff及本次新增文档链接检查通过；各组有重叠，不相加为独立用例数。

覆盖注册版本/合同/路径/hash/缺失/未注册引用、内容改变影响身份、捕获期间 hash 变化阻断、运行文件删除明确失败、两种模式实际出站合同、原文和人工保护不可越权、AB/BA输入一致、失败不择优、只读真实设置预检、原生成快照与未知调用恢复规则。没有迁移或公开请求字段，Web/Agent/MCP/CLI沿用原服务；Skill选择只在发布配置或内部实验设置，用户文字不能注入新策略。
