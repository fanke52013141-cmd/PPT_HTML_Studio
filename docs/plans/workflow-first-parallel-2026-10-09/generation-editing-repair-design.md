# 初稿、可编辑场景与动态修复设计

2026-10-10。以下保留提出方案时的现状与实施验收清单。用户授权1—5后已实施实例编辑、局部修复、时间证据、Prompt/Skill与真实模型验证，当前事实见[编辑与修复交付](deliveries/EDIT-REPAIR.md)，规范见[scene-repair](../../contracts/html-presentation/runtime/visual-v1/scene-repair-0.1.0.md)。下文“当前/尚未实现”是提案时的历史状态，不应作为现行能力说明。本文不替代contracts，不安装Agent框架。

现行来源：[应用生产](../../contracts/html-presentation/runtime/visual-v1/application-production-0.3.0.md)、[场景编辑](../../contracts/html-presentation/runtime/visual-v1/scene-editor-0.1.0.md)、[视觉与生成](../../contracts/html-presentation/framework/08-visual-generation-contract.md)。实测：[E 交付](deliveries/E.md)。

## 1. 已有能力与未完成能力

| 范围 | 事实 |
|---|---|
| 已展示的一页 | 人工准备注册计划，内置生图生成设计和独立主体，现有服务展开场景、共享播放器渲染。不是无人干预的真实规划模型验收 |
| 规划 Prompt | html-plan-0.2.0，返回受限 JSON 计划；服务最多两次生成，第二次追加结构校验诊断。当前没有把上次失败 JSON 显式作为修复输入 |
| 设计与主体 | 完整设计先停点；候选确认后生成独立主体和实际 HTML。设计参考不能覆盖准确文字和关系 |
| 场景编辑 | Web/Agent 读、预览、保存、重开及修订冲突保护已实测。内容、已注册动作、绑定、资产锚点已有入口 |

## 2. 同一份可编辑数据

以结构化 scene、资源清单和时间绑定为作品源。HTML DOM 是渲染结果，PNG/MP4 是衍生产物；不能把浏览器临时 CSS 改动或某帧截图当作已保存修改。

编辑粒度需要在生成前确定：

| 对象 | 目标编辑能力 | 边界 |
|---|---|---|
| 标题、正文、解释语 | 文案、受限字号/字重/行高/对齐、实例位置/尺寸 | 后五类实例能力须补定义与实现，不能写入未知 CSS |
| 卡片与组合 | 容器及登记的标题/正文等公开子目标；整体移动、尺寸与呈现变体 | 内部子目标必须注册，不依赖临时 DOM 选择器 |
| SVG 图标、连线、标注 | 已登记形状/参数、目标关系和锚点 | 不声称任意 path 或新动作已支持 |
| 独立图片 | 按公开能力移动/缩放/裁切、替换或重生成，调整锚点 | 位图内部的水滴、杯壁等不等于独立可编辑对象；需要预先拆层或再生图 |
| 动作 | 登记动作类型、时长、顺序、语块绑定与允许偏移 | 仅支持当前运行能力；新动作先注册，不能让模型注入任意 JS |

“内容必须可编辑”落实为：全部文字/数据/关系拥有可定位的代码对象；图片仅承载声明的独立主体。要求独立控制的部件必须在初稿阶段拆成对象，不能在整页位图上声称可编辑。当前 PPTX 为快照输出，MP4 为视频，不能把 HTML 源可编辑等同于 PPTX 内所有元素原生可编辑。

基础模板与主题提供默认值。新增实例覆盖只作用当前页与当前对象，不通过修改共享模板/主题影响其他课程。需固定基础布局、实例覆盖、动画变换的应用顺序；重新测量文字后再计算依赖几何。

人工与 AI 都使用同一编辑服务、校验与修订机制：人工通过属性面板产生变更；AI 通过修复 Prompt 提议变更。用户拖拽/输入与 AI 不各自维护一套场景。AI 不覆盖用户锁定字段；当前人工覆盖记录仍保留。更细粒度字段锁是待定义能力。

## 3. 固定制作流程：Prompt 与 Skill 共用

1. 校验本页权威内容、可用组件/模板/资产与模型配置；冻结输入版本。
2. 规划 Prompt 生成受注册能力约束的 plan；程序校验内容、槽位、对象和语块映射。
3. 同一 plan 派生完整设计参考任务，实际附入相关组件图与布局；审阅该候选。
4. 复用/生成独立主体，程序展开可编辑 scene 和 binding，使用共享渲染器产生实际 HTML。
5. 运行静态检查、适用时间点/区间检查，展示实际页面和对应截图；视觉验收针对实际输出。
6. 有问题进入局部修复流程；通过后保存新修订并重新检查受影响的输出。

纯代码页遵循现有无新图片需求分支；未绑定真实音频时只作作者时钟预览，明确暂定时间。音频就绪后使用原服务时间轴重新绑定与验收，不创建第二套 TTS 或时钟。

无自主 Agent 时，由后台按上述确定步骤调 Prompt 和工具。使用 Skill 时，将同一流程、可调用接口、字段限制、诊断归因、停止条件写给执行者。Skill 只有被运行环境实际加载并执行才有效，不能仅创建 SKILL.md 就声称模型已经遵循。两种方式复用同一输入输出、渲染器和验收标准。

一致性指注册能力、数据职责、状态和验收规则一致；模型与生图不保证逐像素或逐字节复现。

## 4. 初稿生成的输入输出

### 4.1 模型任务边界

模型选择可用表达结构，填充内容并映射讲稿；不输出自由 HTML/CSS/JS，不承担可由程序展开的最终像素坐标、哈希与绝对音频时间计算。

| 输入 | 用途与来源 |
|---|---|
| 本页准确内容、visual_groups、narration_beats | 确定必须表达的文字/数据/关系，限定语块身份；只提供本页所需内容 |
| 可用模板/组件、节点字段、动作与资源目录 | 仅列当前生产可执行能力、版本、容量；参考图覆盖面不等于运行能力 |
| 设计约束 | 默认黑灰白、画布比例、字幕区、资产预算、已有资产及必须保留项 |
| 相关视觉参考 | 独立设计图任务实际附组件 PNG；与规划任务分工，不把目录全部图片塞进每次调用 |

现有规划输出字段：`slide_id`、`templateRef`、`slots`、`objects`、`beats`、`assets`。沿用当前 normalizer；对象首次建立后身份稳定，后续修复不得重新编号。布局由模板引用展开。若新增实例覆盖，先扩展合法作者格式和消费方，再把允许字段放进 Prompt。

初稿流水线的交付不是模型一句“完成”：实际 scene、资源清单、binding、可打开的 HTML、代表截图、机器校验报告与待审状态。scene 和资源由保存服务管理；截图、审阅结果、版本号和指纹由程序生成，模型不能自签通过。

### 4.2 结构错误重试

这是 JSON/计划结构纠错，区别于画面修复。建议补齐输入为：同一原始任务、上次不合法计划、精确诊断和相应合法字段定义。输出完整的新计划，继续沿用既有一次结构修复上限。此时还没有已批准作品可被覆盖；两次都失败则报告，不放宽 validator 或临时手工替模型完成后记为自动成功。

## 5. 二次修复的输入输出

### 5.1 修复请求

请求先明确修改类别：文案/排版、动态时序、图片主体或结构重规划。主体再生图沿用独立资产流程；三卡改四卡等结构变化进入新规划候选，不能伪装成编辑一个已锁定槽位。

| 输入 | 必要内容 |
|---|---|
| 当前候选与版本 | 服务保存的 scene/binding/resources 快照；系统保存 revision/hash，校验期间冻结它们 |
| 用户目标或诊断 | 如“第三张卡片正文太挤”“第4秒标签被挡住”；已有选中对象 ID 优先使用 |
| 可编辑目标和允许操作 | 公开目标、合法字段、单位、范围、当前值、人工保护项；不能要求模型猜 DOM 或未暴露 ID |
| 动态上下文 | 时间戳/时间区间、作者或音频时钟标记、当前动作/语块绑定；从实际播放器取帧 |
| 视觉与测量证据 | 带时间的实际截图、对象包围框、文字溢出/重叠诊断；美感修复附相关设计参考 |
| 修改约束 | 本次允许变更哪些对象和字段、必须保留哪些内容；只扩大到真实关联依赖 |

没有选中对象时，可让视觉模型从截图提出对象候选，但只能引用已提供 ID；歧义影响内容或范围时需明确目标。固定检测优先于视觉猜测。最终帧不代表动画全过程。

### 5.2 修复输出（拟议，不是现有可调用格式）

输出仅为允许操作的列表，或明确的 `needs_input` / `unsupported` 结果；不重新生成整页。服务把模型结果装入冻结 revision、来源、请求身份的命令记录，再校验和应用。不要让模型生成系统已知哈希或猜测版本号。

下例演示未来字段含义，实施前必须冻结具体 JSON Schema；当前 API 不能直接提交此例：

```json
{
  "status": "candidate",
  "operations": [
    {
      "targetId": "headline",
      "kind": "set_text_style",
      "values": {"fontSizePx": 30}
    },
    {
      "targetId": "headline",
      "kind": "set_instance_offset",
      "values": {"xPx": 20, "yPx": 0}
    }
  ]
}
```

`fontSizePx` 是固定画布上的逻辑像素；实例 offset 是相对注册槽位原点的绝对覆盖值，不是“每次再累加20”。操作重复执行须保持同一结果。上述操作影响对象整个可见生命周期；只改某时段必须使用另行登记的动态操作。组合内部文字只能引用公开子目标，不能给整个卡片随意添加 fontSize。

模型可附简短修改理由供审阅，但截图、复验时间集合、依赖范围、版本和成功状态由程序计算。不能只相信模型声称“没有碰其他对象”。

### 5.3 应用结果

服务先在候选副本中执行，产出变更明细、前后快照、机器检查与视觉待审结果。通过授权范围内的校验后才允许保存；失败保持原场景和用户草稿。当前 full-scene PUT 仍是现有接口，新补丁服务可以在校验合并后复用它，不建立绕过人工保护的第二写入口。

局部修复建议最多两轮自动尝试，超限返回具体未解决项；不得无限生成、扩大修改范围或自行宣布审美通过。这是待实现策略，不能混同已存在的规划一次重试。常规已授权修改不要求逐操作重复批准，最终视觉签收按现有规则。

## 6. 动态内容如何编辑

给定场景源、资源、时间轴与时间 t，渲染器得到该帧。编辑基础属性与编辑时间规则必须区分：

| 用户指令 | 应修改的源 | 必须复查 |
|---|---|---|
| 标题整体向右移20 | 标题实例基础偏移，新增待实现能力 | 整个可见区间、关联目标和安全区 |
| 标题字号从34改30 | 标题实例文字样式，新增待实现能力 | 字体就绪后重新测量换行、容器高度和相关引线 |
| 标题稍晚出现 | 现有 enter 对应语块绑定/允许时间偏移 | 语音同步、完整动作区间、其他内容阅读窗口 |
| 第4秒卡片挡住标签 | 获取该时刻及前后帧，识别遮挡原因；修改基础布局或登记的时序操作 | 不止第4秒，检查对象交会/进入/退出阶段 |
| 杯子换一种样子 | 生成新主体候选并重验锚点 | 身份/透明边缘、比例、指向位置、出现过程 |

编辑器交互建议：播放时选中对象→暂停在所选时刻→选择“整体属性”或“动作/时序”→预览候选→从问题前播放到问题后→保存可撤销修订。暂停与选中不改变时间轴。默认位置/字号修改作用整个可见期；不能把所见动画偏移直接存成新的基础坐标，否则会叠加两次。

AI 使用同样的命令。比如“第4秒把标签移开”不能仅修改那一帧 DOM；应先明确是让标签始终移开，还是只在该阶段移动。后者若当前动作词汇不支持，返回能力缺口，不伪造新的关键帧类型。

普通排版修复不改变旁白和已确认音频；若用户要求改变讲述内容，则先更新权威内容/讲稿，沿用现有音频输入指纹和下游失效规则。纯字幕/标题位置问题不能默默触发整页 TTS。

## 7. 严格验收与防止只看终态

1. **内容**：必需文字、数字、标签和关系完整；未授权的语义变化拒绝，图片文字不反写。
2. **可编辑**：对象/公开子目标可寻址；修改保存、关闭重开、重复保存及撤销/恢复策略可验证。当前会话 undo 不等于持久版本恢复，后者需实现。
3. **几何**：字号/位置合法、文字无溢出、字幕区合规、关系锚点仍命中正确对象。重新计算所有受影响目标，不依赖截图手写坐标。
4. **动态**：动作起点前/起点/结束/结束后与中间样本，相关语块窗口和可能交会时刻；可解析运动使用边界/扫过范围分析。取若干帧不能证明全过程无碰撞，高风险区间需要更密取帧或逐帧渲染。
5. **一致性**：暂停、seek、倒放与导出在同一时刻消费同一场景/资源/时钟；实际音频就绪后再验，暂定时间不记为音画同步通过。
6. **局部性**：检查数据 diff，禁止改保护字段；未授权对象的作者值不变。允许的依赖几何变化需列出并检查，不能只用整图像素相同判断。
7. **失败保护**：409不覆盖新修订；不合法补丁不落盘；素材/渲染失败保留前一有效版本；产物与视觉批准的失效沿用现有机制。
8. **美感**：实际 HTML 与设计并列，审阅字阶、留白、卡片、素材融合和动态阅读感。技术通过与审美认可分开记录。

## 8. 实施次序和可验收交付

| 顺序 | 交付 | 完成条件 |
|---|---|---|
| 1 | 实例文字样式/布局覆盖定义与实现 | 逐对象字号、位置通过同一Web/Agent接口预览/保存/重开；包含限制、依赖、单位和兼容规则；旧场景不变 |
| 2 | 最小修复命令与候选流程 | 人工与AI共用；冻结输入修订、限制目标字段、实际diff、无效/过期拒绝、失败保留原页 |
| 3 | 动态修复证据 | 带时间截图、区间取帧、绑定检查、依赖重验；至少一次中途遮挡修复和一次字号引起换行的修复 |
| 4 | 初稿/修复 Prompt 与生产 Skill | 两份任务边界清晰的Prompt；统一工具步骤；只声明已经实现的能力，写明资源与失败分流；实际运行环境加载验证 |
| 5 | 真实模型闭环 | 配置文字模型后，由同一API完成规划和修复；保留原输出与每次修复证据，不人工补写后算自动成功 |
| 6 | 跨内容验收 | 至少三种注册布局、多种内容密度；每页实际HTML、静态与适用动态检查，记录原始成功率、修复轮次与未解决项；样本通过不声称无限内容泛化 |

框架选择不作为前四项的前置依赖。先让结构化输入、编辑命令和验证可独立调用；后台确定流程与将来自主Agent都调用这些能力。Skill不承担本应由代码执行的校验，不替代场景源或资源契约。
