# 制作流程、职责、人工确认与返工

2026-10-09。配套 [总计划](README.md)。以下区分线上 `main` 已发布能力、本地尚未发布的流程增量和拟补机制；拟补项由 A 线同步所属契约后实现，不把文字表格当作已经存在的界面。

## 1. 两条相连的流程

**公共库建设：** 已发布标准组件库 1.0 → 复核实际样板和适用边界 → 选择相关分类图、独立配色与统一风格 → 新内容构思和分工 → 多参考设计 → 素材与实际 HTML 对照 → 第二内容复用 → 按缺口扩充组件并验证开源动效方案。

**每份作品制作：** 项目设定 → 内容与讲稿 → 画面规划 → 画面设计与生图 → 旁白与音频 → 动画编排 → 可选数字人 → 审阅与输出。

公共库审阅形成可复用范围；每页仍要核对当前内容和最终画面。新构图或超容量进入探索分支，已有合格模板和资产可直接复用，减少重复生成。

## 2. 每一步谁做、看什么、何时确认

表中“人”可以都是同一位项目负责人；AI 是提出候选和执行约束内任务的助手，系统负责版本、校验、保存和执行。确认必须针对可见产物及版本。

| 阶段 | 人负责 | AI 负责 | 系统负责 | 产物与确认 | 当前实现边界 |
| --- | --- | --- | --- | --- | --- |
| 项目设定 | 确定受众、解释目标、风格方向、16:9、数字人开关 | 整理需求及缺项 | 保存当前创作包、风格版本和配置；检查服务可用性 | 项目简报；方向改变时复核 | 配置已有；新增简报冻结证据为拟补 |
| 1 内容与讲稿 | 核对事实、知识完整性、措辞和讲解目标 | 整理分页、上屏信息与旁白初稿，提示需要来源的内容 | 保存内容版本、稳定页面/语块身份 | 每页目标、上屏文字、旁白、来源 | 内容编辑已有；与第2步合并的内容确认记录拟补 |
| 2 画面规划 | 检查画面能否回答讲稿的问题 | 选择表达方式，列出对象、关系、过程状态及代码/图片分工 | 校验当前允许能力、对象身份、素材预算、内容容量；不可执行时诊断 | 分镜清单和初/中/终态说明；建议按一组页面集中确认内容与规划 | 注册模板与规划已有；自由构思先为候选，采用后映射/注册，不执行任意代码 |
| 3a 设计参考 | 新方向时审构图、美感和分工 | 结合代码美术参考、完整可用能力及风格图提出设计 | 实际附带参考；记录模型、参数、来源、哈希；保存候选 | 可见设计方案；有新配图的路径在设计批准后继续 | 已有 design_review 停点和 design 范围批准；纯代码成熟页直接看实际预览 |
| 3b 素材准备 | 选中或替换素材，检查边缘、轮廓、锚点与可动对象粒度 | 根据需求生成必要独立插画或提出复用 | 复用资源；检查透明度、尺寸、来源和锚点；标明提取或重绘 | 独立素材及深浅底预览；常规检查可并入3c审阅，重大差异单独退回 | 已有生成/缓存/质量校验；完整锁定和局部纠偏能力需逐项核实 |
| 3c 实际 HTML | 对照参考审实际画面，确认阅读顺序、知识表达和美感 | 辅助列出差异及修正建议 | 用注册代码组装，实际测量字体/边界并提供截图 | 实际可执行页面与差异清单；必须独立视觉批准 | 已有 visual 批准；设计图批准不能代替此处 |
| 4 旁白与音频 | 试听，确认发音、断句、数字和内容 | 可辅助读音/分段建议 | 复用已有 TTS/导入、字幕和时间对齐，保存确认指纹 | 当前讲稿对应的真实音频和字幕；必须确认音频 | 已有音频确认；流程汇总与场景依赖的耦合需核验 |
| 5 动画编排 | 观看有声预览，调整和确认节奏、阅读窗口与遮挡 | 根据语块与对象安排当前支持的动作 | 绑定确认时间、确定性求值、保存手动偏移/冲突，保护人工编辑 | 有声单页/片段、动作清单、关键状态；独立节奏批准 | 已有 rhythm 批准及对象编辑；新增动作需定义和实现 |
| 6 数字人讲解 | 启用时审实际同步、位置、遮挡；关闭则跳过 | 可建议预留区域 | 使用既有生成/合成服务，检查实际视频新鲜度 | 实际合成预览；建议把人工检查并入最终审阅 | 开关/视频状态已有；独立人工记录是否新增由 A 定义，真实合成仍待验 |
| 7 审阅与输出 | 审完整课程及交付文件 | 辅助检查遗漏和差异 | 按目标格式检查当前证据，导出、探测、登记和下载 | 完整视频及明确类型的 PPTX；最终验收 | 视频/快照已有；完整课程与实际 PPTX 打开仍须执行 |

讲稿稳定时可以提前做音频；草稿动作可以预览。精细联调使用当前有效视觉和确认音频。页面浏览允许回看，进入下一页面与执行下一生产操作分开判断。

## 3. 人工确认应如何组织

建议集中为以下审阅包，避免每个技术子任务都弹确认：

| 确认点 | 人看什么 | 频率 | 系统应保存 |
| --- | --- | --- | --- |
| H0 代码美术参考 | 真实细节、局部组合、完整样页及适用边界 | 新参考包或影响美感的修订 | 采用版本、范围、意见；当前为资产审阅记录，不冒充运行批准 |
| H1 内容与规划 | 页面目标、上屏内容、旁白、表达关系和素材需求 | 一组页面可一起审；语义改变重审 | 拟补内容/规划版本与逐页结论 |
| H2 设计选择 | 构图提案、图片/代码分工、支持范围 | 新设计/新素材路径；成熟纯代码页无需额外生图停点 | 当前 design 指纹批准或修改意见 |
| H3 实际画面 | 最终 HTML 与参考对照、实际素材质量 | 每页，可提供多页审阅界面 | 每页当前 visual 批准；不批准尚未看的页面 |
| H4 音频 | 实际旁白、字幕、读音和断句 | 按相关页/片段 | 现有音频确认及指纹 |
| H5 有声节奏 | 动作时机、可读时间、中间状态和遮挡 | 按相关页/片段 | 每页当前 rhythm 指纹批准 |
| H6 整段交付 | 页间衔接、数字人（启用时）、真实输出文件 | 每个最终版本 | 拟补交付审阅清单；输出检测和用户意见分开 |

H1/H6 的具体持久模型、多页审阅 UI、退回意见统一字段均为本计划拟补，不声称当前已经存在。可以集中展示、一次审多页；保存时应绑定逐页范围和版本。A 需明确批量确认的逐项返回与部分冲突处理，不能用项目总开关覆盖过期页面。

## 4. 不同角色之间传递什么

1. 内容交给规划：稳定 slideId/beatId、文字、知识目标、来源和风格支持集。
2. 规划交给设计：对象身份、关系、初/中/终态、代码/图片职责、可用组件与参考包。能力不支持时交回具体缺口。
3. 设计交给制作：采用提案、差异处理决定、组件/主题版本、精确执行布局及素材要求。探索阶段保留构图自由；执行阶段必须落到受约束数据。
4. 素材交给渲染：资源身份、字节哈希、透明边界、可见尺寸、锚点、来源及控制粒度。
5. 音频交给动效：已确认的语块 ID、时间范围和指纹；不另造一套对齐结果。
6. 渲染交给输出：冻结场景、字体、资源、主题、动作与时间、批准范围、同一运行时。

上述概念复用现有格式。A 在 G0 列出实际字段与文件映射；缺项先补定义，其他线不能自行发明同名不同义字段。

## 5. 状态与失败恢复

分别呈现执行状态、审阅状态、输入新鲜度。建议用户能读到：未准备、制作中、待审阅、已通过、需修改、已过期、失败/中断、不适用。具体枚举及兼容映射由 A 定义，不能直接把文字替换进旧数据库。

每一步都显示“当前产物、还缺什么、下一步动作、失败原因、可复用什么”。状态查看无生成副作用；读取状态不调用模型，不把历史成功当当前通过。

| 场景 | 处理与恢复 |
| --- | --- |
| 模型未配置/不可达 | 保留草稿和旧有效产物，指向项目当前连接；修复后重提受影响任务 |
| 超时但远端可能仍执行 | 查任务/候选状态及已有结果，再决定重试；不把本地取消当远端撤回 |
| 设计或视觉需修改 | 保存对象级意见、锁定项和原版本，生成新候选；在对应阶段重新审阅 |
| 缺素材/质量失败 | 标明具体资源，允许复用/替换/局部再生成；不重做无关页和有效音频 |
| 版本冲突 | 保留候选和用户编辑，说明冲突对象/版本；重新加载后明确合并或重提 |
| 服务重启/任务中断 | 使用已有 interrupted 事实，显式续作或重提，保留尝试记录 |
| 导出失败 | 保留已批准输入，显示编码/资源/权限等具体问题；修复后重试输出 |
| 数字人关闭 | 明确 skipped，不阻塞作品；启用但缺有效视频不能显示完成 |

## 6. 最小返工矩阵

| 修改 | 应重验/重做 | 应尽量复用 |
| --- | --- | --- |
| 讲稿语义/文字 | 内容规划、相关音频/对齐、节奏、数字人和输出 | 未受影响的画面与素材 |
| 上屏文字/数字 | 内容准确性、容量、画面与输出；关系变化再查规划 | 未变化的旁白和已确认音频 |
| 字体/主题/组件 | 相关参考/页面、布局、视觉及涉及动作的关键状态 | 讲稿与有效音频 |
| 构图/对象身份 | 几何、目标关系、视觉、动作冲突和节奏 | 无关资源和音频；同身份手工编辑 |
| 一张素材/锚点 | 该资源的相关页、几何、视觉与动作/输出 | 无关页、素材、音频 |
| 动作/手工偏移 | 节奏、中间状态、合成和输出；当前视觉批准按实际指纹规则处理 | 已确认音频，无需重复 TTS |
| 页顺序 | 课程顺序、整体时间、合成、整段审阅和输出 | 各页内容及有效独立产物 |
| 无变化保存 | 不生成、不失效 | 全部已有有效记录 |

该矩阵说明目标影响范围；不能绕过当前视觉批准包含动作/binding 的指纹校验。如需缩小批准失效范围，A 必须定义并实现证据分层后迁移，不能仅改 UI 提示。
