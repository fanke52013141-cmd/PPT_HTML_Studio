2026-10-09。先读 [总计划](README.md)和[制作流程](workflow.md)。本轮只制定计划，以下实现任务均未启动。

## 1. 共同输入与交付协议

开发目录统一为 `D:\Program Files (x86)\PPT_HTML_Studio`。每个对话先读根 AGENTS.md、现行契约入口、[视觉参考库路线](../html-backend-development/visual-reference-roadmap-2026-10-09.md)、[标准库1.0](../../../html_engine/reference-library/STANDARD-LIBRARY.md)、本包和所属模块契约。已有工作区含未提交内容；线上 main 已有较新的标准库提交，开始开发前需核对线上与本地能力，不把 HEAD 当完整源码，不清理、不回滚、不整体暂存。

A 先在本目录维护 `interface-baseline.md`、`ownership.json`、`integration-status.md`（拟新增）。其余线只写各自的 `deliveries/B.md` 等（拟新增）。A 读取交付记录安排集成；共享文件接入完成前，各线用冻结数据做独立验证，不能将局部通过登记为集成通过。

每次小交付的固定内容：

1. 基线 HEAD、实际工作区相关文件哈希、接口版本。
2. 实际改动文件、文件所有者、受影响 HPS 和原 AC 编号。
3. 可直接查看的结果及准确复现命令。
4. 测试命令、退出码、证据路径；人工/真实服务状态分别记录。
5. 请求 A 接线的明确位置、参数、迁移和兼容影响。
6. 未完成项、待审事项及下一步。暂停依赖实现时可继续专属模块与边界用例。

## 3. A：流程、状态与集成

**目标：** 让七步状态、人工确认、任务、批准和输出形成一致闭环，提供其他线可依赖的接口。

**实施顺序：**

1. A01 记录源码与未提交基线，登记所有权，整理文档历史/当前状态冲突；映射本包 WF-01—07 到现有 AC。
2. A02 为七步列出事实来源、状态转换、执行前置与审阅范围；定义拟补 H1/H6 和错误/退回呈现。页面可浏览不等于任务可执行。
3. A03 定位并修本地现有测试缓存场景：分别覆盖 cache-hit 保留人工动作、合法输入变化后的 cache-miss 身份冲突；确认实际触发了新计划。
4. A04 统一前后端状态；专项验证音频先完成、无场景、坏绑定、过期批准、数字人开关、空项目和不同导出目标。
5. A05 冻结接口和兼容；核查未通过风格的试制/正式范围以及不同页并发冲突处理。
6. A06 逐项合入 B—F 的公共接线、注册、版本和生成产物；维护当前账本。

**独占：** `html_creation_workflow.py`、`html_visual_review_service.py`、`html_visual_store.py`、`html_input_manifest.py`、`html_workflow_jobs.py`、`html_task_store.py`、流程相关 routes；`static/flow.js`、`workflow_state.js`、`workspace_navigation.js`、`event_bindings.js`、`index.html`；下文共享区及流程专项测试。

**依赖：** 可立即开始；其他线提供接口需求。生产服务内部改动通过 E，动作内部改动通过 C，避免同时编辑。

**验收：** WF-01—05 有实际重现/结论；纯代码和素材辅助页两条路径各有停点和继续证据；无变化保存无生成；输入改变准确失效；旧任务不覆盖新编辑；Web/Agent 操作与状态一致。关联 AC08/09/17/18/20。

**启动说明：**

## 4. B：代码美术样板与标准组件

**目标：** 复核已发布标准组件库 1.0 的实际代码美感、使用范围和真实内容表现，再按缺口补生产组件。

**实施顺序：**

1. B01 以标准库1.0的24页、32组件、16变体、28静态效果、18组合作为固定起点；核对 ID、源码、截图、字体和适用范围。
2. B02 选真实课程内容和既有素材做少量完整代码样页，检查精致细节、局部组合及整体阅读；标清代码/图片职责与容量。
3. B03 向用户展示实际 HTML 与截图，记录具体反馈、采用修订和范围；未通过时修现有公共外观源并重新导出。
4. B04 第二个内容主题复用及长标题/长正文/密集标签边界；核对三套配色与统一风格输入。
5. B05 通过 G2 后按真实缺口扩组件，优先将标准库映射到生产 scene；关系与数据固定示例不能直接当通用数据引擎。新变体复用主题参数与公共能力。

**独占：** A 登记的 `html_engine/reference-library/` 中标准库源码、样页和专属验证；拟新增生产组件适配模块与测试。`html_engine/visual/` 的公共 renderer/schema 仍由 A 接入。

**依赖：** B01—B03 可与 G0 并行，直接复用线上已发布标准库。生产扩充依赖接口冻结、真实内容审阅与跨内容复用。审阅未完成不阻塞其他线做状态修复或测试准备。

**验收：** 源码/截图同版本；真实中文排版、层级、留白和图文协调；一套组件换内容不复制业务分支；容量超限明确诊断；主题切换不改语义与身份。关联 AC02/03/04 和代码美术资产规范。

**启动说明：**

> 在唯一开发目录执行本计划 B 线。以线上标准组件库1.0和视觉参考库路线为基线，复核24页中性分类图、三套独立配色和统一风格描述。用真实内容制作少量完整样页，展示实际 HTML 获取审阅，再验证第二个主题与容量边界。只有发现真实表达缺口后才扩组件。只写登记给 B 的参考库和专属适配文件；公共 renderer/compiler/schema 交 A 接线。当前静态效果和实验演示不等于生产 scene 支持。

## 5. C：动效库与音频编排

**目标：** 保证动作可复用、可编辑、可任意定位时间，并验证成熟开源方案能否承载后续动效。

**实施顺序：**

1. C01 盘点已支持 enter/exit/emphasize、批注描线、语块绑定与人工偏移；先补时间、目标和冲突的证据。
2. C02 与 A 定义动作槽位、对象身份和兼容。当前按 objectId:action 索引绑定；需要同对象重复同类动作时先定义版本扩展，不能覆盖旧项。
3. C03 优先验证已有动作的速度、停留和组合；用固定短场景对 HyperFrames、Remotion 或其他成熟候选做许可证、逐帧求值、预览/输出与接入成本对照。按真实课程需要选择适配，不预设自建完整动效库。
4. C04 编辑器只暴露已实现动作，提供可控参数和错误；人工覆盖在重规划后保留，冲突可恢复。
5. C05 同场景顺播/乱序 seek/倒退/重播验证，交 F 比较实际导出帧；有声短片交用户审节奏。

**独占：** `html_audio_binder.py`、`html_audio_preview_service.py`、`html_motion_service.py`、`html_action_editing.py`、`static/html_motion_editor.js/.css`、独立开源对照实验和专属测试。采用方案确定后才新增适配模块；A 对现有失败用例的首轮修订结束后再移交该测试文件给 C。

**依赖：** 盘点可立即开展；实现需 G0 对象/时间/绑定接口；正式动效美感需采用的参考方向。不等待每个组件完成，可用冻结的最小文字/图形 fixture。

**验收：** 同环境同输入同 t 一致；暂停/跳转不累积状态；有效旁白时间是绑定依据；只改动作不触发 TTS；删目标/改身份不静默覆盖；过期音频不能被确认节奏。关联 AC05/09/11/12/13。

**启动说明：**

> 执行本计划 C 线。先核实已有动作、语块绑定和人工覆盖，再在固定短场景中比较成熟开源方案的许可证、逐帧确定性和导出一致性。等 A 发布对象/时间/绑定接口后，按真实课程需求做最小适配。每种动作必须可由指定时间直接求值，覆盖乱序 seek、暂停重播、冲突保护和不重复 TTS。编辑器仅暴露已验证能力；公共 Schema/renderer 和 Agent 增量交 A。选型实验不阻塞流程闭环。

## 8. F：输出与端到端验收

**实施顺序：**

1. F01 准备隔离测试项目、纯代码页/素材页及五页课程；冻结内容、模型配置标识、字体和资源；保留原 image 回归样本。

- 现行契约入口、CHANGELOG、contract-index、任务账本以及跨线验收文件 `checks/test_html_workflow_acceptance.py`。
- `generated/`、`preview/player.js`、`preview/data.js` 等共享生成物，只从源代码统一构建。

共享区不是所有开发都要等 A 写代码：B/C/D/E/F 自己实现专属模块、数据和测试，提交明确接线片段；A 只负责共同入口和集成。需要移交文件时先更新 ownership，移交前所有者停止编辑该文件。

## 10. 开工和收尾节奏

第一批开始 A、B；D/F 可以先盘点与准备，C/E 先核对接口需求。G0 小交付完成后，C/E 开始专属实现；G2 通过后 B/C/D/E 扩充生产能力。每完成一个可验证增量就交付，无需等某个对话整包结束。

每轮集成由 A 固定版本，F 运行相应回归，用户只审实际需要人判断的视觉/音频/节奏产物。新问题回到原负责人；接口变更影响的线明确收到版本记录。最终没有未解决的必需失败项，才能将对应范围标为完成。
