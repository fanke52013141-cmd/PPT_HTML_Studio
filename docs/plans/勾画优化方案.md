# 勾画优化方案

> 文档定位：后续开发重点方案，用于产品、交互、前后端、AI 与渲染开发协作。
> 状态：方案阶段，尚未实现。本文中的新增模块、字段、接口与参数为建议设计，不代表当前系统已有能力。
> 制定日期：2026-09-27。

> 2026-09-27 决策更新：勾画标注采用独立可见模块，位于旁白与音频之后、数字人/作品输出之前，作为可选步骤。具体开发、接口、验证与回归要求见 [勾画标注模块开发与验收交接](勾画标注模块开发与验收交接.md)。新文档落实独立入口决定，其他产品目标继续适用。

## 1. 目标与已确认方向

在现有 PPT 风格讲解视频中增加手写圈注、划线、荧光笔等效果，让强调动作跟随讲解自然发生，并允许用户检查和修改 AI 的结果。

核心体验：**AI 自动识别和规划 → 可视化展示标注块及关联 → 人工修改 → 随音频播放 → 一致地导出视频。**

已确认方向：

- AI 可以自动推荐重点、匹配画面位置和讲稿；用户必须能够修改。
- 标注应可视化显示“圈在哪里”和“关联讲稿中的哪个字词”，交互沿用语块的选择习惯。
- 标注块与语块分别保存：一个语块可以没有标注，也可以包含多条标注。
- 自动定位是默认路径；人工操作用于创作、纠错和处理歧义，不应要求每条标注手工填坐标。
- 保留现有 TTS 接入方式；供应商只返回总时长时，通过音频后处理补充时间定位。
- 重点规划优先复用现有大模型配置，不要求用户新增一个 AI 供应商账号。
- OCR 作为独立、可替换的定位能力；具体引擎与部署方式通过样本评测确定。

本方案的“真人感”主要来自正确的强调对象、自然的动作时机、落笔轨迹及节奏。第一阶段不以手部形象、复杂笔顺或大量装饰为目标。

## 2. 现有基础与需要补齐的能力

当前系统具有页面图片、AI Mask 语义分组、演讲稿语块、音频时间轴与 Remotion 动画渲染链路。

| 已有基础 | 可以复用的部分 | 需要补齐的部分 |
| --- | --- | --- |
| AI Mask 与语义区域 | 页面区域、对象归属、讲稿语块关联 | 可选择的文字定位层与局部字符范围 |
| 讲稿与音频处理 | TTS 文本、供应商句级时间戳、总时长与暂停信息 | 实际音频的字词对齐与可靠程度判断 |
| 动画时间轴绑定 | 语块与画面显现事件的关联 | 批注的起笔、完成、保留和退出事件 |
| Remotion 渲染 | 逐帧动画、透明度、变换与导出 | 独立的手写批注层与路径绘制 |
| Mask 编辑工作区 | 页面选择、画布操作、语块交互经验 | 标注块编辑、讲稿字词选择与双向高亮 |

参考实现位置：

- `narration_audio_service.py`：`rewrite_audio_timeline_by_beats` 保留供应商句级时间戳；缺少相应时间戳时，按文本权重及暂停预算分配时间。后者不能作为精确逐字时间的依据。
- `ai_mask_semantic_matcher.py`：语义对象与区域边界可用于缩小文字匹配范围，不能直接视为可靠的字符框。
- `scripts/bind_reveal_timeline.py`：将显现事件绑定到讲稿片段或音频片段。
- `scripts/remotion/src/Video.tsx`：现有逐帧渲染入口。

开发前仍须复核上述模块的实际版本与边界；本方案不要求把新增逻辑堆入已有大型模块。

## 3. 三种关联与标注块定义

每条标注块至少包含三个独立概念：

1. **画面目标**：要强调哪个文字范围、图表节点或区域。
2. **讲稿锚点**：关联哪一段讲稿中的哪一次字词出现。
3. **播放事件**：根据最终音频，什么时候开始画、画多久、保留多久。

示例：

| 内容 | 值 |
| --- | --- |
| 画面文字 | 报名截止：9月30日 |
| 标注目标 | 9月30日 |
| 讲稿 | 这里特别注意，报名时间到九月三十日截止。 |
| 触发短语 | 九月三十日 |
| 样式 | 手写椭圆圈 |
| 播放 | 对齐到该短语的发音起点附近，绘制后保留至本段结束 |

画面文字、原始讲稿和实际发音文本可能不同，必须保存它们之间的映射，不能依赖完全相同的字符串。

标注不得只保存一个绝对坐标和一个秒数，否则换图、改稿或重生成音频后很容易失效。

## 4. 自动定位方案与 OCR 分工

### 4.1 推荐组合

| 能力 | 责任 |
| --- | --- |
| OCR／文字定位引擎 | 输出画面真实文字、阅读顺序、文字行及可用的字词边界 |
| 现有多模态 AI | 理解版式、语义区域、图表对象及讲稿与画面的关系 |
| 批注规划 AI | 选择值得强调的内容、建议样式、引用候选目标 |
| 确定性程序 | 计算路径、变换坐标、验证目标引用、检查越界和遮挡 |
| 用户 | 修正识别、替换目标、调整样式、关联和播放时机 |

可以先实现“AI 区域标注＋人工修正”进行体验验证；面向具体几个字的可靠自动定位，应增加专门的文字定位模块。

新增模块不等于必须新增云服务。支持本地 OCR 与外部 OCR 适配器，具体选择根据识别效果、安装体积、CPU/GPU 资源、耗时、成本与图片外发要求评估。第一版只接入验证通过的一种实现，接口保留替换能力。

### 4.2 页面文字定位层

页面识别后保存：

- 页面、原图尺寸、图片内容哈希与识别版本。
- 区域 ID、文本行 ID、阅读顺序和语义区域关联。
- 识别原文、用户修正后的文本、识别可靠程度。
- 可用的字符／字词范围、矩形或四边形及基线方向。
- 定位粒度：区域、行、词、字；不能把行级结果标成字符级结果。
- 局部识别裁切、缩放、旋转到原图的坐标变换。

坐标统一转换到原始页面坐标系；展示时再应用画布缩放、留白、平移等变换。可额外保存归一化坐标，原图尺寸和版本始终保留。

### 4.3 自动定位步骤

1. 用已有语块／语义区域映射确定候选区域。
2. 读取页面文字定位层；必要时对候选区域进行高分辨率局部识别。
3. 对重点短语进行原文、规范化文本和语义匹配。
4. 通过所属卡片、邻近文字、阅读顺序及上下文消除重复词歧义。
5. 将选中文字范围映射为一个或多个几何范围。
6. 按样式生成留白、基线偏移和绘制路径。
7. 检查越界、相邻文字误圈、遮挡及目标是否在播放时可见。
8. 保存候选、选择依据及待确认原因。

### 4.4 失败与特殊情况

| 情况 | 行为 |
| --- | --- |
| 同词多次出现 | 展示候选并结合语块定位；仍不确定时要求点选，不静默选择第一处 |
| 目标跨行 | 按行分成多笔横线；圈注改为分行圈或侧括号，预览中展示 |
| 只有文本行边界 | 支持整行强调；不得以平均分字作为可靠的字符定位 |
| 倾斜文字 | 使用文字方向及四边形生成路径 |
| 讲稿关键词不在图上 | 尝试匹配对应图形或区域；无法匹配时不生成精确字词圈注 |
| OCR 读错但图片正确 | 用户修正识别文本；字符数量变化时重新定位局部范围 |
| 图片文字本身错误 | 提示回到图片修改；修改识别文本不会改变原图 |
| 无可识别文字 | 允许区域批注和自由手绘 |
| 图片替换或布局变化 | 旧定位失效，重新匹配；有歧义的人工结果转待确认 |

长期可将关键文字改为系统排版，并保留文字布局信息；背景和插图继续由图片模型生成。该方向不作为第一阶段的前置条件。

## 5. 讲稿重点规划

### 5.1 是否需要新增 AI

需要新增“批注规划任务”，优先复用已有大模型及供应商配置。它与 OCR 分工不同：OCR 找字，规划任务判断讲解意图与重点。

规划必须同时参考讲稿和实际页面候选，避免选出画面不存在的词。对于已有语义关联足够可靠的页面，可先使用结构化文字和区域数据；只有需要视觉判断时再提供相关图片。

### 5.2 输入、输出及验证

输入：当前页讲稿语块、实际文字与区域候选、已有映射、用户强调程度、样式白名单、已锁定的人工标注。

输出：重点讲稿片段、目标候选引用、建议样式、触发短语、简短理由、需要用户确认的歧义。标注 ID、最终坐标、时间和路径由程序生成。

程序必须校验引用确实存在、讲稿范围有效、样式允许、数量限制合理、目标可见。可靠程度综合匹配证据计算，不能只使用模型自报分数。

### 5.3 强调策略

- 克制：优先选择每页最重要的一到两个位置。
- 教学：依讲解顺序强调概念、条件、日期、数字和结论。
- 精讲：允许更密集的批注，但限制同一时刻的动作数量和累积遮挡。
- 重点判断遵循用户设置；不能每个语块强制生成一条标注。
- 勾号、叉号、删除线具有明确判断含义，仅在讲稿明确表达或用户主动选择时使用。

AI 生成的是可编辑草稿。重新规划默认保留人工修改和锁定项；“替换本页全部标注”作为显式操作并支持撤销。

实际编写或修改生产 Prompt 前，按仓库要求使用 `.agents/skills/optimize-prompts/SKILL.md`，同时检查输入、输出解析、降级和编辑器展示。

## 6. 音频时间定位

### 6.1 总时长的限制

只有总时长不能反推出准确的字词时间。但系统拥有生成后的音频和讲稿，可以增加音频后处理，不必先替换 TTS 服务。

| 优先顺序 | 方式 | 使用约束 |
| --- | --- | --- |
| 1 | 供应商字词时间戳 | 校验文本匹配、时间顺序、范围与音频版本 |
| 2 | 实际音频＋已知讲稿强制对齐 | 主要补充方案；中文、数字、英文及特殊读法需实测 |
| 3 | ASR 辅助匹配讲稿 | 用于发现漏读、改读或文本不一致，不应擅自覆盖用户讲稿 |
| 4 | 可靠的句级时间 | 降级为句级强调，并明确精度 |
| 5 | 总时长／文本权重估算 | 仅作粗略预览，不能标成准确同步 |

WhisperX 等对齐实现作为候选评测，不在本方案中提前锁定。必须评估中文发音、CPU/GPU 成本、依赖部署及实际误差。

### 6.2 文本映射

保留原始讲稿、去除控制标签后的文本、实际发音规范化文本及其范围映射。例如 `2026年` 与 `二零二六年`、`30%` 与 `百分之三十`。

标点、暂停标签、数字展开、英文缩写和重音控制不能简单删除后丢弃位置映射。字符偏移须采用明确的统一口径，建议持久化为 Unicode 码点的左闭右开范围，前端转换 JavaScript UTF-16 索引；用户选择边界不得拆开组合字符。

同一关键词多次出现时，使用语块 ID、文本版本、字符范围、前后文及出现序号共同定位。

### 6.3 播放规则

- 圈词优先锚定关键词起点附近；整句横线可按短语或句级触发。
- 逐字点亮和笔尖逐字跟随要求更高精度，放到后续阶段。
- 支持相对触发点的小幅提前／延后，不要求用户手工填写绝对秒数。
- 时间对齐失败时，不把总时长平均分配的结果当作成功；提供句级降级、人工选择时间或禁用该条标注。
- 音频前置延迟、片段起点、停顿、尾部留白和视频变速必须统一转换。
- 对齐结果缓存使用音频内容哈希、发音文本哈希、引擎及配置版本，不以文件名作为唯一依据。

## 7. 样式与参数

### 7.1 样式清单

| 样式 | 用途 | 定位规则 | 阶段 |
| --- | --- | --- | --- |
| 手写椭圆圈 | 日期、数字、关键词 | 合并目标边界并加留白 | 第一阶段 |
| 手写横线 | 短语、结论 | 跟随文字基线，跨行分笔 | 第一阶段 |
| 荧光笔 | 一段重点文字 | 覆盖文字范围，低笔迹浓度 | 第一阶段 |
| 双横线 | 核心结论 | 两笔顺序绘制 | 第二阶段 |
| 箭头 | 图表数据、流程节点 | 指向目标，起点优先选择附近空白 | 第二阶段 |
| 侧线／侧括号 | 多个条件、整段内容 | 沿段落边界 | 第二阶段 |
| 波浪线 | 提醒、易混点 | 沿文字基线生成轻微波形 | 第二阶段 |
| 手写方框 | 定义、公式、卡片 | 沿区域边界并留白 | 第二阶段 |
| 勾／叉 | 对错、条件核验 | 目标旁边空白处，需明确判断依据 | 后续 |
| 星号／感叹号 | 特别提醒 | 目标旁边空白处 | 后续 |
| 编号 | 多个讲解要点 | 多个目标区域 | 后续 |
| 连线／双向箭头 | 因果、对应、比较 | 同时关联两个画面目标 | 后续 |
| 手写短评 | 重点、注意条件等旁注 | 目标附近空白处 | 后续 |
| 笔尖／激光点 | 阅读引导 | 目标或引导路径 | 后续 |
| 局部放大／聚焦 | 密集数字或图表细节 | 目标及批注统一变换 | 后续 |

手写字体显示与真实笔顺写出分别立项；普通字体外轮廓描边不等于真实书写笔顺。

### 7.2 真人笔迹

- 路径逐步显现，有明确落笔、运笔和收笔。
- 椭圆允许轻微不对称、小缺口或收笔重叠。
- 起收笔略慢，中间较快；长路径按长度与可用时间调整。
- 粗细变化和轨迹扰动保持轻微；画完后笔迹稳定。
- 多笔动作有短暂停顿，不同时出现所有笔画。
- 生成路径及随机种子持久化，不在每帧重新随机。
- 提供自然、规整等预设，避免暴露过多算法参数。

### 7.3 编辑参数与默认值

下列值为试片起点，需在真实画面上校准，不是已经验证的效果指标。

| 参数 | 建议默认／范围 |
| --- | --- |
| 圈画绘制时长 | 约 0.4～0.9 秒，随路径长度调整 |
| 短横线时长 | 约 0.25～0.6 秒 |
| 圈、线、箭头笔迹浓度 | 75%～90% |
| 荧光笔笔迹浓度 | 15%～30% |
| 区域浅底纹浓度 | 10%～20% |
| 同时进行的主要动作 | 默认一个 |
| 保留方式 | 到段落结束／到页末／自定义时长 |
| 留白和粗细 | 按目标字高或基准画布尺寸计算 |

界面使用“笔迹浓度”：0% 不可见，100% 完全不透明，避免透明度术语歧义。提供颜色、粗细、大小、留白、旋转、绘制速度、保留和退出方式。

区分画布缩放、调整标注尺寸、视频中的局部放大三种操作。仅缩放编辑视图不得改变导出结果。

扁平图片中的文字不能天然独立置于荧光笔上方。第一阶段采用低浓度覆盖，针对深色背景评估配色与混合效果；不默认依赖精确文字抠图。

## 8. 可视化工作区与人工编辑

### 8.1 入口与流程

保持现有六个必选步骤，新增独立可见的“勾画标注”可选模块，位于“旁白与音频”之后、“数字人讲解”和“作品输出”之前。在 AI Mask 工作区可提供携带目标区域的跳转入口。勾画有自己的工作区与状态，不放在旁白与音频的子视图中；缺少音频时允许编辑位置、样式和讲稿关联。

1. 图片确认后准备文字定位层。
2. 讲稿可用后点击“AI 生成重点标注”。
3. 用户查看目标与讲稿关联，修改草稿。
4. 音频生成后补全时间对齐并支持同步预览。
5. 确认标注后参与视频导出；未启用该功能的项目沿用现有流程。

### 8.2 三栏联动

| 区域 | 内容 | 操作 |
| --- | --- | --- |
| 页面画布 | 文字选区、目标轮廓、批注预览 | 换目标、调整几何、缩放画布、自由绘制 |
| 演讲稿 | 语块、关联短语、播放位置 | 选择字符范围、更换关联、选择重复出现序号 |
| 标注列表／属性 | 样式、目标、触发短语、状态、理由 | 新增、删除、锁定、改样式、调整时机 |

点击任意一侧的标注，其余两侧同步高亮并滚动到可见位置。颜色之外同时使用编号和选中轮廓表达关联。

示例卡片：

```text
标注 03 · 手写圈 · 待确认
画面目标：9月30日
关联讲稿：报名时间到九月三十日截止
触发短语：九月三十日（本语块第 1 次）
时间状态：等待音频对齐
操作：更换目标 / 修改关联 / 预览 / 锁定 / 删除
```

没有音频时可以编辑位置、样式和讲稿关联，但不能将其展示成已经校准的音频同步结果。

### 8.3 三种新增方式

- 从讲稿添加：选中讲稿字词，选择圈注或划线，系统推荐画面目标。
- 从画面添加：点选识别文字或框选区域，系统推荐讲稿关联。
- 自由手绘：记录多笔轨迹与采样时间，推荐关联目标和讲稿；可保留原始节奏或进行轻度平滑。

自由手绘记录顺序、笔画分段、局部坐标和可用的压力数据。没有压力设备时使用稳定的默认笔宽，不伪造实际压力采样。

### 8.4 修改、保存与确认

| 问题 | 操作与结果 |
| --- | --- |
| 不值得强调 | 删除该条或更换重点，不影响语块本身 |
| OCR 文本错 | 编辑识别文本；影响几何关联时重新定位 |
| 圈到相邻文字 | 重新选画面文字范围，保留样式 |
| 同词选错位置 | 点选另一个候选位置 |
| 讲稿重复出现选错 | 更换讲稿范围／出现序号，重新计算时间 |
| 圈太大、太浓 | 修改留白、尺寸、粗细或浓度 |
| 动作早／晚 | 提前一点／延后一点，或编辑相对偏移 |
| 修改后不满意 | 支持撤销／重做和恢复本条 AI 初始建议 |

自动保存显示保存中、已保存、失败可重试；离开页面或导出前等待待保存操作完成。生成过程使用输入版本快照，结果返回时若用户已编辑，不静默覆盖新版本。

未解决项可选择修正、明确接受句级／区域级降级，或禁用该条。批量确认不得把低可靠结果静默提升为精确结果。

## 9. 状态、版本与失效规则

避免一个状态字段承担所有含义，分别记录：

- 内容状态：草稿、已确认、已禁用。
- 空间状态：有效、待确认、失效。
- 时间状态：等待音频、字词对齐、句级降级、手工定时、失败。
- 人工保护：哪些字段经过修改、是否锁定、最近确认的输入版本。

| 输入变化 | 应执行的更新 |
| --- | --- |
| 图片内容或尺寸变化 | 文字定位和空间关联失效，重新识别与匹配 |
| 讲稿变化 | 检查片段映射、重点和时间关联；保留可迁移的人工选择 |
| 音频重新生成 | 重新对齐时间，保留有效空间目标和样式 |
| 只改样式 | 重新生成路径／渲染参数，不重跑 OCR 和 TTS |
| 只调时间偏移 | 只更新该条播放事件 |
| OCR 局部修正 | 只重算受影响的目标和关联 |
| 页面重排 | 保留页内关联，重算作品级起点 |
| 整体变速 | 对声音、批注和显现事件应用统一时间变换 |

路径与坐标关联图片版本；时间关联音频及发音文本版本。用户锁定不能绕过输入失效检查：原图已换时仍需提示确认。

## 10. 数据与模块设计建议

### 10.1 建议产物

以下路径为拟议结构，实施时确认与现有产物登记和失效机制兼容。

| 产物 | 内容 |
| --- | --- |
| `slides/<slide_id>/text_layout.json` | 页面文字、区域、坐标、来源、修正与版本 |
| `slides/<slide_id>/word_alignment.json` | 原文与发音文本映射、时间、精度与失败范围 |
| `slides/<slide_id>/annotations.json` | 标注草稿、用户修改、关联、样式和确认状态 |
| `slides/<slide_id>/annotation_timeline.json` | 解析后的播放事件与渲染路径 |

这些运行产物按现有规则留在运行目录，不提交到代码仓库。

### 10.2 一条标注的概念模型

| 字段组 | 主要内容 |
| --- | --- |
| 身份 | schema_version、annotation_id、slide_id |
| 画面目标 | target_kind、region_id、token_ids／文本范围、目标原文、多边形 |
| 讲稿锚点 | beat_id、范围口径、start/end、quote、context、occurrence |
| 时间 | trigger_mode、offset_sec、draw_duration_sec、hold_mode、resolved_times |
| 样式 | type、color、opacity、width、padding、handwriting_seed |
| 手绘 | strokes、局部点坐标、采样时间、平滑策略 |
| 人工保护 | source、modified_fields、locked、review_state |
| 输入版本 | image_hash、narration_hash、audio_hash、引擎版本 |
| 质量 | 空间／语义／时间各自的证据、精度和待确认原因 |

双目标连线应支持目标数组；跨行文字支持多个范围。关键关联以持久化实体引用和文本范围保存，几何与绝对时间是可重算结果。

### 10.3 模块责任

- 文字定位适配层：识别、缓存、坐标转换和统一结果格式。
- 批注规划服务：组织 AI 输入、验证输出、生成草稿、合并人工锁定项。
- 音频对齐服务：规范化映射、引擎适配、字词时间及降级。
- 批注持久化服务：版本检查、编辑保存、确认及失效。
- 路径与时间轴构建器：确定性计算几何、时间和渲染事件。
- 前端批注工作区：画布、讲稿选区、列表和属性联动。
- Remotion 批注层：按帧消费已解析的路径与时间，不在渲染时调用 AI。

新增能力应同步考虑 Web 与 Agent API 的操作覆盖：读取、生成、编辑、确认、禁用及状态查询。实际模型或接口变化遵守现有 Agent capability 与契约生成规则。

## 11. 渲染与输出约束

- 批注作为独立覆盖层，不烧入页面原图，不混入 AI Mask 的像素归属数据。
- 批注层和页面目标共用裁切、缩放、旋转及平移变换。
- 目标需要通过 Mask 显现时，批注起点不早于其可读时刻；发生冲突时延后或转待确认。
- 按路径弧长和速度曲线推进笔迹，避免按采样点数量均分造成忽快忽慢。
- 预览、逐帧导出和重渲染使用相同路径、随机种子、时间及样式解释。
- 处理字幕、数字人和其他批注的遮挡；自动规划优先避让，无法避让时提示。
- 默认同一时刻仅有一个主要绘制动作；多个已完成标注可保留，但需控制画面密度。
- 第一阶段作用于视频。图片型 PPTX 默认保持原图；后续可提供“合成静态批注”的明确选项，不宣称 PPTX 支持相同动态笔迹。

## 12. 分阶段交付

| 阶段 | 范围 | 交付与通过条件 |
| --- | --- | --- |
| 0：技术验证 | OCR、音频对齐、路径绘制样片 | 使用真实样本记录质量、耗时、依赖；选定首个适配器与降级规则 |
| 1：最小完整链路 | 圈、横线、荧光笔；文字定位；重点规划；三栏编辑；讲稿关联；音频对齐；预览与导出 | 能完成自动草稿、人工修正、保存重开、同步导出；同词与失败场景可解释 |
| 2：编辑与样式扩展 | 自由手绘、双横线、箭头、侧括号、波浪线、方框、批量操作 | 人工轨迹和修改可保护，跨行及双目标关联稳定 |
| 3：高级讲解表现 | 局部放大、聚焦、引导点、明确语义下的勾叉、短评 | 批注与镜头变换一致，不遮挡讲解主体 |
| 4：长期升级 | 系统文字排版、逐字跟读、真实笔顺等 | 依据前期数据评估投入，不作为基本勾画功能的依赖 |

不提前给出未经资源评估的开发天数。阶段 0 结束后，按模块、样本质量和部署约束估算工作量。

## 13. 验收与评测

### 13.1 样本集

覆盖中文、英文、数字与百分比、日期、同词多处出现、讲稿改写、跨行、倾斜、小字、密集排版、浅色／深色背景、图表、静态页面及 Mask 显现页面。另包含漏读、停顿、语速变化、音频重生成和图片替换样本。

样本由人工标注正确目标范围、合理讲稿关联和可接受触发时刻；评测集与调参集分开，保存失败案例。

### 13.2 验收指标

| 维度 | 评估内容 |
| --- | --- |
| 空间准确性 | 目标选对率、邻近文字误圈、文字被笔迹压住、越界情况 |
| 重点合理性 | 是否有讲稿依据、是否重复或过密、是否出现无依据的对错判断 |
| 时间准确性 | 与人工基准的起点误差中位数及 P95；不同定位粒度分别统计 |
| 人工成本 | 每页修改数、无需修改比例、完成确认耗时、候选点选能否解决问题 |
| 失败可见性 | 无法定位或对齐时有明确状态，不静默伪装成功 |
| 编辑可靠性 | 保存重开、撤销、锁定、重跑 AI、换图改稿后的结果符合规则 |
| 渲染一致性 | 预览与导出路径一致；允许的时间量化差异不超过一个输出帧 |
| 性能 | OCR、规划、对齐和渲染耗时，缓存命中率、内存及设备要求 |

字词触发可先以“误差约 200 毫秒以内”的主观同步体验作为试片目标，但须通过样本确认，不能在实现前当作已达到的承诺。句级降级与逐字级能力分开验收。

### 13.3 必须通过的产品场景

1. 自动生成日期圈注，页面目标、讲稿短语与标注卡三处联动。
2. 页面有两个相同日期时，可以选择正确位置。
3. 同一语块重复念到目标词时，可以指定正确出现次数。
4. 跨行横线分笔绘制，不穿过中间无关内容。
5. 未生成音频时可以编辑；音频生成后只补充时间。
6. 重生成音频不覆盖人工空间调整；换图后失效关联明确提示。
7. 低可靠结果能够修正、接受明确降级或禁用。
8. 编辑画布缩放不改变视频结果；镜头变换时标注不漂移。
9. 保存并重新打开项目后，标注、锁定和关联完整恢复。
10. 无标注的旧项目继续沿用原流程；启用标注不强制新增一个工作步骤。

## 14. 待技术验证事项

- 首个 OCR 引擎在真实图片上的字词定位能力、中文支持及部署方式。
- 音频对齐引擎对现有 TTS 输出、数字读法和中英混排的适配效果。
- 文字范围过小、无法字级定位时，区域／句级降级的默认策略。
- 人工轨迹在换图后可迁移的边界，以及必须重新确认的条件。
- 深色背景的荧光笔颜色与混合策略。
- 重点密度、动作时长和保留时间的最终预设。

上述事项通过试片确定；自动识别、可视化关联、人工修改和人工结果保护属于本方案的核心交付要求。
