## 1. 交付目标与范围

首期交付完整链路：页面文字定位 → AI 推荐重点 → 用户编辑画面目标及讲稿关联 → 实际音频时间定位 → 同步预览 → 确认 → 视频导出。

首期必须提供：

- 独立导航入口、独立工作区、项目级启用开关；默认不启用视频勾画。
- 手写椭圆圈、横线、荧光笔三种样式；区域框选和文字候选点选。
- AI 生成当前页重点草稿；允许从画面或讲稿手动新增。
- 画布、讲稿、标注列表三处联动；重复词消歧、跨行拆笔、样式调整。
- 自动保存、撤销/重做、锁定、恢复 AI 原始建议、删除、禁用和显式确认。
- 首个经真实样本验证的 OCR 适配器、音频对齐适配器，以及明确的降级状态。
- 没有音频时可编辑；音频生成后补时间，保留人工空间修改。
- 预览与导出一致；换图、改稿、重生成音频后按依赖失效；旧项目正常输出。
- Web 与 Agent 对读取、生成、编辑、对齐、确认、禁用、任务状态的操作覆盖。

后续版本：自由手绘采样、箭头、双横线、括号、波浪线、方框、局部聚焦、手写短评、真实笔顺。数据模型可扩展，但首期 UI 不展示不可用按钮。首期图片型 PPTX 维持既有输出语义，勾画只作用于视频；不要把当前 PPTX 的静态或 Reveal 导出能力整体改写。

## 2. 独立入口、步骤与兼容规则

### 2.1 导航位置

工作区顺序固定为：

`导入文章 → 分镜规划 → 图片生成 → AI Mask 标注 → 旁白与音频 → 勾画标注（可选） → 数字人讲解（启用时可见，可选） → 作品输出`

“勾画标注”始终有独立导航项，用笔迹图标和“可选”标记。六个必选步骤保留 1–6 的显示编号，可选项使用图标/可选徽标，不占必选序号。数字人隐藏时不得产生空序号。

**建议使用 `data-step="10"`、`step-panel-10` 作为前端兼容标识。** 实施前检索 10 是否被占用；如已占用，集中更换常量并同步本文。10 只是导航标识，首期不新增内部生产阶段，不把它交给 `complete_stage`、`begin_stage`、`mark_downstream_pending`，也不写成项目 `current_step` 的业务完成值。模块完成状态来自勾画自己的摘要。

有当前页图片和有效讲稿即可进入编辑，不要求先完成 AI Mask，也不要求先生成音频。缺图片或讲稿时显示缺失原因及返回对应模块按钮。是否允许导出仍遵守已有音频确认门禁。

### 2.3 启用与导出门禁

项目设置使用 `enabled: boolean`，默认 false。点击生成/手动新增可创建草稿，但最终是否带入视频由“视频中启用勾画”开关明确决定。

| 状态 | 输出行为 |
| --- | --- |
| 无勾画文件或 enabled=false | 完全按既有视频流程；不启动 OCR/对齐 |
| enabled=true，但没有任何有效启用条目 | 提示尚无勾画；用户可关闭功能，不能伪装成已确认 |
| enabled=true，有草稿、未确认降级、失效目标或时间错误 | 阻止带勾画的视频提交，返回逐页逐条原因 |
| enabled=true，所有非禁用条目已确认且版本匹配 | 允许带勾画输出；无标注页面正常渲染 |
| 用户选择“此次不带勾画” | 首期通过明确关闭开关并保存实现，保留草稿；展示导出内容已变更 |

可选模块不增加必选进度分母；用户显式启用后的有效性检查是输出内容校验。编辑勾画不清除音频确认，不启动 TTS，不修改 AI Mask。

## 3. UI 开发说明

### 3.1 沿用现有样式

以 `references/ui_extract/stitch_extract/stitch_web_ui_style_extractor/*/code.html`、当前 `static/index.html`、`static/stitch.css` 和 `static/style.css` 尾部严格对齐层为准。沿用橙色 `#f46a38`、白色圆角卡片、深色主按钮、现有标题栏、间距、图标和表单尺寸。不要恢复旧 Soft Pastel 风格。

复用 `.workflow-header`、`.workflow-title`、`.workflow-toolbar`、`.card` 等现有类；新增 CSS 以 `.annotation-workspace` 限定范围。建议独立 `static/annotations.css`，在现有样式之后加载，只覆盖新面板。Toast、确认弹窗、HTML 转义、HTTP 客户端全部调用现有公共实现。

### 3.2 工作区布局

顶部：标题“勾画标注”、项目启用开关、保存状态、AI 生成当前页、同步预览、确认当前页。

页面缩略图导航沿用图片/Mask 模块交互。正文三栏：

| 区域 | 内容 | 必须支持 |
| --- | --- | --- |
| 主画布，约 55% 可用宽度 | 页面图、文字候选、选中目标、笔迹 | 选择文字/区域、换目标、拖动/缩放几何、缩放编辑视图 |
| 讲稿，约 23% | 当前页语块、关联范围、播放位置 | 选范围、重复出现位置、双向高亮、跳至对应音频 |
| 属性/列表，约 22% | 标注列表、状态、样式、触发与保留 | 锁定、删除、禁用、恢复 AI 建议、提前/延后、确认降级 |

比例是排版起点，不硬编码像素宽度。1440px 和 1920px 窗口保证三栏；1280px 时右侧属性可折叠；更窄视口用切换面板，保持操作可达。画布保持项目宽高比，编辑视图缩放不得改变持久化坐标。

标注卡示例：`03 · 手写圈 · 待确认`，展示画面目标、讲稿引用、时间精度、待确认原因。用户界面显示“笔迹浓度”，0% 不可见、100% 不透明；内部存 0–1。关联同时用编号和边框表达，不只靠颜色。

### 3.3 关键交互

1. AI 返回草稿后显示所有有效建议及待复核原因，不能自动确认。
2. 选择讲稿短语 → 选样式 → 展示画面候选 → 点选目标；反向从画面选词也能推荐讲稿位置。
3. 出现多个相同词时列出所属语块/卡片和上下文，保留选择依据；不得默认第一处。
4. 圈注、划线、荧光笔支持颜色、粗细、留白、浓度、绘制时长、保留方式及相对时间偏移。
5. 撤销/重做作用于本页编辑操作，包括删条目和恢复 AI 建议；自动保存成功不清空历史。切页历史按页隔离，刷新后首期可清空撤销历史，但必须恢复已保存内容。
6. 没音频显示“等待音频”；对齐失败可接受句级降级、手工定时或禁用。不得显示伪造的字级成功状态。
7. 离开页面/项目前等待保存完成；失败保留当前编辑并提供重试。关闭标签页用未保存提示，不依赖 `beforeunload` 异步写入。
8. 长任务显示阶段、可恢复状态和取消按钮；项目 A 返回的异步结果不得写入项目 B。
9. 键盘可访问列表、按钮、候选；选中态可见；输入文本时撤销快捷键不得抢夺文本框原生操作。

### 5.2 单条标注的规范结构

下面是结构示例，示例哈希不是真实摘要；实现应转为严格模型和 JSON schema。

```json
{
  "schema_version": 1,
  "annotation_id": "ann_01",
  "slide_id": "slide_001",
  "target": {
    "kind": "text",
    "layout_revision": 3,
    "token_ids": ["token_07"],
    "polygons": [[[800, 400], [960, 400], [960, 445], [800, 445]]],
    "quote": "9月30日",
    "granularity": "word",
    "mask_group_ids": []
  },
  "anchor": {
    "beat_id": "slide_001_beat_002",
    "offset_unit": "unicode_codepoint",
    "range": [7, 12],
    "quote": "九月三十日",
    "occurrence": 1,
    "context_before": "报名时间到",
    "context_after": "截止"
  },
  "style": {
    "type": "ellipse",
    "color": "#F46A38",
    "opacity": 0.85,
    "width": 5,
    "padding": 8,
    "seed": 1382
  },
  "timing": {
    "trigger_mode": "anchor_start",
    "offset_sec": -0.1,
    "draw_duration_sec": 0.6,
    "hold_mode": "beat_end",
    "exit_duration_sec": 0.15
  },
  "status": {"content": "draft", "spatial": "valid", "temporal": "awaiting_audio"},
  "protection": {"source": "ai", "modified_fields": [], "locked": false},
  "inputs": {"image_hash": "<sha256>", "narration_hash": "<sha256>", "audio_hash": null},
  "review_issues": [],
  "confirmed_inputs": null
}
```

页级包装包括 `schema_version`、`slide_id`、`revision`、`items`、AI 原始建议快照及更新时间。客户端提交 `expected_revision`，服务端分配 ID/revision；`target.polygons` 是当前几何结果，`token_ids`/范围是可追溯来源。区域框选时 token_ids 为空，记录人工几何。多行保留多个多边形，不强制合成一个大框。

枚举至少包括：

- content：draft / confirmed / disabled。
- spatial：valid / needs_review / stale。
- temporal：awaiting_audio / word_aligned / sentence_fallback / manual / failed / stale。
- style.type：ellipse / underline / highlighter。
- hold_mode：beat_end / slide_end / duration；duration 模式要求 hold_duration_sec。

精度与是否接受降级分别记录：`accepted_degradation` 保存类型、确认 revision 和输入摘要；不能把 sentence_fallback 改名为 word_aligned。人工锁定只防止自动改写，不能让旧图片引用继续有效。

### 5.3 坐标、文本和音频时间

- 页面坐标使用实际项目画布尺寸；标准为 1920×1080。不要在新组件里重复硬编码，读取现有 canvas profile。OCR 针对用户看到的规范化 master 图；裁剪/缩放/旋转记录完整反变换。读取 Mask 几何时维持同一原图坐标，不能误把 raw 文件颜色差异当成坐标变化。
- 原文字符范围统一为 Unicode 码点的 `[start,end)`；服务端校验截取内容与 quote 相同。前端显式转换 UTF-16 索引；交互选择遵守组合字符边界。`occurrence` 明确从 1 开始，仅为辅助消歧，不能代替范围。
- 保存原始讲稿、去控制标签文本、规范化发音文本三者的范围映射。数字展开、百分比、中英缩写、多对一和一对多映射必须可表达。音频文本来源复用真实 TTS 输入，不单独猜测发音。
- 对齐时间以音频文件起点为 0。页面事件时间 = 音频内时间 + `audio_start_sec` + 用户偏移；作品时间再加页面起点。上述延迟只能各加一次。
- 音频时间必须有限、单调、非负且不超内容时长。字符无对应发音时标记未对齐；不得平均切分后声称字级准确。

## 6. OCR、重点规划和音频对齐

### 6.1 阶段 0 必须先解决的选型

沿用原方案中的候选（例如 PaddleOCR、WhisperX），仅作为评测候选，不预设它们满足字级定位、中文对齐或本项目 Python/Windows 部署要求。接手 Agent 查阅并记录所选版本的官方文档、许可证、模型来源/摘要和支持环境，再用同一真实样本对比。

先做只读 preflight：当前 Python/依赖版本、CPU/GPU、现有模型和内存；不要自动升级整套生产依赖。若需要不兼容 Python/大型模型，用可选 worker 子进程环境，配置解释器/模型路径，记录安装与卸载步骤。禁止应用启动时隐式下载模型。默认测试全部 stub，真实模型验收单独执行。

交付 `docs/annotation-validation/adapter-decision.md`：选定首个 OCR 与对齐适配器、冻结版本、模型哈希、支持粒度、测试机器、冷热耗时/内存、失败样本、降级行为、可复跑命令。核心自动链路必须有真实验证；只有 stub 不能宣布功能完成。

### 6.2 OCR 统一接口与缓存

输入：图片文件的受控引用、内容哈希、画布尺寸、可选 ROI、引擎配置快照。输出：稳定候选 ID、文本、polygon、方向、粒度、识别证据、阅读顺序、区域关联、坐标变换。

缓存键包含图片字节哈希、ROI、引擎/模型/预处理/配置版本。相同输入重复请求复用；只换音频不重新 OCR。候选 ID 仅保证同一 layout revision 内稳定，重识别后以新 revision 重绑定。

整行框不能均分成“真实字符框”。无字词框时提供整行/区域目标，空间状态进入待确认。OCR 文本纠正保留原识别结果；字符数或文字边界变化时重定位局部范围。

### 6.3 AI 规划契约

新增生产 Prompt 前必须读取并使用 `.agents/skills/optimize-prompts/SKILL.md`。本开发文档不提供可直接上线的 Prompt。

系统消息只放规则、合法输出和样式含义；每次用户输入只含当前页讲稿语块、必要的候选 ID/文本/区域关系、强调强度、需保护的人工项。确需视觉判断时附当前页或候选裁剪，控制请求体和候选预算；超限分页，不能静默丢候选。

模型只返回建议：`beat_id`、讲稿范围/quote、`target_candidate_ids`、样式枚举、简短理由、歧义。最终 annotation_id、路径、时间、颜色默认值和可信度结论由程序产生。校验引用存在、范围一致、样式合法、重复建议和密度上限。首期默认每页 1–2 个重点，可配置上限；不能每个语块强制出一条。

使用现有 JSON LLM 能力及 gateway 并发治理，不另建无预算的模型请求。格式损坏最多一次修复/重试；失败保留现有草稿并报告。重规划默认不覆盖 `modified_fields` 或 locked 项；AI 初始建议作为可恢复快照保存。用户明确“替换本页全部”时先保留可撤销快照。

必须提供用户可编辑 Prompt、完整输入预览和版本；仅迁移识别出的旧内置默认值。测试必须验证实际 runtime payload、解析器、Prompt 帮助和预览一致。

首期 Prompt 和勾画偏好采用项目级覆盖，模型连接复用当前项目实际解析出的 LLM 配置。不额外新增供应商凭据，不把项目偏好偷偷写入全局设置。若实施中需要加入创建配置包或配置导入/导出，必须在同一变更中补齐内部模型、Agent parity、默认值、导入旧包兼容和测试；不能只加 UI 字段。

### 6.4 对齐与降级

优先使用经过校验的供应商字词时间，其次实际音频 + 已知发音文本强制对齐；ASR 只辅助发现漏读/改读。均不可用时采用现有可靠句级时间，并要求用户接受句级精度；只有总时长估算时标为粗略预览，不能直接确认成精确同步。

缓存键：音频字节哈希 + 实际发音文本/映射哈希 + 引擎模型/配置版本。限定超时、输入大小、并发和子进程资源。取消任务后终止或丢弃其结果；worker 不持有 HTTP 请求对象或跨线程 Session。

漏读、重复读、英文读法差异、长静音必须返回失败区间。手工定时是独立 temporal=manual，仍校验时间范围、Reveal 可见性和输入版本。

## 7. 路径生成与渲染协议

### 7.1 明确的技术方案

首期采用**独立 SVG 笔迹覆盖层**：服务端确定性生成受限路径数据，Remotion 逐帧按弧长推进 stroke；页面正文仍来自批准的位图和既有 Reveal PNG。

实施时同步更新 AGENTS.md 的 Image Rules：明确允许勾画模块渲染独立批注路径，并继续禁止用 SVG/HTML/Canvas/React 重建 PPT 正文。此次文档交付不提前改动现有运行规则。

只接受程序生成的路径命令/数值点，样式做白名单和有限数值校验；不接受模型或用户提交任意 SVG/XML/HTML。路径生成版本、种子、控制点、逐段长度、绘制时长全部固化。禁止 render 中使用 Math.random、当前时间或网络请求。

ellipse 留出边缘余量并加入微小固定扰动；underline 沿基线，跨行分笔；highlighter 使用低浓度覆盖及稳定端点。第一版不依赖精确文字抠图或复杂混合模式。使用圆角端点，路径粗细/留白按画布比例或字高计算。

### 7.2 最终事件

`annotation_timeline.json` 应包括输入摘要、resolver_version、canvas、events。每个 event 包含 annotation_id、目标引用、strokes（受限路径与弧长）、start_sec、draw_end_sec、hold_end_sec、exit_end_sec、样式、时间来源和调度依据。

边界约束：`0 <= start < draw_end <= hold_end <= exit_end <= slide_duration`。时间不足时返回 needs_review，不生成负 duration，不静默延长整个视频。计算页长复用 `scripts/build_remotion_props.py` 当前统一口径；首期批注不增加页长。

目标涉及多个 Mask 组时，起笔不早于所有相关目标可读/变换稳定的时刻。没有可靠可读时刻时保守用对应 Reveal 结束时间，并记录依据。静态整页无需 Mask 依赖。共享页面变换容器；不要给批注和图片分别计算缩放。

同一时刻默认一个主要绘制动作，已完成笔迹可保留。按锚点、用户顺序和稳定 ID 排序。冲突可在约定容忍窗口内延后（首期默认 0.2 秒，同时不得超出关联语块）；超过窗口或语块剩余时间不足则待复核。显式人工时间不能被后台静默重排。

### 7.3 预览、导出和变速

- 编辑预览/同步播放/Remotion 调用同一播放采样逻辑，使用同一路径和同一帧量化规则。浏览器以实际 audio.currentTime 驱动，拖动进度和暂停后正确重算；无音频只能显示“动画预览”。
- 图层顺序：背景与正文/Reveal → 勾画 → 数字人/字幕。规划/编辑提示避让，字幕及数字人的安全区域纳入复核；不通过提高 z-index 遮盖字幕。
- `remotion_runner.py` 先完成既有 Reveal/时间轴重建，再构建勾画 timeline，最后构建 props。每次输出都重新验证输入版本；缺有效 timeline 不能沿用旧缓存。
- 新 props 字段可选；旧 props 缺字段时空覆盖层。`Video.tsx` 只挂组件，不塞入规划/对齐逻辑。
- 已有 MP4 后处理变速会同时改变画面和声音，不能再对其中勾画二次缩放。若走 props 重新渲染，声音、Reveal、勾画统一施加一次变速映射，并分别回归两条路径。
- `.render.json` 继续保留既有 Reveal 版本，并新增勾画 schema/resolver 版本和输入摘要。已渲染旧作品保留可下载；内容过期显示 stale，不能删除历史成品冒充失效处理。

## 8. 保存、并发、失效和输出快照

### 8.1 原子编辑协议

所有页面修改都带 `expected_revision`，服务端在项目/页面锁内完成“读取 → 校验 → 合并 → 原子写入 → revision+1”。冲突返回 409 和最新 revision；客户端保留本地编辑供重新加载/合并，不自动覆盖服务器。

编辑 payload 应是明确 operations（add/update/delete/restore），不能让客户端任意替换服务器确认哈希或 AI 来源证据。modified_fields 由服务端比较并维护。校验 NaN/Infinity、范围/颜色/样式、条目数量和请求大小。

长任务获取短锁读取输入快照，释放锁执行网络/模型工作；发布时重新获取锁并检查图片、讲稿、音频、revision。若期间发生编辑/换图，结果存为候选并返回 stale_input，不覆盖正式条目。任务启动不清空现有标注。

文件与数据库不是同一事务：任务成功必须在产物原子发布之后；崩溃恢复核对发布清单再标记终态。不要声称数据库 rollback 会撤销已写 JSON。

### 8.2 失效矩阵

由 `invalidation_service.py` 统一触发，新增勾画服务接收必要依赖；业务失效不得在每条路由里复制。

| 变化 | 需要失效/重算 | 必须保留 |
| --- | --- | --- |
| 替换/删除页面图片 | OCR、目标、路径、确认、勾画时间轴和输出 fingerprint | 原人工条目作为 stale 记录；不得静默搬到新图 |
| 讲稿修改/语块重建 | anchor 映射、规划关联、对齐、确认和事件 | 仍有效的空间选择、样式、锁定证据 |
| 音频重生成 | 对齐、时间确认和事件 | 空间、样式、讲稿关联 |
| Mask 归属/显现动画变化 | 目标组引用校验、可读时刻、事件和确认 | OCR、音频对齐缓存与有效人工几何 |
| 只改颜色/尺寸/留白 | 路径/样式确认、输出输入 | OCR、TTS、音频确认 |
| 只改时间偏移 | 本条调度与确认、输出输入 | OCR、音频对齐原始结果 |
| OCR 局部纠正 | 引用受影响候选的目标及确认 | 其他条目 |
| 页面重排 | 作品级起点及输出 | 页内坐标/时间 |
| 页面删除 | 排除其所有活动条目、取消相关任务 | 历史成品不重写；项目删除按既有生命周期清理 |
| 勾画启停 | 输出配置与指纹 | 草稿、手工编辑、音频和 Mask |

### 8.3 渲染一致性

扩展 `artifact_fingerprint.py`，enabled=true 时包含启用设置、确认内容摘要及实际 timeline 输入。草稿时间戳、轮询进度等非渲染字段不进入有效内容摘要。enabled=false 时不因未使用的草稿编辑把无勾画输出判为新内容。

检查当前 fingerprint 也包含 props/派生产物：记录输出 job 的一致输入快照，构建后写入该快照的 sidecar，不能用任务结束时“当前项目状态”给旧内容盖新哈希。渲染期间编辑采用冻结快照继续旧 job，或检测变更后显式中断；首选复用现有可行的快照机制，禁止混合两个版本的路径/音频。必须有并发编辑测试。

## 9. HTTP、任务和 Agent 接口

### 9.1 拟新增 Web API

前缀 `P=/api/projects/{project_id}/annotations`。这是建议新协议，不代表当前路由存在。实现时在 `annotation_contracts.py` 定义内部模型，所有写操作使用共享 HTTP 请求标记和既有账号授权。

| 方法/路径 | 输入关键项 | 返回/行为 |
| --- | --- | --- |
| GET P | 无 | settings、revision、逐页状态摘要、readiness |
| PUT P/settings | expected_revision、enabled、默认偏好 | 新 revision、摘要；修改设置不调用模型 |
| GET P/slides/{slide_id} | 无 | annotations、layout 摘要、alignment 状态、revision、输入版本 |
| PATCH P/slides/{slide_id} | expected_revision、operations | 新 revision、校验问题；支持新增/修改/删条目/恢复建议 |
| GET P/slides/{slide_id}/text-layout | 无 | 完整文字候选、几何、粒度和 layout_revision；大页采用有界分页 |
| PATCH P/slides/{slide_id}/text-layout | expected_layout_revision、候选 ID、纠正文本 | 保留原识别文本并保存纠正；触发受影响关联重定位/复核 |
| GET P/prompts | 可选 slide_id | 内置/覆盖内容、版本、revision；指定当前页时返回基于实际快照的完整输入预览，不含凭据 |
| PUT P/prompts | expected_revision、Prompt 内容或显式恢复默认 | 校验并保存项目覆盖；不自动触发重规划 |
| POST P/jobs | operation、slide_ids、input_revisions、request_key | 202 + job_id；operation 为 detect_text / plan / align / preview |
| GET P/jobs/{job_id} | 无 | 持久任务状态、stage、progress、result、结构化错误 |
| POST P/jobs/{job_id}/cancel | 无 | 幂等取消；迟到结果不发布 |
| POST P/slides/{slide_id}/confirm | expected_revision、accepted_degradations | 校验所有启用条目及版本后确认，返回 readiness |
| GET P/readiness | 无 | can_render、逐页逐条阻塞原因、输入摘要 |

preview operation 构建受控预览数据/产物，不确认、不改源图、不触发 TTS。返回图片/视频下载沿用现有受授权的 artifact 机制。若已有共享任务接口更合适，可复用，但应在接口设计 ADR 记录映射，覆盖相同操作。

错误：404 不存在/不可访问的项目、slide、job；409 revision 或输入快照冲突；422 非法目标、越界、未解决的确认问题；413 超限；503 引擎未配置。异步运行失败通过 job.error.code/message/retryable 返回；上游配额耗尽按 governor 语义等待/暂停，不当作不可恢复的内容错误。

需要按当前账号检查 project，再校验 slide 属于当前 Visual Contract、job 属于该 project。禁止只靠 job_id 访问另一个账号的数据。文件路径由服务端派生，禁止任意路径、URL 和可执行命令透传。

### 9.2 持久任务

复用 `local_jobs` 表，新增 job_type 例如 annotation_detect / annotation_plan / annotation_align / annotation_preview；独立 store 或抽取窄共享基础，不能让 `VideoJobStore` 承担不同任务。

状态为 queued/running/succeeded/failed/interrupted/cancelled；governor 暂停若复用现有 paused 约定，要统一持久层/查询层枚举。成功 progress=100 且 error=NULL。重启把前进程遗留活动任务标 interrupted；用户恢复生成新 attempt，保留前次诊断。

相同 project、operation、输入快照和 request_key 去重；不同输入不能复用成功缓存或活跃 job。不得仅使用每请求对象实现锁/限流。网络等待不持数据库事务；Session 每次在线程内创建并关闭。

### 9.3 Agent 同步清单

在 `agent_contract/capabilities.py` 集中登记以下能力意图的实际名称、路径、CLI/MCP 映射：读取摘要/页面/文字候选、纠正 OCR 文本、更新设置、读写 Prompt、编辑条目、提交任务、查询/取消任务、确认、readiness。本文不另外建立一份生产命名注册表。

在 `agent_contract/models.py` 定义外部模型，`agent_api/routes.py` 映射内部模型。扩展 `checks/agent/test_contract_model_parity.py`：每个新增内部字段明确公开名或 None；逐项说明隐藏理由。增加传输同步、授权、幂等、状态轮询和可下载预览产物用例。

按兼容性 bump 能力版本及 AGENT_API_VERSION；运行 `python scripts/generate_agent_contracts.py`，提交矩阵。首期不引入新的必选 CHECKPOINT；现有跳过流程仍报告原有阶段 done。若以后接入 One-click，另行扩展明确命名的 pipeline operation 和可选阶段，不向 facade 传 server。

## 11. 评测数据与验证方法

### 11.1 冻结样本

建议首批至少 20 页、40 个待强调目标；不少于 8 页及其目标冻结为盲测，近似页面不能分散到调参与盲测两侧。样本来自获准使用的真实图片/音频副本和可复现合成边界样本，不写回用户项目。

覆盖中文、英文、日期/百分比、数字发音展开、同词多处、同语块重复念词、跨行、斜字、小字/密排、浅/深背景、图表/无字区域、静态页、Mask reveal、数字人遮挡、停顿、漏读、变速。每类至少有可追溯 case；同页可覆盖多类。

小型合成图片和标注 JSON 可放 `checks/fixtures/annotations/`；音频/视频及大模型按仓库规则留在隔离临时目录或测试数据包中，不提交被禁止的文件。提交哈希清单、人工真值、来源说明和生成/取得方式。真实数据不可分发时报告应说明复跑所需本地数据包，不宣称任何机器都可直接复跑。

真值包括：目标 polygon/行范围、正确 beat+字符范围、发音锚点时间、允许的降级、Reveal 可读时间、合理避让区域。算法输入不读取真值；盲测不再用于调阈值。记录模型/Prompt/引擎版本、实际设置、机器配置和全部输入哈希。

### 11.2 首期质量门

| 维度 | 验证方法 | 首期通过规则 |
| --- | --- | --- |
| 空间正确性 | 人工确认目标 ID；检查多边形包含目标且不带相邻词 | 冻结集自动选对率建议 ≥90%，同时报告数量和每类结果；无法确定必须进入复核，所有用户确认结果正确 |
| 精确度诚实 | 审查行/词/字输出来源 | 0 个行框均分冒充字框；0 个失败伪装成功 |
| 时间同步 | 预测关键词起点对照人工标注；按 word/sentence/manual 分组 | word_aligned 起点绝对误差中位数 ≤0.20s、P95 ≤0.35s 为初始发布门；不满足则不能发布“字词准确同步”，须修复或明确收窄支持范围 |
| 目标显现 | 导出逐帧与 Reveal 事件对照 | 0 次目标未可读就开始圈画；冲突不能静默漂移到其他语句 |
| 人工保护 | 锁定/修改后重规划、重对齐、切项目 | 0 次覆盖人工字段、0 次跨项目保存 |
| 确定性 | 同输入两次构建及同环境逐帧渲染 | 路径/事件规范化哈希一致；同帧笔迹像素一致 |
| 预览一致性 | 浏览器固定时间截图与 Remotion 同帧截图 | 时间差不超过 1 个输出帧；轮廓边缘允许 ≤1px 抗锯齿差异，无位置/尺寸偏移 |
| 无勾画兼容 | 固定旧 fixture 输出前后对照 | 页面、音频时长、字幕、Reveal 相同；不以 MP4 容器字节相等代替解码帧验证 |
| 性能 | 各阶段冷 3 次/热 5 次，记录中位数/P95/峰值内存/API等待 | 先报实测，W0 冻结目标硬件预算；缓存命中不得重启模型请求，超时可取消，不得无限等待 |

以上质量值是本次开发的初始验收要求，不是已测结果。真实集覆盖不足或范围调整要在报告里写明；不能通过删失败样本达到门槛。除起点误差，还报告未经延后和最终调度后的误差，防止调度掩盖对齐问题。

### 11.3 真实功能场景验收

每个场景记录 case ID、输入哈希、步骤、预期、实际、截图/视频路径、通过/失败。

| ID | 操作 | 必须观察到 |
| --- | --- | --- |
| A01 | 独立入口进入空项目/有图无音频项目 | 缺失提示准确；有图有稿即可编辑；必选进度不增加 |
| A02 | AI 生成日期圈注并点选列表 | 画面、讲稿、卡片三处关联正确，仍是草稿 |
| A03 | 两个相同日期，讲稿同词重复两次 | 分别选择正确画面实例和发音出现次数 |
| A04 | 跨行横线/荧光笔、旋转文字 | 多笔沿目标行，不穿过邻近内容 |
| A05 | 无音频编辑后生成音频并对齐 | 原位置/颜色/锁定保留，只补时间 |
| A06 | 保存、刷新、重开、撤销/重做、删除/恢复 | 已保存内容完整，revision 单调，无误删他页 |
| A07 | 锁定并改几何后重跑 AI；生成中继续编辑 | 人工结果保留，迟到结果标冲突/候选 |
| A08 | 换图、改稿、重生成音频、改 Mask 动画 | 严格符合失效矩阵，失效确认不能导出 |
| A09 | 模型超时、OCR 无字、漏读、引擎未配置 | 明确失败/降级；可重试/接受降级/禁用 |

| A11 | 两条同时触发及目标晚显现 | 一次一个主要动作，超容忍窗口进入复核 |
| A12 | 字幕/数字人启用后预览并导出 | 不遮挡字幕，目标冲突有提示；数字人开关不改勾画状态 |
| A13 | 不确认即导出、确认后导出、关闭功能导出 | 后端门禁与界面一致；无静默丢条目 |

| A15 | 切项目/双窗口编辑/关闭再启动 | 无串页串项目；409 可恢复；任务 interrupted 可解释 |

| A18 | 渲染进行中修改勾画，再下载旧/新输出 | 每个文件对应单一输入版本，sidecar 不冒充最新内容 |

## 13. 如何运行验证和最后回归

### 13.1 数据隔离与基线

接手后先确认 Git 状态、当前 AGENTS.md 和环境。运行基线检查并保留已有失败，不擅自删除用例或把已有失败写成新功能通过。测试数据库和 runs 都使用临时目录；不导入 server 来检查用户项目，不启动第二个指向真实数据的服务。

`checks/conftest.py` 会为 pytest 提供隔离，但 `scripts/run_checks.py` 还运行独立脚本；因此整组回归命令应在专用 PowerShell 会话先显式设置临时目录：

```powershell
$annotationValidationRoot = Join-Path ([System.IO.Path]::GetTempPath()) ('ppt-annotations-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $annotationValidationRoot | Out-Null
$env:PPT_STUDIO_DB_PATH = Join-Path $annotationValidationRoot 'projects.db'
$env:PPT_STUDIO_RUNS_DIR = Join-Path $annotationValidationRoot 'runs'
$env:PYTHONPATH = (Get-Location).Path
```

这个会话只用于验证；结束后关闭，避免之后用这些环境变量启动生产服务。使用项目已配置 Python/Node 环境，不依赖命令恰好命中全局解释器。首次缺少 dev 依赖时按仓库 requirements-dev.txt 安装到测试环境，不能随意升级 lock。

### 13.2 每个工作包的定向验证

先创建本包对应测试，再运行；下列通配是新模块完成后使用。PowerShell 显式展开路径，避免 pytest 在 Windows 不展开通配符。

```powershell
$annotationTests = @(Get-ChildItem checks -Filter 'test_annotation_*.py' | ForEach-Object { $_.FullName })
if ($annotationTests.Count -eq 0) { throw '缺少勾画模块测试，不能视为通过' }
python -m pytest @annotationTests -q
if ($LASTEXITCODE -ne 0) { throw '勾画 Python 定向测试失败' }
node checks/test_annotation_workspace.js
if ($LASTEXITCODE -ne 0) { throw '勾画工作区测试失败' }
node checks/test_annotation_playback.js
if ($LASTEXITCODE -ne 0) { throw '播放采样测试失败' }
node checks/test_visible_flow.js
if ($LASTEXITCODE -ne 0) { throw '可见流程回归失败' }
node checks/test_frontend_quality.js
if ($LASTEXITCODE -ne 0) { throw '前端职责回归失败' }
```

将新增 JS 行为测试和新生产模块编译检查登记到 `scripts/run_checks.py`，不能只有手工命令而 CI 永远不运行。

### 13.3 合并前全量检查

```powershell
python scripts/run_checks.py --level full --with-remotion
if ($LASTEXITCODE -ne 0) { throw '全量回归失败' }
python scripts/generate_agent_contracts.py --check
if ($LASTEXITCODE -ne 0) { throw 'Agent 生成契约未同步' }
git diff --check
if ($LASTEXITCODE -ne 0) { throw '补丁格式检查失败' }
```

已核对该 full 入口包含 quick、独立 Python 检查、全量 pytest；with-remotion 执行 npm ci 和 TypeScript 检查。**仍须逐项对照当前 AGENTS.md Required Validation**：入口遗漏的必需项补跑；已覆盖项无需为了形式重复运行。Agent 全量、迁移、失效、Mask 完整性、音频确认/尾留白、字幕等不能因新增模块被跳过。

TypeScript 通过不代表视频正确；随后在隔离的已填充测试 run 上执行：

```powershell
python scripts/validate_reveal_scene.py --run-dir $annotationFixtureRun --repo-root .
if ($LASTEXITCODE -ne 0) { throw 'Reveal scene 无效' }
python scripts/validate_run_assets.py --run-dir $annotationFixtureRun --repo-root . --require-layered
if ($LASTEXITCODE -ne 0) { throw '运行资产无效' }
```

`$annotationFixtureRun` 由新测试 fixture 工具创建并返回，必须落在上述临时 runs 内；`--require-layered` 用于已建 Mask 的 fixture。静态无 Mask fixture 依照现有验证器支持的静态模式单独验收，不给它套用错误门禁。

新增勾画 timeline 校验器纳入同一入口，检查输入版本、引用、路径、时间范围和已确认状态；不得以 Reveal validator 通过替代它。

### 13.4 浏览器和实际媒体验收

测试服务采用独立临时数据库/runs/端口，在 composition root 导入前完成环境配置；通过当前启动器支持的方式指定端口，不能猜造参数。已有真实服务保持单实例，不复用其数据目录做自动化。

按 A01–A18 逐项操作，在至少一个静态页、一个 Mask 页、一个多页项目上渲染 MP4。保存预览/导出固定帧：起笔前、起笔、半程、完成、退出、下一页。人工播放听看至少包含日期/数字、停顿、重复词、长句和变速的样片。

核对输出列表、下载、删除（MP4+sidecar+artifact record）、历史输出 stale 状态，以及不启用勾画时不触发任何新模型请求。浏览器控制台不能出现未处理异常；离开工作区后不残留音频播放、动画帧、计时器或轮询。

## 14. 最终交付物与完成定义

开发 Agent 交付：

1. 可运行的独立模块及分包提交；改动职责符合现有边界。
2. 更新后的 AGENTS.md：可选勾画导航映射、模块职责、独立 SVG 覆盖允许范围、必要验证项；README 新功能使用流程；原方案入口和本交接文档与实现一致。
3. 冻结版本/模型及安装说明、真实评测数据清单、adapter-decision、真实误差/性能结果。
4. `docs/annotation-validation/acceptance-report.md`：基线 commit、最终 commit、机器、命令/退出码、用例表、截图/样片位置、失败与降级范围。媒体不提交到禁入目录之外规避仓库规则。
5. Agent 版本/能力矩阵生成文件、接口示例、测试 fixture 和测试入口。
6. 回退说明：关闭项目勾画设置后既有视频流程可用；旧字段缺失可读；迁移只新增不可改已应用 SQL；历史成品可下载。

完成必须同时满足：W0–W6 有证据；A01–A18 全部通过；必需自动回归全绿；空间/同步门达标；真实视频人工验收；无真实用户数据污染；无未登记 Agent 模型差异；没有用 mock 结果冒充真实 OCR/对齐评测。引擎不支持的语言或粒度必须在能力说明中公开，并通过明确降级的用例；这不允许跳过保存、授权、版本保护或导出一致性等必需验收。

如仍存在失败或无法运行的检查，报告准确阻塞原因与未验证范围，不能写“全部通过”。发现基线失败时记录复现与影响，并明确本次是否修复，不能降低门槛掩盖问题。
