# 勾画标注第三轮优化方案:速度、精准度与效果

制定日期:2026-09-28。审查对象:当前工作区(第一/二轮已交付,含栅格墨迹渲染、
三轮精准度评测、演示 MP4)。本文先给出基于实测的现状审查与开源调研结论,
再给出分轨优化方案。所有"本机已验证"的结论都在本仓库 Python 3.13.5 环境
用 `pip install --dry-run` 实际解析过,不是文档转述。

## 0. 一句话结论

**最大的精准度缺口不在"圈得准不准"(已达标:压字率 ≤0.5%、误圈邻词 0%),
而在"圈的时机准不准"(句级对齐实测误差约 0.75 秒)——而它的首选解法
是把我们已在用的 MiniMax TTS 从句级时间戳切到官方词级时间戳,零新依赖。**

## 1. 现状审查(全部为实测数字)

### 1.1 各环节现状与瓶颈

| 环节 | 现状(实测) | 问题 | 严重度 |
| --- | --- | --- | --- |
| 时间定位 | 锚点取语块(beat)起点;实测"9月30日"在句中 7/30 处,句级误差 **≈0.75s** | 句中/句尾关键词会提前圈;数字念法展开("9月30日"→"九月三十日")未做映射 | **P0** |
| 目标构造 | 短语合并+跨行拆分+邻词感知留白;压字 0.2–3.5%、误圈邻词 0%、包围 ≥0.89 | 斜体/旋转字只能按轴对齐框(layout 无 angle 字段) | P1 |
| OCR | 单引擎(百度云);热调用 0.5–1.4s/页;缓存命中零请求 | 断网不可用;小字/低置信框无局部重识别;无角度输出;供应商锁定 | P1 |
| AI 规划输入 | **135 个逐字候选**,无行/卡片上下文(实测 `candidate_tokens` 输出) | 同文字多处出现(两张卡片都有"9月30日")时模型只能猜实例 | **P0** |
| 墨迹渲染 | PIL 画线+噪声;24 帧 38ms;全幅 1920×1080 帧 10.6KB/张 | 画线式墨迹的"钢笔感"仍强于"毛笔/马克笔感";全幅帧有优化空间 | P2 |
| 编辑器预览 | 画布内是矢量轮廓,导出是栅格墨迹 | 用户编辑时看到的与成片不完全一致 | P1 |
| 评测集 | 1 页冻结样本 / 3 用例 | 无法声明普遍精度 | P1 |
| 端到端速度 | OCR 0.5–1.4s/页(网络);确认→时间轴+墨迹 <0.5s/页;Remotion 282 帧 ≈1min | 整体可接受;OCR 网络延迟与帧资产体积是可压缩项 | P2 |

### 1.2 已达标、不需要再投入的项

- 空间精准:压字率 ≤3.5%(第一轮为 10.9%–42.3%)、误圈邻词 0%(第二轮曾 8–11%);
- 确定性:同输入墨迹帧/时间轴逐字节一致;
- 输出门禁:enabled=true 时缺帧/旧哈希/版本过期拒绝渲染;
- 失效矩阵:换图/改稿/重生成音频的保留与失效分离。

## 2. 开源调研(含本机可安装性实测)

### 2.1 词级时间对齐(解决 P0 时间误差)

| 方案 | 是什么 | 许可证 | 本机实测(Python 3.13 dry-run) | 结论 |
| --- | --- | --- | --- | --- |
| **MiniMax `timestamp_enabled: word`** | 我们已在用的 TTS 供应商官方词级时间戳(`t2a_v2`,同步接口支持 sentence/word/word_streaming 三档) | 商用 API(已在用) | 无需安装——`scripts/minimax_tts.py` 当前只传了 `subtitle_enable`(句级),加一个参数即得词级 | **首选**。合成器自己输出的时间就是 ground truth,理论误差≈0;音频与文本天然对齐,无 ASR 误差 |
| **faster-whisper 1.2.1** | CTranslate2 版 Whisper,内置词级时间戳(交叉注意力 DTW) | MIT | ✅ 解析通过,依赖仅 ctranslate2/onnxruntime/av,**无 torch**,体量小 | **次选**。适合"音频已生成、供应商无时间戳"的场景回填;中文词级精度中等(±0.1–0.3s) |
| **WhisperX 3.8.6** | Whisper 转写 + wav2vec2 CTC 强制对齐(音素级) | BSD-2(代码);中文对齐模型 `jonatasgrosman/wav2vec2-large-xlsr-53-chinese-zh-cn` 为 Apache-2.0 | ⚠️ 解析通过但拉入 torch+pyannote(数 GB) | 备选。对齐质量最高(文献报告 >90% 准确),但重;按既有规则放可选 worker 子进程,不进主依赖 |
| stable-ts 2.19.1 | Whisper+精化词级时间 | AGPL-3.0 ⚠️ | ✅ 解析通过(拉 torch) | 不推荐:AGPL 对分发有传染性顾虑,能力与上面重叠 |
| MFA 3.4.2 | Kaldi 系强制对齐,有中文模型 | MIT | 未测(需 Kaldi 生态) | 不推荐:Windows 部署重、链路长,收益不高于 WhisperX |

**结论:三级降级链 —— MiniMax word(首选,零依赖)→ faster-whisper(轻量本地回填)→ 句级(现状兜底)。** 不需要引入 torch 到主进程。

### 2.2 OCR(解决旋转/局部重识别/离线)

| 方案 | 是什么 | 许可证 | 本机实测 | 结论 |
| --- | --- | --- | --- | --- |
| **RapidOCR 3.9.2** | PP-OCR 系模型的 ONNX 封装;v3.0 起集成 PP-OCRv5(旋转/手写场景增强);DB 检测输出四点多边形,可开角度分类 | Apache-2.0 | ✅ 解析通过,依赖仅 opencv/pyclipper/shapely(无 paddle、无 torch),**可进主进程** | **首选本地引擎**。三个用途:①断网/配额耗尽时的回退引擎;②ROI 裁剪+放大的局部重识别;③为 layout 增加角度字段 |
| PaddleOCR 3.7.0 | 上游全量版 | Apache-2.0 | ✅ 解析通过(拉 paddlepaddle 3.3.1,较重) | 不必直接用——RapidOCR 即其模型封装 |
| EasyOCR / Surya | torch 系 | Apache/GPL混杂 | 解析通过(重) | 不推荐:中文精度/体积比不过 PP-OCRv5 路线 |
| 百度云(现状) | 通用文字识别 | 商用 | 已在用,字级框质量好 | **保留为主引擎**;其 `vertexes_location` 顶点亦可换算角度,先于本地引擎利用 |

### 2.3 手写墨迹质感(stamp 笔刷范式)

开源界成熟范式是**纹理盖章(stamping)**:沿中心线按 spacing 插值盖笔尖位图,
尺寸/透明度由压力曲线驱动,笔尖带 hardness 与纸纹(Krita 的 libbrush、
apoorvaj.io 的 stamp 四参数、Hertzmann 的 SBR 综述是直接参考)。
无需引入第三方库——用现有 Pillow 实现盖章渲染即可,效果显著优于现在的
"画线+全局限噪"。真实笔迹模板可后续从有明确授权的在线手写数据集
(如 CASIA-OLHWDB,研究授权)取样,但**首期不引入数据集**,
先把盖章引擎做对。

## 3. 优化方案(四轨)

### T1 时间精准(P0,预期收益最大)

**T1.1 MiniMax 词级时间戳直连(首选,1 天)**

1. `scripts/minimax_tts.py`:payload 增加 `timestamp_enabled: "word"`
   (同步接口),响应解析新增 `word_timestamps`(词 + time_begin/end);
2. `narration_audio_service` 落盘 `audio_timeline.json` 时:
   `segments` 保持句级(字幕用),新增 `words` 数组
   `{text, start, end, sentence_index}`;
3. `annotation_alignment.py` 新增 `word_times_from_provider(audio_timeline)`:
   把 anchor 的原文范围经"念法展开映射"对到词区间起点(见 T1.2);
4. `annotation_timeline` 优先消费词级起点,降级链 word → sentence → manual,
   `temporal` 状态如实标记;`inputs` 记录 `timing_source`。

**T1.2 念法展开映射(数字/百分比的原文↔发音对齐,2 天)**

建立 `spoken_map`:原文 token 序列 ↔ TTS 实际念法词序列的映射器:
- 规则覆盖:数字("9月30日"→"九月三十日")、百分比("23.5%"→
  "百分之二十三点五")、日期/时间/单位缩写;确定性规则先行,覆盖不到
  再用 LLM 一次性生成映射(带缓存);
- 映射存 `word_alignment.json`,anchor 定位 = 在词序列里找到
  映射后的念法片段首词时间;
- 这同时让"音频重生成只补时间"的既有承诺在词级成立。

**T1.3 faster-whisper 回填(音频已存在且无供应商时间戳时,1 天)**

`annotation_alignment` 增加 `align_with_faster_whisper(audio, expected_text)`
适配器:用已知发音文本做 constrained 转写参数(temperature=0,
initial_prompt=讲稿),只取词时间戳不做转写内容;失败自动落句级。
可装性已验证,依赖轻,可作为 `ppt-studio[align]` 可选 extra。

**验收门槛:word_aligned 起点误差中位数 ≤200ms、P95 ≤350ms
(在 ≥10 页真实样本上,以人工标注真值或词级供应商时间戳交叉验证);
句级误差现状 0.75s 必须降为个例。**

### T2 空间与语义精准(P0/P1)

**T2.1 角度感知的 layout(2 天)**

- layout schema 增加 `angle`(来自百度 `vertexes_location` 四点换算,
  或 RapidOCR 的角度分类);`annotation_target_resolver` 排序与
  "同行相邻"判定改用**沿基线投影**而非轴对齐 x;
- 几何层对旋转目标在文字局部坐标系生成笔迹,再旋回画布
  (方案二 4.3 已预留"目标局部坐标变换",本项落实);
- 无角度的旧 layout 兼容:angle=0 走现有逻辑。

**T2.2 RapidOCR 本地回退 + ROI 局部重识别(2 天)**

- `annotation_ocr_rapidocr.py` 适配器,接口与 `annotation_ocr_baidu` 一致
  (engine_version/config/错误分类);百度配额耗尽(417/419)或未配置密钥时
  自动回退,缓存键独立;
- ROI 重识别:对 `probability < 0.9` 或高度 <20px 的候选,裁剪
  上下文 2× 区域放大 2 倍后重识别,记录 `crop_origin/scale`
  并逆变换回原图坐标(layout 记录,评测验证);
- 双引擎在冻结集上对比字框 IoU,择优作为"高置信来源"字段。

**T2.3 规划输入升级为短语候选(R4 补课,1.5 天)**

`compose_plan_prompts` 的 candidates 从 135 个单字改为:
`{candidate_id, text(整词/日期), line_text(整行), region_id(卡片),
region_label}`;同词多卡片保留独立候选;确定性预筛选(日期/数字/百分比
等价写法)先给出一组高分候选,模型只做实例选择,选 `candidate_id`,
程序展开 token_ids。预期把"选错实例"类错误压缩一个数量级。

### T3 手写效果(P2,但用户感知直接)

**T3.1 盖章式笔刷渲染(2 天)**

`annotation_ink` 增加 stamp 渲染路径:
- 预生成 2–3 个笔尖位图(圆头马克笔/扁刷;带 hardness 渐变与纸纹);
- 沿中心线按 spacing(≈笔宽 15%)盖印,尺寸/alpha 由 width_profile 与
  速度(快→墨淡、慢→墨重)驱动;起收笔自动出现干笔效果
  (压力低时 stamp 间隔变大、透明度低);
- 参数与现有确定性要求不变(同种子逐字节一致);
- 荧光笔改用扁刷 stamp + "double-pass 错位叠加"模拟重叠加深。

**T3.2 模板库扩充(1 天)**:圈模板从 3 个扩到 6–8 个
(扁圆/竖长/带明显起笔勾),按目标宽高比自动选择;
"换一种笔迹"按钮循环模板。

### T4 速度与工程(P2)

1. **墨迹帧裁剪存储**:帧只存笔迹包围盒区域 + `region` 元数据,
   Overlay 按区域定位;预计帧体积降 80%+,Remotion 加载与编码更快;
2. **内容寻址缓存**:ink 目录按 `(几何哈希, 种子, 样式)` 命名,
   重复导出零重渲染;
3. **并行渲染**:`render_and_write` 多进程池(页级并行),50 页项目
   确认阶段墨迹渲染从串行秒级降到并行;
4. **编辑器位图预览**:编辑画布直接显示 `full.png`(服务端已在
   get_slide 响应中返回 strokes;补一个 ink 预览 URL 字段),
   编辑所见=导出所得;
5. **评测集扩到 ≥20 页/40 目标**(含 ≥8 页盲测),把三轮对比脚本
   `eval_annotation_precision.py` 作为每轮回归门槛。

## 4. 实施顺序与依赖

```
T1.1 MiniMax 词级 ──→ T1.2 念法映射 ──→ (T1.3 可选)
T2.3 短语候选(独立,随时可做)
T2.1 角度 layout ←─ 依赖 T2.2 RapidOCR(角度来源之一)
T3.1 盖章渲染(独立)
T4 全部独立,穿插做
```

建议两批交付:第一批 T1.1+T1.2+T2.3(纯精准,4.5 天);
第二批 T2.1+T2.2+T3.1+T4(5 天)。每批结束在扩评测集上出对比报告。

## 5. 风险与回退

- MiniMax word 时间戳的实际粒度/稳定性需实测(部分音色可能不返回);
  失败自动落回句级,不影响现有功能;
- RapidOCR 首次运行需下载 PP-OCRv5 ONNX 模型(数十 MB):按既有规则
  **不自动下载**,在设置页显式安装/下载,记录到 adapter-decision;
- 念法映射规则覆盖不全时走 LLM 兜底,必须缓存并允许人工纠正;
- 所有新引擎都走适配器接口 + 缓存键隔离,任何一环可独立回退到现状。
