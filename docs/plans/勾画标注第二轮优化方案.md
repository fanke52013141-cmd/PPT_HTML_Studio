# 勾画标注第二轮优化方案

日期：2026-09-27。审阅对象：本地 `5670f0e` 基线上的未提交勾画实现。

本文是基于当前源码的优化方案。本轮未改生产代码、未调用付费 OCR/LLM、未运行实际视频或真实样本评测；下述“已确认”指代码行为，不能据此推定所有真实页面的误差比例。既有 acceptance-report 中的测试结果是前一实施轮的记录，本轮没有重跑。

用户最新要求优先：勾画标注是第六模块，后续模块顺延；去掉勾画“可选”标签；圈、线需要老师手写质感；提高定位准确度。本文覆盖上一份交接文档中关于勾画使用可选导航徽标的设计。

## 1. 结论和实施重点

目前已经有独立服务、存储、编辑界面、OCR 和路径播放基础，适合在这些边界内修正。主要问题分为四类：

1. 导航沿用了上一版方案的可选入口，编号、完成状态和用户预期不一致。
2. 编辑端直接画标准椭圆，导出端的椭圆也只是规则曲线加整体缩放/平移；没有真实的局部形态和笔压节奏。
3. OCR 字符被拆成独立候选，模型缺少句子/卡片位置上下文；目标构造缺少“字符 → 同行短语 → 分笔区域”的中间层。
4. 编辑预览、导出、时间定位及版本校验尚未形成一致链路。只改样式无法保证用户看到的圈和视频里的圈相同。

推荐实施顺序：先修编号和确定性缺陷；再统一目标几何与预览/导出；然后实现手写笔迹；最后用真实样本优化选择目标和音频时机。精度评测从第一阶段开始记录，避免最后才发现算法改善不了实际页面。

## 3. 模块六：导航与流程优化

### 3.1 用户看到的顺序

| 数字人显示 | 导航顺序 |
| --- | --- |
| 是 | 1 导入文章 → 2 分镜规划 → 3 图片生成 → 4 AI Mask 标注 → 5 旁白与音频 → **6 勾画标注** → 7 数字人讲解 → 8 作品输出 |
| 否 | 前六项相同 → 7 作品输出 |

勾画导航、页面标题和流程说明均取消“可选”徽标/提示，使用与其他模块相同的数字、标题、选中态和完成标记。不要只修改 index.html 中静态文本，其他地方的序号必须使用同一来源。

内部现有 `data-step=10`、API 和旧步骤 ID 可保留作为兼容键。用户显示序号与内部编号分离，不能把旁白内部 step=6 改成新勾画的内部 step=6。新增 `display_flow(context)` 或等价纯函数，由 feature visibility 输出排序后的项目；DOM、visibleStepNumber、上一页/下一页、帮助和进度均消费它。

### 3.2 模块完成与不用勾画的项目

取消可选标签不等于每页必须硬加一个圈。建议新增模块决策状态：not_started / editing / confirmed / no_annotations / stale。只有 confirmed 或用户明确选择“本项目不添加勾画”才算该模块处理完成。enabled 只表示输出是否包含笔迹，不能决定完成状态。

新项目：音频确认后的主流程进入模块六；用户生成并确认，或明确不添加，然后继续。旧项目没有勾画文件时维持可导出兼容，模块摘要说明尚未配置；不能因升级把历史项目卡住。旧项目进入并使用勾画后适用新的确认规则。

项目总体进度采用同一模块状态源；建议新增勾画为需作出决策的流程项，数字人继续按既有功能开关参与导航。进度分母规则、One-click 和 Agent checkpoint 必须一起更新并测试，不能简单把 `optional:true` 删除，让后端不存在的 status[10] 永远 pending。

首期保留项目“不添加”的明确决策，避免必须画无意义的圈。若之后要求 One-click 自动完成勾画，作为单独自动化工作包：生成、对齐、待复核暂停和恢复必须全部接入，不在本次导航调整中偷偷触发新 API 成本。

代码：`static/flow.js`、`workspace_navigation.js`、`workflow_state.js`、`index.html`、`digital_human_panel.js`、`annotations_workspace.js`、项目摘要/Agent mapping。同步 AGENTS.md 和上一轮交接文档的旧编号说明。

## 4. 老师手写质感：轨迹、笔触、节奏一起改

### 4.1 显示技术与视觉要求

用户反对的是机械圆圈的效果。目前确实用了规则椭圆。底层可以继续用 SVG 承载自定义手写轮廓，也可以栅格化同一笔迹；关键是输出可验证的手写形态，不能继续用 `<ellipse>` 冒充手写。

推荐保留 SVG 作为确定性渲染载体，使用“中心线 + 笔宽曲线 → 笔迹轮廓”生成器。这样不新增整套重依赖，并能与当前 Remotion 接入。最终是否满足用户要求以真实尺寸样片确认，不以“使用了贝塞尔”作为完成条件。

### 4.2 两层笔迹模型

第一层是目标几何：精确描述要圈的短语、文字方向和安全留白。第二层是笔迹外观：在不碰到文字、不圈入邻词的范围内改变轨迹。二者独立，使“更自然”不会造成“更不准”。

建议 stroke v2 存储：points/曲线、cumulative_lengths、width_profile、speed_profile、start_offset、duration、seed、preset_version、目标局部坐标变换。seed 只在创建或显式“换一种笔迹”时改变，保存后稳定；重新导出不得换一种形状。

### 4.3 手写圈

- 建立少量经人工筛选的手写圈模板；可用自行录制、有明确来源的笔迹。也可先用控制点生成候选并人工挑选，不能把程序生成轨迹称为真实笔迹采样。
- 模板保留非对称：左右弧度不同、顶部略偏、落笔位置轻微变化；避免全局同比例缩放和简单位置抖动。
- 起笔/收笔有细到粗、粗到细变化；允许小缺口或短重叠。不能用大量逐点随机噪声做成抖线。
- 形变在文字局部坐标中完成，最后施加文字方向；短词和长句采用不同纵横比模板，防止长词两端被勒住。
- 用“文字保护区”和“邻词排除区”约束模板；路径最内侧不得穿字，最外侧不得圈入邻词。空间不足时降低扰动/减小留白，仍无解则提示改用横线。

初始调参范围（仅样片起点）：局部非对称约短边 2%–5%；笔宽约基准的 0.7–1.2 倍；起收笔占弧长 5%–12%；圈的缺口约 5°–15°或小幅收笔重叠。所有值最终由目标大小和邻近留白约束，并用样片校准。

### 4.4 手写横线与荧光笔

横线沿文字基线生成，保留轻微弧度/倾角和收笔上扬；粗细随行笔平滑变化。长横线控制低频变化，避免周期正弦波看起来像波浪线。跨行每行一笔，不在两个文本行之间连线。

荧光笔改为扁笔刷轨迹扫过，轻微不齐的端部、低浓度、稳定笔宽。不要在起笔时显示整块矩形；0% 真正不可见。首版优先做好圈和横线，荧光笔复用同一播放协议。

### 4.5 行笔节奏

每笔独立安排 start/draw_end：起笔稍缓、主体快速、转弯略慢、收笔减速。跨行分笔有短暂抬笔间隔，默认样片可从 60–120ms 起调。同一条标注的多笔按阅读顺序执行，不能把同一个 progress 传给所有 strokes。

笔迹绘制速度沿弧长计算，压力轮廓在固定轨迹上随进度显露。画完保持稳定；轻微纹理应预计算，不能逐帧噪声。播放采样接收实际 fps，避免目前固定 30fps 的量化与其他输出帧率冲突。

### 4.6 预览和导出统一

编辑器不得重新用 bounds 画另一种椭圆。通过受 revision 保护的几何预览接口返回正式 strokes，编辑态以 progress=1 显示，播放态按时间显示，Remotion 消费同一数据和采样器。属性拖动可节流/乐观预览，但正式保存后必须替换成权威结果；迟到响应按 revision 丢弃。

选中框、拖动手柄、候选轮廓作为编辑辅助单独叠加，不进入成品。统一 bounds、canvas、缩放和坐标转换。对照测试必须覆盖多字短语与跨行，不能仅单矩形。

## 5. 标注精准度：先修目标构造，再优化模型

### 5.1 增加“短语目标解析器”

建议新增 `annotation_target_resolver.py`，职责是从被选择的真实 OCR tokens 构建可画目标，不处理 LLM 请求或文件保存。

输入：layout_revision、token_ids、行/区域归属、字框、基线方向、样式。输出：ordered_tokens、screen_quote、fragments、baseline、target_geometry、mask_group_ids、quality_issues。

规则：

1. 拒绝未知/重复 token、失效 layout revision、越界或退化框。
2. token 按 line_id、阅读顺序、沿基线投影排序，不依赖模型返回顺序。
3. 同行连续字符组成一个短语片段，圈整个词。例如“9月30日”的五个字框合成一个目标圈。
4. 同行不连续选择若中间有未选字符，不能跨过它们合并；保留分离片段或要求用户确认。
5. 跨行拆成多个片段；不同卡片不能因文字相同而合成一个大框。
6. 保留原四边形/局部坐标，不能先变成轴对齐外接框再丢掉旋转信息。
7. 目标区域引用 Mask 作为上下文及可见时刻证据，实际文字边界以 OCR/人工选择为准；静态图无需依赖 Mask。

`target.quote` 必须是画面 OCR/纠正后的文字；`anchor.quote` 是讲稿文字。两者可不同，使用映射保存关系。改 token 范围后只重新解析目标，不重跑整页 TTS 或 AI Mask。

### 5.2 AI 输入恢复必要上下文

当前输入被压缩为散落单字，会迫使模型猜测“这个字属于哪句话”。下一版使用短语/文字行候选：

```json
{
  "beat_id": "b2",
  "spoken_text": "这里提醒一下，报名在九月三十日截止。",
  "candidates": [
    {"candidate_id": "c12", "text": "9月30日", "line_text": "报名截止：9月30日", "region_id": "card_a", "region_label": "报名时间"},
    {"candidate_id": "c18", "text": "9月30日", "line_text": "缴费截止：9月30日", "region_id": "card_b", "region_label": "缴费时间"}
  ]
}
```

模型选择 candidate_id 和讲稿锚点；程序再展开为真实 token IDs。若选取整行中的子串，返回 line_id+quote+occurrence，程序解析范围，不能让模型发明字符框。对于结构化数据无法区分的图表/同名位置，再附局部裁剪和必要页面上下文；不默认每次重复发送整图及冗长坐标。

确定性预筛选支持常见日期、数字、百分比的等价写法，保存规范化映射，不能改写原文。不同区域的重复词保留独立候选。候选数量超限按区域分页，最终跨页冲突校验，不静默截掉后面的候选。

按 optimize-prompts 技能落实：模板、真实 user payload、解析器、帮助/完整预览、旧默认迁移和测试同改；保护用户自定义 Prompt。新增字段每个都应解释它支持的选择决策，纯坐标/路径仍由程序计算。

### 5.3 空间质量检查与局部复核

不要仅凭模型 ambiguous=false 就标 spatial=valid。至少检查文字匹配、区域一致、字符连续、邻词排除、是否越界及识别粒度。字符数变化的人工纠正必须触发局部重定位/待确认。

对小字/低可信框/倾斜文字采用局部重识别：从原图裁剪适当上下文，可放大后再 OCR，记录 crop_origin、scale 和 rotation，明确把结果逆变换回原图。当前 layout 的 ROI 只是缓存/元数据字段，不能当作已经实现了局部裁剪与坐标恢复。

第一轮先保留现有 OCR 适配器评估解析层修正效果；只有样本证明原始框质量仍是瓶颈，才对相同冻结样本比较其他 OCR 方案。是否更换供应商依据目标框误差和人工修正量，而不只看识别文本正确率。

### 5.4 人工修正体验

- 在画面上拖选连续文字形成短语，支持增减首尾字；候选列表按文字行/卡片显示，避免一长串单字按钮。
- 同词候选显示局部缩略图和所属卡片；点选即画面定位，不能只靠相同文字区分。
- “换目标”修改当前条目，不默认新增条目。
- 支持直接拖动、调整留白/大小，并实时显示同一正式手写笔迹；保留样式、讲稿锚点和锁定状态。
- 增加“圈偏了 / 多圈了字 / 少圈了字 / 时机不对”反馈分类，保存修正前后几何和原因用于离线评测；不未经授权上传用户数据。

## 6. 时间准确性与正式输出补齐

目前只有 sentence_fallback：同一语块里不同关键词都会从整句起点开始。需单独接真实字词对齐，在原文 → TTS 实际发音文本 → 音频之间保留范围映射，按 anchor.range 取发音时间。没有可靠结果时清晰显示句级/人工模式，不能用平均分时替代。

事件时间统一为音频内时间 + audio_start_sec + 相对偏移；再叠加页面在作品中的起点。复用最终页长计算，不能把内容时长当最终页长。Reveal 目标未显现时不得起笔；若为了等显现导致偏离关键词太远，转为待复核，而不是无限延后。

渲染编排必须在生成 props 前构建/验证勾画产物。enabled=false 时忽略旧 timeline；enabled=true 时缺文件、未确认、输入哈希不匹配、解析器版本过期均应返回可操作错误。通过前端 readiness 不足以保护直接 API/Agent 渲染请求，后端 worker 也要复查。

新增有效内容 fingerprint、sidecar 勾画版本/输入摘要；冻结渲染输入，避免用户编辑时把旧输出登记成新版本。同步 Agent capability、模型 parity 和矩阵。这些作为正式交付前的 P0 项，与视觉打磨并行安排，不用漂亮预览掩盖导出缺口。

## 7. 分阶段实施和验收

| 阶段 | 改动 | 验收 |
| --- | --- | --- |
| R0 基线与故障样本 | 固定当前代码摘要，收集现有项目的只读副本；记录错误类型 | 至少分别有多字圈、重复词、跨行、倾斜、句尾触发、换图旧缓存案例 |
| R1 模块六与确定性缺陷 | 编号/状态、bounds.right、opacity=0、输出版本门禁 | 两种数字人显示模式编号正确；真实 DOM path 无 NaN；旧项目兼容 |
| R2 目标解析与两端统一 | 短语片段合并、跨行拆分、旋转坐标、正式 strokes 共用 | 五字日期为一个圈；跨行两笔；编辑预览与导出几何一致 |
| R3 手写质感 | 模板/局部非对称、笔压轮廓、起收笔、速度/抬笔、荧光推进 | 圈/横线各提供多个真实尺寸样片，用户能看出手写且不压字；重渲染一致 |
| R4 语义选择与修正 | 结构化候选、上下文、局部 OCR、重复词定位、目标修正 | 冻结集准确率和人工修正次数优于旧版；错误可定位到阶段 |
| R5 音频同步与完整回归 | 字词对齐、Reveal 时机、最终视频/变速、Agent 与历史输出 | 音画同步门、真实 MP4、Agent、旧项目全流程通过 |

每阶段保持可回退版本，保存旧输出用于 A/B。STROKES_VERSION、resolver、候选/布局 schema 与 Prompt 版本按实际变化递增，迁移时保留人工选择和原始快照；不能自动把所有用户手动圈换成新位置。

## 8. 测试与质量标准

### 8.1 必补自动化用例

- `test_visible_flow.js`：数字人显示/隐藏、模块六编辑/完成/无标注/失效、新旧项目、进入/恢复/下一步；不能只测数组中有 step10。
- 编辑器 DOM 测试：真实调用 renderAnnotationOverlay，校验 path 的每个数值有限；0% 不可见；多字和跨行片段正确。当前纯 core 测试无法捕获 bounds.right。
- target resolver：重复词不同卡片、同行连续/不连续、跨行、旋转框、乱序/重复 token、纠正字符数变化、日期/百分比等价文本。
- 几何：同输入一致、不同 seed 有局部形态差异、保护区不相交、邻词不误圈、短词/长词、页面边缘、最大采样量仍保留完整收笔。
- 播放：跨行顺序、多笔间隔、0%/退出连续、荧光推进、25/30/60fps、暂停/seek、同帧结果一致。
- 时间：同语块两个不同范围不再固定同起点、重复词第二次出现、前置延迟只加一次、Reveal 晚显现、页尾/尾留白、manual 不被静默改写。
- 输出集成：点击实际确认/导出 API 生成 MP4 所需 timeline；关闭功能后旧文件不带入；修改图片/讲稿/音频/笔迹后旧输入拒绝；并发编辑不混合快照。

### 8.2 真实样本 A/B

沿用原交接目标：至少 20 页/40 个目标，至少 8 页冻结盲测。覆盖用户实际课件，而不只是规整合成图。分别记录：OCR 原框、模型选中实例、合并后片段、最终笔迹、最终起笔时间；这样能区分识字错、选词错、画圈错、时机错。

建议首期门槛：

| 指标 | 通过标准 |
| --- | --- |
| 目标实例选择 | 盲测整体 ≥90%，同时报告样本数与各类别；重复词不能靠总平均掩盖 |
| 笔迹空间 | 已确认样本不压目标字、不圈进相邻词、无越界；逐例人工复核 |
| 短语粒度 | 所有同行连续多字目标合为所需的一笔/一个圈；跨行不包成一个大框 |
| 时间 | word_aligned 起点误差中位数 ≤200ms、P95 ≤350ms；句级/人工分别报告 |
| 自然度 | 至少 3 名评审对旧版/新版匿名打分，目标新版手写自然度中位数 ≥4/5 且多数偏好新版；保留分歧样本，用户最终看片确认 |
| 两端一致 | 编辑最终笔迹与同帧导出几何一致，允许 ≤1px 抗锯齿差异；时间量化差 ≤1 帧 |
| 修正成本 | 记录每页修改数/耗时，目标相对旧版中位数下降 ≥30%，同时报告未改善类别 |

这些是拟定验收要求，不是本轮已测结果。每种样式制作“落笔前、半程、收笔、停留”四帧和一段带音频视频；截图用于看形状，视频用于看节奏，两者都要验收。

### 8.3 回归执行

所有测试使用临时 PPT_STUDIO_DB_PATH / PPT_STUDIO_RUNS_DIR，依照前一交接文档的隔离命令。不得把真实 runs 作为可写 fixture，不启动第二个共享真实数据的服务。

新增 target resolver、DOM 和正式导出集成测试后，执行定向 annotation Python/JS 测试、visible_flow/frontend_quality，再执行：

```powershell
python scripts/run_checks.py --level full --with-remotion
python scripts/generate_agent_contracts.py --check
git diff --check
```

逐条检查退出码，失败停止，不以最后一条成功覆盖前面的失败。将新增测试纳入 run_checks；对照当前 AGENTS.md Required Validation 补跑未覆盖项。实际渲染必须走正式入口，另检查原 Mask、字幕、数字人、音频确认、视频变速、PPTX 和旧项目。

最终报告保存到 `docs/annotation-validation/round2-report.md`：本轮实际代码版本/未提交补丁摘要、样本哈希、基线与新版指标、失败分类、测试命令/退出码、截图/MP4 位置、未完成范围。不得将“单测通过”表述成“标注已经精准”或“已实现老师手写质感”。

## 9. 给开发 Agent 的执行说明

> 按本方案优化当前已有勾画实现，保留现有未提交工作。先完成 R0/R1，并核对真实代码是否已变化。导航显示为第六模块，后续按数字人是否显示连续顺延，取消勾画可选标签；内部 API/步骤 ID 维持兼容。增加目标短语解析，修复预览与导出多字/跨行不一致；用同一受约束手写笔迹与采样实现编辑、预览、输出。然后补语义候选上下文、局部复核和字词时间定位。每阶段有回归证据，最终用真实页面和实际视频验证自然度、空间及时间准确率。不要只增加随机抖动，不要只调 Prompt，不要在未完成输出门禁和契约同步时宣布交付。
