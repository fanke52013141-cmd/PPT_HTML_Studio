## 结论与当前能力边界

产品目标应为“内容可视化与讲解动画”，PPT 是呈现模式和一种输出，不作为全部作品的数据上限。
用户认可现有混合页的方向；下一层要验证的是对象运动、时间编排和镜头，不必丢弃现有基础。
已验证的“生图提供美术资产、代码提供准确信息与控制”适用于场景动画；需要移动/表演的物体
必须提前分层，而非把静态整页资产整体平移就称为机制动画。

| 层 | 现有覆盖 | 当前缺口 |
| --- | --- | --- |
| 内容/关系/来源 | 八层分类可容纳现象、过程、时间和空间关系 | P01 具体关系仍只定义 contrast；真实过程数据要补卡 |
| 资产/原子/身份 | Text/Image/Vector/Group、固定资源版本、公开目标 | 持续角色、姿态帧、活动关节、视频素材的具体协议 |
| 风格与模板 | 图文分工、验收模板、内容容量 | 动态构图、运动范围、镜头/角色模板支持声明 |
| 时间 | t 时刻重新求值的原则，既有音频适配方向 | P01 只有 reveal/highlight/annotate，不含路径/角色/镜头动作 |
| 场景 | 页内画布、节点和分组 | 多镜头共用场景、跨场景持续对象、世界坐标与画面坐标 |
| 输出 | 分级视频/PPTX与明确降级 | 动画的逐帧一致性、镜头取帧、PPTX 静态化策略的实际实现 |

目录中的 T-CAMERA/T-MORPH/T-INTERACTION/E-SIMULATION 仅为 candidate，未具体定义、未实现。
P02 按钮切换也只证明有限状态的视觉分层，并非时间驱动动画内核。不能回答“现在全部支持”。

## 外部项目实际如何构建

它是浏览器 HTML 容器 + Canvas 2D 绘制；engine.js 接受时间，组合场景/转场，render.py
通过 Playwright 调 renderFrame(t) 取 Canvas 像素并交 ffmpeg。HTML 容器不意味着内容由 DOM 排版。
motion.js 提供时间函数；camera.js 处理世界与屏幕坐标、关键帧、推近与视差。
clip.js 接受语法、时长、规格、素材、数据和 cues；参数化片段有声明范围，不能无限自由生成。

参考目录把艺术风格与动画语法分开：风格决定视觉语言，语法决定如何讲，例如白板推导、
证据拼贴、动态文字、数据展开、角色讲解。一个产品可以支持多个语法，组合须有任务边界。
我们应增加“讲解动画配方”，不把这些名称全部当成颜色主题。

截图的年份顶栏、讲解员和回收一级，能在 spacex_lin/common.js 与 scenes/s05.js 中找到
相应机制；内容方向一致，不能据此声明截图对应公开仓库的完整当前成片。
y6 卡及 reference_films/spacex/README 明确：这是参考快照，角色 sprite 和口播等素材不随包。
第九种讲解员语法没有独立参数化片段。借鉴方法不等于复制目录即可运行截图动画。

## 需要补的最小架构，而非重做已有体系

建议组织为：内容/讲稿 → 可视化序列 → 场景与镜头 → 对象/资源/关系 → 动作轨 → 渲染与输出。
其中页面是固定镜头、布局受约束的场景特例；镜头是观察场景的一段时间，不自动等同换页。
同一场景可有多个镜头，镜头中也可逐步改变对象状态。词名变化必须伴随数据契约变化。

1. 场景结构：区分版式场景、对象/过程场景、互动场景；共享语义与原子，不强迫自由舞台套左右卡片。
2. 空间：对象局部坐标、世界坐标、屏幕坐标；镜头作用于世界，字幕/进度/年份在屏幕层。
3. 时间：文档/场景/镜头区间，各自明确原点；动画读统一时间，不另建墙钟计时；毫秒与秒显式转换。
4. 动作：先补 transform 与路径位移，再补镜头、姿态/帧序列、关系/数据变化；形变和模拟另定义。
5. 通道：position/rotation/scale/opacity/pose/camera 等明确所有权、冲突及叠加；不静默采用最后写入。
6. 资产：按独立控制单元拆角色/道具/前后景；脚底/关节/接触点、像素尺寸、帧时长及遮挡契约。
7. 模板：从页面版式升级到“场景骨架 + 讲解步骤 + 动作范围 + 镜头”，配方仍不保存某个课程正文。
8. 渲染：DOM/SVG 优先承载准确文字、图表、普通可编辑对象；Canvas 按需要承载粒子/复杂绘制。
   不全盘切换 Canvas；Canvas 对象同样要有模型身份、目标几何和可访问性/编辑支持声明。

几何检查也要改变：世界中的对象允许离开视口，不能沿用“所有节点每帧都必须在页内”。
应检查必需知识在指定讲解窗口可见、屏幕关键文字未裁切、字幕安全区、角色遮挡与追踪目标。
动态场景不存在一张最终帧展示所有必需内容的保证，验收要按时间覆盖与证据取帧。

这些是扩展提案，尚非正式字段。实施前按 HPS-018/021 填定义卡并修订 Schema，保留
P01 slides/slideOrder/Beat.slideId 0.1.0；新版本通过显式适配映射到场景，不全局搜改 slide 为 scene。
旧页式作品继续可读；持续对象/跨镜头语块的新范围必须独立定义，不能从 extension 偷塞。

## 美感与动效的验收

先用选定设定帧确认美感，再设计动作前、中、后的关键帧。动作应体现方向、变化、关系或
讲解焦点，避免给所有元素加漂浮让画面更忙。空间构图与时间编排必须一起设计。
定义动作目标、开始/结束状态、轨迹、节奏、停留、遮挡与镜头，让观众有时间理解变化。
动画增长/粒子数量不能伪造真实定量关系。重要内容的阅读停留从呈现完成开始计算。
检查空场、跳版、换姿双影、对象穿字、镜头裁切、字幕遮挡及回退残影。

不照搬 qa.py 的经验运动阈值来给美感打分；有意停顿、硬切和强调须人工解释。
其文字框景也有图像遮挡、段首/转场取样等盲区，应按我们的目标几何和实际合成补查。

## 接入边界和不宜照搬的实现

现有课程管理、讲稿、任务、音频时间轴、数字人、作品管理继续复用。新增场景编排输出
固定版本的渲染输入，再进入既有视频合成适配；不直接以外部 engine 替换现有业务服务。
视频与 HTML 动画优先验证；PPTX可输出关键状态快照或已支持对象，连续镜头/角色动作
要明确降级，不能让 PPTX 可编辑性反过来限制可视化能力。互动必须提供固定剧本才能导出视频。

不照搬：clip.js 的 eval/同步加载、无完整输入校验的容错丢 cue、render.py 的浏览器安全关闭
参数、round(duration×fps) 帧数规则。我们保留显式注册与输入校验、资产就绪阻断、
稳定 ID 和有理帧率/ceil 约定。外部代码不是生产安全与兼容门槛的替代。
上游主体为 MIT；若以后复制代码须保留许可。字体与笔顺数据有各自许可，不能按主体 MIT
推断全部素材可随意复用。本次没有导入上游生产代码或第三方素材。

## 建议下一轮实验顺序

先补场景/镜头与 transform/路径最小定义，再做一个 10—15 秒对象过程演示：保留已选
科普画风，用独立对象沿轨迹移动，标签按讲解出现，一次镜头聚焦；暂不加入复杂演员。
这个实验不需重做语音方案，可先用明确人工测试时间，之后消费既有时间轴。
通过暂停、跳转、倒放、同 t 重渲、关键帧与实际观看检查后，再做截图类似的 2D 讲解员样例。
如果直接在原水碗整图内让分子移动，需先拆分分子与碗，不把整图平移冒充内部运动。

本轮完成源码调研与扩展建议，未制作新动画、未执行外部引擎、未证明任何新动作支持。
应在 P03 Schema 定型前确认场景扩展，使课程演示成为内容可视化的一条路线。
