## 2. 音频时间轴与语音合成的区别

语音合成负责把讲稿变成音频；音频时间轴描述音频里的语块/词语在何时发生；动作时间轴
将这些时刻转换为元素出现、强调、勾画等动作。三者职责不同，即使部分语音服务返回
时间戳，也不意味着时间轴就是另一套语音合成方案。

本项目这几项都有已有基础：`audio_timeline.json`、语块 ID、provider 时间戳、
Qwen 强制对齐适配、人工校准，以及揭示/勾画的调度。代码核对发现当前锚点解析对历史
WhisperX 引擎结果还有迁移保护。因此不能按报告把 WhisperX 作为“缺失模块”再次接入。

本次只定义新 HTML 目标如何消费既有时间结果：语块身份 → 原文范围 → 已验证时间 →
HTML 公开目标 → 指定时刻的动作状态。已有音频生成、对齐、确认和校准流程继续复用。
源码存在不等于当前机器全部服务已经运行或验收；后续检查新画面接入，不重做模型比较。

## 3. HBA-01：风格规则落到可解析配置

借鉴 html-ppt-skill 的基础样式/主题划分与 ppt-master 的可读设计说明/执行锁分工。
参考：[主题与基础样式](https://github.com/lewislulu/html-ppt-skill)、
[ppt-master 技术设计](https://github.com/hugohe3/ppt-master/blob/main/docs/technical-design.md)。

我们已有正式契约与风格包定义，但还没有可执行 token 和解析器。新增的是对已选规则、
风格和实例约束的解析结果，不是再写一份与契约竞争的 `spec_lock.md`。

### 配置的所有权

| 对象 | 保存内容 | 所有者 | 不能代替的部分 |
| --- | --- | --- | --- |
| 公共参数 Schema | 类型、语义、允许范围、默认来源、覆盖权限 | 公共能力定义 | 不指定所有风格的同一组色值 |
| 风格值与组合规则 | 字色、字阶、空间刻度、描边、材质、配方与参考页 | 风格包 | 不重写组件职责、身份或时间逻辑 |
| 实例选择/覆盖 | 正文、素材选择、允许的布局及人工约束 | 页面实例 | 不得让模型自改容量和校验阈值 |
| 解析快照 | 实际使用的参数、来源、版本与哈希 | 派生生产数据 | 不另维护一套人工修改后的真相 |

token 可分基础值、语义角色、组件别名三层。例如强调色的基础值被解释为 `accent`，
讲解卡标题再引用 `accent`。组件使用语义角色；普通页面不能任意覆盖一串裸色值。
数据图表编码、用户导入素材和定义中允许的一次性例外应单独声明，不能靠“禁止一切 hex”
误伤内容。最终 CSS 与必要的 JS 配置从同一份解析结果生成。

### 首轮需要定义的字段

- 颜色角色及前景/背景配对；文字角色的字号、行高、字重、字体与中文回退。
- 间距刻度、边框、圆角、阴影、图标线宽；布局密度与安全区。
- 组件变体支持集、素材画风引用和动作默认；允许实例覆盖的字段及优先级。
- 每个有效值的来源、风格/组件/规则版本；缺值、循环引用、未知角色与非法范围的错误。

采用 Style Dictionary 作为编译器是候选，首个风格也可使用简单受控解析器。
如果选择 DTCG，应固定格式版本并使用对应结构；报告中的 hex 字符串/尺寸字符串示例
不是可直接当作完整 DTCG 2025.10 Schema 的正式输入。参考：
[Style Dictionary token 文档](https://styledictionary.com/info/tokens/)、
[DTCG 格式](https://www.w3.org/community/reports/design-tokens/CG-FINAL-format-20251028/)。

快照哈希能发现变化和防止旧产物误用，不能证明美感正确。仍需参数校验、真实排版和视觉审阅。
不复制外部工作流的逐阶段人工签字门；当前用户授权范围内完成可审阅结果，已有确认机制
按对应业务规则使用，不新增反复确认步骤。

## 4. HBA-02：从现有分镜到语义场景

PPTAgent 的编辑式生成与 Presenton 的模板数据结构可作为受约束生成的参考。
参考：[PPTAgent 论文](https://arxiv.org/abs/2501.03936)、
[Presenton 模板机制说明](https://github.com/presenton/presenton/issues/67)。

现有 `storyboard_planning.py` 已把 script/visual plan 转为 visual contract，包含
slide、element、group、content unit 和 narration beat 等身份。新的 HTML 规划应沿用
这组语义与映射，再加入组件、布局/配方、风格和素材槽位，而不是重新生成一组无关讲稿。

### 生成输入与输出职责

1. 系统提供当前允许的布局、组件、风格变体、字段、容量与素材能力。
2. 模型只选已登记能力并填内容/素材意图/动作目标；ID、版本和可计算字段由系统分配或保留。
3. 格式校验通过后检查内容覆盖、引用、风格支持、容量和资源需求。
4. 排版器生成几何，编译器生成 HTML 与动作求值所需数据。
5. 后续修改优先以小范围变更提案完成，保留未修改组件、绑定与人工覆盖。

| 输入内容 | 来源 | 需要保留 | HTML 中新增的解释 |
| --- | --- | --- | --- |
| 讲稿语块 | 已有 script/visual plan | 语块身份、原文与内容来源 | 绑定哪些公开目标 |
| 视觉元素 | 已有 visual plan | 意图、内容和可见文字 | 公共组件类型与语义内容 |
| 视觉组 | 已有 visual contract | 组与内容单元关系 | 目标集合；不再必须对应像素 Mask |
| 资源意图 | 既有视觉描述/风格上下文 | 引用与用户选择 | 独立插画/图标槽位及规格 |
| 时刻 | 既有音频/动作结果 | 来源、偏移与人工校准 | 对新目标求值；不重新识别音频 |

稳定 ID 不能用数组位置充当长期身份。既有部分规范化会补顺序 ID，接入时需要明确创建、
重排、复制、删除的身份策略与旧 ID 映射；不能假定现有补 ID 逻辑已满足全部 HTML 生命周期。

“模型编辑”可落实为替换文本、选择素材、调整允许布局参数、更新动作绑定等受限操作。
操作携带预期修订、目标和字段范围，先验证，再原子应用；并发旧提案应返回冲突。
操作名称与载荷要填写定义卡，本文没有新增运行 API。新建页面仍可生成结构化内容；
无需强制先存在一个完整模板再才能开始。

容量来自布局/组件定义。不能让模型在输出中同时填写 `value` 和任意加大的 `maxLen`。
数量和长度是预检；真实字形、换行和保护区仍需测量。

## 5. HBA-03：公共资产、风格配方与真实参考页

可借鉴外部项目把样式、单页布局、整套演示配方和预览分开维护的组织方法。我们已有
公共/风格/实例/派生四类归属，继续使用这套概念，不照搬 Brand/Style/Layout/Deck 作为
第二组相互重叠的业务对象。

### 资产库的最小分类

| 类别 | 注册内容 | 复用方式 |
| --- | --- | --- |
| 公共原子/组件 | 语义、输入、子项身份、公开目标、测量与动作接口 | 不同风格消费相同能力 |
| 布局 | 插槽角色、支持组件、容量、比例、保护区、溢出策略 | 同一结构接受不同内容与风格参数 |
| 公共呈现变体 | 同一职责的结构/绘制变化 | 风格选择，不复制业务逻辑 |
| 风格包 | 参数、变体选择、素材画风、密度与组合限制、参考页 | 同一场景切换，检查覆盖支持 |
| 页面/整套配方 | 表达目的、组合、页角色与节奏、默认讲解阶段 | 可展开为实例，保留语义可编辑 |

美感需要经过设计的搭配。第一种风格要有两列概念页的初始、逐步显示和最终参考状态，
长标题/长正文、不同素材比例的边界页。之后加入第二种风格，检验组件是否真正复用。
整套课件还要检查连续页密度、插图风格和视觉节奏，避免每一页各自好看但整套割裂。

参考页必须用真实教学内容渲染，不用写着“主题选项/内部参数”的诊断卡代表视觉效果。
可借鉴 frontend-slides 的真实预览思路，但不规定每次生产都出三套风格让用户重新选择。
参考：[真实风格预览](https://github.com/zarazhangrui/frontend-slides/blob/main/SKILL.md)。

建立可浏览的真实组件/布局/风格样例库，显示其 ID、版本和支持范围；元数据放在画布外。
预览隔离可用 iframe 或样式作用域，但不得每页复制一份不同的公共运行时。
注册索引、引用资源和参考截图需要一致性检查。

报告假定“我们已有 IDML/PPTX 模板资产”，当前没有证据确认这点。扫描工程资产时未发现
可直接使用的模板文件；生成作品与可复用模板也不是同一类资产。因此模板导入不作为
首轮前置。未来有实际模板时，再考虑解析几何、字体、截图和结构并人工抽象为公共布局；
不能把源文件全部坐标直接登记为通用布局。

## 6. HBA-04：生图用于独立素材，槽位负责装配

html-ppt-skill 的图片容器与 guizang 的素材槽位绑定可供参考。
参考：[图片容器用法](https://github.com/lewislulu/html-ppt-skill)、
[素材槽位校验](https://github.com/op7418/guizang-ppt-skill/blob/main/scripts/validate-swiss-deck.mjs)。

现有 AI provider、风格参考、模型设置、并发治理与素材确认可以复用；原图片阶段以整页
图为产物的编排需要增加 HTML 后端的素材任务，不应把独立图标假装成完整 slide 图。

### 素材请求与绑定必须分开

素材请求记录用途、内容意图、风格/参考资源版本、宽高比、透明需求、主体与安全留白、
允许裁切范围、控制粒度。素材产物记录实际尺寸、透明边界、资源 ID/哈希和审阅状态。
槽位绑定记录资源引用、contain/cover、焦点/裁切与允许的变换；排版后的坐标是派生结果。

具体 Schema、字段名及 provider 参数映射待定义。通用接口不能假设所有生图模型都支持
`negative_prompt`、IP-Adapter scale、seed 或透明输出；应登记实际能力，再选择有效参数。

| 使用场景 | 组织方式 | 需要验证 |
| --- | --- | --- |
| 两个概念逐个讲 | 两个独立素材，各绑定各自组件目标 | 可独立显示，不重新切整图 |
| 课程框图/流程箭头 | 数据和关系由 HTML/SVG 绘制，装饰插画独立 | 文字/数值准确、节点关系正确 |
| 一张完整照片 | 一个图片目标与焦点/安全区 | 允许裁切，不损失主体或证据信息 |
| 技术截图/已有图表 | 优先 contain 或明确的裁切授权 | 标签不被意外切掉 |
| 图内局部需要勾画 | 独立素材锚点或人工区域 | DOM 整体框不能替代内部区域身份 |

统一画风主要通过风格包、参考图、素材规格和批量审阅落实；同一色板可供 HTML 与素材
请求使用，但提示颜色不能保证像素精确一致。不自动色相吸附图表、照片或证据截图。
IP-Adapter/ControlNet/LoRA 的部署训练及报告中的固定参数不纳入当前任务。

课程文字、数字和需要编辑的标注优先放在 HTML/SVG；允许摄影中的自然文字、装饰纹理
或无需编辑的整图作为素材，但要明确控制与输出边界，不能把“禁止生图写任何字”扩为
不分用途的公共限制。

## 7. HBA-05：机器检查与美感审阅分别落实

借鉴 guizang 的静态检查、渲染测量、修复方向以及共享运行时同步检查。
参考：[检查器](https://github.com/op7418/guizang-ppt-skill/blob/main/scripts/validate-swiss-deck.mjs)、
[同步检查](https://github.com/op7418/guizang-ppt-skill/blob/main/scripts/check-presenter-runtime-sync.mjs)。

### 检查分层

| 层 | 检查对象 | 缺失/失败处理 |
| --- | --- | --- |
| 结构预检 | 注册能力、字段、引用、资源槽位、内容覆盖 | 拒绝非法输入并聚合独立错误 |
| 解析配置 | token 引用、取值范围、支持集、未声明覆盖 | 返回所属规则与修复位置 |
| 资源就绪 | 字体、图片解码、素材版本、所需脚本 | 必需资源未就绪禁止捕获 |
| 真实排版 | 文本截断、越界、保护区、间距、裁切、意外重叠 | 报告目标与可测量偏差 |
| 时间与动作 | 目标存在、状态边界、偏移、倒退与冲突 | 对当前输出明确阻断/降级 |
| 视觉审阅 | 重心、留白、层级、插图协调、连续页节奏 | 用实际页面与阶段画面审阅 |

报告里的居中禁令、8/12px 网格、14/32px 间距、21:9 比例和修复像素阈值是特定风格的
经验，不能成为所有风格的共同规范。公共规则要求检查和明确归属；具体值由风格、布局、
画布与输出定义。文字与背景配对的对比检查可参考 WCAG，但应区分字号、图像背景与
必要边界，不能把一组主题抽样通过推广为所有素材/状态合格。
参考：[对比要求](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。

### 修复闭环

诊断包括规则 ID、页面/组件/字段、严重度、测量值、阻断输出、修复方向和失败上下文。
修复优先保持内容：调整允许间距/布局参数 → 重新分配区域 → 更高容量布局或拆页。
字号只在允许范围内变化；缩写/删除改变信息，应作为单独内容修改提案记录来源和影响，
不以“排版修复”静默删掉知识点或人工内容。

独立错误可一次聚合；依赖字体就绪的测量不能在字体缺失时给出伪造结论。记录
passed/failed/skipped 的检查范围；本地缺浏览器可完成静态预检，但不能据此标记“视觉通过”
或发布需要真实渲染证明的作品。自动修复应有次数/耗时上限与修复前后证据。

截图或质量分数只能提示变化，不能自动决定美感。对同一输入的阶段关键帧审阅，区分
允许的装饰覆盖、分组重叠与意外遮挡；不能把一切矩形交叠都判为错误。

## 8. HBA-06：扩展已有时间消费与定位

现有 `scripts/remotion/src/Video.tsx` 已经使用帧号和插值，其 SceneLayer 仍是 PNG。
因此新增 HTML 画面适配和公开目标测量，保留现有任务/编码器与时间逻辑的职责。

1. 设计画布尺寸固定；浏览器预览整体缩放。9:16 使用匹配的布局/内容密度，不是永久强制
   1920×1080，也不只是缩小横屏。不同输出布局保留同一内容身份与讲稿关系。
2. HTML 内容目标及句内范围在字体就绪后测量，换算为设计画布坐标，考虑父组变换、
   裁切与多行矩形；勾画几何消费这些结果，逐步替换 OCR 定位来源。
3. 动作绑定公开语义目标；既有音频时间、offset 与视觉提前量须明确参考系，偏移只加一次。
   目标几何变化不自动重做音频，对齐变化也不自动重生成插图。
4. 普通 reveal 保留占位，状态按时间区间/进度求值；支持顺序播放、跳转、倒退与乱序取帧。
5. 参考外部 CSS 动画的视觉样式/缓动，转换成受控动作；不能直接把墙钟 transition 或
   canvas 随机效果当作视频取帧的唯一实现。

共享语义场景不要求共享 Vue/React 源组件。报告的“Slidev Vue 组件直接进入 Remotion”
不能当作现成方案；必要时共用计算/样式和资源，通过适配器输出不同运行表示。
暂不因报告重选课件框架或第二个视频引擎，先验证已有 Remotion 路线的新增适配成本。

## 9. HBA-07：PPTX 导出能力必须明确分级

现有 `pptx_export.py` 导出整页图片，`pptx_reveal_export.py` 导出逐步累积画面。
这两种任务管理和产物机制可复用；可编辑对象是新的转换能力。
参考：[ppt-master 能力映射](https://github.com/hugohe3/ppt-master/blob/main/docs/powerpoint-svg-mapping.md)、
[Slidev 导出边界](https://sli.dev/guide/exporting)。

| 路径 | 场景到 PPTX 的处理 | 应如何声明 |
| --- | --- | --- |
| 最终状态整页图 | HTML 指定状态截图后调用图片型导出适配 | 图片型，页面文字不可原生编辑 |
| 分步状态图 | 相同动作状态序列生成页面 | 分步快照，不是 PowerPoint 原生动画 |
| 基础可编辑对象 | 从场景及测量结果写文字、图片、基础形状 | 只对已验证对象与属性声明可编辑 |
| 混合输出 | 受支持对象原生，复杂效果局部转图 | 给出转图对象、原因、保留/丢失语义 |
| 超支持集 | 拒绝或按事先选定策略降级 | 未登记能力不默认支持 |

首轮可编辑范围建议从文字、图片、矩形、圆和直线开始。记录位置、字号、中文字体、
行高/段落、填充、描边、裁切、旋转与 Z 序的实际支持。图表/表格、母版、公式、
连接线编辑性与原生动画以后分别定义，不能因为有 HTML/SVG 就宣称全部支持。

写入几何优先消费场景与浏览器测量结果，不逆向猜任意 HTML 的业务语义。导出时保留
内容/对象身份用于结果诊断。字体差异和 PPTX 换行可能影响布局，须在目标软件验证。
截图模式保真和原生编辑模式需要分别验收。

报告 A 的 `1pt = 1px @96dpi` 是错误单位关系：CSS 的 1in = 96px = 72pt，
因此 1px = 0.75pt。输出应以设计画布与目标尺寸的比例换算，并分清 CSS 像素、设备像素
和 PPTX 单位，不能把缩放后浏览器窗口坐标直接写入文稿。
参考：[CSS 绝对长度](https://www.w3.org/TR/css-values-4/#absolute-lengths)。

不默认采用“含原文字的整页截图再叠文字框”。这会留下旧文字像素，改字后可能重影。
混合路径需要独立的无文字背景/素材层及原生文本，或完整对象重建，并实际测试修改内容。
单页转换失败也不能无提示插空白页后宣布全部成功；导出摘要逐页记录结果，必需页面失败
依所选输出策略阻断或交付明确的部分结果。

## 10. HBA-08：复用现有任务与最小失效体系

报告中的槽位级重试和固定输入有用；新系统已有任务、输入指纹、失效登记和确认链，
应扩展这些服务，避免独立“HTML 任务数据库”绕开它们。

| 变化 | 新画面应重算 | 通常可复用，但须检查具体依赖 |
| --- | --- | --- |
| 文本修改 | 内容覆盖、布局、范围锚点、画面与输出 | 未改变的素材；讲稿不变时已有音频 |
| 换色/描边 | 配置解析、画面、视觉验收、输出 | 几何/音频；素材若依赖改动色板须重新判断 |
| 更换插图 | 素材绑定、裁切/几何、画面与输出 | 讲稿与音频；尺寸/锚点变化需重新定位 |
| 改布局 | 几何、文字分行、标注、画面/输出 | 素材与音频；相关人工覆盖需重新校验 |
| 音频/校准变化 | 已有时间结果的更新、动作时间、口型与视频 | 文本/素材与静态排版 |
| 无变化保存 | 不失效 | 当前有效产物与确认 |

这是需要按实际字段登记的建议矩阵，不能直接覆盖 `impact_registry.py` 的现有规则。
图片后端仍验证图片/Mask；HTML 后端验证场景/资源/排版/目标/时间，不能伪造旧 Mask
满足图片门禁。文件路径登记到 `repository_paths.py`，新增持久化按迁移和 Agent 契约同步。

重试固定场景修订、风格/组件版本与素材请求哈希，只重做失败素材或受影响页面。
失败资源的占位可以用于草稿预览；正式导出是否允许必须由输出策略声明，不能静默用
占位图替换教学证据。已经确认的内容、人工调整和有效缓存不能被自动回滚成模板默认值。
