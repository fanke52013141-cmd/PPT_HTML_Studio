1.2  ★ 我必须纠正自己之前的一个误判
--------------------------------------------------------------------------------

  我在给子agent 的指令里写「ppt-master 不走 HTML，直接生成原生 PPTX，
  和用户方向相反」——★【这个判断是错的】。

  它的真实架构（目录树实证）：

    源材料 → source_to_md.py → 规划 → 手写 SVG → svg_to_pptx/ → DrawingML → .pptx
                                            ↑                ↓
                                      svg_finalize/ ←── pptx_to_svg/（反向投影）

  ★ 【SVG 就是它的中间表示，而且  双向的】：
    svg_to_pptx/  40 个模块（drawingml/ 12 + native_objects/ 20 + pptx_package/ 9）
    pptx_to_svg/  30 个模块（converter / shape_walker / txbody_to_svg /
                custgeom_to_svg / prstgeom_to_svg / chart_to_svg /
                chartex_to_svg / tbl_to_svg / notes_import / animation_import /
                transition_import …）

  官方映射指南开篇原话：
    "The main route compiles **project-canonical SVG**, not general browser SVG"
    "PowerPoint intent ↔ project-canonical SVG or an explicit sidecar
     ↔ DrawingML / PPTX package semantics"

  → 所以不是「不做 HTML」，而是【它用 SVG 而不是 HTML 做 IR】。
    这对你极重要：SVG-as-IR 和 HTML-as-IR 是**同一层抽象的两种选择**，
    而它在 OOXML 输出层（pptx_package/、native_objects/、pptx_ooxml/）
    与你的方向完全无关，可以 100% 借鉴。

1.5  ★★ 它怎么解决「靠文档约束不稳定」—— 治你病根的三件事
--------------------------------------------------------------------------------

  ★ 你说「靠文档规定设计风格，每次生成不稳定，必须堆模板」。
  ppt-master 的解法不是「写更详细的文档」，而是：
  【把文档降级为提案，把约束降级为可执行锁】。

  ───────────────────────────────────────────────────────────────────
  【第一件】三层收敛：提案 → 人类签字 → 执行锁
  ───────────────────────────────────────────────────────────────────

  1. design_spec.md —— 提案
     用四级 provenance 标注来源，来源可追：
       [fact] / [suggested] / [decision] / [derived]

  2. ★ BLOCKING 门 —— 人类签字
     ★【原文："No final template directory, template SVG, or Design Spec
       may be written until [TEMPLATE_BRIEF_CONFIRMED] is emitted"】
     ★ 签字前禁止写任何模板目录 / SVG / spec 文件

  3. spec_lock.md —— 执行锁（★ 核心设计）

  spec_lock.md 的关键设计（已核实）：
    · 首行必须是 <!-- ppt-master-schema: spec-lock/v1 -->
    · ★【只允许 ## 段和 - key: value 行】（## forbidden 例外）
      → 机械可解析，★ 不许抄指导性段落进锁
    · 段：
        canvas画布
        communication     沟通策略
        mode              模式
        visual_style      视觉风格
        colors            ★语义角色，非具体色值
        typography        排版
        icons             图标
        page_rhythm       每页 P<NN> 行：anchor / dense / breathing
        pptx_structure    PPTX 结构
        forbidden         禁令
    · ★【forbidden 段的每一条用户禁令必须逐字引用原话并以 (user) 结尾】
      project_manager.py validate 会拒绝未标注的非基线行。
      技术基线行不带标签。
    · ★ 分工明确：Strategist 起草的方向性指导（哪怕已确认）属于
      visual_style_behavior 散文，★【不是禁令，不投影进 lock】。
      这条把「设计建议」和「硬约束」物理隔开。

  ───────────────────────────────────────────────────────────────────
  【第二件】⭐ BLOCKING 硬门 —— 让"确认"无法被绕过
  ───────────────────────────────────────────────────────────────────

  ★ 原文："Blocking means stop — 等显式确认，不得替用户决定"
  具体规则：
    · ⛔ 每个阻塞门必须停下等用户显式确认，禁止替用户决定
    · ⛔ 禁止跨未闭合门打包多阶段执行
    · ⛔ ★【"从文件/文本/IDE 打开的内容静默推断即违规"】
    · 允许显式委托，但须记录理由

  ★ 这条正好治你的病：
    之前你的「可视化描述」是模型一次生成的，中间没有签字点。
    现在拆成：设计简报 → ★你确认 → 生成 → 原型评审 → ★你确认 → 导出。
    模型不能自己往下跑。

  【第三件】★ 渲染前契约 checker + 诚实降级七档 + 公开映射表
  ───────────────────────────────────────────────────────────────────

  ① 独立校验层级（不在导出时崩溃，在作者化时就拒）

    · Chromium 以 --use-angle=swiftshader 启动，1600×900 视口
      （★ swiftshader = 软件光栅化，无需GPU，CI 友好）
    · M1 溢出：scrollHeight 溢出、视觉顶/底溢出（阈值 4px）

      主标题最小 32px，.h-md/h3 最小 14px

      ≤40px 挪内容 / ≤90px 压缩间距 / ≤160px 缩标题 / 更高换版式
      ★ 明确禁止「删内容」
      →★★★【这是最值得抄的一点：校验器不该只说「溢出了」，
        该说「怎么修」。而且明确禁止删内容——

  1. ★★【DSL 作为中间表示 + lint 校验 —— 这是解你病根的另一种解法】
     每个 PPT 对应一个 project_dir：
       <workspace_dir>/
       └── <project_dir>/                    # 目录名 = pptx 文件名去后缀

           └── <pptx_name>.pptx

     命令：
       slidep create <file>                              # 创建空白 PPTX
       slidep upsert-dsl <file> --dsl-file <path> \

5.4★★ 关于 HTML 作为唯一载体：一句诚实的判断
--------------------------------------------------------------------------------

  你三次强调「HTML 为唯一载体」，这个判断有道理（文本排版、浏览器免费、
  中文字体好处理），但也有一个盲区要提醒：

  ★ ppt-master 用 SVG-as-IR 而不用 HTML-as-IR 的原因，
  不是它不知道 HTML 好，
  而是★「目标格式的能力边界」不同：
    · HTML 做不到真 slide master 继承
    · HTML 做不到 OMML 公式
    · HTML 做不到原生 chart 工作簿（Edit Data）
    · HTML 做不到 prst 几何 + 连接线调节柄
    · HTML 做不到 PPTX 内嵌字体

  ★★【所以纯 HTML 路线能做到的最好结果，是「视觉100% 还原 +
    文字可改」的 PPTX（路线 B），不是「原生可编辑 PPTX」。
    如果你的交付要求是后者，HTML 只能是中间表示之一，
    最终一定要有一个 OOXML 写入层。

  → 这不是劝你放弃 HTML，而是：
    ★ HTML 负责「好看和正确」，OOXML 写入层负责「可编辑和能被 PowerPoint 认」。
    ppt-master 的 pptx_package/ + native_objects/ 就是那个写入层，
    ★★ 【而且它是 MIT、纯 Python、可直接读源码借鉴的。】
