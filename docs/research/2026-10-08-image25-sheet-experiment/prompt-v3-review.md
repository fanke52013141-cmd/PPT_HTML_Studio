# v3 提示词优化与验证方案

关联RES-20261008-04、HPS-026–030、036。状态：实验增强版已编写，静态排布核验通过；没有本轮付费调用或效果提升结论。完整指令见[prompt-v3.txt](prompt-v3.txt)。上一轮真实失败证据保持在[toapis-2k-low-results.md](toapis-2k-low-results.md)，v2及生产默认不覆盖。

## 核心诊断

| 问题 | 等级与影响 | 对应修复 |
| --- | --- | --- |
| “extract / recognizable appearance”没有排除重绘美化，参考复用与自由插画任务混淆 | 重要：模型可能补腿、改表情、加装饰；不能直接认定这是唯一原因 | 明确参考负责身份/形状/姿态；任务只做忠实隔离、移动和缩放，不补原图没有的部分 |
| 灯泡及rays易被表现为发光；泛称无haze/shadows仍未阻止光晕 | 重要：半透明光晕扩散，提取失败 | 黄色短线是实心墨迹，平面无照明呈现；逐项排除glow/bloom/halo/地面/投影 |
| 同时使用象限、中心百分比、最大比例、十字留白，规则重复 | 一般：增加长度及排布误差机会 | 程序确定四个内框，只给像素内框、完整包络、保持比例 |
| API的2K/quality/background与Prompt职责不同 | 重要：提示词不能保证服务精确遵从alpha/尺寸 | API保持2048×2048、low、background=transparent；Prompt描述视觉，文件读取和提取器验证实际输出，不要求模型报hash/ID/JSON |
| 2K板被四个对象共享 | 重要：板尺寸不是每个对象2K；对象约560长边 | 效率比较必须控制对象有效像素，不与单张2K主体直接比较 |

光晕/alpha残留的成因可能来自模型或供应商输出处理；现有证据不能证明完全由Prompt导致，也不能保证v3消除。v3给出明确可检验要求，非已验证生产修复。

## I/O与最小输入

模型唯一任务：把原Token图的四个指定对象忠实隔离并重排为单张素材板。实际请求为Images generations +一张reference_images URL，单一prompt字段，没有伪造system/user分层。参考图片提供身份/画风；文本仅补对象选择、排除项、固定位置、透明及不可补画规则。

只保留四对象语义和对应内框；移除重复中心/百分比、无下游消费的内部ID/hash/anchors、质量与费用描述。画布尺寸支持排布判断，API尺寸支持真实输出验证，职责不同。模型只输出图像；尺寸/alpha/槽位/清理/候选key/审核由系统负责。

程序排布：每槽1024平方，内框560平方，中央定位，四边至少232像素留白；四内框不重叠。目标对象保持比例并完整落内框，所有原图短线也算入可见范围。实际裁切仍使用原四槽1024平方；不根据生成结果挪槽、缩放或放松门禁。

## 实施边界

仅新增可审阅实验Prompt和本文，不更换html_asset_sheet_generation的生产默认、不写用户Prompt或配置、不改变候选缓存/版本/接口。通过真实试验后再把通用规则提升为版本化生产模板；Token专用对象内容保留在实例中。生产生图与参考重试应区分输入角色：前者创造资产，后者保留已提供参考身份，不能在没有参考图片时声称忠实提取。

## 下一轮验证

保持Flare VIP、2048平方、low、同一原参考图及现有清理参数。先仅一次v3四对象板，与v2比较实际尺寸、每槽边界alpha、光晕、原始/清理后通过数、身份和补画、费用、总耗时；源图永久保留。原图4/4且人工身份/边缘通过才判直接可用；清理后4/4只判候选，不能替代视觉批准。失败只重试问题对象；不提高清理预算掩盖失败。

若仍有光晕，下一独立变量是参考上下文：提供清楚标注角色的目标区域参考图，或选择供应商支持的edits接口。不要同时改模型、质量、接口及Prompt，否则无法归因。仍需四次同有效对象像素尺寸的单图基线和人工分钟，才能评估整体效率。纯色背景为另一个明确模式，不把边界去色当成原生透明或精确AI分割。
