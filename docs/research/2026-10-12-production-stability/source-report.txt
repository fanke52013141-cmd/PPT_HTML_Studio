01. 项目目标与稳定性定义
======================================================================

1.1 目标
系统接受一个选题或已有稿件，生成风格统一、角色可识别、音画同步、可修改、可重现的手绘讲解视频，同时提供封面、字幕、旁白、来源说明和验收结果。

四个核心目标：
（1）视觉风格固定：线条、字体、颜色、人物、版式属于同一个系列。
（2）形成自己的 IP：角色形象和讲解习惯有持续辨识度。
（3）稳定产出：更换选题、修改内容、遇到服务故障时仍可管理质量。
（4）可迁移：其他具备工具调用与执行能力的 Agent 能调用同一生产系统。

1.2 稳定性分为五类
执行稳定：命令失败可识别；缺文件不伪装成功；任务能续跑。
数据稳定：素材、旁白、音频、时间戳、字幕、成片对应同一版本。
视觉稳定：角色身份、排版、线条、配色保持在规定范围。
内容稳定：事实有依据，旁白和图示一致，没有把估计写成事实。
复现稳定：冻结的输入在固定环境下重新渲染，得到一致画面和时间安排。

必须分清“固定工程重复渲染”和“相同选题重新创作”。前者可以严格验证，后者具有生成变化，只能通过规则、组件、评估控制质量。

1.3 基本原则
把每次重新创造的内容压缩到选题、故事、旁白、案例与少量新素材。
固定品牌、角色资产、布局组件、动画能力、数据接口和质量规则。
创作过程允许迭代；正式生产使用已经确定的实际输入。
新模型、新 Agent 或新组件必须先经过基准样片验证。
失败能定位到阶段、镜头、素材或句子；返修从最小受影响范围开始。

02. 当前项目实际如何工作
======================================================================

2.1 真实技术路线
【现有】Agent 查资料、写旁白、决定画面、编写 scenes.js；程序将场景转换为 Excalidraw 数据，在 HTML/SVG 页面里执行动画，Playwright 驱动 Chromium 截帧，FFmpeg 编码与合成。

不是由图像模型生成完整视频。图像模型主要负责人物和道具贴纸，语音服务负责配音。几何图形、文字显示、动画排期、截图、编码主要由代码执行。

“最后形成一张完整图”描述的是画面结果，不能推出“先生成整张图，再还原真实绘画过程”。当前系统从独立元素开始构建画面。

2.2 三种元素的不同动画机制
线框形状：rough.js 根据参数产生手绘风 SVG 路径，程序拆分子路径，用描边长度和偏移控制逐段显现；双线描边分层处理，营造手绘效果。
文字：使用手写字体；程序测量浏览器实际文本宽度，按行用裁剪区域从左到右显示。不是汉字真实笔顺动画。
图片：使用 PNG 贴纸或 Logo；程序扩大裁剪区域使图片显现，铅笔位置是视觉模拟。没有从图片提取真实人物绘画笔顺。

图片自动转 SVG、自动恢复语义图层、生成真实笔顺都不是现有默认能力。未来需要时应作为独立功能评估。

2.3 当前的一期流程
选题与查证 → 编写 scenes.js → 获取 Logo/生成贴纸 → 编译场景 → 导出静帧检查 → 合成配音和字词时间戳 → 排期和字幕 → 渲染分段 → 拼接 master → 混背景音乐 → 出封面 → 写发布稿 → 验收交付。

【现有】wb build 主要执行 scenes、tts、render、mix、cover、clean。它不会自动完成所有研究、生图、文案和人工审查；这些由 Agent 按 skill 组织。不能把 build 成功理解为整个创作和审校已全部完成。

2.4 当前时序
旁白中用“|”划分 beat。场景代码中调用 nextBeat() 后加入的元素归属相应 beat。
配音通常以整个场景合成，字词时间戳用来映射各旁白段起点。不是每句话必然发起一次配音请求。
元素按所属 beat 和添加顺序绘制；自然绘制时长由路径长度、文字长度等估算。
放不下时允许溢出到下一 beat 的一部分，必要时压缩，最后仍超出场景则整体缩短排期。
【建议】过度压缩应形成明确错误或返修建议，不能仅靠加速解决所有阅读负担。

03. 当前文件地图、输入输出和已有保障
======================================================================

3.1 核心文件
SKILL.md：Agent 的制作流程、要求和参考文档入口。
config.json：目录、语速、字幕、笔速、配乐、品牌、水印、片尾、封面参数。
bin/wb：Bash 命令入口，调用 Node 脚本执行各阶段。
lib/paths.cjs：配置读取、项目查找、工程与构建路径。
lib/scene-dsl.js：场景 API、元素、封面、品牌卡、场景文件和旁白稿生成。
lib/gen-image.mjs：调用本地 Codex 生图，四宫格、参考图和抠图处理。
lib/fetch-logo.mjs：Commons 搜索、SVG 下载、PNG 转换、来源记录。
lib/tts-volc.mjs：场景旁白配音、完整性粗查、beat 时间映射。
lib/tts/tts.mjs：语音服务请求、音频与字词时间戳收集、音频转换与复用。
lib/tts/content-cache.mjs：配音身份、内容散列、文件校验、缓存记录辅助函数。
lib/captions.cjs：用原文及时间戳生成字幕和全片 SRT。
lib/render.html：手绘画面、动画、品牌、字幕、seek(t)。
lib/render.js：浏览器、静帧、封面、并行截帧、分段编码和 master 拼接。
lib/mix-bgm.mjs：根据旁白音量生成配乐包络并混音。
templates/scenes.js：现有每期脚本模板。
templates/发布.md：现有发布文案模板。
references/：DSL、布局、素材、发布说明。
../video-common/references/：查证、封面、交付等共用规范。

3.2 当前目录与数据
内容工程默认在 episodes/<日期 标题>/。
scenes.js 为主要手写内容源；README.md 保存资料；发布.md 保存发布文案。
assets/ 保存素材；scenes/ 保存场景、script.json、cover.json 和引用图片副本。
旁白稿.md、字幕.srt、封面图片属于生成物。
build/<日期 标题>/work/audio 保存配音及时间信息。
work/raw 保存生图原图和原始素材；work/frames 保存检查静帧。
work/out 保存场景分段和 master.mp4。
outputs/final.mp4 是混音后的成片。

3.3 已有保障，应保留
配音缓存既比较文本、音色、语速、资源等身份，也校验音频 SHA-256 和元数据，命中时复用对应时间戳。
配音有有限重试与返回字数粗查，降低半段音频风险。
截帧有有限重试。
场景保存时提醒字幕安全区和水印区冲突。
单场景重渲后可重新拼接，配乐可单独重混。
seek(t) 以时间控制画面；各 worker 使用独立浏览器，代码通过整屏重绘减少出帧顺序影响。
字幕文字使用原稿，减少 TTS 规范化文本污染字幕。

这些是代码能力，不等于在当前机器已完成所有故障测试。串行/并行一致性仍需实际比较。

3.4 需要优先改造的薄弱点
生图失败后寻找共享目录“最近生成图片”的兜底可能拿错结果，必须改为请求与文件一一绑定。
项目标题子串匹配多个目录时默认选最新，自动化应改用明确 episode_id；歧义时不自动猜。
Bash、sed、grep、open 和 HOME 等处理需要适配 Windows；不能仅凭 Node 代码就宣称跨平台完成。
当前配音规范化字数达到输入的 85% 可通过粗查，这不是全文完整、读音正确的证明。
配音字词对齐和字幕字数映射存在近似情况，需要记录对齐质量。
部分渲染缺少分段时代码打印提示后返回；正式流程应返回非成功状态，禁止继续复用旧 master。
现有最终文件和旁白链接主要按路径存在判断，没有完整的整期版本证明；需要补构建清单。
字体、纸色和生图风格分散配置；品牌升级未形成完整版本包。
目前的模板自由填写坐标较多，质量依赖 Agent 编排能力。
【代码级推断】上述风险来自控制流与数据关系，未把每一项都作为实际故障复现。

04. 目标系统架构与模块职责
======================================================================

4.1 创作层
负责需求解析、资料取舍、旁白、分镜、素材选择和内容审查。
输出结构化工程数据，不直接控制生产目录里的任意临时文件。
AI 可以提出新布局或新素材，但正式使用前需进入可检查的组件/资产流程。

4.2 品牌与资产层
保存视觉规范、角色规范、已验收动作、道具、声音配置和风格样例。
提供带版本的引用，禁止在制作中无记录地覆盖共享资产。

4.3 编译层
将语义分镜、版式和素材解析成渲染所需的元素、位置、图层、事件与时间轴。
检验输入结构和容量，测量实际文字，产生可定位的错误。

4.4 服务适配层
封装图像、配音、可选音频对齐与资料检索服务。
统一输入输出和错误分类，供应商具体参数只在适配器内部转换。

4.5 生产层
运行浏览器渲染、编码、拼接、混音、封面及字幕导出。
读取冻结输入，不临时调用 AI 改稿或改版式。

4.6 编排与状态层
管理依赖、任务编号、锁、缓存、预算、重试、运行日志和恢复。
CLI、HTTP、MCP 使用同一核心编排逻辑，避免三个接口各自维护一套流程。

4.7 验收层
程序处理可计算检查；视觉模型辅助检查语义与观感；人处理定稿和最终判断。
验收结果必须绑定被检查文件的散列，修改后旧结论失效。

5.3 ID 与版本
episode_id 是一期稳定标识，标题修改不改变 ID。
revision 是内容版本；run_id 是一次执行标识；同一内容可能执行多次。
scene_id、beat_id、element_id 使用稳定 ID，不能仅靠数组索引。
brand_version、character_version、layout_version、schema_version、renderer_version 明确记录。
相对路径必须约定相对于哪一个根目录，适配器返回路径也遵守同一规定。

06. 全链路数据流与阶段依赖
======================================================================

6.1 主链路
用户输入
  → brief（结构化需求）
  → facts（资料与事实记录）
  → storyboard（旁白、画面与模板选择）
  → assets manifest（素材需求与实际文件）
  → compiled scene（布局与元素）
  → audio + alignment（实际音频与匹配时间）
  → timeline + captions（动画时间轴与字幕）
  → preview + QA（预览和检查结果）
  → segment videos（镜头分段）
  → master + mixed audio（总片与混音）
  → outputs + delivery manifest（有效交付版本）

6.2 每阶段的输入输出
需求解析：输入用户要求，输出 brief。AI 填内容，程序校验字段。
研究查证：输入选题及关键结论，输出 facts。AI 组织查证，检索工具提供资料。
文案分镜：输入 brief、facts、品牌和模板，输出 storyboard。AI 创作。
结构检查：输入 storyboard，输出结构报告。程序计算，必要时 AI 修改。
资产解析：输入素材需求、资产库，输出复用列表和缺失列表。程序检索，AI 判断语义。
资产制作：输入缺失任务、参考、品牌，输出图片和元数据。图像模型生成，程序处理。
静态编译：输入分镜、素材、版式、画幅，输出元素和边界。程序执行。
配音：输入朗读文本、声音配置，输出音频与时间戳。语音服务加适配器。
时间编译：输入事件锚点、音频对齐和布局，输出 timeline、captions。程序执行。
预览：输入编译画面和时间轴，输出预览视频、检查图。程序执行。
验收：输入预览和工程，输出问题列表、人工记录。程序、视觉模型、人分别记录。
正式生产：输入通过检查的快照，输出分段、总片、封面、字幕。程序执行。
交付：输入验证结果及实际文件，输出 delivery manifest 和用户说明。程序组装，AI 写说明。

6.3 时间来源
内容层引用 beat_id 或明确的词句锚点，不在写稿时猜最终秒数。
实际时间来自该次配音返回的时间戳，或对该音频执行的对齐结果。
每个场景的全片起点来自实际分段时长；字幕和动画共用同一累计偏移。
帧时间 t=n/fps；浮点时间到帧边界使用统一舍入策略。
字幕不得用一套时长累计、视频用另一套累计，否则逐场景误差会累积。

6.4 并行与顺序
不同素材任务在严格隔离后可并行；现有“最近图片”兜底移除前不得并发生图。
不同场景配音可按服务限制并行；同一任务音频和时间戳必须成对。
排版可先做无音频静态预览，但必须标记 estimated。
正式动态预览必须等待实际音频和时间轴。
最终交付必须等待编码完成、文件检查和验收，不能仅等待截帧结束。

07. 从选题到交付的逐步操作流程
======================================================================

步骤 01：运行环境诊断
执行者：程序。
检查 Node、FFmpeg、ffprobe、浏览器、字体、输出目录权限、磁盘、配置字段和供应商连接。
输出 doctor report，区分渲染可用、生图可用、配音可用、正式生产可用。
缺少生图服务但资产已齐时可以继续；缺少正式字体或有效配音时不得声称正式成片可用。
连接测试使用小请求，记录实际消耗，避免无必要重复调用。

步骤 02：建立需求
执行者：AI，必要时由人补充关键偏好。
确定观众、主题、一个主问题、预期时长、画幅、语气、品牌、IP、交付格式。
可选偏好缺失时使用项目默认并记录；关键事实范围不清时先澄清或缩小表述。
创建 episode_id，保存需求版本。

步骤 03：研究与事实账本
执行者：AI + 检索工具；程序检查字段。
列出将出现在旁白、图表、封面和标题中的事实。
记录来源 URL、标题、发布/访问日期、支持的主张、单位、时间范围、适用对象。
数据换算保留输入、公式和舍入规则。
事实状态使用 verified、qualified、unverified；qualified 保留限定措辞。
不可确认的核心结论不得无依据进入正式稿。

步骤 04：选择叙事结构
执行者：AI。
根据内容选择反差解释、原理拆解、方法流程、对比判断或事件时间线。
每期形成一句“观众看完能得到什么”。
开头、主体、结尾服务同一个主问题，避免为了套模板增加无关内容。
保存叙事模板版本及本期参数。

步骤 05：写旁白与显示文本
执行者：AI。
短句表达；同一讲解单元承载一个核心意思。
显示文本保留正确名称、数字和单位；朗读文本通过读音规则转换。
为两种文本建立可追踪映射，不允许完全独立重写后再按字数硬对齐。
标题、屏幕文字、字幕和发布数据引用同一事实记录。

步骤 06：编写语义分镜
执行者：AI。
每镜头写 goal、layout、beats、元素、角色动作、事件、阅读停留和转场。
检查每个重要旁白点有相应视觉表达；装饰不替代解释。
通过 schema 后进入静态编译；字段缺失返回字段路径。

步骤 07：解析素材
执行者：程序 + AI。
先查本期素材，再查角色动作和品牌资产，最后提出生成任务。
已入库资产按版本及 SHA-256 引用。
外部 Logo 记录来源并人工核对实体与版本；素材库收录不自动证明官方身份。
没有完全匹配动作时，可调整构图或改用相近动作，但必须满足讲解目标。

步骤 08：生成并验收缺失素材
执行者：图像模型 + 程序 + 视觉检查。
任务绑定 request_id、episode_id、asset_id、输入散列、期望输出。
保存原图，执行透明背景检查、可选抠图、裁边、尺寸处理。
检查角色、姿势、主体完整性和风格；通过后纳入本期 assets manifest。
只有需要跨期复用且通过审核的素材才进入共享库。

步骤 09：静态编译和排版检查
执行者：程序。
按照模板槽位放入素材和文字，实际测量字体，生成 scene graph。
检查越界、禁区、文字容量、合法叠放关系和颜色规则。
生成每 beat 完整状态、关键局部图和手机尺寸检查图。
未配音的估计时间仅用于排版，不用于最终同步。

步骤 10：配音及对齐
执行者：语音服务 + 程序。
默认按场景或稳定段落合成；不为了局部重做把所有短句切得过碎而损害语气。
获得音频、真实时长、字词信息；确认与当前朗读输入一致。
检查末句、关键名称、关键数字及时间范围。
供应商无时间戳时使用已知文本对齐，必要时 ASR 辅助查漏，记录近似程度。

步骤 11：字幕和动画时间编译
执行者：程序。
根据显示/朗读映射、音频对齐和事件锚点生成 cues 和 timeline。
排期中应用动画上限、关键关注点、阅读停留、移动速度与场景结尾规则。
无法容纳时返回事件与镜头的具体原因，修改内容或拆镜头。

步骤 12：低清动态预览
执行者：程序；AI/人检查。
输出低清 MP4，采集开始、出现、运动中间、完整结论和转场前后状态。
用连续播放判断移动是否顺畅，完整听审判断声音和同步。
问题记录绑定 scene_id、beat_id、时间点及输入版本。

步骤 13：局部返修
执行者：AI 提出内容修改，程序计算影响范围。
默认每次只修一类主要问题，以便追踪因果。
修改后旧检查结论失效，重新执行受影响检查。
反复不通过到达边界后停止该任务，保留有效进度和说明。

步骤 14：冻结发布候选快照
执行者：程序。
冻结旁白、分镜、素材、字体、品牌、时间轴和运行版本。
从快照正式渲染，生产中不临时生图或改稿。
技术问题修复涉及输入变化时创建新候选版本。

步骤 15：正式渲染与混音
执行者：程序。
按帧渲染，分段编码，验证分段；拼接总片，再按规则混音。
所有中间结果先写临时路径，验证成功后提交为有效产物。
编码和子进程错误必须传播到总任务状态。

步骤 16：封面、发布稿与资料说明
执行者：程序生成封面，AI 写文案。
封面使用本期同一 IP 与事实；横竖版独立排版。
发布稿数字对照 facts，不重新凭记忆写一套。
正式封面标题不必照搬正文长标题，应遵循容量和账号规范。

步骤 17：最终验收与交付
执行者：程序 + AI/人。
检查实际最终文件，完整解码、时长、音轨、字幕和可播放性。
生成交付清单，写明检查已完成、未完成和已接受限制。
更新 active delivery 指针为本次有效文件，而不是只依赖 final.mp4 文件名。
制作和验收不自动代表已经对外发布。

======================================================================
08. 模板体系：品牌、角色、叙事、版式、动画和交付
======================================================================

8.1 模板的定义
模板是带输入字段、默认值、容量、行为和校验规则的可复用组件。
不是只提供一段“请保持手绘风格”的提示词，也不是复制一张固定图片。
每个模板记录 ID、版本、支持画幅、参数、输出、容量、例子和测试。

8.2 品牌模板
字段：brand_id、version、name、slogan、palette、fonts、typography、stroke、spacing、safe_areas、watermark、end_card、motion_defaults。
palette 保存语义颜色，如 paper、ink、accent、muted、warning、fill_primary。
typography 保存标题、正文、注释、字幕的字号层级和行距。
stroke 保存主次线条、roughness、虚线和箭头规范。
safe_areas 按画幅保存，不把横屏坐标直接用于竖屏。
品牌包同时给编译器、渲染器、生图提示词生成器和质量检查使用。
一张 style-board 作为视觉定稿，配置不能代替画面检查。
适配器可将透明背景要求转换为供应商参数；模型仍可能画出白底，必须检查实际 alpha。

8.3 角色模板
字段：character_id、version、identity、fixed_features、allowed_changes、prohibited_changes、reference_images、action_library、review_examples。
identity 写脸型、发型、眼睛、比例、服装和标志物。
fixed_features 写不可变特征；allowed_changes 写表情、姿势、道具等可变部分。
action_library 的每项记录 asset_id、姿势、表情、朝向、尺寸、内容边界、视觉重心和可选指向锚点。
使用相同文件不会发生重新生成漂移；新增动作仍需验收。
三视图和表情图用于约束，不假定模型会百分之百遵守。

8.4 表达与声音模板
字段：account_position、audience、tone、analogy_preferences、sentence_rules、ending_patterns、pronunciation_dictionary、voice_provider、voice_id、speed、style。
明确角色是提问者、解释者还是演示者。
用认可样例说明口吻，避免塞入大量泛化形容词。
读音字典按文本到读法映射，例如缩写、产品名、数字单位；变更字典需参与配音缓存。
音色必须显式固定，供应商故障不得悄悄换声音。

8.5 叙事模板
反差解释：现象/矛盾 → 原因 → 可视化机制 → 例子 → 判断标准。
原理拆解：对象 → 部件 → 相互作用 → 条件/边界 → 总结。
方法流程：目标 → 前置条件 → 步骤 → 易错点 → 可执行建议。
对比判断：共同问题 → 同一维度比较 → 代价/收益 → 适用条件。
事件时间线：起点 → 变化 → 关键节点 → 影响 → 未确定部分。
每个模板提供可选段落，不强制固定镜头数量和通用反转。

8.6 版式模板：首批六类
（1）对比 compare：标题、左右对象、比较项、底部结论。竖屏改为上下或逐步对比。
（2）流程 steps：步骤、连接、当前状态、行动结果。超出容量拆为连续镜头。
（3）因果 cause：原因节点、机制节点、结果节点、条件说明。箭头要有语义方向。
（4）时间线 timeline：事件时间、事件卡、关键节点、当前讲解位置。
（5）数量关系 quantity：数据、单位、比例/差额、来源标识。视觉尺度必须来自数值。
（6）角色演示 actor_demo：角色、区域/道具、状态变化、结论。
首批 compare 可限制为每侧一个主对象和三条短项；只是初始容量，需结合样片确定。

每个版式说明：输入字段、允许元素、槽位、优先级、边距、溢出策略、横竖变体和错误代码。
文字超长按“去冗余 → 换行 → 拆项/拆镜头”处理；缩小字号只能到预设下限。
角色、图表和字幕都算占用空间，不能单独排好后随意叠放。

8.7 动画模板
draw：路径逐段绘制；适合框、箭头、线条。
reveal：裁剪显示文字或贴纸。
fade：简单入场，避免所有内容都需要铅笔擦出。
highlight：圈选、底色、下划线，跟随旁白强调。
move：角色或标记位置变化，路径和缓动固定。
state_change：切换表情或前后状态；锚点对齐以防跳动。
zoom_focus：局部聚焦；不得让字幕、水印同时缩放或被遮挡。

每个事件具有 target_id、trigger、duration_policy、easing、layer、priority、end_state。
初期试验参数：普通入场约0.3～0.8秒，强调约0.2～0.5秒，简单结论约0.8～1.5秒阅读停留。
上述只是样片调参起点，不是对所有语言、观众、图形成立的普遍标准。
原则上同一时刻只有一个主关注点，允许次要动作但不得争抢理解。

8.8 转场模板
replace：切换场景，保持字幕时间连续。
carry：保留稳定对象，改变周围信息。
pan/zoom：适量移动画面重点，内容层变换与字幕品牌层分开。
transition 内部只控制表现，不自动改变事实和讲解顺序。
对象从一个镜头延续到另一个镜头应按 ID 绑定，不靠屏幕相似度猜。

8.9 封面模板
输入：主题、短标题、补充、主角资产、品牌、画幅。
规定标题行数、字号下限、资产区域和品牌区域。
不同画幅重新布局；封面竖版不代表正文已适配竖屏。
核对封面数据与正文一致；不为了钩子夸大结论。

8.10 交付与验收模板
交付清单：视频、封面、字幕、旁白、来源、发布稿、QA、快照标识。
QA 字段：check_id、scope、artifact_hash、status、evidence、reviewer、timestamp。
status 使用 passed、failed、not_run、waived；waived 必须记录原因及适用范围。
未运行检查不能统计为通过。

09. 核心数据合同与完整分镜示例
======================================================================

9.1 brief 合同
必填：schema_version、episode_id、topic、audience、goal、brand_ref、character_ref、outputs。
可选：duration_target、tone_override、provided_sources、provided_assets、constraints。
outputs 明确画幅、分辨率、fps、封面、字幕和交付路径。
字幕安全区等来自对应画幅的品牌配置，而非临时用户文本坐标。

9.2 facts 合同
每条记录 fact_id、claim、source、dates、scope、value、unit、calculation、status、qualifier。
来源支持的是哪一句必须明确；网页存在不等于支持主张。
calculation 包含操作数、公式和取整方式；程序能验证算术，不能验证来源真实可信。
不依赖事实来源的情境例子标为 illustrative，不包装为研究结果。

9.3 assets 合同
每项记录 asset_id、kind、path、sha256、source_kind、character_ref、brand_ref、dimensions、alpha、anchors、review_status。
生成资产额外记录 request_id、provider、model、prompt_hash、reference_hashes、parameters、raw_path、processing_version。
外部资产记录来源、获取时间和使用条件记录；不根据“从某网站下载”自动推断许可。
构建只接受 review_status 为 accepted 的正式资产，草稿用于 preview mode。

9.4 storyboard 合同
每镜头：id、goal、layout_ref、beats、elements、continuity、fact_refs。
每 beat：id、display_text、spoken_text、text_mapping、events、hold_policy。
每元素：id、type、role、slot、content/asset_ref、style_role、z_index、overlap_policy。
事件 trigger 优先使用 beat_start、aligned_phrase 或 after_event。
phrase 锚点可能重复，需有 occurrence 或明确范围；找不到不能默认映射为0秒。
hold_policy 指定最短阅读需求，时间编译器决定是否需要加停顿或拆镜头。

9.6 编译场景合同
记录 canvas、safe_areas、elements、actual_bounds、resolved_assets、source_mapping。
actual_bounds 来自浏览器字体测量和图片内容边界，不仅依赖粗略字数。
每项保留原 storyboard 字段路径，报错可回到源位置。

9.7 音频与对齐合同
记录 audio_path、audio_sha256、duration、sample_rate、channels、spoken_text_hash、voice_identity、words、alignment_method、alignment_status。
words 项包含文本、起止时间、可获得的置信信息。不能假设所有服务都提供可靠置信分数。
时间戳重复、倒序、超时长要检查；词与音频必须同一来源。
显示文本与朗读文本不等长时依照 text_mapping 生成显示 cue。

9.8 时间轴合同
记录 fps、scene_duration_frames、events、captions、audio_offset、resolved_anchors、compression_report。
事件有 start_frame、end_frame、target、motion_parameters、final_state。
使用明确帧区间定义，例如 [start_frame, end_frame)，防止边界重复或漏一帧。
每段真实帧长作为全片累计依据，音频尾部需验证未截断。

9.9 QA 与 manifest 合同
QA 记录检查内容、实际状态、证据、待处理问题，绑定输入和输出散列。
manifest 记录输入版本、阶段依赖、输入指纹、状态、产物、尝试次数、时间、错误和 active delivery。
文件存在只是一个条件；还需验证文件有效、内容散列和来源版本。

======================================================================
10. AI、程序、服务与人的具体分工
======================================================================

10.1 由文本 Agent 负责
理解需求、研究问题、筛选来源、写旁白、选叙事模板、选择版式与素材、设计可解释的动作、写发布文案、根据问题列表修改源稿。
这些属于判断和创作工作，输出必须接受结构及内容检查。

10.2 由视觉模型辅助
对照角色参考检查形象；查看预览是否能理解；发现明显错图、裁切、风格不一致；给出问题与证据。
视觉模型不是绝对正确的质量裁判，不能替代数值检查、实际听审或关键人工定稿。

10.3 由图像模型负责
制作缺失的角色新动作、道具、情境插画。
输入角色、风格、姿势参考；输出位图素材。
不依赖图像模型生成关键正文数字、字幕或官方 Logo。

10.4 由语音模型/服务负责
把朗读文本变为音频；有能力时返回时间戳。
程序负责响应解析、音频转换、缓存、完整性检查和文本映射。
语音服务结果不保证无读音错误，关键专名和数字要核对。

10.5 由确定性程序负责
schema、ID、素材文件、版本、缓存、布局、实际文本测量、容量、安全区、时间编译、字幕、逐帧渲染、编码、混音、QA 汇总、局部重建。
可用规则精确计算的事情优先用程序，减少 Agent 每次自由判断。

10.6 由人负责
首次品牌和角色定稿、重要表达偏好、关键事实边界、最终听审和接受无法自动确定的问题。
定稿后的常规生产可以高度自动化，不必每步都询问。
人工参与应集中到有判断价值的地方，并把决定转成可复用配置。

10.7 控制 AI 的自由度
输入只提供当前阶段必要资料，输出使用明确结构。
提示词含本期目标、模板选择、固定品牌与角色引用、字段格式、失败处理和合格样例。
允许有理据地换模板，不能绕过检查修改渲染器。
修复输出指向具体字段与原因，不把整个工程无差别重写。
无需先上多 Agent；单 Agent 加固定程序即可实现第一版。多 Agent 增加时，也必须共用合同和状态管理。

======================================================================
11. 生图接口、素材处理与角色一致性
======================================================================

11.1 请求合同
generateAsset(request) 接收任务 ID、素材 ID、描述、角色/风格/姿势参考、输出规格、供应商参数配置、预算和超时。
返回 output_path、sha256、实际尺寸、alpha、provider_request_id、model、parameters、耗时和可获得的用量。
供应商上传的参考图应与记录的 reference hashes 对应。
秘密凭证由环境或密钥管理提供，运行清单只保存凭证引用，不复制秘密值。

11.2 任务隔离
每个任务使用独立 job directory 和临时文件。
只接收本请求响应中的图片，或本任务明确绑定的工具输出。
删除按生成时间寻找全局“最新图片”的机制。
目标文件路径错误、返回空文件、解码失败都应报错，不复用同名旧图片。
流式中间图只用于 preview，不标记为正式资产。

11.3 生成策略
核心 IP 优先单张；普通低重要性道具可以批量，但每项要独立验收。
可优先请求透明 PNG/WebP，仍检查 alpha 和边缘；供应商不支持时使用白底后处理。
参考图分角色、画风、姿势三种作用；同一图可以兼具作用但应明确说明。
固定模型版本有助于控制变化，不能保证同一提示词再次生成完全一致。
通过的实际文件存档比依赖重生更可靠。

11.4 后处理
保存原图 → 检查尺寸/格数 → 分割 → 抠图 → 内容边界 → 必要边缘处理 → 导出 → 检查。
连通块过滤不能固定删除所有小块，因为手指、道具或符号可能天然独立。
建议阈值可配置并保留处理前后对照；主体面积异常下降时阻止入库。
已经有透明通道时避免再次抠白导致浅色部位损失。
无法确定主体完整性时交给视觉检查，不凭一条面积阈值直接判成功。

11.5 一致性检查
固定特征：发型、脸型、服装、识别标志、比例。
风格特征：线条、填充、颜色、细节密度。
任务特征：姿势、表情、朝向、手持物。
人工定稿参考作为标准；视觉评分只作辅助，不承诺绝对准确。
新动作失败可选择已有动作并调整构图，但应记录差异，不能忽略讲解需求。

======================================================================
12. 配音、读音、时间对齐与字幕
======================================================================

12.1 两套文本与映射
display_text 为用户看到的正确正文。
spoken_text 为服务读出的文字。
pronunciation transformation 保存修改范围和映射，例如名称读法、数字中文读法。
字幕使用显示文本，时间来自朗读文本与音频，二者通过映射关联。
不要简单比较两套文本字符数后假定逐字一一对应。

12.2 合成单位
初期沿用场景级，减少拼接语气变化。
场景很长且频繁局部修改时可分为有稳定段落边界的语音单元。
选定单位后保存 unit_id 和顺序，缓存和时间轴都以它为基础。
跨单元停顿、音量和音色一致性需检查。

12.3 时间戳
优先使用该音频同次生成的字词时间戳。
无时间戳时，对实际音频做已知文本对齐；ASR 可辅助找漏读和专名问题。
ASR 文本不是原稿替代品；可能听错数字和名称。
句级时间戳只能保证较粗同步，字数插值须标近似。
正式规则可对关键事件要求词句级可靠锚点，普通淡入允许句级精度。

12.4 检查
音频可解码、时长合理、非全静音、没有明显截断。
规范化文本覆盖检查要考虑读音替换，不能把85%粗查当成完全文本校验。
时间戳在合理范围内、顺序合理、末句已覆盖。
关键数字、专名、否定词和结论完整听审。
加入超时和取消；鉴权、参数错误立即返回，网络或限流按边界重试。

12.5 字幕
按标点、语义和实际宽度切句；保护数值、单位、英文名称。
先用可靠对齐边界；不得只因句数相同就认定语义完全对应。
过长字幕拆句时尽量用字词边界，时间插值需记录。
字幕 start<end、有序、不非法重叠，短句有合理阅读时间。
字幕字体、位置和背景对比按对应画幅验证。
全片 SRT 的偏移来自实际分段帧时长，不能仅加音频估时。

======================================================================
13. 布局、动画排期与确定性渲染
======================================================================

13.1 布局步骤
读取画幅品牌规则 → 选模板变体 → 放主对象 → 测量文字 → 放次要说明 → 放结论 → 验证边界。
图表从数据计算；数值为零、负数、缺值时有明确策略。
布局失败返回哪个槽位、需要多少空间、实际有多少空间。
预览和正式使用同一编译结果，不分别计算两套坐标。

13.2 动画排期
解析旁白锚点 → 得到事件起点 → 计算自然时长 → 检查关注点竞争 → 检查阅读停留 → 决定场景结束。
填充、描边、文本和图片具有不同自然时长模型。
读取已完成事件依赖，检测循环和不存在的目标。
允许有限压缩但记录比例和最短时长；超限则拆镜头。
不能为容纳图形截断音频；需要加尾部停留则统一延长镜头并同步字幕规则。

13.3 确定性要求
画面由固定 scene graph、timeline、asset bytes、font bytes、renderer 和 t 唯一决定。
不在渲染时调用 Math.random、实时网络、系统时间来改变画面。
手绘种子建议由 scene_id、element_id、样式版本散列生成；前面插入元素不影响其他元素。
seek(t) 能正向、反向、乱序访问得到一致状态。
浏览器初始化等字体、图像和场景状态就绪，失败不得吞掉后当已就绪。

13.4 编码与资源
按帧号排序把截图输入编码器，限制在途帧数和缓存，防止某 worker 迟缓造成内存积压。
所有编码子进程必须监测启动错误、非零退出、取消和完成。
finally 关闭浏览器和子进程；失败临时产物不成为有效分段。
相同编码参数保证分段可拼接；不兼容时明确重编码策略。
并发数根据 CPU、内存和实际基准选择，不固定认为4路始终最佳。

13.5 复现标准
同一固定环境比较解码后像素/帧散列及时间轴。
不要以 MP4 整文件二进制相同作为所有场景唯一标准，容器元数据可能不同。
跨环境记录字体和浏览器差异，检查布局、内容、时序，必要时用容器固定依赖。
容器有助于运行一致，但不会消除生成模型的随机变化。

======================================================================
14. 构建状态、缓存、版本、快照与断点恢复
======================================================================

14.1 阶段状态
pending：未开始。
running：正在执行，含 worker/job 标识和开始时间。
succeeded：产物已经验证并提交。
failed：有明确错误和重试信息。
stale：输入或依赖变化，旧产物不再有效。
cancelled：已取消。
skipped：规则允许跳过，必须有原因，不等于验收通过。
整期状态为 draft、building、needs_revision、candidate、validated、delivered。
delivered 只由有效产物与交付检查共同确定。

14.2 指纹
输入 JSON 先规范化字段顺序和表示，再计算 SHA-256。
文件以实际 bytes 计算，路径和修改时间不能替代内容。
生图：模型、提示词、参考文件、尺寸、质量、背景和适配版本。
TTS：朗读文本、映射/读音版本、供应商、音色、速度、风格、音频规格。
布局：分镜、版式版本、字体、品牌、画幅、素材内容。
时间轴：布局事件、对应音频/对齐、fps、节奏规则。
渲染：编译场景、时间轴、素材字体、浏览器、渲染器、编码参数。
混音：分段/总片、BGM、音量与包络规则。
QA：被检验产物、检查器及规则版本。

14.3 缓存命中条件
身份匹配、文件存在、散列一致、格式有效、状态允许复用。
不得只读 manifest 的 succeeded 就跳过实际文件验证。
缓存音频和时间戳成对恢复；字幕配置变化只重做字幕/相关渲染，不必重配声音。
网络 URL 相同不代表内容相同；正式素材先落盘并记录散列。
已验收资产即使供应商不再提供原模型，也仍可作为冻结文件使用。

14.4 原子提交与锁
先写任务临时文件 → 验证 → 提交有效文件 → 写状态。
每个 run 独立目录；共享资产库入库使用锁或单独事务。
同一期源稿修改、有效交付指针更新需要协调，避免两个运行相互覆盖。
重启后 running 状态需要核对活进程/租约和产物，不能直接假定仍在执行。
原子重命名不等于能跨文件系统完成事务；临时与目标文件尽量同一文件系统。

14.5 manifest 示例（缩写示例）
{
  "schema_version": "1.0",
  "episode_id": "ep-001",
  "revision": 1,
  "run_id": "run-001",
  "state": "building",
  "stages": {
    "audio:s01": {
      "status": "succeeded",
      "input_hash": "sha256:<实际输入摘要>",
      "artifacts": [{"path": "audio/s01.wav", "sha256": "<实际文件摘要>"}],
      "attempts": 1
    },
    "render:s01:landscape": {
      "status": "pending",
      "depends_on": ["audio:s01", "layout:s01:landscape"]
    }
  },
  "active_delivery": null
}

14.6 快照
保存全部实际输入或不可变内容寻址引用，并保证恢复时能获得文件。
包含正文、分镜、事实、素材、音频、时间戳、字体、品牌、组件、配置与工具版本。
不包含明文凭证和无必要的账号秘密。
长期项目还保存依赖锁文件、源码版本和必要运行镜像说明。
旧交付保留；新候选通过后才更新当前有效交付指针。

14.7 清理
可以清理可重新生成的临时帧、失效分段和任务临时目录。
不删除有效快照、原始参考、通过素材、有效交付和必要QA证据。
清理前核对依赖及保留策略；不能直接沿用“所有frames都删”而丢失审查证据。

======================================================================
15. 校验体系、错误等级与修复闭环
======================================================================

15.1 等级
BLOCKER：缺关键输入、错版本、错图、音频截断、文件不可播放等，阻止交付。
ERROR：可定位的严重内容或布局问题，要求返修。
WARNING：需要检查但可能合理，例如刻意重叠、较长停留。
INFO：提示、估时、性能、缓存记录。
规则可按产品模式调整，但调整写入版本和QA，不在运行中临时掩盖。

15.2 需求与结构检查（程序）
schema 版本支持；必填字段；ID唯一；路径可解析；引用存在；事件无循环；画幅支持。
检查 beat 与元素关系，内容没有全部集中在错误 beat。
拒绝非有限数值、负尺寸、未知动作与非法时间。

15.3 内容检查（AI/人，程序辅助）
关键事实有明确来源；数据单位、口径、日期、适用条件一致。
计算可复核；示意图和实际数据图区分。
字幕、旁白、封面、文案没有互相矛盾。
把“可能、估计、在某条件下”保留，不能视觉表现为无条件结论。
来源检查要求阅读相关正文，不能只使用搜索摘要。

15.4 素材检查（程序 + 视觉）
解码、尺寸、透明通道、有效像素范围、引用散列、任务绑定。
主体完整、姿势正确、没有误入另一任务的主体。
角色固定特征与参考比较；外部Logo实体核对。
抠图前后面积及边缘对照，防止误删合法小部件。

15.5 布局检查（程序 + 视觉）
实际文字边界、换行、字号下限、安全区、品牌区、画布边界。
关系图箭头连接正确；正当叠放用 overlap_policy 声明。
手机版预览检查阅读层级，不能以1080p放大查看通过代表手机可读。

15.6 时间检查（程序）
事件起止合法；不越界；触发锚点存在；阅读停留满足规则。
过度压缩、过多同时强调、运动速度异常形成问题。
字幕顺序、持续、全片偏移及最终尾句验证。
音频时间戳与实际文件绑定，不拿另一条wav的时间戳凑合。

15.7 音频检查（程序 + 听审）
ffprobe 读取真实参数；解码；静音、峰值与响度检查。
不要用“有音轨”代替“有完整旁白”。
配乐遮挡、断句、读音、情绪不自然通过完整听审检查。
音量阈值按交付目标制定，不在本文硬编码一个适合所有平台的值。

15.8 视频检查（程序 + 连续观看）
完整解码无异常；尺寸、fps、帧数、音轨与时长符合任务。
黑帧/静帧检测只发现候选问题；深色品牌卡、阅读停留可以合法。
镜头边界无误拼、缺段、重复段；运动看连续片段。
首帧、中段、尾句、转场、最终品牌状态必须覆盖。

15.9 检查工具示例
ffprobe -v error -show_entries format=duration:stream=index,codec_type,codec_name,width,height,r_frame_rate,duration -of json <final.mp4>
ffmpeg -v error -i <final.mp4> -f null -
ffmpeg -i <sample.mp4> -f framemd5 <sample.framemd5>
实际执行使用参数数组并正确处理路径；不要把输入文本拼接成Shell代码。
以上命令检查结构、解码和帧内容，不能证明科学内容正确、角色一致或发音正确。

15.10 修复循环
收集问题 → 按影响和严重度排序 → 选最小源修改 → 计算失效范围 → 重做 → 同规则再检。
每轮记录修复前后版本、改了什么、是否解决、是否新增问题。
示例可限制最多3轮视觉返修，具体次数由时间/费用预算决定。
达到边界仍失败时输出 needs_revision 与明确问题；禁止伪造通过。

======================================================================
16. 修改请求与局部重建规则
======================================================================

改旁白：变更正文版本 → 受影响语音单元 → 对齐、字幕、排期 → 对应镜头 → 总片、混音 → 对应QA。
改显示字而读法不变：显示映射/字幕/布局 → 对应渲染；语音是否复用由spoken input决定。
改素材：素材散列 → 使用它的布局和渲染 → 总片；尺寸/内容边界不变时布局可快速验证。
改字体：所有使用字体的文字测量、布局、字幕和渲染失效，不仅替换字体文件。
改品牌色：相关图形和封面重渲；已有PNG不会自动变色，需要决定保留、替换或重生成。
改音色/语速：全部相应配音和时间相关产物失效。
改动画速度：时间轴和受影响渲染失效；不必重配声音，除非内容因容量调整。
改BGM：只重混音及音频/最终QA；画面可复用。
改封面标题：封面和文案相关检查；不重出正文。
改来源事实：检查所有引用 fact_id 的旁白、屏幕字、图表、封面和发布稿。
删除镜头：更新顺序和累计偏移，旧分段不得继续进入总片。
新增镜头：稳定ID和种子保证其他镜头不无故变化，但累计时间和全片字幕仍需更新。
新模型配置：已有冻结产物不自动失效；用户/项目显式要求重新生成时创建新版本。

======================================================================
17. 跨 Agent、跨平台与能力诊断
======================================================================

17.1 最小能力
Agent 能读规范、写分镜、调用程序、查看预览、读取QA并改源稿。
执行环境能访问文件、运行 Node/Chromium/FFmpeg，或调用提供这些能力的服务。
生图与配音凭证属于运行环境，不要求每个 Agent 自己具有相同的原生工具。
纯聊天入口只能协助创作，是否能完成视频取决于接入的执行工具。

17.2 首选接口：跨平台CLI
【建议命令】wb doctor、wb init、wb validate、wb assets、wb tts、wb compile、wb preview、wb render、wb mix、wb qa、wb build、wb resume、wb status、wb snapshot。
机器输出模式支持 --json，返回状态、job_id、错误代码和产物；人类模式输出简明进度。
所有变更任务支持明确 episode_id 和输入版本。
使用 Node 文件API、os.homedir()、pathToFileURL()、execFile 参数数组。
避免依赖 Bash文本替换、macOS open、字符串file://拼接和仅有HOME的环境。
可打开文件作为可选便利功能，不能成为构建成功的前提。

17.3 HTTP/MCP（第二阶段）
包装CLI核心能力：create_episode、validate_storyboard、generate_assets、build_preview、build_video、get_status、get_qa、resume_job。
长任务立即返回 job_id，通过状态或事件读取进度；不要求一次工具调用长时间阻塞。
tool capability discovery 返回支持画幅、供应商、schema和执行模式。
重复提交同一幂等任务返回已有任务，避免Agent超时后重复扣费。
取消和恢复有明确语义，后台任务不依赖Agent持续在线。

17.4 可移植工程包
包含skill、schema、模板、固定资产、示例、依赖锁和环境诊断。
清楚说明可选服务、必须能力、正式与预览差别。
不同Agent对同一schema提交，渲染核心不随Agent改变。
先验证Windows本地和第二Agent，再按需要验证Linux/容器；不能未经测试宣称全平台。

18. 实施顺序与阶段交付物
======================================================================

阶段A：建立真实基准
保存原示例源、素材、已有音频和版本；运行环境诊断，记录实际能否出片。
建立代表性选题和基准场景；记录当前一次通过率、返修原因、耗时。
交付：基准工程、代码地图、运行说明、首份问题清单。
通过条件：知道目前哪些能用、哪些失败，结果可重现。

阶段B：优先修数据与失败可信度
移除最近图片兜底；绑定图片任务；明确项目ID；失效输出不复用。
增加总任务清单、返回状态、网络超时、取消、临时文件提交。
把已有配音内容缓存接入阶段依赖，不重复造一套不兼容缓存。
交付：可靠任务执行器、阶段日志、最基本素材/音频/文件检查。
通过条件：错图、旧master、空文件和故障均可定位，不出现假成功。

阶段C：固定风格和IP
品牌配置集中化；角色定稿；制作12～20个常用动作；建立style-board。
配音读音规则和表达样例定稿。
交付：品牌包、角色包、素材索引、验收样例。
通过条件：跨三个选题使用同一IP，视觉一致性可确认。

阶段D：结构化分镜和模板
完成schema、六种版式、基础动画和编译器；保留旧工程兼容入口。
先覆盖已知样片，不为未知需求建立大量空模板。
交付：分镜示例、编译场景、字段报错、静态预览。
通过条件：Agent可以只填写内容与模板参数，不用每期自由写坐标。

阶段E：时间与QA闭环
音频/显示文本映射；关键锚点；帧时间轴；阅读容量；动态预览。
自动QA及有限局部返修；正式快照、最终文件验证和交付指针。
交付：三条短样片、完整QA、局部重做记录。
通过条件：改稿、换图、中断恢复可完成，旧结论不错误继承。

阶段F：迁移与升级回归
跨平台NodeCLI，第二Agent操作；必要时服务包装。
基准场景固定输入回归；生成阶段单独做内容质量评估。
交付：第二Agent执行记录、运行包和回归报告。
通过条件：不修改渲染核心即可运行，有失败信息及恢复能力。

第一版建议范围：一个品牌、一个主IP、六种版式、六种基础动画、一种图像服务、现有配音服务、完整日志与QA。
具体日程取决于人员、旧工程可运行情况和资产制作耗时，本文不给未经评估的工期承诺。

19. 稳定性测试、故障注入与质量指标
======================================================================

19.1 固定工程测试
保存通过的素材和音频，不调用生成服务，重复渲染比较画面/时间轴。
比较workers=1与多worker；测试乱序seek、返回早期时间、第一帧和最后一帧。
测试中文/英文/数字混排、长标题、图片透明边缘、所有版式、横竖画幅。
相同环境严格比较，跨环境按可读性、布局、内容及时序检查。

19.2 创作能力测试
同样选题、品牌和组件交给不同Agent，分别记录质量。
无需稿件完全相同，要求结构、事实、风格、可读性和技术通过。
模型或提示词升级时，与旧基准做对照，不能仅挑最好的一次展示。
样本数、重试策略和是否人工介入都写明，避免指标不可比较。

19.3 故障注入
图片请求超时：只该job重试，没有混入其他图片。
图片空白/截断：资产检查拦截。
配音无时间戳：明确alignment状态，不假装精确。
配音缺尾句：完整性检查或听审发现，局部重配。
Chromium中断：临时分段无效，浏览器清理，已完成分段可复用。
FFmpeg启动失败/编码失败：总任务failed，不更新交付。
分段缺失：拼接失败，旧master不被当新输出。
删除缓存文件：校验失败后重建，manifest旧状态不能掩盖。
同名文件内容变化：SHA-256发现，受影响下游失效。
两个任务同时运行：彼此目录、结果和状态不串。
运行中改稿：旧run基于快照继续或明确取消，新revision独立。
磁盘不足/字体丢失：环境或阶段检查报告，未产生正式交付。

19.4 指标
技术完成率 = 完成技术验收的任务数 / 实际启动的任务数。
内容视觉一次通过率 = 未经过人工返修且通过规定质量检查的作品数 / 被评估作品数。
返修次数、人工分钟数、每分钟有效成片成本、各阶段耗时中位数及较慢分位数。
恢复成功率 = 在规定故障中成功恢复且结果有效的案例 / 运行的故障案例。
错版本/串素材次数单独记录，目标为0，不与普通美观问题平均。
not_run 不计入 passed，取消和放弃任务如实列出。

19.5 初始验收目标
关键素材引用错误、关键文字裁切、明显角色身份漂移：0项。
固定环境、固定输入的渲染结果按基准标准一致。
改一个素材或语音单元不重做无关生成任务。
发生中断后未变的有效结果可复用。
先连续做一批样片建立真实基线，再设一次通过率目标；本文不宣称达到95%等未测数值。

20. 标准演示片与验收方法
======================================================================

20.1 使用现有主题做可比较演示
主题示例：为什么懂很多道理，行动却没有变化。
时长试验目标45～60秒，实际由旁白和阅读时间决定。
0～5秒：IP拿着计划表，结果仍停在原地，呈现矛盾。
5～15秒：建立三个区域，IP进入中间区域，说明情境。
15～30秒：用同一个具体任务演示难度过低、适中、过高的区别。
30～45秒：演示怎样调整成能完成的一小步。
45～60秒：保留核心图形，给一个判断标准和行动建议。
科学结论需事实核查；三个圈可以作为解释模型，不直接包装为所有领域成立的定律。

20.2 验收
IP不同姿势是否同一角色；重点是否与讲解同步。
动画是否传达关系，而非仅增加移动。
手机尺寸正文可读，字幕不挡关键信息。
结论停留合理，无长时间无意义空白。
完整听审专名、否定词和结尾，检查BGM遮挡。

20.3 必做三次修改实验
修改一句旁白：确认受影响配音、时间轴、字幕更新，无旧声音。
替换一个动作：确认只影响引用它的镜头/封面，角色不跳位。
中途打断并恢复：确认不重复调用已完成的模型任务，不混入临时分段。
再让第二Agent执行同样实验，记录是否需要改代码和解释。

21. 成本、速度与运行记录
======================================================================

21.1 记录口径
分别记录研究、文字生成、生图、配音、编译、预览、QA、正式渲染、混音和人工时间。
供应商未返回费用时标unknown；可以按公开单价估算但标estimated并记录单价版本。
区分首次制作、缓存重跑和局部修改，不能把缓存命中的渲染耗时当全链路首次耗时。
已有文档中的约35～40秒性能属于原作者环境描述，当前机器和新流程应重新测量。

21.2 优化顺序
优先复用有效IP/道具和音频，其次减少无必要返修，再调整并发和编码。
草稿可以低清，正式渲染使用同一布局和时间轴。
按任务配置费用、重试、最长运行时间和并发；达到边界停止对应任务。
质量设定与模型更换都用相同任务对照，不只看单张效果或参数名称。

21.3 日志
每条事件带episode_id、revision、run_id、stage_id、job_id。
记录输入指纹、开始结束、缓存命中、重试原因和实际输出。
错误避免打印秘密凭证；保存能排障的供应商请求ID和错误分类。
用户可看到“哪个镜头失败、为什么、已有多少完成、怎样恢复”。

22. Skill 入口与 Agent 执行说明模板
======================================================================

22.1 Skill 应包含
适用范围；默认模式；工程权威源；可用命令；执行流程；关键约束；失败边界；QA处理；交付要求；按需参考链接。
品牌描述、供应商API细节、完整schema和版式坐标放独立资料，不全部复制进入口。
用户允许制作时可自主执行常规步骤；缺关键要求才询问，避免每一步停下来。

22.2 可复用 Agent 指令示例
你负责制作本期手绘讲解视频。读取brief、指定版本品牌和角色、facts及模板目录。
以storyboard为内容权威源，按schema填写分镜；正文数据引用fact_id。
优先复用已验收角色与素材，只为缺失内容提交生成任务。
调用生产CLI完成编译、预览和检查，读取结构化QA报告。
遇到BLOCKER或ERROR，修改对应源字段并重做受影响阶段；不要改编译产物绕过检查。
正式渲染只使用已确定快照；无法通过时保留进度并输出needs_revision及具体问题。
交付使用manifest指定的有效文件，说明实际执行的检查；未听审不能写已完成听审。

22.3 研究提示模板
输入：主题、观众、需要支持的主张、用户资料、时效要求。
输出：facts结构，每项来源、原文支持范围、数值单位、条件和不确定性。
要求：检索和阅读相关正文；无法验证明确标记；生活例子标示为例子。

22.4 分镜提示模板
输入：brief、facts、品牌与角色引用、版式可用项、合格样例。
输出：storyboard；每镜头一个理解目标，beat与视觉有对应关系。
要求：通过schema；不发明资产ID；不自由写未知动作；超过模板容量拆镜头。

22.5 视觉审查提示模板
输入：基准风格板、角色参考、指定预览图或片段、源分镜、规则。
输出：可定位问题列表、证据、严重度和建议修改范围。
要求：先判断是否理解本镜头目标，再看风格；不把个人偏好当严重错误；不猜听不到的声音。

22.6 修复提示模板
输入：原分镜、QA问题、允许修改范围、已定稿资产、预算。
输出：最小源修改及原因；声明哪些检查需要重跑。
要求：避免无关改稿；不替换已定稿IP；不静默更换音色/模型/画风。

24. 完成标准、约束与长期维护
======================================================================

24.1 第一个可用版本完成标准
一个品牌和主IP已定稿，至少覆盖常用动作及关键版式。
Agent能根据统一schema填写分镜，并通过固定程序形成预览和正式输出。
图片任务、音频时间戳、素材版本及成片都有明确对应关系。
关键失败有错误状态，旧成片不会冒充新版本。
至少完成三个选题、三种修改实验和第二Agent执行验证。
正式交付有实际文件检查、视觉检查、听审记录和有效版本标识。

24.2 不能通过技术结构保证的事情
参考图和固定模型不能保证每张新图完全一致。
结构检查不能保证文案好看、逻辑正确或事实可信。
字幕时间戳不能保证语音读音正确。
完整解码不能保证观众理解或完播率提高。
短期样片通过不能证明所有未来选题都稳定，需要持续记录真实失败。

24.3 长期维护
每次故障归类到素材、内容、布局、时间、服务、执行或版本。
高频故障用具体规则/组件修复，不为一次偶发现象无限追加通用约束。
新模板必须有合格样例、容量、失败案例和测试，避免模板数量增长而质量下降。
品牌、角色、读音和组件升级使用新版本，旧工程保持恢复能力。
升级先跑固定工程回归，再跑创作质量对照，通过后切换默认版本。
定期核对资产库中的孤立引用和有效快照，不清除仍被交付使用的文件。

24.4 系统应始终维护的关系
每一条旁白对应当前源稿。
每一份时间戳对应实际使用的音频。
每一个素材对应明确任务或已验收资产。
每一帧画面来自冻结的布局和时间轴。
每一份QA对应被检查的具体版本。
每一次交付指向实际通过检查的有效产物。

这六项关系完整，才能在增加选题、切换Agent、修改内容和处理故障时维持整体稳定。
