# 设计先行生产链路审计与优化顺序

2026-10-13。基于当前本地源码、design-first round-2/3/4真实请求与截图、A02/A03和设计先行交接；本轮只审核并提出方案，没有修改业务代码或发起新的模型请求。

## 结论与验证边界

### 用户确认的方向（本条优先于下方原审计建议）

组件库＋生图模型生成的图片 → Agent理解设计并选择代码/图片分工 → 用代码组件＋独立图片素材还原 → 实际截图与逐句验证。组件库既是生图参考，也是Agent可调用的实现能力；整页设计图必须实际进入Agent，不以固定模板自动套版替代。文字、数据、关系保持可编辑，图片承担代码不擅长的视觉主体。需要的素材可提取或独立生成，身份/边缘/来源须验证；多素材拆分仍需独立实现与实测。

质量优先：保留模型正常思考，不因延迟自动关闭或降低思考。优先延长等待时间并展示真实任务状态；超时保持unknown及原请求身份，不自动重发。此前关闭思考的实验只保留为历史证据，不作为生产默认或质量最优依据。下一批统一调用策略应遵循此修正。

单页核心链路已有真实证据：语义计划→整页设计图→Pro受限静态操作→共享组件HTML→已有真实配音→逐句与全输出帧检查。最后成功请求为单参考图、关闭思考、12.587秒、5072 tokens，无手改模型输出。

该结果尚不等于正式应用整课全链路验收：设计图由Codex内置生图提供，试听组装由实验脚本完成，本轮未跑正式项目签收与最终视频导出；该页asset_needs为空，没有证明多元素素材板拆分链路。已有恢复、快照、编辑、导出能力应继续复用。

## Agent与Skill收束

本段记录审计当时状态：当时注册的运行 Skill 只有 `candidate-layout-repair`，`produce-editable-html` 是 Codex 操作说明，设计还原 SYSTEM 尚在 Python 中。随后 2026-10-13 的设计 Agent 增量已将设计理解、受控还原、视觉对照审核三个独立策略迁入受控注册体系，与容量修复合计四个运行 Skill；当前状态、实际模型结果和限制以[设计 Agent 交接](../plans/html-backend-development/handoff-design-agent-2026-10-13.md)为准。

尚未进入运行 Skill 的是 A04 讲稿/动作语义审查。各策略只收自己需要的当前页证据，输出受限结构，不互相签发批准；人工编辑继续走公共编辑 API。无需为了 Skill 数量而拆更多 Agent 或更换框架。

## 推荐实施批次

1. **生产一致性**：统一真实调用策略；补全阶段/验收状态；复用已通过页，从应用入口完成设计停点、确认、HTML、局部编辑、恢复、正式导出一次。新图片连接需就绪，不能把内置生图实验当应用供应商已接通。
2. **质量闭环**：完成A04和设计对照审查；先修通用卡片/总结/字体层次，合并重复修复循环。语义错误回规划，外观错误回还原，图片问题回素材阶段。
3. **稳定性与效率**：固定12页实测，统计首轮/最终通过、真实HTTP次数、耗时、tokens、未知结果、人工介入和视觉认可率；费用没有账单则保持null。指标达标后再推进课程调度与候选区并发。

任何一批都不将“可播放/可导出”当作“表达正确/美感通过”。新样本和已有用户修改不得用于无记录的择优演示。
