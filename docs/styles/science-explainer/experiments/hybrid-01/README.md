## 实际怎么做的

1. 用户参考板 + 精简且准确的屏幕内容 + 分层职责，经 ToAPIs 生成 1536×864 整页设计稿。
2. 以选定设计稿为参考，分别请求两个独立对象。显式 transparent 参数的两次任务失败；
   改 auto 后得到 RGB 棋盘格，均未通过透明素材验收。不能凭这些请求断言供应商普遍不支持透明。
3. 使用内置 image_gen 对两张 RGB 素材做背景提取，得到实际 RGBA，保留原失败资产作证据。
4. 根据设计回收构图和字号，人工制作受约束 HTML；插画使用新资产，文字真实可编辑，箭头为 SVG。
5. 固定图位、控制两侧说明显隐；检查字体、解码、容量、观看缩放及越界，保留截图。

最终资产是 [水碗 PNG](evaporation-alpha.png) 与 [冷杯 PNG](condensation-alpha.png)。
任务文本见 [整页提示词](design-prompt.txt)、[水碗提示词](evaporation-prompt.txt)、
[冷杯提示词](condensation-prompt.txt)、[水碗透明编辑](evaporation-alpha-prompt.txt)、

## 对照观察

保留了暖白底、粉蓝术语、双主视觉、短说明与留白。参考板中的立体素材质感通过位图承担；
标题与关系的准确性、编辑和讲解目标通过代码承担。两侧不再叠加编号/英文/例子卡。
HTML 字体、插图尺度与生成稿仍有差异；提取/重生成也改变了局部水面、分子位置和玻璃细节。
底部来源是可控文字，装饰分子未照搬。没有像素级还原或相似度保证。

透明编辑结果能在暖白底融合；本轮人工查看未见棋盘背景或明显切边，细小分子边缘仍需
高倍/深浅背景专项审阅。透明 alpha 的存在只证明分层技术成立，不能代替美术判断。
示意分子并非实物；水蒸气通常不可见，水碗没有沸腾，冷杯水滴指向外壁，知识来源沿用
[USGS 来源记录](../../content-sources.md)。本页仅概念科普，不表达分子数量或速率。

## 从这次实验得到的生产建议

采用两段生产：新模板设计阶段用整页稿探索构图；模板通过后，日常生产只填槽位和制作
所需素材，避免每页重新走“整页图→重生成两图”的成本与漂移。
独立对象优先选择经验证可交付 alpha 的工具，或明确使用统一底色的场景插画变体；
后者须重新验收，不允许用伪透明资产顶替。简单容器/标签/箭头无需生图。
科学图示精度需求高时用可靠素材/矢量结构；当前模型插画不应替代精确机制与定量图。

下一步先取得本页视觉反馈，再用另一个双概念内容和对应新插画验证模板复用，然后按
支持范围提炼正式参数。先验证这张页真的值得复用，再进入 P03。

代码审查：样稿与业务服务隔离，固定本地内容通过 textContent 构建；有限枚举视图/状态，
不执行模型返回的 HTML；仅两图与参考图，无新依赖或秘密。主要检查实际视觉与容量边界，
本次无数据库/API/Agent/生产影响登记变化。
