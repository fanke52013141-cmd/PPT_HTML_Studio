# 关键帧与资产方案验证报告

日期：2026-10-07；关联 HPS-023—030；范围：motion-02 独立实验。

## 结论

流程已经走到实际 HTML 过程动画和无声视频输出：预填对象/运动→固定槽位资产板→修复→设计参照→矩形提取→代码组装→时间状态检查。
原有对象定义保持有效，没有通过识别整页图片来重建对象。临时轨迹由代码生成，终态消失也不丢失身份。
资产方案具有可操作性，但本例不能把资产板直接发布为生产库：模型没有完全遵守留边与边缘要求。流程通过与美术发布通过分开记录。

## 实际发生的修正

首张板生成了正确数量和指定对象，未把标题或轨迹画进素材，但边缘存在杂点、对象占比超出要求。保留 v1，再用模型编辑修复为 v2。
v2 具有真实 RGBA，三个槽位可按固定矩形提取，右下空槽最大 alpha 为 1/255。不是伪透明棋盘格，也不是严格全零空槽。
修复后实际显示尺寸的边缘可用于演示，源尺寸仍有细小边缘噪点，主体未严格全部处在中间 70% 区域；这些是未通过项，不能写成自动抠图完美成功。
提取仅为确定性矩形裁切，不进行识别、分割、背景替换或生成式修补。保留整槽边距，记录源板/输出哈希和裁切偏移；三个资源仍保持独立身份。

资产板先生成，设计图随后参考同板，减少另画一套角色的漂移。两者都依据预先填写的定义，顺序并不改变规范源头。
设计图引用 v1、运行引用修复 v2，存在主体缩放/轮廓差异，已记录；更严格的生产应在最终资产确认后重验或更新设计参考。
最初 SVG 轨迹改为 Canvas 代码路径，方形图片槽位改为等比方形显示，避免图片变形；初版定义保留，没有静默覆盖。

## 对后续实施的价值

1. 对象清单必须前置；资源与 HTML 的分工可明确约束模型，但仍需实际验收。
2. 固定槽位可以省去本例的自动命名/分割；提取效率不能由一个样例推断为所有内容有效。
3. 同板有助于视角/光照协调，不能替代完整轮廓、透明、留边和边缘检查。
4. 终态图不够描述过程；至少配全过程对象清单和实际关键帧。本例仅生一个代表帧，其他帧复用资源渲染。
5. 美感需要对照实际合成，而不是只看生成图。本例实际图的云和文字比参照更小，画面更疏；应由用户审阅后决定模板参数。

下一步先审阅本例视觉与动作，再提高资产板边缘/主体包围框质量，并用换主题实例测试复用。暂不将本例扩成生产通用 Schema，也不重选已有音频或数字人服务。
