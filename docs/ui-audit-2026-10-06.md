## 一、总体结论

用户的四条抱怨**全部属实**，且比描述的更系统化：

| 用户反馈 | 核实结论 |
| --- | --- |
| (a) 弹窗关闭按钮有的有、有的没有 | **属实**。18 个静态弹窗里出现了 **5 种关闭方式**（见 §3.1），其中 9 个完全没有关闭按钮 |
| (a) 弹窗标题有的左对齐、有的不左对齐 | **属实**。只有「操作确认」弹窗居中，其余全部左对齐（§3.2） |
| (a) 标题下横线和下面的框切在一起 | **属实**。有分隔线的弹窗里，分隔线 padding 各不相同（4px/12px），「图片风格设置」的 pb=4px 视觉上贴住内容（§3.3） |
| (b) 「导入文章」不该提示「保存修改」，应该是实时保存 | **部分属实，方向相反**：文章步骤**没有**实时保存，只有手动「保存修改」；真正的问题是**保存模型不统一**——旁白、Mask 等步骤都是自动保存，唯独步骤 1 要手动点保存，且没有未保存提示、离开不拦截，存在**静默丢失**风险（§5.1） |
| (c) 按钮状态不明确 | **属实**。存在禁用无说明（步骤 2「进入图片生成」、步骤 8「生成 MP4」）、可点但看起来禁用（步骤 3「批量删除」、步骤 6「撤销/重做」）、蓝色高亮被误读为开关（步骤 5「添加停顿与语气」）三类问题（§5） |
| (d) 「复用旧标注」看不懂 | **属实，且工作区未提交的修改已把它删掉**（`git diff static/images.js`）。本报告把它列入"已修复待提交"清单（§7） |

另有 **2 个功能性缺陷**在走查中被直接撞上：编辑创作账号弹窗标题错误（§4.1）、
「系统设置」面板无任何入口成为死代码（§4.2）。

## 三、弹窗规范审查（用户重点 (a)）

对 18 个静态弹窗 + 5 个动态弹窗逐一做了 DOM 结构提取 + 截图比对。

### 3.1 关闭方式：5 种并存

| 方式 | 弹窗 |
| --- | --- |
| ① 右上角 × 图标 | 模型设置、创作配置、新建图片风格、图片风格设置、一键生成、账号对话框、视频背景 |
| ② 右上角「× 关闭」文字按钮 | AI 生成图片（step3-ai） |
| ③ 右上角「关闭」文字按钮（带边框盒） | 字幕样式与位置、统一动画设置、Prompt 帮助 |
| ④ 底部「关闭」按钮 | IP 形象管理（关闭+保存设置 并列在底部） |
| ⑤ **完全没有关闭**（只能取消/ESC/点遮罩） | 新建视频项目、修改视频设定、系统设置(死)、生成演讲稿、批量导入分镜、图片生成 Prompt、演讲稿 prompt、旁白 AI 标注 Prompt、AI Mask 自动标注设置、操作确认 |

问题：用户在「新建视频项目」里找不到关闭按钮时，只能赌左下角的「取消」；
而在「IP 形象管理」里底部同时出现「关闭」和「保存设置」，语义重叠
（关掉到底存不存？）。

### 3.2 标题对齐：1 个例外破坏统一

所有弹窗标题左对齐，唯独 `modal-confirm`（删除等高危操作确认）标题居中
（`static/index.html:1372-1381`，`text-align: center`）。它恰恰是曝光频次最高的
弹窗，最显眼的不统一。

### 3.3 标题分隔线：有无不一、间距不一

- 有分隔线：字幕（`border-bottom 0.67px #E2E8F0, padding-bottom 12px`）、
  动画（同上）、图片风格设置（**padding-bottom 4px**，视觉贴住下方内容——即用户说的
  "横线和框切在一起"）、IP 形象（分节线 0.67px #EDF0F4）。
- 无分隔线：其余全部。
- "用户补充说明行"也是有的弹窗有（字幕/动画/AI Mask/生图 Prompt），有的没有。

### 3.4 主按钮颜色：4 种并存

| 颜色 | 出现的弹窗 |
| --- | --- |
| 深色（规范主色） | 创建项目、保存字幕设置、应用到全部语块、保存当前 Prompt、保存设置(IP) |
| 橙色 | 生成演讲稿（modal-step2-generate 的确认按钮） |
| **紫蓝色** | 图片风格设置（应用到本次生成、✦生成3张预览图、选中卡片边框、Tab 激活色）、**视频背景设置（保存设置）** |
| 红字 | 操作确认「确认」、覆盖导入、删除模板 |

紫色是已退役的 "Soft Pastel Studio" 风格残留，与品牌橙 `#f46a36`/`#ee5d36`
直接冲突，且同一个「保存设置」按钮在 IP 形象弹窗是深色、在视频背景弹窗是紫色。

### 3.5 标题文案不统一

- 「演讲稿prompt」（全小写、无空格）vs「图片生成 Prompt」vs「旁白 AI 标注 Prompt」vs「可视化」（丢了 Prompt 后缀）。
- 演讲稿 Prompt 弹窗内下拉框文案 **「当前 演讲稿prompt Prompt」**——"Prompt" 重复拼接，属文案 bug（`modal-storyboard-rules` 模板渲染）。
- 「AI 生成图片：slide_001」把内部 ID 直接暴露给用户，应显示「第 1 页 · 标题」。

### 3.6 建议统一规范（可直接落地）

1. **所有弹窗**：右上角统一 × 图标按钮（`icon-button`），ESC + 点击遮罩关闭；底部「取消」仅在会丢失输入的表单弹窗保留，二者不并用语义（取消=放弃修改并关闭）。
2. **标题**：一律左对齐 + 副说明行（可省略）+ `0.67px var(--border-faint)` 分隔线 + `padding-bottom 12px / margin-bottom 16px`。
3. **主按钮**：一律深色 `ws-primary`；橙色仅用于工作区底部 CTA；红字仅用于不可逆破坏性操作且必须配确认弹窗；**清除全部紫色**。
4. **命名**：Prompt 一律大写「Prompt」；弹窗标题 = 工具栏按钮名，一个入口一个名字；「可视化」→「可视化 Prompt」。
5. **操作确认弹窗**：标题改左对齐，与全站一致；危险操作按钮用红色实底而非红字。

## 四、功能性缺陷（走查中直接撞上）

### 4.1 编辑创作账号弹出「创建创作账号」标题 【P1 · 文案 bug】
- 复现：首页点击账号旁 **✎**（修改当前创作账号）→ 弹窗标题「创建创作账号」，输入框预填「默认创作账号」，按钮却是「保存修改」。
- 根因：编辑复用创建对话框，只改了按钮文案（`static/account_management.js:345`），标题 `<h3 id="account-create-title">创建创作账号</h3>`（`account_management.js:145`）从不更新。
- 截图：`logs/ui_audit/12_modal_settings.png`。

### 4.2 「系统设置」面板无任何入口（死代码）【P1】
- `btn-open-settings` 被内联 `style="display:none;"` 隐藏（`static/index.html:47`），
  全站没有第二个入口调用 `openSettingsModal()`（`static/settings.js:165`）。
- 该面板承载的**任务并发、上游网关额度（RPM/并发）、队列等待**等全局设置随之不可达；
  同名能力已迁入「创作配置」（基础与模型/视觉与风格/输出与交付/提示词工程），
  应删除 `modal-settings` + `btn-open-settings` + `settings.js` 中对应死代码，
  并确认网关额度等全局项在「创作配置」或设置页有归属。

### 4.3 配置导出无确认直接打包全部密钥 【P1 · 安全体验】
- 首页「配置导出」一键触发 `/api/config/export-with-secrets-zip`（含 API/TTS 明文凭据），
  没有任何确认弹窗，导出完成后才弹 toast 提示"请妥善保管该 ZIP"（`static/settings.js:235-244`）。
- 建议：导出前弹确认（说明包含明文凭据），或默认导出不含密钥、密钥单独二次确认。

### 4.4 项目卡片 ⋯ 菜单：悬停展开 + 点击翻转，存在"闪断" 【P2】
- 菜单由 `mouseenter` 打开（`static/courses.js:474-487`），点击是 toggle；
  悬停展开的瞬间紧接着点击会把菜单立刻关掉（走查中复现一次），用户感知为"点了没反应"。
- 菜单按钮本身是 hover 才可见（`icon-btn-hover`），触屏/键盘用户只能靠 Tab focus 展开。
- 建议：点击始终展开；已展开时点击项外部才关闭。

## 五、按钮状态审查（用户重点 (c)）

### 5.1 步骤 1「保存修改」：保存模型不统一 【P1】
- 事实：`static/article.js` **没有自动保存**——只有 `saveStep1Edit()` 手动保存；
  文章导入成功后「保存修改」常驻显示（`article.js:313`、`loadStep1Data` 有文章即显示）。
- 用户以为实时保存（因为旁白/Mask/字幕等步骤都是自动保存），点进去发现要手动保存，预期落空。
- 更严重的隐患：**没有脏状态标记、离开不拦截**——编辑文章后直接点「分镜规划 →」或
  「返回首页」，修改静默丢失。
- 建议（二选一，倾向 ①）：① 给步骤 1 加与其他步骤一致的防抖自动保存 + 「已保存」轻提示，删除手动按钮；② 保留手动保存，但加未保存圆点标记 + 离开确认。

### 5.2 禁用无说明 【P1】
- 步骤 2「进入图片生成」`disabled`，唯一原因（"演讲稿已修改，请重新生成可视化"）写在
  页面中部一段灰字里，按钮旁无 tooltip、无行内原因（`storyboard.js:766-775` 置灰逻辑）。
- 步骤 8「生成 MP4」disabled：未提交修改**删掉了原来的原因文案**
  （`git diff static/index.html`：`请先生成全部页面音频` 提示被移除），现在只剩灰按钮，是**回归**。
- 规范建议：禁用必须三选一——按钮旁行内原因 / `title` tooltip / 点击后 toast 说明原因；推荐行内原因，紧跟按钮。

### 5.3 可点但看起来禁用 【P2】
- 步骤 3 工具栏「批量删除」「批量下载」、步骤 6「撤销」「重做」实测均为 **enabled**
  （无 title、无 disabled 属性），但浅灰样式与主操作反差弱，用户会以为不可点；
  反过来，全工具栏白底按钮也无法区分"哪个是当前推荐操作"。

### 5.4 高亮被误读为开关 【P1/P2】
- 步骤 5「添加停顿与语气」常态蓝色高亮，视觉上是"已开启的开关"，实际是动作按钮；
  同一工具栏「生成音频」是深色主按钮，双重点导致层级混乱。
- 步骤 5 三个并列生成按钮「生成音频 / 补齐音频 / 强制重新生成」无任何解释，
  新用户无从判断该点哪个（差异：全部生成/只生成缺失/忽略缓存重来）。
  建议合并为一个「生成音频」+ 下拉或"仅缺失/强制重生成"次级选项。

### 5.5 状态自相矛盾 【P1】
- 步骤 5 每页都挂着橙色「语音配置已变更，请重新生成」，右上角「确认进入勾画」却是
  高亮可点状态——页面同时告诉用户"过期了"和"可以确认"。
- 步骤 7 侧栏打 ✓（已完成），步骤 8 顶部横幅却提示"数字人视频未就绪"。
  根因：可选步骤被跳过即记 completed（`step_status`），完成态与产物就绪态混用。
  建议侧栏区分「已完成 / 已跳过(灰勾) / 需重确认(橙点)」三态。
