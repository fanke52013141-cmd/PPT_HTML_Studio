### 1.1 「分页时间窗」是什么（你要的解释）

它是**字幕分段的合并窗口**，字段名 `paging_window_ms`，默认 1300 毫秒。作用：视频字幕不是一句一条单独闪现——**相邻两句字幕之间的间隔小于这个窗口时，就把它们合并成同一页字幕一起显示**，避免字幕频繁闪切。数值越小越接近逐句切换，越大越倾向多句合并（`index.html:1732` 的说明原文也是这个意思）。改成「分页MS」没问题，两处文案同步改，悬停提示保留完整解释（§5.2）。

## 二、统一设计规范（本轮的核心交付）

### 2.1 按钮体系：图标与动效的统一规则

现状问题不是"缺规范"，而是三种历史风格叠加。我的建议是**收敛为一种**：

**规则 A（推荐）：工具栏动作按钮一律纯文字，只有两类例外带图标**

| 按钮类型 | 样式 | 图标 | 动效 |
| --- | --- | --- | --- |
| 常规动作（同步/批量上传/复制提示词/Prompt 类/风格类/IP 形象…） | 白底 1px 灰边胶囊，30px 高，12px 字 | **无图标** | 仅底色/边框 150ms 过渡，**无位移** |
| 每页主推进按钮（进入图片生成/确认进入下一步/生成音频/确认进入勾画/进入作品输出/完成并退出） | 深色 `#17191D` 底白字（或橙 `#EE5D36`，二选一全站统一） | **统一右箭头 →**，14px | hover 箭头右移 2px（唯一图标动效） |
| 进行中状态（生成中/AI 分块中/正在确认…） | 按钮原样式 + 禁用 | **统一 spinner**（替代文字前的图标） | spinner 旋转 |
| 特殊语义强调（添加停顿与语气） | 靛蓝 `#4F46E5`（现状保留） | 无图标 | 同常规 |

理由：标题栏一排 7-9 个按钮，图标混搭正是"不统一"观感的主要来源；纯文字信息密度最高、永不缺图；主推进按钮带统一箭头形成全站"完成本页"的视觉锚点；spinner 是状态不是装饰，必须保留。备选规则 B（全部统一带 14px 图标）不推荐：9 个动作里"同步/补齐音频/导出语音"的图标语义都很弱，且更挤。

**动效总则**：除上表三类外，全站按钮**不加任何位移动画**（旧层的 `translate(-1px,-1px)` 硬阴影位移感已在上轮清除页签时处理，本轮扫尾按钮残留）；卡片 hover 上浮保留 4px（首页卡既有）；禁止 hover 换图标。

### 2.2 弹窗三段式标准（回应你的 (a)，我的意见：必须固定）

你的直觉是对的——**标题固定、主体滚动、底部固定**是唯一正确形态。标准：

```
┌─────────────────────────────────┐
│ 固定标题栏：标题 + × 关闭（不滚动）      │ 56px，底部 1px 分隔线
├─────────────────────────────────┤
│ 固定 Tab 条（有多 Tab 的弹窗才有）       │ 40px，不随主体滚动
├─────────────────────────────────┤
│ 主体：唯一可滚动区                     │ max-height 限高，细滚动条
│ （长表单、列表、预览都在这里滚）          │
├─────────────────────────────────┤
│ 固定底部：右对齐按钮组                  │ 次按钮 / 主按钮 / 危险按钮，顶部 1px 分隔线
└─────────────────────────────────┘
```

- **Tab 必须固定不滚**：否则长表单滚到一半不知道自己在哪个 Tab（现状创作配置正是如此）。
- 遮罩统一 `rgba(0,0,0,.45)`（工作区）／首页弹窗保持 Stitch 层；圆角 16px；宽度分三档：小 440 / 中 720 / 大 1080（超宽预览类 1280）。
- 需要迁移的弹窗：`config-editor-modal` 族（现状整体滚含标题）、一键生成（无 ×）、style-ref / storyboard-bg（自有 footer）、字幕设置（预览区改为主体顶部 sticky，滚动时预览不消失）。
- 例外仅一个：`modal-confirm` 确认框（无主体滚动，天然三段）。

### 2.3 Master-Detail（左目录右编辑）布局标准

模型设置与创作配置包共用同一骨架，学一次会用两处：

```
┌──────────────┬──────────────────────────┐
│ 左栏 260px     │ 右栏（编辑区）                │
│ ─ 分组标题 ─   │ 标题：编辑「XX」/ 新增 XX      │
│ ▸ 条目(选中态) │ 表单字段（两列网格）           │
│ ▸ 条目        │ ...                        │
│ ─ 分组标题 ─   │                            │
│ ▸ 条目        │                            │
│ ＋ 新增       │                            │
└──────────────┴──────────────────────────┘
│ 底部（固定）：取消编辑 / 保存 / 删除(危险)     │
```

## 四、各页面具体改造方案

### 4.1 Step3 图片生成与管理（图3/图4 的问题）

1. **标题栏恢复单行**：删 `stitch.css:2467` 的标题独占行规则，对齐其他步骤（标题左 + 按钮右，`overflow-x` 兜底）——这同时解决"内容偏下"（标题栏从两行变一行，内容上移）。
2. **卡片头部重排**（解决把手 > 徽章）：
   - 状态徽章移到**第一位**（状态优先），12px 胶囊不变；
   - 拖拽把手缩到 **16×16px**（svg 14px），常驻但淡灰 `#C0C4CC`，hover 变橙、cursor grab；不再 28×30 抢视觉；
   - 「第 N 页」+ 标题行、上传/AI生成 按钮行保持，AI生成为主按钮样式。
3. 按钮图标按规则 A 清理（批量上传/批量生图/复制提示词/IP形象去图标，下一步保留箭头）。

### 4.2 模型设置重构（回应你的 (c)，同意你的方向）

现状：类型 Tab + 已有模型列表在上、「新增」大表单整块在下——选择与编辑上下割裂。改造为 §2.3 master-detail：

- **左栏**：三个分组标题（文本模型/图片模型/语音模型）+ 各组下模型条目（名称 + 「默认」标记 + 选中高亮），分组可折叠但默认全展开；底部「＋ 新增模型」（先选类型再出现空表单）。
- **右栏**：未选中 = 空态卡（"从左侧选择一个模型查看或编辑，或点击新增"）；选中/新增 = 现有表单字段原样复用（接入方式/BaseURL/密钥/模型 ID/参数…），标题随状态变「编辑：豆包写作模型 / 新增文本模型」。
- **底部固定**：取消编辑（编辑态）/ 保存 / 删除该模型（危险，仅编辑态）。
- 类型切换逻辑不变（`data-model-kind` 全保留），只是从顶部 Tab 变为左栏分组。

### 4.3 创作配置包拆分（回应你的 (b)，同意拆分，两个方案供你在设计稿上选）

现状丑的根源：包管理（列表+包名输入）与编辑（四 Tab）纵向堆叠，一个弹窗干两件事。**方案一（推荐）：弹窗内左右分栏**——左栏 = 配置包列表（卡片式：名称+摘要+「使用中」标记）+「＋ 新建配置包」；右栏 = 现有四 Tab 编辑器（Tab 固定不滚）；底部固定 = 另存为新包 / 保存当前包 / 删除当前包（危险）。「当前配置包名称」输入框从顶部挪进「另存为/新建」流程。与模型设置同构，学习成本为零。
**方案二：两个独立弹窗**——顶栏「创作配置」直接开当前包的四 Tab 编辑器（顶部一个包切换下拉）；另设「管理配置包」子弹窗只做列表/新建/重命名/删除/切换。层级更清但多一次跳转，且两处入口要维护。
我推荐方案一：分离体现在布局层级上（左管理右编辑），不产生二级弹窗；Stitch 两案都会画一屏供你对比。
