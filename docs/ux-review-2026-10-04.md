## 二、🔴 Blocker：静默失效（本次走查新发现，最高优先级）

>共同特征：**没有报错、没有提示、用户以为操作成功了**。这类问题比"报错"更危险——用户不会去反馈，因为"看起来一切正常"。

### B1. Step3 两个功能按钮永久缺失，用户无法执行"视频背景"与"删除全部图片"

**现象**
进入「图片生成与管理」步骤，工具栏只有 6 个按钮：批量上传 / 批量生图 / 复制提示词 / 生图 Prompt / 图片风格 / IP 形象 / 下一步。
代码里明确要动态注入的 **「视频背景」和「删除全部图片」两个按钮，从未出现在界面上**。

**根因（已精确定位）**
`static/storyboard_background_extension.js:81`
```js
const toolbar = document.querySelector('#step-panel-3 .step3-toolbar-row'); // 父容器
const confirmButton = document.getElementById('step3-btn-confirm');          // 参照节点
toolbar.insertBefore(button, confirmButton || null);                        // 跨父节点 → 抛错
```
实测证据：
```json
{ "toolbarChildren": ["highlight-title workflow-title", "workflow-toolbar"],
  "confirmParent": "workflow-toolbar",
  "isSameParent": false }        ← 参照节点不在同一父节点内
```
浏览器控制台持续报错（每 500ms 一次，贯穿整个会话）：
```
NotFoundError: Failed to execute 'insertBefore' on 'Node':
The node before which the new node is to be inserted is not a child of this node.
    at ensureButton (storyboard_background_extension.js:81:15)
```
同类错误还有 `style_reference_manager_extension.js:381` 的 `ensureStep3EntryButton`。

**为什么连报错日志都被忽略**
`storyboard_background_extension.js:316-319` 的重试逻辑：
```js
const timer = setInterval(() => {
  boot();
  if (document.getElementById('step3-btn-background-settings')) clearInterval(timer);
}, 500);
```
按钮因异常永远插不进去 → 清除条件永远不成立 → **每500ms 无限重试直到页面关闭**。这不仅让功能失效，还持续占用主线程、污染控制台，使真实错误被淹没。

**用户影响**
用户想设置视频背景时，界面上根本没有这个按钮，且没有任何提示说明"功能不可用"；只能放弃或提工单。删除全部图片同理——这是清理项目的高频操作。

**修复方案（最小改动）**
```js
// 方案 A（推荐）：改为向同一父节点的参照元素插入
const host = document.querySelector('#step-panel-3 .workflow-toolbar') || toolbar;
// 方案 B：兜底 try/catch + 有限重试，杜绝无限循环
let tries = 0;
const timer = setInterval(() => {
  if (++tries > 20) return clearInterval(timer);   // 最多重试 20 次
  try { boot(); } catch (_) {}
  if (document.getElementById('step3-btn-background-settings')) clearInterval(timer);
}, 500);
```

### B2. 分镜数据缺失时，Step3 呈现「红色报错 + 完全空白」，用户无处下手

**现象**
打开一个未生成分镜的项目并进入「图片生成」，顶栏弹出红色「错误: 分镜规划尚未生成」，同时**整个内容区一片空白**——只有工具栏，没有任何空状态说明下一步该做什么。

**完整因果链（已实测追踪）**
```
用户点击步骤栏「3 图片生成」
   ↓
前端直接放行，切到 Step3 面板（未校验 Step2 是否已完成）
   ↓
页面加载即请求 /api/projects/<id>/steps/3/prompts
   ↓
后端返回 400  {"detail":"分镜规划尚未生成"}
   ↓
前端弹出红色错误 Toast
   ↓
但 Step3 界面已切换、内容区空白、网格容器 #step3-images-grid 为空
```

实测证据：
```json
"apiCalls": [{ "url": "/api/projects/.../steps/3/prompts",
                "status": 400, "body": "{\"detail\":\"分镜规划尚未生成\"}" }],
"banner": { "text": "错误: 分镜规划尚未生成", "color": "rgb(185,28,28)" },
"empty":  { "hasVisual": false, "textPreview": "图片生成与管理 批量上传 批量生图 复制提示词 生图 Prompt 图片风格 IP 形象" }
```
`index.html:364` 存在 `<div id="step3-images-grid" class="step3-grid-four"></div>`，但**该容器没有任何空状态兜底内容**。

**用户影响**
用户已经完成前几步，点「图片生成」却看到红色报错和空白页。红色 Toast 是全局浮层，几秒后消失，而页面留白是永久的——用户既不知道发生了什么，也不知道该回到第2 步还是先上传图片。**这是最典型的"用户流失点"**。

**修复方案**
1. `navigateToStep()` 增加前置校验：`data-step="3"` 需校验 Step2 是否 `done`，未完成则**阻止跳转 + 就地提示"请先完成第 2 步：分镜规划"**，而不是放行后弹全局错误。
2. 为 `#step3-images-grid` 补空状态（与项目现有风格一致，参考 `projects.js` 已有的"立即新建"按钮模式）：
   ```html
   <div class="step3-empty">
     <p>还没有可生成的画面。</p>
     <p class="step3-empty-hint">请先完成第 2 步分镜规划，或直接批量上传图片。</p>
     <button class="secondary">批量上传</button>
   </div>
   ```
3. 后端 400 属"预期内的流程未完成"，不应走错误 Toast 通道（与项目既定的"校验提示就地呈现"策略一致，见下）。

### B3. 八步导航完全无法用键盘操作

**现象**
实测步骤栏8 个步骤项：`stepItems: 8`、`stepItemsFocusable: 0`、`stepItemsWithRole: 0`。
尝试 `first.focus()` 后 `document.activeElement` 仍是 `BODY`（`focused: false`）——**用户无法用 Tab 键到达任何步骤**。

**证据**
- `index.html:100-152`：8 个 `<li class="step-item">` 无 `tabindex`、无 `role`
- `event_bindings.js:94-100`：只绑定 `click`，无键盘事件
- 全站 `onkeydown` 数量 = **0**

**用户影响**
这是整个应用的**主干导航**。键盘用户、开关机用户、运动障碍用户、语音控制用户**无法在八步之间移动**，等于应用不可用。这不是边缘场景，是可用性阻断（WCAG 2.1 AA 键盘可达性）。

同时，分镜缩略图拖拽排序（`storyboard.js:871`）也**没有任何键盘替代方案**，而分镜顺序直接决定视频页序。

**修复方案**
```html
<!-- index.html:100 -->
<li class="step-item" data-step="1" role="tab" tabindex="0" aria-selected="true">
```
```js
// event_bindings.js:94 追加方向键漫游
stepItems.forEach((item, i) => item.addEventListener('keydown', e => {
  const d = { ArrowDown: 1, ArrowRight: 1, ArrowUp: -1, ArrowLeft: -1 }[e.key];
  if (!d) return;
  e.preventDefault();
  stepItems[(i + d + stepItems.length) % stepItems.length].focus();
}));
```
拖拽排序补充：在缩略图上监听 `Alt + ←/→` 调换顺序，`aria-label` 写明「第 N 页，Alt+左右方向键调整顺序」。

## 三、🟠 Warning

### W1. 校验失败被"静默"，且承诺的"就地呈现"未落地（设计契约违约）

这是本次评审**定性最需要准确**的一条，务必区分清楚：

**这不是"Toast 被丢弃"的bug，而是一次明确的、有意的产品决策。**
证据链完整：
- `docs/notification-audit-2026-09-29.md:49`：「引导/校验提示（请先/请填写/请至少/不能为空）**一律静默。它们是预期交互，就地呈现（表单高亮、按钮禁用、步骤内状态条）即可**」
- git 记录显示这是连续三次收紧的结果：`0b540a3 Reduce workspace notification noise` → `f7d8c01 fix: show notifications only for actionable failures` → `a7f991d fix: show toasts only for genuine failures and errors`
- `ui_foundation.js:28-30` 的实现与文档完全一致：
  ```js
  const presentation = getToastPresentation(message);
  if (presentation.tone !== 'error') return null;   // 只有真实失败才弹
  ```

**真正的问题是：文档承诺的"就地呈现"在部分场景没有实现。**

以 `static/storyboard.js:453-480` 的分镜校验为例：
```js
if (!slides[i].main_title) {
  showToast(`⚠️ 第 ${i + 1} 页标题不能为空`);  // ← 被 ui_foundation.js:30 丢弃
  return false;                                 // ← 且无任何就地提示
}
```
同一文件 `storyboard.js:548-586`（批量导入）却**正确实现了就地错误**：
```js
previewEl.innerHTML = `<div class="step2-batch-import-error">❌ 第 ${i+1} 项缺少字段</div>`;
```
**同一功能的两个入口，一个做了就地提示、一个没做**——这证明是遗漏，不是设计。

叠加问题：`storyboard.js:450` 的 `focus()` 定位到演讲稿框，但报错说的是"标题不能为空"，**焦点与错误对象不一致**，用户会盯着错误的字段。

**用户影响**
用户点了"进入图片生成"，什么都没发生，也不知道哪里错了，只能反复点击并认为应用卡死。

**修复方案**
在 `storyboard.js` 校验失败处补就地错误（复用已有样式类）：
```js
function showStep2FieldError(msg, fieldEl) {
  clearStep2FieldErrors();
  const tip = document.createElement('div');
  tip.className = 'step2-batch-import-error';   // 复用现成样式，零新增CSS
  tip.textContent = msg;
  fieldEl?.closest('.step2-slide-card')?.appendChild(tip);
  fieldEl?.focus();
}
```
并补一条 `checks/` 下的断言：所有 `showToast` 调用点若属校验类，必须存在对应就地提示元素。

### W2. 15/16 弹窗无 Esc 关闭、无焦点陷阱、无焦点管理

**证据**
- 全站 Escape 处理仅 1 处：`event_bindings.js:167`（只针对 `modal-step3-ai`）
- `grep "trapFocus|focusable"` 命中 0；`autofocus` 计数 0
- 19 处 `.focus()` 全部用于"校验失败回焦"，**没有一处是"打开弹窗时移入焦点"**

最严重的是 `ui_foundation.js:65-99` 的**全局确认框 `showCustomConfirm`**——19 处危险删除全部走它。它只能点"是/否"，**纯键盘用户无法完成任何一次删除确认**。

未支持 Esc 的弹窗（15 个）：`modal-create`、`modal-edit-project`、`modal-settings`、`modal-creation-config-*`、`modal-model-management`、`modal-confirm`、`modal-ip-character`、`modal-step2-generate`、`modal-step2-batch-import`、`modal-step6-ai-prompt`、`modal-storyboard-rules`、`modal-subtitle-settings`、`modal-animation-settings` 等。

**修复方案**（在 `ui_foundation.js` 统一实现，一次接入 16 处）
```js
const FOCUSABLE = 'button,[href],input,select,textarea,[tabindex]:not([tabindex="-1"])';
function openModal(el, opener) {
  el.style.display = 'flex';
  (el.querySelector(FOCUSABLE) || el).focus?.();
  el._trap = e => {
    if (e.key !== 'Tab') return;
    const f = [...el.querySelectorAll(FOCUSABLE)].filter(n => n.offsetParent);
    if (!f.length) return;
    const [first, last] = [f[0], f.at(-1)];
    if (e.shiftKey && document.activeElement === first) { e.preventDefault(); last.focus(); }
    else if (!e.shiftKey && document.activeElement === last) { e.preventDefault(); first.focus(); }
  };
  document.addEventListener('keydown', el._trap, true);
}
document.addEventListener('keydown', e => {
  if (e.key !== 'Escape') return;
  const top = [...document.querySelectorAll('.modal-overlay')].filter(n => n.offsetParent).pop();
  if (top) { top.style.display = 'none'; document.removeEventListener('keydown', top._trap, true); }
});
```
另：全局确认框的两个按钮建议加 `autofocus` 到「否」（安全侧默认），当前是默认聚焦「是」，存在误按风险。

### W4. 禁用态没有解释"为什么灰"（156 处）

**证据**：全站 `.disabled =` 共 156 处 / 22 个文件；HTML 静态 `disabled` 7 处，仅 2 处带 `title`——且这 2 处 `title`答非所问：
- `index.html:472` `title="确认并进入勾画标注"`（功能说明，非禁用原因）
- `index.html:711` `title="仅在点击后下载字幕文件"`

其余 5 处（`:203,238,1566,1567,1613`）**完全无任何说明**。

典型：`index.html:238` 的 `<button id="step2-btn-generate-visual" disabled>`，用户无法得知是要先生成演讲稿、还是要等项目状态同步。

**用户影响**：按钮灰掉时用户只能猜，倾向于反复点击。

**修复**：统一工具函数，禁用时同时设置 `title` + `aria-describedby`：
```js
function setDisabledReason(btn, reason) {
  btn.disabled = true;
  btn.title = reason;
  btn.setAttribute('aria-describedby', 'hint-' + btn.id);
}
```

### W5. 六类长耗时操作无法取消，且未告知"可以离开页面"

演讲稿生成、内容可视化、生图、TTS、Mask 标注、视频渲染——全部无取消按钮。全站搜索 `取消生成|停止生成|中止|abortRender|cancelRender` 命中 **0**。

`api_client.js:10` 的 `AbortController` 仅用于 120s 超时，**不是用户可触发的取消**。`narration_audio.js:549` 的注释明确写着"客户端断连不再中断合成"——说明**技术上可以后台继续跑，但从未告知用户**。

**用户影响**：点"批量生成 20 张图"后无法反悔，唯一"逃离"手段是关页面，但不知道关了会怎样，于是只能干等。

**修复**：
1. 长任务按钮旁加"取消"（接`AbortController.abort()` + 后端任务取消接口）
2. 任务启动时统一提示：**「任务在后台运行，可切换页面；关闭浏览器不会中断。」**

## 五、⚪ 技术债（不直接影响当前体验）

### D1. 样式层"三层叠加"结构
4 个 CSS 文件共 18608 行、2107+ 条规则；硬编码 hex 色值 **1590 处 / 596 个不同色值**；`!important` 共 **4959 处**（style.css 2619 + stitch.css 2340）；两套互不共享的 CSS 变量（`--color-primary-deep` ≠ `--stitch-navy`）。

其中 **"Soft Pastel Studio" 遗留块占 style.css 的 28%**（3561 行 / 665 条规则），而 `AGENTS.md:61-62` 已声明该主题"已退役"。真正纯粹的死代码约 2000 行。

**风险**：当前渲染正确（实测 CTA 30px 橙色合规），但**这种"靠层叠顺序侥幸正确"的模式极其脆弱**——本次评审中 `stitch.css:430` 的深色规则被覆盖就是例证。任何人在前面加一层都可能让界面静默变形。

**建议**：用 PurgeCSS 清理死代码 → 建立唯一 `:root` 令牌层 → 收敛断点（85 个 `@media` 用了约 30 个不同断点值）。

### D2. 步骤编号内外不一致
实测 `data-step` 序列为 `1, 2, 3, 5, 6, 10, 9, 8`，而显示顺序是第 1~8 步。这是"可见步骤"与"内部 API 编号"的历史映射（`AGENTS.md` 有说明）。当前功能正常，但**维护时极易误判**——例如误以为"第 6 步"对应 `data-step="6"`，实际 `data-step="10"` 才是"第 6 步：勾画标注"。建议在 DOM 上增加 `data-visible-step` 显式标注，减少误读。

## 八、给项目的一句建议

这个项目的**设计规范质量高于实现质量**——`ui-spec.md` 精确到"按钮高 30px、圆角 8px、同组间距 8px"，实测发现工作区关键指标（CTA 30px 橙色、标题栏 59px、按钮高度统一）**确实达标**，说明规范在落地层面是被认真执行的。

真正的风险不在"做得不够"，而在**两处**：
1. **静默失效**（B1/B2）——规范覆盖不到"功能压根没渲染出来"的情况，需要靠运行时巡检而非文档审查发现
2. **样式层叠的脆弱性**（D1）——当前正确是靠层叠顺序"侥幸"维持的，`stitch.css:430` 就是活例

建议建立**自动化 UI 回归基线**：把本次 7 项实测指标写成断言脚本（项目已有 `checks/` 目录和 `test_frontend_quality.js` 基础，接入成本很低），每次改动后自动校验。这样 B1/B2 这类问题会在第一次发生时就被拦下。
